# محل مشاهده‌شدهٔ host_id پیش از حساب: UserUUID در رجیستری

## به‌روزرسانی a11: نوشتن و خواندن مستقیم ثبت شد

در a11، UserUUID پیش از هدف غایب بود؛ Setup در startup اول مقدار برابر با host_id پیام سخت‌افزار را با RegSetValueExW موفق نوشت، و Agent در هر دو startup مقدار برابر را با RegQueryValueExW موفق خواند. بنابراین محدودیت a10 دربارهٔ نبود شاهد مستقیم خواندن/ایجاد، در سطح API با آزمایش مستقل جدید رفع شد؛ مسیر تخصیص داخلی provider هنوز اثبات نشده است. [گزارش کامل a11](PRELOGIN-HOST-ID-REGISTRY-TRACE.fa.md).

بخش‌های زیر تاریخچه و حدود **a10** هستند، نه نفی نتیجهٔ جدید a11.

## نتیجهٔ قطعی در محدودهٔ a10

در اجرای a10، مقدار `host_id` همراه پیام سخت‌افزار پیش از ورود به حساب، پس از هر دو startup دقیقاً با مقدار رجیستری زیر برابر بود:

```text
HKEY_CURRENT_USER\Software\Blizzard Entertainment\Blizzard Error
Value name: UserUUID
```

شناسهٔ واقعی و hash آن منتشر نشده‌اند. برابری دقیق در حافظهٔ ماشین آزمایش محاسبه شد؛ گزارش عمومی فقط نام ثابت نرم‌افزاری و نتیجهٔ مقایسه را دارد. نام‌های کلید/مقدار با literalهای تصویر اجرایی pinned نیز تأیید شدند تا نام خصوصی دستگاه یا کاربر منتشر نشود.

هر دو مرحله بدون ورود به حساب، بدون اقدام Install و بدون دانلود بازی انجام شدند. پس از توقف کامل فرایندها، startup دوم با پیکربندی حفظ‌شده انجام شد: `host_id` برابر بود. در هر مرحله، یک پیام مشخصات تا ارسال موفق سوکت و تطبیق ciphertext در ضبط محلی NIC پیوند خورد. دریافت کاربردی یا ذخیرهٔ سرور هنوز اثبات نشده است.

## محدودیت‌های a10؛ برای به‌روزرسانی API به a11 مراجعه شود

- **محل حضور مقدار با منشأ خواندن آن یکی نیست.** ابزار پس از خروج فرایندها رجیستری را خواند؛ هنوز trace مستقیمی از خواندن همین مقدار توسط provider نداریم. `provider_read_source_proven=false` عمداً حفظ شده است.
- snapshot رجیستری پیش از اولین اجرا نداریم؛ بنابراین نمی‌گوییم نصاب در همین مرحله مقدار را ساخته است.
- `source_id` نام داخلی interface پیکربندی در بررسی ایستا است؛ مقدار مشاهده‌شده در رجیستری `UserUUID` نام دارد. برابری نام‌ها یا مسیر دادهٔ بین آن‌ها هنوز ثابت نشده است.
- HKCU محدودهٔ پروفایل کاربر ویندوز است، نه اثبات «شناسهٔ یکتا برای هر نصب»، هویت واقعی شخص یا HWID دائمی.
- نام `Blizzard Error` استفادهٔ انحصاری برای کرش را ثابت نمی‌کند؛ همین شناسه همراه پیام عادی StartAgent پیش از حساب مشاهده شد.
- reboot ویندوز، reinstall، مقایسهٔ ماشین مستقل، اتصال به حساب و علامت‌گذاری فایل‌های WoW بررسی نشده‌اند.

در هر مرحله یک فایل بزرگ‌تر از سقف کنار گذاشته شد؛ خطاهای فایل و رجیستری صفر و budget_reached=false بودند. جست‌وجو محدود به ریشه‌های نرم‌افزاری مشخص، سقف اندازه و تعداد، و بدون دنبال‌کردن reparse بود؛ نبود تطبیق در فایل‌های خوانده‌شده، اثبات نبود آن در تمام دیسک نیست. ابزار storage فقط‌خواندنی است و رجیستری هدف را تغییر نمی‌دهد.

۸۰ آزمون Python با وابستگی decoder موجود پاس شدند؛ اعتبارسنجی schema خروجی a10 نیز پاس شد. هر دو مرحله خطای collector، رویداد افتاده و خطای مهلک صفر داشتند. غیرفعال‌سازی LSO تنظیم کارایی capture بود، نه تضعیف TLS؛ هیچ تغییری در اعتبارسنجی TLS انجام نشد.

## گام بعدی

snapshot پیش از هدف و trace مستقیم خواندن/نوشتن API در a11 انجام شد؛ تکمیل مسیر تخصیص داخلی provider و آزمون‌های مستقل reboot/reinstall هنوز باقی است. حضور شناسهٔ پایدار، امکان مرتبط‌کردن پیام‌ها را توضیح می‌دهد؛ دلیل سازمانی و ضرورت جمع‌آوری را ثابت نمی‌کند. سؤال فایل‌های WoW همچنان در صف است.
