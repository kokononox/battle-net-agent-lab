# اصلاحیهٔ ابزار مرحله‌ای 0.1.1 — خطای add هنوز ریشه‌یابی نشده

کاربر روی نسخهٔ 0.1.0 خطای firewall_operation_failed_add گزارش کرد. این خطا مرحلهٔ ساخت و تمام readbackهای بعدی را یکی کرده بود؛ متن اصلی استثنا ذخیره نشده و علت دقیق تاریخی هنوز معلوم نیست. ساخته‌شدن احتمالی rule منتفی نیست. کاربر ابتدا مسیر تشخیصی جدا را کنار گذاشت و سپس اصلاح ابزار اصلی را خواست.

منبع 0.1.1 با مقایسهٔ صریح protocol/filter، پذیرش فقط /32 همان IPv4، readback محدود و گزارش مرحلهٔ امنٔ خطا آماده شد. New-NetFirewallRule فقط یک بار فراخوانی می‌شود؛ تکرار فقط خواندن وضعیت است. timeout مدیریت ۶۰ ثانیه است و guard/journal/rollback قبلی حفظ شده‌اند. خروجی firewall-error JSON شامل مرحله، reason، کدهای عددی و پرچم تطبیق‌هاست، نه متن خام استثنا یا مسیر/حساب.

۴۴ تست محلی/mock پاس شدند؛ این تست‌های واقعی Windows نیستند. علت خطای کاربر و رفع واقعی آن هنوز تأیید نشده‌اند. هیچ سیاست امنیتی برای رفع خطا ضعیف نشده است.

بستهٔ تحویلی Update بدون runtime است و باید روی همان پوشهٔ قبلی، با حفظ runtime/private-state/output اعمال شود. پس از بستن کنسول و پایان مهلت guard، Restore.cmd اصلاح‌شده باید نبود ruleهای همان journalها را تأیید کند؛ تا آن زمان آزمایش تازه انجام نشود. سپس فقط یک مرحله مجاز به آزمون دستی است. پوشهٔ قبلی نباید پیش از بازیابی حذف یا جابه‌جا شود. گزارش عمومی add به معنی نبود rule یا شکست قطعی خود New-NetFirewallRule نیست.
