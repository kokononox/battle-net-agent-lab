# ابزار مرحله‌ای مقصدهای WoW — نسخهٔ آزمایشی 0.1.0

## ورودی و مرحلهٔ بازی
کاربر در نمونهٔ `dependency-result-865e73faab304d5eb897afc386f28eab.json` ورود موفق و حدود ۱۰ ثانیه حضور در محیط ریلم را گزارش کرد. این مرحله گزارش کاربر است، نه تشخیص خودکار. گزارش ابزار 0.2.2 زمان ۶۱٫۲ ثانیه و وضعیت capture_incomplete_with_metadata با exit code 1 دارد؛ metadata خوانده شده اما پوشش کامل تأیید نشده. TLS خوانده نشده و ارسال CPU/BIOS همچنان نامعلوم است.

## درخواست و پیاده‌سازی
کاربر ابزار مرحله‌ای خواست: هر بار یک مقصد مسدود، کاربر ورود تا محیط بازی را امتحان کند و مشاهده را انتخاب کند. نسخهٔ 0.1.0 در `user-tools/wow-endpoint-steps-0.1.0/` آماده شد. فهرست هفت مقصد TCP و بیست مقصد UDP از همان نمونه است؛ loopback حذف شده و UDP اختیاری است.

هر مرحله فقط یک قانون outbound برای مسیر منتخب Wow.exe و یک IP/پورت/پروتکل می‌سازد. ایجاد rule در PersistentStore و حضور enabled آن در ActiveStore خوانده می‌شود؛ packet-level blocking ثابت نشده، به‌خصوص با VPN. نتیجهٔ کاربر ثبت، حذف rule و نبود آن بررسی، سپس بازگشت رفتار عادی از کاربر پرسیده می‌شود. تا پاسخ مثبت مرحلهٔ بعد باز نمی‌شود. ابزار حساب/رمز نمی‌گیرد، وارد بازی نمی‌شود و اتصال‌های قبلی را به‌اجبار قطع نمی‌کند.

## بازیابی و حدود
Name و Group تصادفی و journal اختصاصی قبل از ساخت؛ حذف فقط با مالکیت مطابق. نگهبان مستقل پیش از ساخت آماده می‌شود و پس از ۵ دقیقه یا خروج پردازهٔ اصلی حذف را درخواست می‌کند. توقف سیستم/sleep/kill/خطای فایروال می‌تواند بازیابی را به تأخیر بیندازد. قواعد PersistentStore ذاتاً خودمنقضی نیستند؛ حذف در تمام شرایط تضمین نمی‌شود. Restore.cmd و بازیابی اجباری journalهای همان پوشه در شروع فراهم‌اند. پوشه را پیش از بازیابی جابه‌جا یا حذف نکنید. در خطای مبهم ساخت، journal/نگهبان نگه داشته می‌شوند و مرحلهٔ بعد قفل است.

hosts، VPN، وایت‌لیست، پروفایل‌های فایروال، گواهی، ExecutionPolicy و تنظیمات بازی تغییر نمی‌کنند. ازقبل‌فعال‌بودن همهٔ پروفایل‌های فایروال و سرویس لازم است؛ ابزار آن‌ها را روشن نمی‌کند و سیاست سازمانی را دور نمی‌زند. هیچ proxy، debugger، injection یا capture تازه‌ای اضافه نشده است.

## QA و وضعیت واقعی
۳۶ آزمون محلی/مصنوعی پاس شدند؛ workflow HTTP با firewall mock و نگهبان با WinAPI mock بررسی شدند. syntax و manifest/ZIP بررسی و چهار حالت رابط شامل حالت باریک/خطا بصری بازبینی شدند. اجرای واقعی Windows Firewall، نگهبان Windows، VPN یا لاگین بازی توسط سازنده انجام نشده است. اولین اجرای کاربر باید فقط یک مرحله و سپس تأیید بازیابی باشد؛ موفقیت بازی یا جلوگیری از تله‌متری ادعا نشده است.

منبع، راهنما و تست‌ها در Git هستند؛ runtime باینری فقط در ZIP تحویلی است. manifest تحویلی شامل runtime نیز هست و checkout Git بدون آن قابل اجرا نیست. گزارش اشتراکی IP/پورت/hash/زمان و انتخاب کاربر دارد؛ private-state شامل مسیر و journal بازیابی محلی است و نباید ارسال شود. دادهٔ خام ضبط و متن خام جلسه سینک نشده‌اند.
