# N1 — شناسایی فقط‌خواندنی کتابخانه‌های شبکه

## هدف
در گزارش T1.1، چهار مقصد عمومی TCP/443 از یک battle.net.exe امضاشده دیده شد، ولی از همان فرایند هیچ input capture ثبت نشد. هنوز محتوا یا علتِ فقدان پوشش معلوم نیست. N1 فهرست محدود کتابخانه‌های مرتبطِ بارشده و نام APIهای شناخته‌شده در جدول import/export فایل آن‌ها را با PID صاحب TCP مرتبط می‌کند؛ **محتوا را رمزگشایی نمی‌کند و هیچ کتابخانه‌ای را دلیل قطعیِ استفاده واقعی از TLS نمی‌داند**.

شواهد قدیمی D2/E2 عمدتاً setup و Agent را پوشش می‌دهند و module categories محدودی دارند؛ شناسایی فرایند صاحب HTTPSهای نمونه جدید را جایگزین نمی‌کنند. صرف وجود نام libcef/OpenSSL/Schannel، استفاده از آن برای آن اتصال را ثابت نمی‌کند؛ نبود SSL_write در export هم statically linked یا dynamic resolving را رد نمی‌کند.

## نصب مکمل بدون دانلود دوباره runtime
1. ZIP را **داخل ریشه همان بسته اصلی Level3-Request-Audit-T1.1** استخراج کنید؛ جایی که runtime و app و MANIFEST-SHA256.json دارد. app ادغام می‌شود؛ هیچ فایل قبلی جایگزین نمی‌شود. این مکمل standalone نیست و Python جدید/وابستگی جدید نمی‌خواهد.
2. پنجره همه مشاهده‌گرهای قبلی از جمله T1.1 را ببندید. WoW بسته بماند. **Battle.net می‌تواند باز باشد، اما آپدیت حتماً Pause، automatic updates خاموش و حساب signed out بماند. BAT۰۶ را تغییر ندهید.**
3. `N1-Network-Inventory.cmd` را با **Run as administrator** اجرا کنید. اگر Battle.net بسته است، فقط خودتان با شرایط فوق بازش کنید؛ Resume نکنید.
4. پیش‌شرط‌ها را با `PAUSED` تأیید کنید. حدود یک دقیقه نمونه‌برداری می‌کند؛ کارِ جاری بررسی امضا/فایل ممکن است زمان بیشتری بگیرد. Q پایان زودهنگام است، نه فرمان Pause یا بستن Battle.net. این مرحله اصلاً نیاز به دانلود ندارد.
5. فایل `output/n1-network-inventory-....json` را بفرستید. اگر STOP دیدید، متن همان پیام را بفرستید؛ دانلود را برای دورزدن خطا شروع نکنید.

## چه می‌خواند و چه صادر می‌شود؟
- فقط Battle.net.exe و Agent.exe با image basename سازگار و امضای native معتبر Blizzard؛ PID/parent PID، هش image و وضعیت بررسی ثبت می‌شود. هویت creation/path در RAM پیش/پس از snapshot TCP دوباره کنترل می‌شود تا PID reuse بی‌دلیل نسبت داده نشود.
- فهرست بارشده با API استاندارد Windows خوانده می‌شود. نام‌های خارج فهرست ثابت networking/CEF/TLS صادر نمی‌شوند؛ فقط شمار آن‌ها ثبت می‌شود. مسیر کامل هیچ فایل یا command line صادر نمی‌شود.
- فایل image و ماژول‌های شناخته‌شده فقط روی دیسک، به‌صورت داده خوانده و hash می‌شوند؛ برای بازرسی load/execute نمی‌شوند. جدول PE import/export فقط برای نام ثابت APIهای شبکه/TLS بررسی می‌شود؛ آدرس تابع/رشته‌های آزاد/مقادیر کاربر صادر نمی‌شود. اثبات تطابق دقیق فایل دیسک با memory image نیست.
- IP/port عمومی TCP و فرایندِ دارای هویت بررسی‌شده ثبت می‌شود؛ به معنی دریافت سرور یا حجم upload/download نیست. اتصال‌ها ممکن است در حالت Pause دیده نشوند. UDP/QUIC، delay import و تمام static/dynamic linking پوشش کامل ندارند؛ نبود ماژول/نماد برابر نبود استفاده نیست.
- هیچ payload، کلید TLS، command line یا مقدار حساب خوانده نمی‌شود؛ hook/injection، hosts/firewall/cache write، Update/Pause/Cancel/Repair، lifecycle control، game-file write یا upload خودکار ندارد.
- بررسی امضای image توسط همان helper قبلاً آزموده‌شده T1.1 انجام می‌شود و ممکن است با سرویس‌های گواهی ارتباط بگیرد. باز بودن Battle.net می‌تواند ترافیک خودش را داشته باشد؛ این ابزار privacy firewall نیست.
- سقف‌ها:۴۸ فرایند،۹۶ فایل شناخته‌شده، هر فایل تا۱GiB و مجموع hash تا۲GiB؛۲۵۶ مقصد TCP؛ PE تا۹۶ section/۶۵۵۳۶ export name/۳۲۷۶۸ thunk. رسیدن به سقف یا خطا پوشش را ناقص می‌کند.

## سلامت بسته و آزمون
مکمل manifest اصلی را حذف/بازنویسی نمی‌کند؛ hash manifest و source build باید دقیقاً با T1.1 تحویلی (`7eacb50b04ffe4676ff85a8c37df9f5e03d1a97e`) سازگار باشد، و فایل‌های اصلی نیز بررسی می‌شوند. خود فایل‌های جدید جزء manifest قدیمی نیستند؛ منبع و SHA256 مستقل آن‌ها همراه مکمل است و در مخزن ثبت می‌شود.

۲۵ آزمون آفلاین parser/bounds/identity/non-mutation/حذف مسیرها با PE مصنوعی متعلق به تست پاس شده‌اند. **این مکمل جدید هنوز روی Windows اجرا نشده است**؛ helperهای native پایه همان نسخه قبلاً آزموده‌شده‌اند. runner/build/نصب بازی یا هزینه تازه‌ای برای ساخت این ZIP راه‌اندازی نشده است. گزارش کاربر گام اعتبارسنجی بعد است؛ هیچ مجوز Resume از N1 صادر نمی‌شود.
