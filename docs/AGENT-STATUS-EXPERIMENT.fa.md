# آزمایش مشاهدهٔ وضعیت Agent بدون حساب یا بازی

## سؤال و منبع

بعد از شاهد واقعی `/agent` در run `39098949663`، آیا Agent بدون ورود حساب یک درخواست `GET /game` با توکن محلی همان اجرا را پاسخ می‌دهد؟ منبع مسیر، تابع `get_install_summary` در [bnet-toolbox، commit ثابت](https://github.com/Ghostopheles/bnet-toolbox/blob/d4956d9aa3eaa858b1d2606093298c066ec8a2b7/bnet_toolbox/tools.py) است. این API عمومیِ پشتیبانی‌شدهٔ Blizzard فرض نمی‌شود.

## دامنهٔ اجرای یک‌باره

- فقط Windows hosted تازه، push دارای پیام مجوز دقیق مرحلهٔ وضعیت و run_attempt=1؛ تکرار/dispatch، self-hosted و دستگاه کاربر مجاز نیستند. bootstrap مرحلهٔ قبل، امضا/ناشر Blizzard، محیط پاک و محافظ انتخاب زبان بدون کلیک نصب حفظ می‌شوند.
- حداکثر دو درخواست HTTP محلی: یک `GET /agent` برای دریافت token و، فقط در صورت موفقیت آن، یک `GET /game` به همان loopback listener/PID/فایل امضاشده. ریدایرکت، retry، port scan، endpoint جایگزین و Cookie وجود ندارند. token بدون CR/LF و ASCII چاپ‌پذیر لازم است.
- token فقط در حافظهٔ همان process استفاده می‌شود؛ report sink داخلی صرفاً dictionary بدون token است. قبل/بعد هر درخواست مسیر فرایند و مالک listener بررسی می‌شوند. hook فقط برای observer ثابت در مخزن است، نه plugin یا پیکربندی خارجی.
- درخواست `/game` فقط برای مشاهدهٔ summary انتخاب شده؛ هیچ `POST/PUT/DELETE`، initialize/install/update/repair/uninstall، hardware، session حساب، فایل بازی، کشور/locale فرضی یا محصول مشخصی ارسال نمی‌شود. درخواست مشاهده‌ای نیز تضمین صفر side-effect داخلی Agent نیست؛ همه چیز در VM دورریختنی است.
- حداکثر پاسخ پذیرفته‌شدهٔ هر درخواست 64 KiB؛ یک بایت اضافه فقط برای تشخیص تجاوز. socket timeout سه ثانیه برای I/O و سقف کل job ده دقیقه؛ مهلت کل پاسخ سه ثانیه ادعا نمی‌شود. راه‌انداز حداکثر 128 MiB است؛ سقف سخت حجم شبکهٔ فرزند نداریم. هیچ دانلود بازی درخواست نمی‌شود.

## خروجی و معنای موفقیت

گزارش nested، schema=`logged-out-agent-status-1`، دارای handshake با سقف یک درخواست و شمار جداگانهٔ `/game` با سقف یک درخواست است؛ total باید جمع دقیق آن دو و حداکثر دو باشد. هیچ token، نام محصول، link، مسیر، response خام، log یا binary صادر نمی‌شود. فقط HTTP status، طول، enum شکل پاسخ و count محدود گزارش می‌شوند.

شکل پذیرفته‌شده: object خالی، error=0 بدون entry، یا حداکثر 256 entry با شکل mapping دارای link رشته‌ای. error مثبت به‌عنوان محصول شمرده نمی‌شود. schema ناشناخته، redirect، 401/403، تغییر مالکیت و تجاوز سقف به توقف می‌انجامند؛ نیاز ورود حساب از شکست نتیجه گرفته نمی‌شود و endpoint تازه حدس زده نمی‌شود.

`local_authorization_sent` به معنی تلاش با header محلی است، نه اثبات اینکه سرور الزاماً آن را احراز کرده است. پاسخ 200 به درخواست دارای token، بدون مقایسه با درخواست فاقد token، اثبات ضرورت token نیست. summary خالی در محیط بدون بازی، وضعیت نصب موجود کاربر یا تشخیص نسخهٔ Retail را ثابت نمی‌کند.

publisher مجزا در Linux schema و source/run identity را دوباره بررسی و فقط `reports/agent-status-latest.json` و سابقهٔ همان run را منتشر می‌کند. گزارش قدیمی handshake دست‌نخورده می‌ماند. گزارش bootstrap و پاسخ خام در artifact نیستند. تست native مالکیت و تست واقعی HTTP تنها از fixture مصنوعی loopback استفاده می‌کنند؛ جای نتیجهٔ Agent واقعی را نمی‌گیرند.

## مرز گام بعد

Classic فعلاً دانلود یا initialize نمی‌شود. پیش از هر آزمایش بازی باید محصول/build دقیق، حجم معتبر دانلود/نصب/staging، فضای واقعی مقصد و baseline قدیمی قابل‌استفاده مشخص شوند. نصب تازهٔ build جاری، تست آپدیت نسخه‌به‌نسخه نیست؛ موفقیت Classic هم سیاست کامل Retail را اثبات نمی‌کند. هیچ کپی نصب 130 گیگی، فایل حجیم، حساب یا تغییر نصب اصلی لازم نیست. اجرای این مرحله انتخاب معماری وابسته به Agent به جای موتور مستقل محسوب نمی‌شود.
