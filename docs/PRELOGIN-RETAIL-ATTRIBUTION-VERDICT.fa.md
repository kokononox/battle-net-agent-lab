# حکم شواهد: ترافیک پیش از حساب، وضعیت نصب و دانلود واقعی WoW

## نتیجهٔ اصلی

**شمارش ترافیک، حتی وقتی به خود Agent منتسب باشد، شاهد کافیِ دانلود فایل بازی نیست.** در کنترل تازهٔ T7، ابزار آزمایش هیچ API محصولی را فراخوانی نکرد؛ تنها handshake اولیهٔ `GET /agent` انجام شد. با این حال شمارندهٔ بومی ویندوز روی اتصال‌های خارجی IPv4 TCP متعلق به همان فرایند، **۲٬۷۹۵٬۲۴۱ بایت ورودی** ثبت کرد. کنترل، بررسی هویت قبل و بعد، کالیبراسیون تازه و پاک‌سازی Job همگی کامل شدند.

این نتیجه فرض «هر ترافیک Agent پس از بازشدن نصاب، همان دانلود WoW است» را رد می‌کند؛ **نشان نمی‌دهد این ترافیک دقیقاً چه محتوایی دارد**. فعالیت خودکارِ Agent، بروزرسانی اجزای آن، درخواست‌های درونی آن، و سایر انواع محتوا از هم تفکیک نشده‌اند. این آزمایش، مقایسهٔ علّیِ تصادفی‌شده با/بدون initialize نیست؛ اعداد اجراهای جدا از هم کم نشده‌اند.

- [کنترل بدون فراخوانی محصول، T7](https://github.com/kokononox/battle-net-agent-lab/blob/aa1a08300b6c1d44b8057ea19464c78adca4e74b/reports/prelogin-preproduct-control-latest.json)
- [شمارندهٔ فرایند، T7](https://github.com/kokononox/battle-net-agent-lab/blob/aa1a08300b6c1d44b8057ea19464c78adca4e74b/reports/prelogin-owned-tcp-meter-latest.json)
- [گزارش کامل با صفر درخواست محصول و initialize=false](https://github.com/kokononox/battle-net-agent-lab/blob/aa1a08300b6c1d44b8057ea19464c78adca4e74b/reports/prelogin-retail-prepare-runtime.json)

## سه پرسش، سه سطح متفاوت از شواهد

1. **ارسال مشخصات سیستم پیش از حساب:** از قبل در H3/e7، پیام ۲۲فیلدی StartAgent تا رمزنگاری، ارسال موفق سوکت و بایت‌های جریان TCP یکتا در capture محلی پیوند خورده است. این نتیجهٔ startup است، نه اثبات ارسال همان مشخصات هنگام دانلود واقعی بازی. پاسخ اختصاصی آن پیام و ذخیره‌سازی سرور همچنان ثابت نشده‌اند. [حکم سؤال اول](PRELOGIN-Q1-VERDICT.fa.md).
2. **دسترسی به چرخهٔ عملیات نصب در حالت بدون حساب:** در T5، پاسخ نهایی‌سازی به `/install/wow` ارجاع داد؛ GET آن وضعیت عملیات بود، نه فرم. پس از بررسی هویت و وضعیت ناقصِ شناخته‌شده، دقیقاً یک `POST /update` فرستاده شد و پاسخ محلی HTTP 200 با ۶۴ بایت رسید. GET بعدی نیز HTTP 200 و ۱۸۳۰ بایت داشت؛ اجرای T5 در بررسی هویت پس از آن قطع شد. این‌ها سند پاسخ‌گویی API محلی‌اند، نه سند دانلود محتوا، پذیرش تله‌متری یا نصب موفق. [رسید ثابت T5](https://github.com/kokononox/battle-net-agent-lab/blob/4f6333c892c6f916536b1e82c353a511a0cf9766/reports/prelogin-retail-transfer-latest.json).
3. **ورود دادهٔ واقعی بازی به مقصد و شناسایی مبدأ فایل منتقل‌شده:** هنوز اثبات نشده است. snapshotهای ۱۷۴بایتی پیش از update، فایل کامل بازی یا نتیجهٔ پس از update نیستند. شمارندهٔ شبکه، progress صفر، HTTP 200 و ایجاد فایل‌های کوچک را به‌جای شاهد محتوایی نمی‌نشانیم. برای سؤال کپی‌کردن بازی نیز هنوز هیچ نتیجهٔ مثبت دربارهٔ watermark یا هویت دانلودکننده نداریم.

## چرا شمارندهٔ جدید قابل اتکاتر است، اما همه‌چیز را ثابت نمی‌کند؟

کنترل T1 در Windows مقدار مستقلِ دریافت برنامه، ۱٬۰۴۸٬۵۷۶ بایت، و ارسال برنامه، ۶۵٬۵۳۶ بایت، را با هر دو دستهٔ EStats تطبیق داد؛ اتصال idle همان فرایند تغییر نکرد. کنترل تازهٔ T7 نیز پیش از راه‌اندازی هدف دوباره پاس شد. استفاده از داده منوط به موفقیت enable و بازگشت EnableCollection=true است؛ صفرهای نامعتبر یا دادهٔ تعریف‌نشده وارد نتیجه نمی‌شوند.

- [کالیبراسیون مستقل T1](https://github.com/kokononox/battle-net-agent-lab/blob/6c099304156d1ce28f181f538a769164f766b3ab/reports/prelogin-tcp-calibration-t1.json)
- [کالیبراسیون تازهٔ اجرای T7](https://github.com/kokononox/battle-net-agent-lab/blob/aa1a08300b6c1d44b8057ea19464c78adca4e74b/reports/prelogin-tcp-target-calibration-latest.json)

مالکیت اتصال با PID، handle زندهٔ فرایند و listener یکتای موردانتظار بررسی شد؛ endpoint یا PID خام منتشر نشده است. در T7 شمارنده تا checkpoint نهایی ۱۱۸۷ میلی‌ثانیه ثبت کرد؛ پنجرهٔ خواسته‌شدهٔ مشاهده یک ثانیه بود و بررسی هویت و خاتمه می‌تواند مدت ثبت را بیشتر کند. وضعیت نهایی meter برابر completed، خطای خواندن و reset صفر، و یک تغییر مجموعهٔ اتصال ثبت شد.

**محدودیت:** فقط اتصال‌های خارجیِ برقرارشدهٔ IPv4 TCP که به‌موقع کشف شدند پوشش دارند. IPv6، UDP، اتصال‌های کوتاهِ ازدست‌رفته و دنبالهٔ خوانده‌نشدهٔ اتصال بسته پوشش کامل ندارند. DataBytes می‌تواند retransmission را در بر بگیرد؛ تعداد بایت یکتای فایل، TCP header، یا کل ترافیک فرایند نیست. کالیبراسیون loopback اعتبار همهٔ مسیرهای شبکه را اثبات نمی‌کند. صفرِ خروجیِ مشاهده‌شده هم دلیل سکوت کامل Agent نیست.

## دو کنترل که جلوی نتیجه‌گیری اشتباه را گرفتند

### D20: عبور از سقف، بدون درخواست HTTP مرحله‌ای

کنترل D20 با صفر درخواست HTTP در مرحلهٔ armed، از آستانهٔ شبکه گذشت. پس وضعیت `phase_network_limit` را نمی‌توان به‌تنهایی سند شروع دانلود دانست. آن کنترل انتساب فرایندی نداشت؛ خطای شمارنده یا نبود فعالیت خودکار را نیز ثابت نکرد. [گزارش D20](PRELOGIN-RETAIL-D20-CONTROL.fa.md).

### T6: انتساب فرایندی مثبت پیش از نهایی‌سازی و update

پس از آماده‌سازی غیرنهایی فرم، اما پیش از هر درخواست مرحلهٔ نهایی‌سازی/شروع، EStats روی اتصال‌های متعلق به Agent مقدار ۱۴۴٬۶۴۱٬۷۳۹ بایت ورودی ثبت کرد. در این اجرا initialize و تنظیم غیرنهایی قبلاً انجام شده بودند؛ بنابراین آن را کنترل «صفر API محصول» نمی‌نامیم. native guard در سقف کلی ۱GiB متوقف کرد؛ T7 محدودتر و مستقل برای رفع همین ابهام طراحی شد.

[رسید meter در T6](https://github.com/kokononox/battle-net-agent-lab/blob/11390229eec20f115f2b556258aa841f731436bc/reports/prelogin-owned-tcp-meter-latest.json)، [رسید صفر درخواست مرحله‌ای](https://github.com/kokononox/battle-net-agent-lab/blob/11390229eec20f115f2b556258aa841f731436bc/reports/prelogin-retail-transfer-latest.json)، [توقف مستقل](https://github.com/kokononox/battle-net-agent-lab/blob/11390229eec20f115f2b556258aa841f731436bc/reports/prelogin-retail-supervision-latest.json).

## آخرین آزمون T8: توقفِ مستند، نه نتیجهٔ دانلود

در T8 ثبت زودهنگام پاسخ و snapshot حفظ شد. نهایی‌سازی پاسخ HTTP 200 با ۶۵ بایت داد و handoff متعلق به install شناخته شد؛ **هیچ درخواست update در این اجرا ارسال نشد**. guard پس از ۲۶۵ms از مرحله، با `phase_network_limit` هدف را خاتمه داد و Job خالی شد. تنها snapshot مقصد، پیش از نهایی‌سازی و خالی بود؛ پس دربارهٔ مقصد پس از آن نتیجه‌ای نداریم. فایل operation-state موجود در آن commit هنوز source/run مربوط به T5 را دارد و به‌عنوان شاهد T8 مصرف نشده است.

[رسید T8](https://github.com/kokononox/battle-net-agent-lab/blob/a77c81a33598edf82a2b45595d0cf34b61f3db1c/reports/prelogin-retail-transfer-latest.json)، [supervisor](https://github.com/kokononox/battle-net-agent-lab/blob/a77c81a33598edf82a2b45595d0cf34b61f3db1c/reports/prelogin-retail-supervision-latest.json).

## مانع کمیِ روشن: اندازهٔ فرادادهٔ رسمی

فقط پیکربندی عمومی ۸۷٬۸۳۶بایتیِ همان build با HTTPS خوانده شد؛ MD5 محتوای config دقیقاً با کلید build-config ثبت‌شده در T7 برابر بود. نام build برابر `WOW-70575patch12.1.5_Retail` و build-uid برابر wow است. محتوای manifestهای زیر در این بررسی دریافت نشده است؛ اندازه‌ها **اعلام‌شده در config رسمی‌اند**، نه اندازه‌گیری دریافت آن‌ها توسط Agent:

- شیء encoded مربوط به encoding: **۱۸۸٬۰۵۸٬۴۷۰ بایت**؛ بزرگ‌تر از آستانهٔ مرحله‌ای ۶۷٬۱۰۸٬۸۶۴ بایت.
- این مقایسه مشروط است: **اگر تمام این شیء، بدون cache و داخل مرحلهٔ armed موردنیاز باشد، بودجهٔ مرحله کافی نیست.** cache، دریافت پیش از arm، resume و ترتیب واقعی درخواست‌های Agent هنوز مشخص نیستند.
- بنابراین این یافته مانع بالقوهٔ آزمایش را کمی می‌کند، اما علت دقیق ترافیک T6/T8 یا دریافت همان manifest را ثابت نمی‌کند. decoded-size را با بایت شبکه اشتباه نگرفته‌ایم و اندازهٔ encoding را به کل حجم بازی تعمیم نمی‌دهیم.

[پیکربندی رسمی نسخه‌ثابت](https://level3.ssl.blizzard.com/tpr/wow/config/d7/18/d718abcc42604d8efbd35aecfa5bb75b)، [خلاصهٔ بودجهٔ فراداده](../reports/prelogin-public-manifest-budget.json). ابزار آفلاین `public_manifest_sizes.py` checksum، نام Retail، کلیدها، اندازه‌ها و URL دقیق را بررسی می‌کند؛ خودش هیچ دانلود یا درخواست Agent انجام نمی‌دهد.

## اصلاحات ضروری در تفسیر پروتکل

- مقدار غایب `error`، صفرِ مشاهده‌شده نیست. fallback تاریخی D13 نباید به‌عنوان پاسخ واقعی Agent نقل شود؛ رسیدهای جدید null نگه می‌دارند.
- پاسخ ۶۵بایتی نهایی‌سازی یک handoff با `response_uri` است. فقط مسیرهای دقیقِ همان محصول روی listener موردتأیید دنبال می‌شوند؛ هیچ URL دلخواهی پذیرفته نمی‌شود.
- GET `/install/wow` می‌تواند وضعیت عملیات باشد، نه فرم. `schema_invalid` ناشی از انتظار نادرست فرم، خطای واقعی Agent نیست.
- وجود قرارداد در پروژهٔ عمومی Battle.Net-Installer، شاهد رفتار حالت logged-out نیست. توضیحات آن پروژه ورود قبلی را فرض می‌کند؛ نتیجهٔ بدون حساب فقط از اجرای تازهٔ خودمان اخذ شده است. countryهای پیش‌فرض آن پروژه کپی نشدند.

## حدود ایمنی و معنی توقف

هیچ ورود به حساب، country ساختگی، پذیرش EULA، دورزدن min-spec یا اجرای بازی انجام نشد. سقف‌های مستقل بدون تغییر ماندند: ۲۴۰ ثانیه / ۱GiB کل RX+TX میزبان / ذخیرهٔ ۱۰GiB دیسک؛ مرحلهٔ دانلود ۳۰ ثانیه / ۶۴MiB. شمارنده هر ۲۵۰ms خوانده می‌شود؛ این‌ها آستانهٔ توقف‌اند، نه سقف سختِ بدون overshoot. baseline مرحله فقط یک بار پیش از درخواست تأیید می‌شود؛ ترافیک پیش از آن از بودجهٔ کلی حذف نشده است.

## بازتولید آفلاین و کنترل کیفیت

ورودی‌ها، SHA-256 فایل‌های گزارش و لینک‌های immutable در `analysis-tools/prelogin-retail-prepare/testdata/attribution/manifest.json` نگه‌داری شده‌اند. هر ورودی یک رسیدِ مستقلِ اجرا است؛ این مجموعه نمونهٔ آماری برای نرخ یا روند نیست. مقادیر null یعنی مشاهده‌نشده، نه صفر. hashهای فایل‌ها تغییر ناخواستهٔ ورودی را کشف می‌کنند، نه اینکه به‌تنهایی صحت آزمایش اصلی را امضا کنند.

```sh
python analysis-tools/prelogin-retail-prepare/attribution_verdict.py \
  analysis-tools/prelogin-retail-prepare/testdata/attribution \
  reports/prelogin-attribution-verdict.json
python -m unittest discover -s analysis-tools/prelogin-retail-prepare -p 'test_*.py'
```

داوری، رسیدِ اجرای دیگر، hash تغییرکرده، کالیبراسیون ناموفق، خطای شمارنده و درخواست محصول در کنترل T7 را رد می‌کند. `observing` با `completed` برابر نیست. هیچ تفاضل بین اجراها، اثبات محتوای بازی، ذخیرهٔ سرور، watermark یا «پوشش همهٔ ترافیک» تولید نمی‌کند. فایل خام بازی، باینری، capture، token، UUID، hash شناسه یا مسیر خام در این مجموعه منتشر نشده‌اند.

## نقطهٔ پایان این نوبت

نتیجهٔ مثبت و بازتولیدپذیر این نوبت، **تفکیک عملی ترافیک خودکارِ متعلق به Agent از ادعای دانلود بازی، و کشف مانع کمیِ بودجهٔ فراداده** است. مسیر API محلی نیز تا پاسخ update در T5 پیش رفت، اما شواهدِ محتوا هنوز کامل نیست. تکرار مشابه یا بالابردن پنهانی سقف‌ها نتیجهٔ علمی تازه‌ای نمی‌سازد؛ اجرای زندهٔ بیشتر در این نوبت متوقف شد.

قدم معتبر بعدی برای اثبات دانلود: طراحی بودجهٔ صریح و موردتأیید برای آماده‌شدن فراداده، سپس تطبیق یک قطعه/فایل واقعیِ مقصد با CKey/EKey موردانتظار همان build. بعد از آن می‌توان ارسال مشخصات را دقیقاً در همان مرحله بررسی کرد. تا آن زمان، ادعای «دانلود واقعی بدون حساب»، «ارسال سخت‌افزار حین آن دانلود» یا «شناسایی دانلودکننده از فایل کپی‌شده» باز است.
