# کارهای باقی‌مانده — پس از ۰٫۱۸

اصل محصول: در هر اجرای جدید نسخهٔ نصب‌شده و مقصد سازگار جاری تشخیص داده شوند؛ دو نسخهٔ ثابت منطق محصول نیستند. مقصد اجرای شروع‌شده pinned بماند؛ انتشار جدید نباید checkpoint موجود را خودکار به هدف دیگری منتقل کند.

## پیشرفت تأییدشده
verifier جریانی، staging فایل‌محور POSIX و اکنون backend بومی Windows برای scratch مصنوعی پیاده شده‌اند. ۴۷۹ تست Linux و ۱۱۱ تست Windows (۷۳ portable و ۳۸ native) پاس شده‌اند. محدودیت prototype کوچک ۴ MiB به ماژول‌های جدید تعمیم داده نشود؛ parser جریانی آزمایش‌های بزرگ‌تری دارد، اما سقف عددی parser اثبات مقیاس تولیدی نیست. نصب‌کنندهٔ CASC هنوز نداریم.

## ترتیب کارهای قابل ادامه اکنون
1. **اتصال native stage به candidate admission:** gate دقیق نوع POSIX هنوز WindowsStreamStage را نمی‌پذیرد. اضافه‌کردن نوع شناخته‌شده با تازه‌بررسی همهٔ segmentها و EKey/CKey، binding catalogue/target و تست Windows؛ بدون apply یا اعتباردادن به نصب زنده.
2. **انتقال و staging یکپارچه:** کنترلر budget/Range/ETag/resume برای فایل بزرگ و چندشیء، cancellation و توقف در تغییر هدف/مبدأ/منبع. backend فعلی ArchiveResponse تأمین‌شده را مصرف می‌کند، نه شبکهٔ خودکار. scope شبکهٔ تازه باید مستقل مشخص شود؛ مجوز بسته‌شده دوباره استفاده نشود.
3. **سیاست انتخاب و closure:** qualification مستقل platform/architecture/region/locale و feature/variant/dependency/patch در برابر فایل کامل. bitmap صحیح یا tag نوع 16384 جای سیاست رسمی Agent نیست؛ Alternate/Talebound هنوز حل نشده‌اند.
4. **backend فقط‌خواندنی نصب Windows:** پروفایل تازه و نسل فعال منسجم؛ V8 ناشناخته حدس زده نشود. فقط اگر آزمون آماده و ضروری شد، از کاربر اجرای محدود با دامنه/خروجی روشن خواسته شود؛ نه اسکن کور.
5. **reuse و برنامهٔ دقیق/حجم‌ها:** پس از اثبات کامل هویت محتوای نصب و منبع، نامزدها به reuse/دریافت/unknown تفکیک شوند. نشانی تکراری انتخاب نشود؛ نبود مرجع در کپی ایندکس missing نیست. شبکه/patch/write/temp/free-space جدا محاسبه شوند؛ حجم ضروری فعلاً null است.
6. **نویسندهٔ تراکنشی CASC و activation:** فقط کپی مستقل Windows، journal/rollback/crash recovery، کنترل قبل/بعد و حفظ نسخهٔ قبلی تا commit معتبر. آزمایش synthetic staging یا FlushFileBuffers جای qualification قطع برق واقعی نیست. apply نصب اصلی مجاز نیست.
7. **end-to-end بومی Windows:** چند baseline/target، نصب ناقص، قطع شبکه/پردازش، دیسک پر، رمزگذاری/قالب پشتیبانی‌نشده، بازی باز، مسیر نامعتبر و rollback؛ هیچ وضعیت نیمه‌نوشته‌ای فعال نشود.
8. **UI و بستهٔ انتشار:** انتخاب پوشه، نمایش برنامه و حجم معتبر، تأیید روشن apply، پیشرفت/توقف/ادامه، گزارش حداقلی، بسته‌بندی و تست ارتقای خود برنامه.

کاربر Windows و فضای کپی آزمایشی دارد؛ فعلاً نیاز به کپی‌کردن بازی، admin، تغییر permission، prepare، اسکن یا دانلود گسترده نیست. کار آفلاین در بندهای ۱ و ۲ باقی است. مسیر تله‌متری و آزمایش مستقل Agent با این کار دوباره اجرا نشده‌اند. installation_ready=false و apply_authorized=false.
