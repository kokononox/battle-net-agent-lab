# کارهای باقی‌مانده — پس از ۰٫۱۹

اصل محصول: در هر اجرای جدید نسخهٔ نصب‌شده و مقصد سازگار جاری تشخیص داده شوند؛ دو نسخهٔ ثابت منطق محصول نیستند. مقصد اجرای شروع‌شده pinned بماند؛ انتشار جدید نباید checkpoint موجود را خودکار به هدف دیگری منتقل کند.

## پیشرفت تأییدشده
verifier جریانی، staging فایل‌محور POSIX و اکنون backend بومی Windows برای scratch مصنوعی پیاده شده‌اند. ۴۸۳ تست Linux و ۱۲۱ تست Windows (۷۳ portable، ۳۸ native stage و ۱۰ native admission) پاس شده‌اند. محدودیت prototype کوچک ۴ MiB به ماژول‌های جدید تعمیم داده نشود؛ parser جریانی آزمایش‌های بزرگ‌تری دارد، اما سقف عددی parser اثبات مقیاس تولیدی نیست. نصب‌کنندهٔ CASC هنوز نداریم.

## ترتیب کارهای قابل ادامه اکنون
**اتصال native stage به candidate admission انجام شد:** فقط دو نوع دقیق شناخته‌شده پذیرفته می‌شوند و همهٔ هویت‌ها/محتوا تازه بررسی می‌شوند. این نتیجه مجوز نصب یا اثبات reuse نصب زنده نیست.

1. **انتقال و staging یکپارچه:** کنترلر budget/Range/ETag/resume برای فایل بزرگ و چندشیء، cancellation و توقف در تغییر هدف/مبدأ/منبع. backend فعلی ArchiveResponse تأمین‌شده را مصرف می‌کند، نه شبکهٔ خودکار. scope شبکهٔ تازه باید مستقل مشخص شود؛ مجوز بسته‌شده دوباره استفاده نشود.
2. **سیاست انتخاب و closure:** qualification مستقل platform/architecture/region/locale و feature/variant/dependency/patch در برابر فایل کامل. bitmap صحیح یا tag نوع 16384 جای سیاست رسمی Agent نیست؛ Alternate/Talebound هنوز حل نشده‌اند.
3. **backend فقط‌خواندنی نصب Windows:** پروفایل تازه و نسل فعال منسجم؛ V8 ناشناخته حدس زده نشود. فقط اگر آزمون آماده و ضروری شد، از کاربر اجرای محدود با دامنه/خروجی روشن خواسته شود؛ نه اسکن کور.
4. **reuse و برنامهٔ دقیق/حجم‌ها:** پس از اثبات کامل هویت محتوای نصب و منبع، نامزدها به reuse/دریافت/unknown تفکیک شوند. نشانی تکراری انتخاب نشود؛ نبود مرجع در کپی ایندکس missing نیست. شبکه/patch/write/temp/free-space جدا محاسبه شوند؛ حجم ضروری فعلاً null است.
5. **نویسندهٔ تراکنشی CASC و activation:** فقط کپی مستقل Windows، journal/rollback/crash recovery، کنترل قبل/بعد و حفظ نسخهٔ قبلی تا commit معتبر. آزمایش synthetic staging یا FlushFileBuffers جای qualification قطع برق واقعی نیست. apply نصب اصلی مجاز نیست.
6. **end-to-end بومی Windows:** چند baseline/target، نصب ناقص، قطع شبکه/پردازش، دیسک پر، رمزگذاری/قالب پشتیبانی‌نشده، بازی باز، مسیر نامعتبر و rollback؛ هیچ وضعیت نیمه‌نوشته‌ای فعال نشود.
7. **UI و بستهٔ انتشار:** انتخاب پوشه، نمایش برنامه و حجم معتبر، تأیید روشن apply، پیشرفت/توقف/ادامه، گزارش حداقلی، بسته‌بندی و تست ارتقای خود برنامه.

کاربر Windows و فضای کپی آزمایشی دارد؛ فعلاً نیاز به کپی‌کردن بازی، admin، تغییر permission، prepare، اسکن یا دانلود گسترده نیست. کار آفلاین در کنترلر انتقال و تست خطاهای آن باقی است؛ حل سیاست انتخاب و نسل فعال هم پیش‌نیاز apply است. مسیر تله‌متری و آزمایش مستقل Agent با این کار دوباره اجرا نشده‌اند. installation_ready=false و apply_authorized=false.
