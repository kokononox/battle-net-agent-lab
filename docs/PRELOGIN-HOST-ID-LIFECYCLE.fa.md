# آزمون ماندگاری host_id: برابر پس از اجرای مجدد فرایند

تاریخ: 2026-10-24. مرحلهٔ جدید سؤال اول؛ سؤال دوم و فایل‌های WoW اجرا نشده‌اند.

## نتیجهٔ فعلی a8

**در اجرای `40145528838`، مقدار host_id در دو startup پیش از حساب روی همان ماشین دقیقاً برابر بود.** فرایندهای مرتبط پس از مرحلهٔ اول کاملاً متوقف شدند؛ همان Setup دارای pin و امضای معتبر در همان محل دوباره اجرا شد و harness هیچ فایل یا registry پیکربندی را پاک/بازنویسی نکرد. هر مرحله دقیقاً یک host_id معتبر در context پیام مشخصات StartAgent داشت و equality بایت‌های واقعی فقط در RAM مقایسه شد؛ `comparison=true` است.

در هر دو مرحله یک پیام سخت‌افزاری به ارسال موفق سوکت و تطبیق کامل ciphertext در ضبط محلی شبکه پیوند خورد. در هر مرحله خطا، افت و خطای مهلک collector صفر بود؛ سه فرایند در مرحلهٔ اول و چهار فرایند در مرحلهٔ دوم همگی پیش از resume ابزارگذاری شدند. کنترل بومی تازهٔ x86/x64 پیش از هدف پاس شد. **این نتیجه فقط توقف/اجرای مجدد فرایند با پیکربندی حفظ‌شده را پوشش می‌دهد**؛ ری‌استارت ویندوز، نصب مجدد، ماشین دوم یا نصب کامل Desktop App انجام نشد.

این برابری امکان مرتبط‌کردن همین دو اجرای قبل از حساب را فراهم می‌کند؛ نه اثبات اتصال به حساب، یکتایی جهانی، HWID دائمی، محل ذخیرهٔ source_id یا علامت‌گذاری فایل‌های WoW. اثبات پذیرش/ذخیرهٔ سرور نیز از این گزارش به دست نمی‌آید.

### رفع مانع AgentHelper و کنترل هویت والد

فرزند متوقف‌شدهٔ a5، فایل امضاشدهٔ Blizzard با SHA-256 `a3a444e6bd163732a648967c01a5fd509f7f33d6963b381c19bdffb604138651` و اندازهٔ 3,642,064 بایت بود. خواندن فقط‌داده‌ای ZIP خصوصی کاربر، دو فایل هم‌هش با basename برابر **AgentHelper.exe** یافت. مقدار واقعی host_id یا hash آن منتشر نشد؛ این hash مربوط به فایل اجرایی است.

در a6/a7، سیاست اضافهٔ هم‌پوشه‌بودن نسخه و برابری pathname والد مانع بود. a8 نشان داد زمان ایجاد والد یکسان و تصویر فعلی آن با hash و امضای معتبرِ والد مجاز دوباره تأیید شده، اما pathname گزارش‌شده برابر نیست. علت جزئی اختلاف pathname تعیین نشده و صرفاً به‌عنوان rename، بدافزار یا PID reuse تفسیر نمی‌شود. به‌جای اتکا به مسیر به‌تنهایی، همان زمان ایجاد + تصویر دقیقاً pinned با امضای معتبر لازم است. Helper نیز فقط با نام/hash مشخص، مسیر زیر درخت Agent بدون reparse و والد pinned و از قبل ابزارگذاری‌شده مجاز شد؛ سایر فرزندان ناشناخته همچنان رد می‌شوند.

## تاریخچهٔ a4: اجرای قبلیِ نامشخص

- دو startup محدود روی یک runner موقت GitHub؛ بدون نصب کامل Desktop App، ورود، Install، حذف نصب، ری‌استارت ویندوز یا دانلود بازی.
- native gate تازهٔ x86/x64 پیش از هدف پاس شد و LSO از طریق مسیر تأییدشدهٔ H3 تنظیم بود.
- مرحلهٔ اول: سه فرایند ابزارگذاری‌شده، صفر خطای اسکریپت/افت/خطای مهلک؛ یک پیام مشخصات با پیوند کامل ciphertext تا ضبط محلی شبکه و یک host_id معتبر مشاهده شد.
- مرحلهٔ دوم: سه فرایند تأیید و resume شدند؛ فرزند چهارم در verify رد شد. صفر خطای اسکریپت به معنی کامل‌بودن collector نیست: `collector_fatal=true` و `all_processes_instrumented=false` هستند. ادعای شبکه یا پایداری شناسه از این مرحله پذیرفته نیست.
- UUIDها فقط در RAM برای equality نگه داشته می‌شوند. هیچ مقدار واقعی، hash شناسه، capture، TLS buffer یا باینری منتشر نشده است. نگاشت نام host_id به همان SHA-256 بررسی‌شده محدود است.

## تاریخچهٔ شکست‌ها و اصلاح ابزار

1. **a1 — run 40088494910:** پیام مشخصات تا شبکه تأیید شد؛ parser جدید به دلیل محدودیت نادرستِ فقط حروف کوچک، شناسه را رد کرد. مقایسه انجام نشد. بررسی خصوصی baseline نشان داد UUIDv4 با حروف بزرگ هم وجود دارد.
2. **a2 — run 40089112247:** regex برای حروف بزرگ/کوچک اصلاح شد، بدون تغییر equality دقیق bytes؛ کنترل بومی پیش از هدف پاس نشد و نصاب اصلاً اجرا نشد. جزئیات کامل gate این اجرای تاریخی منتشر نشده و علت دقیق آن را تعیین نمی‌کنیم.
3. **a3 — run 40089538604:** کنترل بومی و مرحلهٔ اول پاس شدند و یک host_id معتبر استخراج شد؛ مرحلهٔ دوم متوقف شد، اما metadata شکست در مسیر exception قدیمی حفظ نمی‌شد. گزارش آن مرحلهٔ دوم کامل نیست.
4. **a4 — run 40090018452:** ثبت metadata به finally منتقل و با شمارنده‌های مرحله cross-check شد؛ علت توقف دوم اکنون مشخص است: رد نام فرزند خارج از allowlist در verify. هیچ معیار مثبت یا محدودیت امضا برای عبور دادن آن حذف نشده است.

5. **a5 — run 40144180232:** metadata فرزندِ معلق، امضای معتبر Blizzard و hash فایل را ثبت کرد؛ اجازهٔ resume داده نشد. با ZIP خصوصی، AgentHelper.exe شناسایی شد.
6. **a6 — run 40144632517:** مجوز دقیق نام/hash/امضا اضافه شد، اما شرط اضافی والد/پوشه اجرا را متوقف نگه داشت. نتیجه هنوز null بود.
7. **a7 — run 40145069834:** تمام شروط فایل Helper پاس شدند، ولی tuple قدیمی هویت والد برابر نبود؛ معیار مثبت صادر نشد.
8. **a8 — run 40145528838:** زمان ایجاد والد و تصویر امضاشدهٔ pinned برابر بودند، pathname برابر نبود. پس از بازبینی هویت بر این مبنا، Helper پیش از resume ابزارگذاری شد و هر دو مرحله بدون خطا تکمیل شدند؛ host_id دقیقاً برابر بود.

در a4 تعداد ۲۹ تست محلی پاس شده بود. مجموعهٔ فعلی a8 با تست‌های خواندن فقط‌داده‌ای امضا، مجوز محدود Helper و هویت والد، ۵۸ تست پاس دارد. این تعداد با native gate یا تست‌های تاریخی H3 جمع نمی‌شود.

## پاسخ به ابهام «مهر مخصوص هر نصب»

وجود host_id همراه گزارش پیش از حساب و ثابت‌بودنش در برابر توقف/اجرای مجدد فرایند اکنون مشاهده شده است. این فقط یک شناسهٔ تصادفی تازه برای هر بار اجرای Agent نبوده است **در همین دو اجرای بررسی‌شده**؛ امکان مرتبط‌کردن آن‌ها وجود دارد. هنوز نمی‌دانیم شناسه برای یک نصب، چند نصب روی دستگاه، یک نشست ویندوز یا سازوکار دیگر چه چرخهٔ عمری دارد. هدف سازمانی جمع‌آوری داده هم از برابری شناسه به دست نمی‌آید. هیچ نتیجه‌ای دربارهٔ درج شناسه در فایل‌های WoW نمی‌گیریم.

## گام بعدی دقیق

در a9/a10، حضور همان host_id در `HKCU\Software\Blizzard Entertainment\Blizzard Error`، مقدار `UserUUID`، پس از هر دو startup تأیید شد. این مشاهده هنوز منشأ خواندن provider یا زمان ایجاد مقدار را ثابت نمی‌کند. [گزارش محل مشاهده‌شده](PRELOGIN-HOST-ID-STORAGE.fa.md). گام بعدی trace مستقیم خواندن/نوشتن و baseline پیش از startup است؛ سپس reboot/reinstall و محیط مستقل، بدون تعمیم نتیجهٔ restart فرایند.
