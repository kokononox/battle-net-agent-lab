# تحویل کامل وضعیت کاری جلسه

این سند نقطهٔ شروع ادامهٔ پروژه است؛ بازسازی مستندِ هدف‌ها، تصمیم‌ها، نتایج و محدودیت‌های جلسه است، نه رونویسی کلمه‌به‌کلمهٔ گفتگوها. برای دامنهٔ دقیق همگام‌سازی [SYNC-SCOPE.fa.md](SYNC-SCOPE.fa.md) را ببینید. تاریخ وضعیت: ۲۰۲۶-۱۰-۱۶ (UTC). نتیجهٔ آزمایش جدید را همیشه با منشأ commit/run در گزارش بخوانید؛ «latest» به‌تنهایی مرجع تاریخی ثابت نیست.

## ۱. مقصد اصلی، و علت انحراف موقت

هدف اصلی این است که بفهمیم WoW واقعاً چه فیلدهای سخت‌افزاری/سیستمی را، در کدام درخواست و به کدام مقصد می‌فرستد؛ مراحل پیش از ورود، هنگام ورود و داخل بازی جدا بررسی شوند. مشاهدهٔ یک رشته در فایل اجرایی یا اتصال TLS، اثبات ارسال یک فیلد نیست.

هنگام تست چهارشنبه، به‌دلیل maintenance/update نتوانستیم به جهان بازی برسیم. کاربر بعداً روشن کرد ورود موفق به character/in-world رخ نداده؛ تلاش اتصال حساب/realm با سرورهای بسته بوده است. درخواست به‌روزرسانی مستقل از Battle.net، پروژهٔ دانلودر/تعمیر را به‌عنوان پیش‌نیاز شروع کرد. پس از آماده‌شدن مسیر امن و کارآمد، باید به آزمایش اصلی تله‌متری برگردیم، نه اینکه دانلودر جای آن را بگیرد.

کاربر با تست‌های ضروری مخالف نیست؛ با نسخه‌سازی طولانیِ بدون نزدیک‌شدن به نتیجه و تکرار کارهای سنگین مخالف است. دستکاری غیراصولی بازی قابل‌قبول نیست. هر تست تازه باید یک ابهام مشخص را رفع کند و نتیجه/شرط توقف داشته باشد.

## ۲. سه مسیر مستقل

1. **دانلودر روی کامپیوتر کاربر:** Lab جدا، منابع بازی فقط‌خواندنی، کش و checkpoint قابل‌ادامه. آخرین کد تحویلی: `downloader/` از بستهٔ TagFix، ۴۴۶ آزمون.
2. **شناخت Setup/Agent روی GitHub:** Windows hosted VM دورریختنی، بدون حساب/بازی؛ فقط bootstrap و مشاهده. به Lab کاربر دسترسی ندارد و هنوز الگوریتم کامل آپدیت را آشکار نکرده است.
3. **تله‌متری WoW:** آزمایش درخواست/بدنه و مقصد؛ شواهد تاریخی محدود، تست واقعی درون‌بازی هنوز باقی است.

## ۳. وضعیت قطعی دانلودر

- نصب فعلی گزارش‌شده: `12.1.0.69933`، هدف pinشده: `12.1.5.70391`. هدف pinشده را «آخرین نسخهٔ آنلاین امروز» ننامید.
- پروفایل: `Windows / x86_64 / EU / enUS`.
- metadata هدف: ۲٬۸۸۱٬۶۱۹ رکورد؛ پس از projection محافظه‌کارانه، ۱٬۵۷۸٬۰۱۳ انتخاب و ۱٬۳۰۳٬۶۰۶ کنار گذاشته شده‌اند.
- مرور طولانی محلی **تمام شده**: ۱٬۵۳۱٬۱۶۷ نامزد، ۱٬۵۰۰٬۰۶۴ اثبات کامل encoded+decoded، ۳۱٬۱۰۳ unsupported/encrypted؛ مورد پشتیبانی‌نشده مساوی خراب نیست. pending صفر.
- این مرور ۴۴۱ batch و ۱۱۶٬۷۲۲٬۸۰۳٬۰۶۳ بایت خواندن محلی گزارش کرده؛ این عدد مصرف اینترنت نیست. صف بعداً آفلاین به‌روز شده و dirty=false است.
- TagFix روی Windows کاربر با status `profile_and_local_proof_scope_complete` موفق شده است. عملیات scope شبکه/اسکن مجدد payload نداشته، صف فعال را عوض نکرده و فایل بازی را ننوشته است.
- ۳۶٬۸۰۴ مورد تازه بدون اثبات encoded، مجموع نمایش encoded برابر ۵٬۱۱۲٬۶۹۵٬۷۸۵ بایت؛ شامل ۹ مورد دارای decoded-only است. این **حجم قطعی اینترنت نیست**.
- ۴۱٬۱۴۵ مورد مشترک/قدیمی conditional با ۲٬۲۳۶٬۶۸۴٬۸۹۱ بایت نمایش encoded داریم. نبود اثبات کافی، دلیل missing/corrupt بودن آن‌ها نیست.
- ۱٬۵۰۰٬۰۶۴ مورد انتخاب‌شده encoded_available با ۱۲۵٬۲۸۷٬۸۱۴٬۰۴۳ بایت داریم. شمارش‌ها با گزارش اصلی cross-check شده‌اند.
- `required_network_download_bytes = null` و `installation_ready = false`. دانلودر فعلی **نصاب کامل یا CASC writer نیست**؛ patch savings و فعال‌سازی نصب هنوز پیاده/اثبات نشده‌اند.

گزارش‌های اصلی در [فهرست شواهد](../evidence/INDEX.json) هستند. گزارش اولیهٔ prepare و اعداد conditional آن، وضعیت قدیمی و گستردهٔ کاتالوگ‌اند؛ آن‌ها را جایگزین scope نهایی یا اندازهٔ آپدیت نکنید.

## ۴. تصمیم‌های مهم برای کاربر

- Lab فعلی، objects، manifestهای PRIVATE و checkpointها حفظ شوند؛ منبع کد و پوشهٔ Lab دو چیز متفاوت‌اند.
- برای ادامه، **metadata prepare یا اسکن ۱٫۵میلیونی را صرفاً به‌خاطر تعویض نسخه/جلسه تکرار نکنید**. اگر fingerprint منبع واقعاً تغییر کرد باید همان تغییر بررسی شود؛ ادامهٔ کورکورانه مجاز نیست.
- به‌خاطر عدد چندگیگابایتی scope، دکمهٔ دریافت صف گسترده را نزنید؛ این هنوز برنامهٔ آپدیت نهایی نیست.
- ۳٫۸۸GB اندازهٔ پوشهٔ Lab/objects گزارش شده بود، نه اندازهٔ قطعی آپدیت یا مصرف اینترنت. SQLite، encoding، index، decoded و part هم فضا می‌گیرند.
- فایل‌های partial/cache تنها پس از اعتبارسنجی شناسه/اندازه/هش و قرارداد Range قابل‌بازاستفاده‌اند. «ادامه» تضمین بی‌قیدوشرط عدم دریافت مجدد هر بایت نیست؛ بخش نامعتبر یا batch ناتمام ممکن است تکرار شود.
- سیستم دیگری که Battle.net روی آن حدود ۴۵۰MB initializing، سپس ۱٫۷۸GB download و ۵٫۸۸GB patch نشان داد، **همان سیستم Lab نیست**. این عددها را جمع نکنید یا برای تخمین قطعی شبکهٔ Lab به کار نبرید.
- قطع اینترنت/VPN و اجرای از فلش در مراحل قبلی مطرح شد؛ همهٔ خطاهای HTTP/IO را بدون شاهد به یک علت واحد نسبت ندهید.

## ۵. نتیجهٔ واقعی GitHub تا پیش از probe تازه

مرجع ثابت: [گزارش commit 9b2f3b3](https://github.com/kokononox/battle-net-agent-lab/blob/9b2f3b3700b1a4619eda3db710f443185aa63ad7/reports/latest.json).

- Setup رسمی ۴٬۸۹۶٬۴۶۴ بایت، یک redirect؛ Authenticode معتبر و ناشر مورد انتظار Blizzard تأیید و Setup واقعاً اجرا شد.
- ۳۰ نمونه تا حدود ۱۴۵ ثانیه فقط `battle.net-setup.exe` را دیدند؛ Agent process/binary و فایل‌های scoped مشاهده نشدند. فهرست TCP نمونه‌ها خالی بود؛ این اثبات صفر بودن کل شبکه نیست.
- status `bootstrapper_observed_agent_not_observed` و phase complete؛ **کامل‌شدن آزمایش برابر کامل‌شدن نصب نیست**.
- علت ندیدن Agent هنوز اثبات نشده بود. فرض انتظار برای GUI فقط فرضیه بود، نه نتیجه.
- پیش‌تر timeout در baseline PowerShell/WMI رخ داده بود؛ snapshot با API بومی جایگزین شد. این خطای ابزار بود، نه شاهد خرابی CDN یا بازی.

گام تازهٔ محدود: دو بررسی فقط‌خواندنی session/desktop/window/control طی ۴۵ ثانیه؛ بدون کلیک، پذیرش توافق‌نامه، تایپ، ورود، screenshot یا متن خام پنجره. schema2 منشأ commit/run را ذخیره می‌کند. نتیجهٔ اجرای تازه در `reports/latest.json` می‌آید؛ سند حاضر موفقیت آن را پیشاپیش ادعا نمی‌کند.

## ۶. شرط ادامه و توقف

اول نتیجهٔ probe مشخص را بخوانید؛ نصب/دانلود واقعی بازی در runner کوچک را خودکار شروع نکنید. اگر hosted runner دسکتاپ تعاملی کافی ندارد، همان محدودیت را ثبت کنید و از تکرار بی‌هدف پرهیز کنید. برای مرحلهٔ واقعی patch/activation به محیط Windows دورریختنی کافی، نصب آزمایشی، snapshot/rollback و اجازهٔ روشن نیاز است.

برای دانلودر، قبل از writer باید closure و policy نصب/زبان/manifest، executable/config و منابع patch روشن شوند. projection فعلی vendor policy قطعی نیست. تعمیر فایل معیوب در هستهٔ مصنوعی جدا آزموده شده؛ این معادل مجوز تعمیر CASC واقعی کاربر نیست.

برای تله‌متری، ادامه مطابق [برنامهٔ گام بعد](NEXT-STEPS.fa.md) با حفظ مرز «مشاهده» و «اثبات ارسال» انجام شود.
