# تحویل R1 — بازگشت به مبنای BAT 3 و شناسایی بدون hook

## تغییر مسیر با درخواست تازه کاربر
U2 با پنجره‌های ۱۲۰ثانیه‌ای و baseline محدود تله‌متری ساخته شد، ولی کاربر پیش از اجرای آن خواست از فهرست BAT 3 خودش شروع کنیم: ابتدا حذف فعالیت‌های جانبی و شناسایی مقصدهای لازم برای آپدیت، سپس بررسی محتوای مقصدهای باقی‌مانده.

مسیر فعال اکنون R1 است. U2 حذف نشده ولی فعلاً فایل پیشنهادی اجرای بعدی نیست. تکمیل بی‌هدف دانلود یا اجرای تمام پروفایل‌ها بدون بررسی مبنا درخواست نمی‌شود.

## آنچه از BATهای واقعی خوانده شد
- `3-fixed.bat` و `4-fixed.bat` ارسالی کاربر صرفاً خوانده شدند، نه اجرا.
- BAT 3 دارای ۲۰ خط واقعی block در hosts است، نه فایروال IP یا allowlist. `www.google.com` در خطوط block نیست، هرچند در آرایه پاک‌سازی دیده می‌شود.
- خط news به شکل `breaking-news.support.blizzard.com:443` است؛ hosts نام دامنه بدون port می‌خواهد. اصلاح آن می‌تواند رفتار را نسبت به آزمایش قدیمی تغییر دهد.
- هر دو اسکریپت همان backup ثابت را با `/Y` بازنویسی می‌کنند؛ اجرای unblock پس از block می‌تواند backup اولیه را با نسخه blocked جایگزین کند.
- پاک‌سازی بر اساس دامنه/marker ممکن است ورودی قبلی را حذف کند؛ تضمین حفظ دقیق original bytes ندارد. آرایه پاک‌سازی شامل www.google.com است که خود BAT 3 در block واقعی اضافه نکرده است.
- بنابراین original BATها بازتوزیع اجرایی یا به‌عنوان recovery توصیه نشدند.

## بسته جدید و پروفایل‌ها
۷ BAT کوچک، Python قابل‌حمل و helper امضای native در یک بسته جدا:
1. `01-Telemetry-Only.bat`: مرجع محدود قبلی، فقط در صورت نیاز به مقایسه.
2. **`02-BAT3-Corrected.bat`**: همان ۲۰ نام واقعی با اصلاح news؛ **فقط این اول اجرا و گزارش شود**.
3. `03-BAT3-Plus-OAuth.bat`: مبنا + oauth.battle.net.
4. `04-BAT3-Plus-Distribution.bat`: مبنا + distribution.version.battle.net.
5. `05-BAT3-Plus-US-Version.bat`: مبنا + us.version.battle.net.
6. `06-BAT3-Plus-Level3-TLS.bat`: مبنا + level3.ssl.blizzard.com.
7. `07-BAT3-Plus-Level3.bat`: مبنا + level3.blizzard.com.

نسخه‌های ۳ تا ۷ مستقل‌اند، نه انباشته. مرحله ۲ یک group screening است، نه انتساب اثر به هرکدام از ۲۰ دامنه. اگر ۲ شکست خورد ابتدا باید گروه محدودتر بررسی شود؛ اجرای خودکار ۳ تا ۷ معنی ندارد.

## رفتار و حدود
- در مسیر `recon.py` هیچ Frida/injection/hook یا رمزگشایی TLS اجرا نمی‌شود. فقط process identity، امضای Blizzard، هش image و snapshot مقصدهای عمومی TCP نمونه‌برداری می‌شود.
- تشخیص Agent زنده و signed صرفاً اجازه شروع پنجره network observation است، نه اثبات آماده‌بودن updater یا محتوای ترافیک.
- زمان مشاهده هر BAT، ۱۲۰ثانیه پس از READY است؛ نه از لحظه کلیک Resume. Q یا تایمر فقط مشاهده را پایان می‌دهد. Update/Pause/Exit/Play/Repair/Login همگی خارج از کنترل ابزار و دستی‌اند.
- پیش از شروع Battle.net/Agent/WoW بسته باشند. بعد از پنجره کاربر دستی Pause/Exit می‌کند؛ اتصال قدیمی را با تغییر hosts «قطع‌شده» فرض نمی‌کنیم.
- hosts موقت، system-wide، با journal خصوصی original bytes و checksum است. ورودی قبلی از فهرست آزمایش یا :443 قدیمی → توقف بدون پاک‌سازی. تغییر خارجی → حفظ و اعلام نیاز به recovery دستی، نه overwrite.
- پس از restore موفق بلوکی باقی نمی‌ماند. اگر تستی نیست Battle.net کامل بسته شود. دو نسخه U1/U2/R1 همزمان مجاز نیستند؛ mutex مشترک است.
- گزارش خروجی schema `retail-destination-recon-1` دارد: پروفایل، دامنه‌ها، resolver states، timestamps، نتیجه دستی دانلود و فراداده process/TCP. payload/header/URL/query/key یا مقدار CPU صادر نمی‌شود.
- نسخه/Finished/Play/تعداد TCP sample به‌تنهایی اثبات صحت کامل بازی، مقدار دانلود/آپلود یا حذف تله‌متری نیست.
- denylist همه نام‌ها، IP مستقیم، DoH، UDP/QUIC و fallback را کنترل نمی‌کند. IP مقصد نیز Host یا محتوای درخواست را ثابت نمی‌کند.
- بستن یک دامنه و ادامه دانلود می‌تواند به cache/fallback مرتبط باشد؛ توقف هم می‌تواند علت دیگری داشته باشد. این غربالگری وابستگی است، نه اثبات causal necessity یا تله‌متری.
- هیچ نصب بازی، حذف/rollback/Repair/Cancel، اسکن ۱۳۰GB، ورود به حساب، پذیرش EULA یا تضعیف TLS/ضدتقلب به کار اضافه نشده است.

## کنترل کیفیت
۷۳ unit/safety/recovery/schema test روی Linux پاس شد. فهرست ۲۰ نام با خطوط واقعی BAT 3 به‌صورت ماشینی تطبیق داده شد؛ فقط یک اصلاح :443 انجام شده است. بازیابی تمام پروفایل‌ها با فایل hosts موقت و مسیر کامل تایمر با APIهای مصنوعی آزموده شد.

Build ویندوز جدا شامل همان gate بومی runtime/امضای معتبر و selftest شبکه متعلق به ابزار است: ساخت اتصال loopback خودِ Python و تطبیق PID identity و TCP table. هیچ Battle.net برای این build اجرا یا نصب نمی‌شود. نتیجه بومی و لینک بسته در STATUS و رسید build ثبت می‌شود؛ این آزمون روی کاربر یا آپدیت واقعی نیست.

## مرحله بعد پس از گزارش ۰۲
ابتدا بررسی کنیم مبنای اصلاح‌شده بدون injection واقعاً برای دانلود کار می‌کند یا نه و کدام image/مقصد TCP مشاهده شده است. فقط سپس پروفایل بعدی انتخاب شود. اثر فرق فهرست block و فرق پیشرفت/cache از اثر hook جدا نگه داشته شود؛ این اجرای R1 به‌تنهایی A/B هم‌شرط در برابر U1 نیست.

پایش محتوای پیش از رمزنگاری برای مسیرهای باقی‌مانده مرحله جداست. مشاهده بسته رمز‌شده یا IP به‌تنهایی نوع اطلاعات را نشان نمی‌دهد؛ اگر TLS/plaintext مسیر خاص قابل مشاهده نشد، نتیجه «نامعلوم» است، نه «پاک». سؤال fingerprint فایل‌های A→B هم همچنان آزمایش‌نشده است.
