# بازبینی شواهد محدودسازی — ابزار 0.1.2

## نتیجهٔ قبلی کاربر
گزارش endpoint-results-5c09bf0304d04d8fbdb2d8921014fef3.json نسخهٔ 0.1.1 شامل هفت آزمایش TCP است: شش world_ok و یک auth_failed برای 37.244.29.11:3724. نبود قوانین پس از حذف و رفتار عادی برای هر هفت تأیید شده‌اند؛ packet_block_verified همه false است. نتیجه‌ها انتخاب کاربرند، نه تشخیص خودکار احراز هویت. شش world_ok اثبات بی‌استفاده‌بودن مقصدها یا جلوگیری از تله‌متری نیست.

## درخواست و تغییر
کاربر ادامهٔ بررسی اتصال تازه/مسدودسازی واقعی را خواست. نسخهٔ 0.1.2 فقط شش مقصد TCP با world_ok را برای بازبینی باز می‌گذارد؛ مقصدِ مختل‌کنندهٔ ورود و UDP وارد این مرحله نمی‌شوند. فهرست قدیمی ۲۷ مقصد برای اعتبارسنجی journalهای بازیابی حفظ شده است.

بعد از ساخت و readback قانون، monitor فقط‌خواندنی با حداکثر ۹۰ ثانیه نمونه‌برداری Get-NetTCPConnection و خواندن رویدادهای موجود Security 5152/5157 شروع می‌شود. مسیر دقیق پردازه، PID و زمان شروع/آخرین مشاهده برای نسبت‌دهی داخلی کنترل می‌شوند؛ PID یا مسیر در گزارش اشتراکی نیست. برای تست اتصال تازه کاربر بازی را عادی می‌بندد و همان نصب را باز می‌کند؛ ابزار بازی را اجرا یا متوقف نمی‌کند. پایان/جمع‌آوری monitor پیش از درخواست حذف rule است و پنجرهٔ log با stop marker محدود می‌شود. نگهبان پنج‌دقیقه‌ای و بازیابی قبلی حفظ شده‌اند.

## تفسیر
WFP match تصمیم block ویندوز را برای همان پردازه/مقصد نشان می‌دهد؛ نگاشت FilterRTID به rule خود ابزار انجام نشده و rule_causality_proven همچنان false است. رویداد می‌تواند متعلق به سیاست دیگری باشد. صفر event/سوکت اثبات مسدودسازی یا صفر ترافیک نیست؛ auditing ممکن است خاموش، log غیرقابل‌خواندن یا نمونه‌برداری ناقص باشد. سیاست audit تغییر نمی‌کند. Established در پردازهٔ ساخته‌شده پس از شروع پایش جدا علامت می‌خورد؛ این مشاهدهٔ سوکت است نه wire capture یا محتوای پیام. مقصد دیگر صرفاً مشاهده است، نه fallback اثبات‌شده.

رویدادهای Security فقط در حافظه خوانده می‌شوند؛ متن خام، مسیر، PID، حساب یا log صادر نمی‌شود. خلاصهٔ مقصدهای TCP فقط IPهای عمومی را صادر می‌کند. هیچ hosts/VPN/گواهی/ExecutionPolicy/audit policy یا تنظیم بازی تغییر نمی‌کند. TLS و CPU/BIOS همچنان خارج از توان این ابزارند.

## اعتبارسنجی و تحویل
۵۶ تست محلی/mock شامل پاک‌سازی، ترتیب monitor-before-remove، sanitizer و تفکیک شواهد پاس شدند؛ syntax و manifest/ZIP بررسی و حالت فعال/نتیجهٔ باریک بصری بازبینی شدند. monitor.ps1 و WFP روی Windows واقعی توسط سازنده اجرا نشده‌اند. روش جدید هنوز نتیجهٔ کاربر ندارد. بستهٔ Update بدون runtime باید روی همان پوشهٔ قبلی با حفظ runtime/private-state/output استخراج شود؛ اول Restore.cmd باید نبود قوانین را تأیید کند، سپس فقط یک مرحله آزمایش شود.
