# نتیجه b1 و ارزیابی اسکریپت‌های hosts کاربر

## منشأ و دامنه
run 39157489237، source bc5aa27842e123271eb794794bb6bd4dbfa93f44؛ گزارش reports/startup-network-20261018-b1.json. محیط GitHub Windows تازه، signed bootstrap و Continue صفحه زبان؛ بدون نصب از صفحه بعد، حساب یا بازی. این رفتار کلاینت کامل نصب‌شده/آپدیت WoW نیست.

## یافته مستقیم
ضبط Pktmon، تبدیل pcapng و parser موفق شدند. نام‌های استخراج‌شده از SNI یا HTTP Host: nydus.battle.net، telemetry-in.battle.net، us.version.battle.net، level3.blizzard.com، us.cdn.blizzard.com.

SNI به telemetry-in.battle.net در سه ردیف flow منتسب به battle.net-setup.exe دیده شد؛ این شاهد جدید مربوط به Setup است، نه WoW.exe. برای Agent.exe، DNS candidate همین نام در IP مشترک وجود دارد اما SNI همان نام در خروجی Agent دیده نشد؛ این دو سطح شاهد نباید یکی شوند. SNI/Host محتوای رمزگشایی‌شده، پذیرش درخواست سرور یا ارسال اطلاعات سخت‌افزاری را ثابت نمی‌کند. نام telemetry به‌تنهایی نوع دقیق فیلدهای ارسالی را مشخص نمی‌کند.

## پوشش و محدودیت
مسیر PowerShell/Get-DnsClientCache قبل و بعد هر دو timeout شدند؛ محل دقیق تأخیر در راه‌اندازی PowerShell یا cmdlet از این گزارش معلوم نیست. این timeout مربوط به probe محلی است، نه شاهد شکست DNS کلاینت. DNS responses در خود capture قابل استخراج بود و نام‌های بالا از SNI/Host نیز شاهد مستقل دارند. نبود SSLKEYLOGFILE دوباره آزمایش نشد؛ رمزگشایی HTTPS انجام نشد.

۸۷۸۳ packet observation در کل NIC capture و ۳۳۴۰ بسته truncate‌شده گزارش شد؛ این‌ها حجم مصرف یا درخواست‌های بتل‌نت نیستند و ممکن است تکرار NIC/offload داشته باشند. ۴۱ flow row داریم، نه ۴۱ درخواست. ردیف‌های ظاهراً یکسان نگه داشته شده‌اند چون tuple محلی برای حریم خصوصی از گزارش حذف شده؛ dedup آن‌ها غلط است. null بودن SNI/Host به معنی نبود TLS/HTTP یا نبود telemetry نیست؛ parser فقط prefix پیوسته اولیه را می‌بیند، gap/truncation/out-of-order محدودیت است. IP/hostname ثابت جهانی و همیشگی فرض نشود. داده خام ترافیک و فایل‌های اجرایی صادر نشدند.

وجود رشته‌های secur32.dll/winhttp.dll/wininet.dll/libcurl در bootstrap فقط string hint است؛ import معتبر یا کتابخانه TLSِ واقعاً استفاده‌شده ثابت نشده. فایل Agent کاندید همان binary تمام processها ثابت نشده است.

## ورودی‌های کاربر — فقط خوانده شدند، اجرا نشدند
3-fixed.bat و 4-fixed.bat در research-inputs/20261018-hosts/ کپی شده‌اند. اصل فایل‌ها تغییر داده نشده است.

- 3-fixed.bat قانون فایروال/IP نیست؛ فایل hosts سیستم را تغییر می‌دهد و سپس DNS cache را flush می‌کند. دامنه‌های telemetry/store/web content را با 0.0.0.0 می‌نویسد. موفقیت تجربه کاربر را به همان شرایط آزمون محدود می‌کنیم؛ موفقیت یک چرخه کامل آپدیت از این اظهار به‌تنهایی ثابت نمی‌شود.
- breaking-news.support.blizzard.com:443 قالب صحیح hostname در hosts نیست و پورت را به این روش نمی‌توان مسدود کرد. در این بررسی هیچ اصلاحی روی اصل فایل اعمال نشد.
- مقصد telemetry-in.battle.net بین فهرست block و نام‌های مستقیمِ دیده‌شده در b1 مشترک است. این overlap ضرورت/عدم ضرورت سرویس یا اثر قطع آن بر چرخه کامل آپدیت را ثابت نمی‌کند. اجرا baseline بود؛ این دو اسکریپت روی runner هم اعمال نشدند.
- هر دو script بخش markerدار را حذف می‌کنند و همچنین ورودی‌های 0.0.0.0 مطابق فهرست را خارج marker حذف می‌کنند. بنابراین عنوان «فقط ورودی همین اسکریپت» تضمین مالکیت نیست؛ قوانین قبلی هم ممکن است حذف شوند. marker ناقص START بدون END می‌تواند باقی فایل را حذف کند.
- هر دو با /Y همان hosts.blizzard-backup را بازنویسی می‌کنند؛ اجرای Unblock می‌تواند بکاپ پیش از Block را با نسخه مسدودشده جایگزین کند. Unblock، بازگردانی دقیق و کامل snapshot قبل نیست.
- حذف block مانع ارسال فیلدهای اضافی در دامنه‌های مجاز باقی‌مانده نمی‌شود. hosts یک فیلتر محتوا/HTTPS body یا sandbox نیست. وجود fallback، اتصال مستقیم به IP، cache داخلی یا روش حل نام متفاوت باید جدا آزموده شود، نه اینکه عبور همه آن‌ها در این نسخه فرض شود.

## ادامه محدود و قابل سنجش
۱. پیش از HTTPS interception، کتابخانه TLS و binary واقعاً اجراشده در هر process با انتساب مسیر/هش/ماژول معتبر شناسایی شود؛ string hint کافی نیست. از تکرار SSLKEYLOGFILE بدون دلیل جدید خودداری شود.
۲. مقایسه baseline با block فقط در VM تازه و با کنترل‌شده‌ترین تغییر دامنه، تایید مؤثر بودن resolve/block و گزارش رفتار/fallback؛ بدون تغییر hosts کاربر و بدون ادعای آپدیت بازی. اسکریپت‌های اصلی به‌صورت کور اجرا نشوند.
۳. پاسخ نهایی محتوا/فیلدهای سخت‌افزاری و انتقال A→B همچنان باز است؛ برای سؤال دوم آزمایش مستقل محتوای بیلد و metadata جانبی لازم است. عدم مشاهده در یک بازه تضمین عدم ارسال در آینده نیست.
