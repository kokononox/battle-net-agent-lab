# Level3 Request Audit T1

این بسته برای حالت **06-All-Except-Level3.bat** ساخته شده است: در فهرست شناخته‌شده، ۲۴ نام بسته و `level3.blizzard.com` باز می‌ماند. خود ابزار hosts را نمی‌نویسد و در پایان نیز بلاک BAT را حذف نمی‌کند. این حالت فایروال/allowlist کل اینترنت نیست.

## اجرا
1. WoW و همه مشاهده‌گرهای قبلی را ببندید. Battle.net و Agent را خودتان کامل Exit کنید؛ ابزار هیچ فرایند Blizzard را باز یا متوقف نمی‌کند.
2. فقط BAT شماره ۰۶ همان بسته ساده را با Administrator اجرا کنید. اگر قبلاً فعال است، ابزار صرفاً DNS آن را بررسی می‌کند. ابزارهای R1/U1 را همزمان اجرا نکنید؛ ممکن است hosts را بازیابی کنند.
3. ZIP جدید را کامل در پوشه‌ای تازه Extract کنید. `Start-Level3-Audit.cmd` را با **Run as administrator** اجرا کنید. runtime همراه است؛ نصب Python لازم نیست. حفاظت Windows یا بررسی گواهی را خاموش نکنید.
4. تست داخلی فقط به worker متعلق به ابزار روی loopback وصل می‌شود؛ سپس لازم است Battle.net/Agent/WoW بسته باشند. مسیر بازی `G:\World of Warcraft` و پیش‌شرط‌ها را تأیید کنید: backup موجود، signed out، آپدیت Pause و automatic updates خاموش.
5. بعد از درخواست ابزار، Battle.net را دستی باز کنید؛ **تا READY به Resume دست نزنید**. اگر STOP/خطا دیدید، دانلود را برای دورزدن خطا شروع نکنید؛ متن خطا را ارسال کنید.
6. بعد از READY، خودتان Resume کنید. برای نمونه اول حدود ۶۰ تا ۱۲۰ ثانیه مشاهده کافی است؛ سپس **خودتان Pause کنید** و در پنجره ابزار Q بزنید. این پیشنهاد مدت نمونه است، نه تضمین کمبود دانلود/تغییرات فایل. ابزار تایمر حداکثر ۱۰ دقیقه دارد ولی نه تایمر نه Q دانلود را Pause نمی‌کند. بازی را هنگام اتصال hook اجرا نکنید.
7. وضعیت Paused/Finished و Progressed/Stalled را پاسخ دهید. فقط فایل `output/level3-audit-....json` را بفرستید. گزارش خودکار upload نمی‌شود. پس از تست Battle.net را دستی Exit کنید. بلاک‌های BAT۰۶ باقی می‌مانند؛ ابزار آن‌ها را restore نمی‌کند.

## چه چیزی می‌بینیم؟
- ورودی APIهای خروجی send، WSASend و EncryptMessage در فرایندهای Blizzard دارای امضای تأییدشده. hook صرفاً می‌خواند و آرگومان/خروجی/TLS را تغییر نمی‌دهد؛ با این حال injection می‌تواند روی پایداری و زمان‌بندی اثر بگذارد.
- HTTP/1 قابل‌بازسازی با ترتیب event، طول بدنه، Content-Length/chunked و وضعیت شکاف/ناقص. داده‌های خام موقتاً در RAM پردازش می‌شوند، نه در فایل گزارش. پاک‌کردن referenceهای Python تضمین zeroization حافظه یا نبود paging سیستم‌عامل نیست.
- هدر/پارامتر/بدنه از نظر کلیدهای شناخته‌شده CPU/GPU/RAM/OS/device ID و تطبیق **رشته واقعی CPU محلی** بررسی می‌شوند. مقادیر دیگر سخت‌افزار به صورت مرجع استخراج/تطبیق داده نمی‌شوند؛ شناسه hashشده، اختصاصی، مبهم یا کدگذاری ناشناخته ممکن است تشخیص داده نشود.
- فقط فراداده صادر می‌شود: method، hostname، نوع مسیر `/tpr/` یا other، وجود query و تعداد/نام‌های طبقه‌بندی‌شده آن، نام هدرهای مجاز، تعداد هدرهای ناشناخته، وجود Cookie/Authorization، اندازه/نوع بدنه، field hints و نتیجه boolean تطبیق CPU. **مقدار User-Agent/هدر/URL/query/body، مسیر واقعی درخواست، هش محتوا، کلید TLS و نام واقعی CPU صادر نمی‌شود.** وجود User-Agent می‌تواند خودش metadata منتقل کند؛ GET بدون بدنه معادل نبود اطلاعات شخصی نیست.
- hostnameهای مشاهده‌شده دیگر، IP/port عمومی نمونه‌برداری‌شده و هویت/هش فرایند نیز در گزارش هستند تا fallback آشکار پنهان نشود. hostname هدر، اتصال رمزنگاری‌شده به IP یا دریافت واقعی سرور را ثابت نمی‌کند.

## حدود نتیجه
- بازسازی خروجی فقط HTTP/1 است؛ recv/بدنه پاسخ یا تعداد بایت دانلود اندازه‌گیری نمی‌شود. اطلاعات startup و پنجره update در یک audit هستند؛ metadata رخدادهای پایه phase جدا دارد، اما درخواست بازسازی‌شده دقیقاً به لحظه کلیک Resume منتسب نمی‌شود.
- SSPI موفق فقط پذیرش محلی رمزنگاری را نشان می‌دهد، نه ارسال/دریافت. نمونه SSPI منفی fixture، TLS واقعی موفق نیست. کلید جلسه TLS لازم یا ذخیره نمی‌شود؛ OpenSSL/HTTP2/QUIC و رمزگذاری داخلی برنامه پوشش کامل ندارند.
- attach دیرهنگام ممکن است نخستین درخواست‌ها را از دست بدهد. آغاز HTTP شکسته بین چند input بسیار کوچک ممکن است از hook عبور کند. همزمانی، reuse context TLS و APIهای پوشش‌نداده‌شده محدودیت دارند. ترتیب sequence تضمین ترتیب شبکه در همه حالت‌های همزمان نیست.
- حدود: input تا ۱۶KiB، کل RAM خام ۳۲MiB/۳۲۷۶۸ رخداد، ۴۰۹۶ channel، پیشوند هر stream تا۲۵۶KiB و۶۴ درخواست؛ حداکثر۲۰۴۸ درخواست صادر می‌شود. parser در ابهام/framing/gap resync نمی‌کند. شکاف یا cap باید در تحلیل لحاظ شود؛ گزارش ناقص را clean تلقی نکنید.
- DNSِ sink شامل 0.0.0.0 و loopback است؛ این فقط نتیجه resolver در زمان بررسی است، نه اثبات منع همه اتصال‌های موجود/IPv6/DoH/IP مستقیم. تطابق hash ابتدا/انتها هم مانع تغییر موقت همزمان نیست.
- نبود تطبیق CPU یا بدنه/کلید حساس در نمونه، **نبود همه اطلاعات شخصی را ثابت نمی‌کند**. هیچ verdict پاک/فقط دانلود خودکار داده نمی‌شود. completion و مسئله fingerprint انتقال A→B جدا و حل‌نشده‌اند.
- تأیید امضای native با سیاست قبلی و revocation حفظ شده و ممکن است با سرویس گواهی ارتباط بگیرد. SelfTest واقعی فقط worker loopback متعلق به ابزار است؛ Windows runner، ویندوز شما یا آپدیت کامل بازی را شبیه‌سازی نمی‌کند.
