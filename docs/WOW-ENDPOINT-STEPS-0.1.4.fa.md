# WoW Endpoint Steps 0.1.4 — آزمایش گروهی پنج مقصد

## مبنای انتخاب
پنج مقصد TCP در endpoint-results-3d2d02144dcd4572ade5fa45a9031011.json ورود عادی و حذف تأییدشده داشتند؛ اجرای تازه در آن گزارش تأیید نشده بود. در endpoint-results-69ad6e3c94074847844debe3f8556360.json برای 3.124.215.108:443 اجرای تازه هم با انتخاب کاربر و مشاهدهٔ اتصال پردازش تازه پشتیبانی شد؛ world_ok، baseline_restored=yes و rule_absence_verified=true بود. هیچ سوکت هدف یا WFP block منطبق دیده نشد. این‌ها بدون اختلال مشاهده‌شده‌اند، نه غیرضروری/CDN/فاقد تله‌متریِ اثبات‌شده.

## تغییر
در UI حالت تک‌مقصد حفظ شده و حالت صریح گروه پنج‌تایی اضافه شد. فهرست ثابت: 3.124.215.108:443، 3.75.62.211:443، 35.204.95.176:1119، 37.244.29.93:3724، 37.244.62.205:3724، همگی TCP. مقصد مختل‌کنندهٔ ورود 37.244.29.11:3724، مقصد ششم 37.244.62.60:3724 و UDPها خارج گروه‌اند. فقط برنامهٔ انتخابی و همان tupleهای خروجی محدود می‌شوند؛ نه تمام سیستم و نه subnet/تمام پورت‌ها.

هر عضو journal/مالکیت/نگهبان جدا دارد و همه یک مهلت ۳۰۰ ثانیه‌ای از آغاز آماده‌سازی دارند. ساخت ترتیبی است نه اتمیک؛ مرحلهٔ فعال فقط پس از موفقیت همه و آمادگی یک پایشگر گروه باز می‌شود. شکست میانی، بازیابی همه را درخواست می‌کند. خطای حذف یک عضو باعث رهاکردن حذف بقیه نمی‌شود. نتیجهٔ موفقیت و گذر از baseline تا تأیید حذف همه ممنوع است. journalها در بازیابی ناقص حفظ می‌شوند. guard expiry یک عضو نیز بازیابی کل گروه را در کنترل‌کننده درخواست می‌کند؛ مستقل از کنترل‌کننده هر guard عضو خود را بازیابی می‌کند.

در توقف، marker پایان پایش پیش از حذف نوشته می‌شود و انتظار نتیجهٔ monitor به بعد از تلاش حذف همه منتقل شده است. گروه یک پایشگر دارد که تا پایان مهلت یا توقف نمونه می‌گیرد؛ تک‌مقصد همچنان ۹۰ ثانیه است. نتیجهٔ هدف گروه aggregate با scope=any_group_target است، نه attribution برای هر IP یا rule. record گروه mode=group و endpoints دارد، نه پنج آزمایش مستقل. rule_causality_proven و packet_block_verified false هستند.

## QA و تحویل
۸۴ تست بدون failure/skip با PowerShell رسمی QA روی Linux پاس شدند: workflow قبلی، گروه، API، رضایت، rollback جزئی، uncertainty، شکست حذف یک عضو و ادامهٔ بقیه، recovery پس از restart، deadline، guard، عدم صدور مسیر خصوصی، parser و handoff واقعی و تشخیص یک مقصد غیرِعضو اول در worker واقعی با Windows API mock. UI در desktop و 390px و حالت تیره رندر و مشاهده شد. گروه روی Windows واقعی/بازی توسط سازنده اجرا نشده و رفتار واقعی Firewall/WFP هنوز نیازمند اجرای کاربر است.

بستهٔ کامل دارای همان ۳۴ فایل runtime بدون تغییر است؛ دانلود شبکه/نصب Python/تغییر ExecutionPolicy لازم نیست. ابتدا ابزار قبلی بازیابی و بسته شود؛ در صورت نیاز Restore.cmd همان پوشه تا تأیید حذف، سپس استخراج بستهٔ کامل در همان پوشه با حفظ private-state و output. پس از شروع موفق گروه، کاربر بازی را عادی کامل ببندد/باز کند؛ یک تلاش ورود و مشاهدهٔ محیط، سپس نتیجه و baseline را ثبت و JSON خروجی را ارسال کند. خطای احراز هویت را تکرار نکند. قوانین ذاتاً منقضی نمی‌شوند؛ نگهبان حذف می‌کند و sleep/خاموشی/خطا ممکن است بازیابی را عقب بیندازد. پوشه تا تأیید حذف حفظ شود. هیچ سیاست امنیتی، VPN، hosts، گواهی، تنظیم بازی یا rule غیرخودی تغییر نمی‌کند.
