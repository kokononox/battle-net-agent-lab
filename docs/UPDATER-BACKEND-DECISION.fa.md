# تصمیم معماری موتور اپدیتر

## نتیجه و وضعیت

بررسی کد عمومی مسیر جایگزینِ Agent را روشن می‌کند، نه اینکه مانع موتور مستقل را حل‌شده اعلام کند. این گزینه از قبل در Sources مخزن ذکر شده بود؛ یافتهٔ این گام بررسی مستقیم رفتار اجرایی و محدودیت‌های آن است، نه کشف یک الگوریتم مستقل تازه.

وضعیت: تصمیم کاربر لازم؛ معماری تغییر نکرده، backend اجرایی تازه ساخته یا آزموده نشده است. معیار فعلی همچنان اپدیتر قابل‌استفاده برای نسخه‌های آینده است، نه تبدیل ثابت بین دو build تاریخی.

## منابع دقیق و آنچه واقعاً نشان می‌دهند

منبع community، نه API پشتیبانی‌شدهٔ رسمی Blizzard: `barncastle/Battle.Net-Installer` در commit ثابت `3aa2d98d866b393197da0b75d7381b7fff495ad9`.

- [README](https://github.com/barncastle/Battle.Net-Installer/blob/3aa2d98d866b393197da0b75d7381b7fff495ad9/README.md): Windows و .NET 8، نصب و به‌روز بودن Battle.net و ورود اخیر لازم‌اند؛ اگر همان محصول در مسیر موجود باشد و آپدیتی وجود داشته باشد، آن را آپدیت می‌کند. این ادعای مستندات آن پروژه است، نه آزمون موفق این پروژه با Retail فعلی یا تضمین همهٔ نسخه‌های آینده.
- [AgentApp.cs](https://github.com/barncastle/Battle.Net-Installer/blob/3aa2d98d866b393197da0b75d7381b7fff495ad9/BNetInstaller/AgentApp.cs): Agent.exe را با `--internalclienttools` اجرا می‌کند و پورت آن را پیدا می‌کند؛ Dispose نیز فرایند را می‌بندد. این یک probe بی‌اثر یا dry-run نیست. سیاست start/stop آن بدون بررسی به اپدیتر منتقل نمی‌شود.
- [AgentClient.cs](https://github.com/barncastle/Battle.Net-Installer/blob/3aa2d98d866b393197da0b75d7381b7fff495ad9/BNetInstaller/AgentClient.cs): ارتباط HTTP با loopback و هدر Authorization. وجود کلاینت HTTP محلی به‌تنهایی اثبات بی‌خطر بودن فراخوانی، قرارداد پایدار نسخه‌ای یا بی‌نیازی از احراز هویت نیست.
- [InstallProductTask.cs](https://github.com/barncastle/Battle.Net-Installer/blob/3aa2d98d866b393197da0b75d7381b7fff495ad9/BNetInstaller/Operations/InstallProductTask.cs): پس از تنظیم UID، صریحاً `UpdateEndpoint.Post()` را فراخوانی می‌کند، سپس پیشرفت install/update را می‌خواند. اجرای ابزار برای «فقط دیدن برنامهٔ آپدیت» مجاز یا بی‌اثر فرض نمی‌شود.

هیچ‌یک از این چهار فایل، سیاست کامل مستقل locale/category/0x4000، variant/dependency/patch closure یا یک plan فقط‌خواندنیِ معتبر برای Retail ما را اثبات نمی‌کند. عمومی بودن کد ابزار، API خصوصی Agent را رسمی یا پایدار نمی‌کند.

## دو مسیر با خروجی متفاوت

### A — اپدیتر با backend رسمی Agent

رابط و کنترل عملیات متعلق به برنامهٔ ماست؛ انتخاب فایل و اعمال به‌روزرسانی به موتور Blizzard واگذار می‌شود. این انتخاب نیاز به بازسازی قواعد خصوصی و CASC writer خودمان را از مسیر این محصول برمی‌دارد، ولی به معنی حل آن مسائل در موتور مستقل نیست.

وابستگی آشکار: Battle.net/Agent، وضعیت حساب، شبکه و تغییرات احتمالی API خصوصی. تضمین پشتیبانی آینده نداریم؛ شناسایی قابلیت و توقف روی نسخهٔ پشتیبانی‌نشده لازم است. هدف telemetry اصلی نیز باید جدا بماند؛ اجرای Agent ممکن است ترافیک و state خودش را ایجاد کند.

پس از انتخاب این مسیر: قرارداد عملیات و مالکیت فرایند، اعتبارسنجی محصول/مسیر، رفتار تعارض با Battle.net باز، حذف فرمان post-download/repair از مسیر عادی، گزارش حداقلی بدون token و سپس آزمون توافق‌شده روی کپی جدا بررسی می‌شود. این فهرست طراحی آینده است، نه قابلیت پیاده‌شده. انتخاب معماری به‌خودی‌خود اجازهٔ اجرا، ورود حساب، دانلود یا نوشتن روی بازی نیست.

### B — اپدیتر مستقل از Battle.net/Agent

پیش‌فرض فعلی بدون تأیید معماری حفظ می‌شود. باید شواهد مستقیم Retail یا تطبیق کنترل‌شده برای قواعد انتخاب و سپس نویسندهٔ تراکنشی CASC، بازیابی قطع عملیات و آزمون end-to-end فراهم شود. منابع Classic و تست‌های مصنوعی جای این شاهد را نمی‌گیرند. افزودن wrapper و شمار تست بیشتر به‌تنهایی این مانع را رفع نمی‌کند؛ زمان قطعی تکمیل اعلام نمی‌شود.

تحقیق عمومی و داده‌های قبلی قابل استفاده‌اند؛ هر آزمایش رسمی یا خواندن تازهٔ نصب، فقط با دامنه و تأیید جدا. فعلاً درخواست فایل حجیم، اسکن کامل یا تغییر دسترسی وجود ندارد.

## دامنهٔ این تغییر

فقط مستندسازی تصمیم و لینک README. هیچ کد اجرایی، fixture، workflow، پرچم qualification یا نتیجهٔ QA عوض نشده؛ تست تازه اجرا نشده و موفقیت تازه‌ای ادعا نمی‌شود. Agent اجرا نشد، ورود حساب/شبکهٔ بازی/خواندن یا نوشتن نصب انجام نشد، ZIP تازه تولید نشد. وضعیت قدیمی machine-readable نباید به معنی تأیید مسیر A تعبیر شود؛ این تصمیم هنوز pending است.
