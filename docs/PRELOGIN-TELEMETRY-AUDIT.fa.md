# ممیزی پیش از ورود: آیا مشخصات فقط به مقصد تله‌متری می‌رود؟

تاریخ: 2026-10-24. مرحله: ممیزی آفلاین شواهد موجود؛ هیچ اجرای تازهٔ Setup، workflow یا تغییر امنیت سیستم انجام نشده است.

## نتیجهٔ فعلی

- **یافتهٔ مثبت:** در آزمایش startup بدون ورود H1، رشتهٔ نام CPU مرجع همان VM در بدنهٔ خروجی `POST /data` به `telemetry-in.battle.net`، از Agent امضاشده، مشاهده شده است. محل مشاهده ورودی پیش از TLS تابع EncryptMessage است. در همان نمونه رمزگذاری محلی موفق گزارش شده؛ این نه صرفاً لاگ سخت‌افزار محلی است و نه خواندن اطلاعات از ciphertext.
- **تنها مقصد سخت‌افزار؟ اثبات نشده.** تنها مقصدی که در درخواست‌های قابل‌بازسازی این نمونه تطبیق لفظی CPU دارد، دامنهٔ بالا است. این جمله با «همهٔ مسیرها فقط همین مقصد را دارند» متفاوت است.
- **متادیتای نرم‌افزار فقط در تله‌متری نیست.** درخواست‌های سرویس نسخه، Level3 و nydus شامل User-Agent با نسخهٔ Agent یا Bootstrapper هستند. این مشخصات نرم‌افزار است، نه شاهد شماره‌سریال دستگاه یا ارسال CPU به همان مقصدها.
- پذیرش/ذخیره‌سازی سمت سرور، فهرست کامل مشخصات، رفتار همهٔ کاربران/نسخه‌ها و fingerprint دادهٔ بازی از این شواهد نتیجه نمی‌شود.

| nydus.battle.net | GET geoip با بدنهٔ صفر؛ نسخهٔ Bootstrapper | درخواست geoip شاهد ارسال موقعیت دقیق GPS نیست |

این جدول ممیزی شواهد پروتکلی است، نه مقایسهٔ حجم/اثر انسداد؛ نمودار کاهش ترافیک تولید نمی‌شود.

## پوشش ابزار و علت بازبودن سؤال انحصار

کد H1 فقط send/WSASend قابل‌تشخیص به‌عنوان HTTP و ورودی SSPI EncryptMessage را دنبال می‌کند. دادهٔ رمزگذاری‌شدهٔ غیرHTTP در مسیر Winsock عمداً کنار گذاشته می‌شود. پوشش OpenSSL/BoringSSL، HTTP/2، QUIC و همهٔ فرایندهای بیرون از درخت تضمین نشده است. هر ورودی حداکثر 16 KiB و تعداد رویدادها محدود است. ثبت کامل بدنه در نمونه با پوشش کامل همهٔ ترافیک متفاوت است. صفر بودن dropped event یا gap گزارش‌شده این نقاط کور را حذف نمی‌کند.

در capture کاربر مقصد ingest.gdp.blizzard.com نیز دیده شده، اما بدنهٔ رمزگشایی‌شدهٔ آن در اختیار نیست. این فقط یک مقصدِ حل‌نشده است؛ هنوز شاهد سخت‌افزار در آن نداریم. capture کاربر مرحلهٔ اولیهٔ فایل حدود 4 مگابایتی را پوشش نمی‌دهد. این capture و لاگ‌های خصوصی کاربر به مخزن منتقل نشده‌اند.

## ابزار قابل‌بازتولید این شاخه

ابزار `analysis-tools/prelogin-audit/audit_startup.py` فقط یک گزارش موجود را می‌خواند، درخواست شبکه یا اجرای هدف ندارد و مقادیر بدنه/هدر/CPU را در خروجی کپی نمی‌کند. نتیجهٔ آن در `reports/prelogin-startup-baseline-audit.json` است.

```sh
python analysis-tools/prelogin-audit/audit_startup.py baseline-api.json result.json
python -m unittest discover -s analysis-tools/prelogin-audit -p 'test_*.py' -v
```

هفت آزمون مصنوعی محلی پاس شدند. جمع مقصدها و تطبیق CPU با یک مسیر محاسبهٔ مستقل بازبینی شدند. آزمون‌ها fixture هستند، نه اجرای تازهٔ ویندوز یا شاهد جدید ارسال.

## کار بعدی سؤال اول

1. بررسی ساختار پیام‌های باینری و ارتباط آن‌ها با schema همان نسخه؛ استخراج فهرست فیلدها، بدون انتشار شناسه‌های دستگاه.
2. تکمیل مشاهدهٔ مسیر واقعی API و caller-module برای فرایندهای صاحب اتصال؛ شمارش جداگانهٔ مسیرهای پوشش‌داده‌نشده و محدودیت‌ها، به‌جای تکرار inventory مشابه.
3. پس از آماده‌شدن و آزمون ابزار، طراحی اجرای startup بدون ورود روی Windows دورریختنی با شروع ثبت پیش از اجرای فایل اولیه؛ کنترل دقیق نسخه/هش و تمایز فرایندها. این سند خودش workflow را dispatch نمی‌کند.
4. برای ادعای تحویل شبکه، هم‌بسته‌کردن بدنهٔ پیش-TLS با خروجی شبکه/پاسخ کاربردی؛ موفقیت EncryptMessage به‌تنهایی تأیید سرور نیست.

TLS verification، CA، فایروال یا نصب اصلی کاربر در این گام تغییر نمی‌کند. ابزارگذاری ممکن است زمان‌بندی/پایداری را تغییر دهد و برای اجرای واقعی gate مستقل لازم دارد. هیچ آزمایش محدود نمی‌تواند رفتار همهٔ نسخه‌های آینده را تضمین کند.

## صف سؤال دوم — هنوز شروع نشده

ابزار اجرایی فقط‌خواندنی مسیر نصب WoW Retail را بگیرد، فایل‌ها و ساختارهای idx/data/lru/CASC را متناسب با فرمت واقعی بررسی کند و مقایسهٔ کنترل‌شدهٔ دو نصب هم‌نسخه را ممکن کند. دادهٔ اصلی بازی از cache/log/config جدا باشد. بدون تغییر، repair، اجرای بازی یا upload خودکار. نبود رشتهٔ واضح، اثبات نبود fingerprint نیست. تا پیشروی سؤال اول، پیاده‌سازی این ابزار در صف می‌ماند.
