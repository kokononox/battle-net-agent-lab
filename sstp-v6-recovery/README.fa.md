# وایت‌لیست مقصد روی تونل — نسخهٔ آزمون، نه کیل‌سوییچ جدید

## ابتدا محدوده را بدانید
این ابزار، **مقصدهای خارج از فهرست را روی همهٔ رابط‌های RemoteAccess مسدود می‌کند**. به‌جای اضافه‌کردن Allowهای بی‌اثر کنار Allow عمومیِ فایل قبلی، از تقدم Block صریح استفاده می‌کند: متمم IPهای مجاز در IPv4 و IPv6 مسدود می‌شود. برای مقصد مجاز، این ابزار هیچ Allow اضافه نمی‌کند؛ همان اجازهٔ قبلی VPN باید وجود داشته باشد.

**این بسته تضمین «هیچ نشتی از کل ویندوز» نیست.** فقط یک لایهٔ محدودسازی اضافی روی تونل است. محافظت بیرون تونل همچنان همان فایل SstpKillSwitch-v1.2 فعلی شماست؛ Allowهای قبلی، استثناهای DNS و TCP443 آن اصلاح نشده‌اند. این بسته مشکل‌های آن را پنهان یا حل‌شده اعلام نمی‌کند. اگر فقط نسخه‌ای با تضمین کامل می‌خواهید، Enable این نسخهٔ آزمایشی را اجرا نکنید.

این ابزار به یک نشست یا پروفایل خاص SSTP قفل نشده است؛ روی **همهٔ RemoteAccessها** اثر دارد. پیش از Prepare/Enable فقط یک VPN متصل و از نوع SSTP باید وجود داشته باشد، اما بعد از خروج برنامه نگهبان تشخیص تونل تازه وجود ندارد. هویت پروفایل، تغییر رابط، قطع‌وصل واقعی SSTP و boot هنوز qualified نیستند.

## چیزهایی که تغییر نمی‌کند
- شورتکات Connect-rus و فایل کیل‌سوییچ قبلی تغییر یا اجرا نمی‌شوند.
- هیچ Allow یا تغییر DefaultOutboundAction/Profile/DNS/NIC/Route/Service/Task ایجاد نمی‌شود.
- هیچ قاعدهٔ قبلی غیرفعال یا حذف نمی‌شود؛ حذف با Group/DisplayName یا reset عمومی وجود ندارد.
- این برنامه سرویس/پردازش نگهبان/تایمر انقضا ندارد. Enable + exit و Disable + exit پنجره و PowerShell اختصاصی ابزار را تمام می‌کنند؛ محدودیت در Windows Firewall می‌ماند.
- پردازش‌های داخلی Windows، فایروال و SSTP برای شبکه همچنان لازم‌اند.

## پیش‌نیاز آزمون
Windows 10/11 با Windows PowerShell 5.1 و NetSecurity و دسترسی Administrator. بسته را کامل از ZIP خارج کنید. کدها امضای Authenticode ندارند؛ فقط از همین بستهٔ با hash مشخص استفاده کنید. دو نسخه از ابزار را همزمان باز نکنید. در صورت UAC، درخواست مربوط به همین فایل را بررسی کنید.

پیش از Enable، بازی، دانلود، مرورگر و برنامه‌های دارای اتصال شبکه را ببندید. پایان اعمال، barrier اثبات‌شده برای همهٔ اتصال‌های قدیمی نیست. این آزمون ممکن است دسترسی به وب/چت را روی VPN قطع کند؛ فایل Disable.cmd و این راهنما را آفلاین در همان پوشه نگه دارید. تست اولیه را با کار حساس یا بازی در حال اجرا انجام ندهید.

## راه سادهٔ آزمون
1. با همان شورتکات فعلی خودتان SSTP را وصل کنید. کیل‌سوییچ قبلی باید از قبل فعال باشد؛ این ابزار آن را فعال نمی‌کند.
2. Start.cmd را اجرا کنید و درخواست Administrator را بررسی/تأیید کنید. بازشدن پنجره هیچ قاعدهٔ فعال شبکه‌ای نمی‌سازد.
3. Check only را بزنید. اگر خطا دیدید، Enable نکنید. این check گواه نبود نشتی نیست؛ فقط سه profile فعال با default Block، یک اتصال SSTP و وجود یک اجازهٔ RemoteAccess از گروه قدیمی را می‌سنجد.
4. فهرست را ویرایش کنید: هر خط یک دامنهٔ دقیق یا public IP. مقصد اولیه level3.blizzard.com است. Save list فقط فایل را ذخیره می‌کند.
5. Prepare disabled را بزنید. دامنه‌ها با resolver **فعلی ویندوز** resolve می‌شوند؛ مسیر DNS به VPN pin نشده است و این lookup ممکن است از استثنای DNS فعلی استفاده کند. اگر این موضوع برایتان پذیرفتنی نیست، فقط IP وارد کنید و همهٔ دامنه‌ها را حذف کنید؛ یا تست را متوقف کنید. خروجی، snapshot IP است و خودکار به‌روزرسانی نمی‌شود.
6. Prepare فقط سه قانون غیرفعال خودی می‌سازد. بعد از خواندن هشدار، Enable + exit را بزنید. پنجره باید بسته شود. ابزار نباید در پس‌زمینه به‌عنوان سرویس/نگهبان بماند.
7. روی همان VPN، دسترسی موردنیاز به مقصد مجاز و عدم دسترسی به یک مقصد خارج فهرست را بررسی کنید. صرف بازشدن دامنهٔ مجاز یا timeout دامنهٔ دیگر اثبات نبود نشتی، DNS/IPv6 درست یا انحصار hostname نیست؛ ممکن است cache/proxy/IP مشترک دخیل باشد.
8. برای بازگشت، Disable.cmd را اجرا و تأیید کنید. این فرمان فقط محدودیت‌های همین ابزار را غیرفعال می‌کند؛ کیل‌سوییچ قبلی را خاموش یا reset نمی‌کند. پس از آن می‌توانید Start.cmd → Remove disabled را برای حذف دقیق سه قانون غیرفعال ابزار بزنید.

## ویرایش فهرست پس از فعال‌سازی
Save list به‌تنهایی سیاست فعال را تغییر نمی‌دهد. Disable → Prepare disabled → Enable لازم است. تغییر فایل بعد از Prepare موجب رد Enable می‌شود تا snapshot قبلی با فهرست تازه اشتباه نشود. هنگام Disable تا Enable جدید، محدودیت وایت‌لیست موقتاً وجود ندارد و فقط کیل‌سوییچ قبلی برقرار است؛ در این فاصله برنامهٔ شبکه‌ای باز نکنید. این نسخه live-update اتمیکِ بدون فاصله نیست.

نام دامنه فقط برای resolve اولیه است؛ همهٔ سرویس‌های روی IP مشترک می‌توانند از همان مجوز قبلی تونل استفاده کنند. هدف «وایت‌لیست hostname انحصاری» نیست. DNS داخل تونل اگر public IP باشد باید در فهرست باشد تا از این لایه عبور کند. این نسخه private IP نمی‌پذیرد و برای DNS خصوصیِ داخل VPN استثنای اختصاصی ندارد؛ آن ترافیک ممکن است مسدود شود. استثنای DNS بیرون تونلِ فایل قبلی همچنان دست‌نخورده است. ممکن است بازی علاوه بر مقصد اولیه به IPهای دیگری نیاز داشته باشد؛ این ابزار خودش چیزی به فهرست اضافه نمی‌کند.

## خطا، توقف وسط کار و بازگردانی
سه قانون خودی با نام GUIDدار ساخته می‌شوند: guard گذار و دو Block متمم v4/v6. guard فقط روی RemoteAccess است، نه کل دستگاه. ایجاد اولیه همه غیرفعال است. تصویر کامل raw rule و هفت filter در journal با ACL محدود Admin/SYSTEM ثبت می‌شود. تغییر Enabled با write-ahead و readback انجام می‌شود؛ guard تا تأیید قواعد متمم نگه داشته می‌شود. Exit/Exception به‌خودیِ‌خود guard را برنمی‌دارد.

Disable به اتصال فعال VPN و نتیجهٔ Full در ActiveStore وابسته نیست؛ فقط تصویر دقیق قواعد خودش در PersistentStore را لازم دارد. در صورت توقف فرایند وسط Enable، Disable در اجرای تازه می‌تواند pending دقیق before/after را بازیابی کند. journal گمشده/خراب/backup-only یا تغییر قاعدهٔ خودی موجب توقف می‌شود، نه حدس، Force-Allow یا حذف عمومی. اگر guard برقرار مانده باشد، ترافیک تونل ممکن است بسته بماند؛ ابتدا Disable.cmd همین بسته را امتحان کنید. هنگام این تست، Disable/Enable فایل کیل‌سوییچ قدیمی را نیز همزمان اجرا نکنید؛ به‌خصوص Disable آن می‌تواند محافظت بیرون تونل را بردارد. از EmergencyReset فایل قبلی استفاده نکنید؛ آن با Allowکردن profileها محافظت قبلی را تضعیف می‌کند و Blockهای این بسته را هم حذف نمی‌کند.

توقف بین ساخت قاعدهٔ غیرفعال و ثبت تصویر کامل آن، وضعیت staging نامعلوم را ایجاد می‌کند؛ ابزار آن را خودکار adopt/delete نمی‌کند. چنین حالتی ممکن است نیاز به بررسی دقیق داشته باشد، اما این مرحله هنوز guard فعال نمی‌سازد. مقابله با مدیر محلی متخاصم، تغییر همزمان مستقل فایروال، GPO بعدی یا مهاجم kernel جزو تضمین نیست. lock فقط دو اجرای همکار همین ابزار را سریالی می‌کند.

journal محلی در `%ProgramData%\SstpDestinationOverlayTest` است؛ allowlist.json کنار ابزار قرار دارد. journal/پیکربندی/نام شبکه‌ها را عمومی آپلود نکنید. برنامه خطای ثابت می‌دهد و فایل‌های خصوصی را در log عمومی dump نمی‌کند.

## وضعیت آزمون این بسته
نتیجهٔ همین نسخه در BuildReceipt.json و RECOVERY.fa.md مستند می‌شود. قواعد آزمایشی فعال، فقط برنامهٔ fixture روی runner ویندوز را هدف می‌گیرند. آزمون بازیابی صرفاً قواعد خودی غیرفعال دارد. ساخت و Dispose رابط، آزمون کلیک تعاملی و مسیر UAC کاربر غیرمدیر نیست.

IPv6 arithmetic/rule creation != IPv6 packet proof. Windows CI != دستگاه کاربر. موفقیت TCP connect یا رد آن != نبود هرگونه packet leak. reboot/SSTP disconnect/UDP/DNS/LAN/ICMP و اتصال‌های ازقبل‌باز هنوز qualification نهایی ندارند. این بسته برای آزمون محدود است، نه استفادهٔ قطعی امنیتی.

برای خواندن وضعیت بدون تغییر قواعد، فرمان توسعهٔ `Run.ps1 -Action Status` وجود دارد؛ خروجی آن phase و تطبیق دقیق قواعد خودی را نشان می‌دهد، نه گواه نبود نشتی.

در طول آزمون، VPN یا رابط RemoteAccess دیگری وصل نکنید و فعلاً ری‌استارت/تغییر تنظیمات شبکه را وارد تست اول نکنید. بستن پنجره یا حذف پوشه، قواعد فعال را برنمی‌دارد. پیش از حذف فایل‌های ابزار، Disable و سپس Remove disabled را انجام دهید؛ journal را برای وادارکردن برنامه به شروع دوباره پاک نکنید.
