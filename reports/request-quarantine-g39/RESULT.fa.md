# نتیجهٔ G39 — ثبت خصوصی بدون عبور درخواست ناشناخته

## ساخته شد
نمونهٔ آفلاین قرنطینهٔ HTTP ساخته شد. برخلاف گزارش قبلی که فقط hash مسیر را داشت، path/query/headerهای قابل بررسی در رکورد خصوصی باقی می‌مانند؛ هیچ درخواست در این مسیر به upstream نمی‌رود. همهٔ رسیدها blocked هستند و ثبت موفق به معنی approved شدن resource نیست.

کل raw request و body خام ذخیره نمی‌شوند. credentialهای شناخته‌شده حتی در رکورد خصوصی حذف می‌شوند. path/query و header ناشناخته ممکن است حساس باشند و خصوصی باقی می‌مانند. رسید عمومی هیچ path، header، hash مسیر، digest بدنه یا شناسهٔ دستگاه ندارد؛ فقط شناسهٔ تصادفی capture و وضعیت محدود منتشر می‌شود.

## آزمون و محدودیت
30آزمون روی POSIX موفق شدند: حفظ خصوصی path/query/header، حذف credential/body خام، جلوگیری از نشت در رسید، رد خطای حاوی دادهٔ حساس، دسترسی0700/0600، رد symlink/hardlink و تغییر مجوز، quota پس از بازکردن مجدد، پاک‌کردن نوشتن ناقص، درخواست‌های نامعتبر و هم‌زمان. در آزمون32ثبت هم‌زمان با سقف16رکورد، همهٔ درخواست‌ها blocked ماندند و سقف ذخیره رعایت شد. در مدت هر test ساخت socket ممنوع بود.

هیچ Setup اجرا نشد، ارتباط خارجی یا TLS session ایجاد نشد، فایروال و Windows task تغییر نکردند، و هیچ private capture واقعی یا آزمایشی منتشر نشد. فقط کد، نتیجهٔ تست و توضیحات منتشر می‌شوند. هیچ resource واقعی به allowlist اضافه نشد.

این هنوز اصلاحِ فعال پراکسی ویندوز نیست: backend فعلی فقط POSIX است و روی Windows عمداً fail-closed می‌کند. هیچ رکوردی از نصب واقعی به این نمونه وارد نشده است. پس هنوز manifest واقعی payloadهای Battle.net نداریم. دیدن body خام، رمزگشایی HTTPS، سازگاری نصب و ضد فینگرپرینت عملی اثبات نشده‌اند.

## قدم بعدی
پیش از هر اجرای نصاب، backend خصوصی ویندوز و جای‌گذاری hook پیش از dial/send باید پیاده و با دادهٔ ساختگی روی VM آزموده شوند. کنترل مالک/Job/lease نباید حذف شود. بعد می‌توان فاز کشف محدودِ درخواست‌های قابل‌مشاهده را با همهٔ موارد ناشناخته مسدود بررسی کرد؛ اگر دانلود وابسته به HTTPS ناشناخته بود، همان وابستگی گزارش شود، نه اینکه برای تکمیل تست مجاز شود.

رکوردهای خصوصی باید محلی بررسی شوند تا ضرورت درخواست و احتمال شناسه‌بودن فیلدها تعیین شود؛ سپس فقط resourceهای دارای شواهد مستقل وارد policy بررسی‌شده شوند. hash یک مسیر یا ثبت موفق آن به‌خودی‌خود مجوز نیست.
