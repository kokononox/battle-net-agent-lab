# بازبینی محدود Level3 در داده‌های قدیمی

سه گزارش موجود G1، H1-baseline و H1-blocked با اسکریپت شمارش واحد بازخوانی و نتیجه اصلی با یک حلقه مستقل کنترل شد. این داده‌ها **startup روی VM موقت** هستند؛ نه دانلود کامل WoW و نه اجرای جدید BAT۰۶ کاربر.

| نمونه | درخواست به level3.blizzard.com | روش | بدنه غیرصفر | query |
| --- | --- | --- | --- | --- |
| G1 | 54 | GET | 0 | 0 |
| H1 baseline | 49 | GET | 0 | 0 |
| H1 blocked telemetry | 34 | GET | 0 | 0 |

مجموع۱۳۷؛ بدنه همه درخواست‌های این subset کامل/خالی و مسیر طبقه‌بندی‌شده `/tpr/` بود. فقط نام هدرهای accept، connection، host، range و user-agent دیده شد. مقادیر هدر/مسیر/محتوا در این سند صادر نشده‌اند. User-Agent می‌تواند metadata نسخه/کلاینت حمل کند؛ GET خالی، نبود همه اطلاعات شخصی را ثابت نمی‌کند. محتوای کدگذاری‌شده در مسیر، پوشش API ناقص، late attach و دریافت/ذخیره سرور با این بررسی رد/اثبات نمی‌شوند.

این شواهد انگیزه ابزار T1 است، نه verdict درباره سیستم کاربر. در حال حاضر تنها شاهد کاربر برای سری مکمل‌ها این است که می‌گوید فقط BAT۰۶ دانلود را راه انداخته و سپس عمداً Pause کرده؛ گزارش محتوایی تازه دریافت نشده است.

[شواهد ماشینی](historical-level3-review.json) شامل hash ورودی‌های قدیمی، run و source commit است؛ [اسکریپت بازتولید](../analysis/historical-level3-review.py) مسیر فایل‌های محلی ورودی را ثبت می‌کند. فایل‌های خام قدیمی و مجوز دسترسی‌شان جدا هستند؛ این اسکریپت از شبکه دانلودی ندارد.
