# اولین نمونه محتوایی T1.1 روی سیستم کاربر

## نتیجه محدود
گزارش کاربر READY=true، status=observation_ended، بدون error_code دارد. کاربر reported_progress و reported_paused انتخاب کرده؛ بایت/درصد دانلود مستقل اندازه‌گیری نشده است. ابزار hosts را تغییر نداده و hash ابتدا/انتها برابر است؛ هر سه snapshot پروفایل۲۴ sink صریح همراه Windows NO_DATA و Level3 عمومی را پاس می‌کنند. این enforcement کامل شبکه نیست.

## درخواست‌های قابل بازسازی Level3
۲۶ درخواست از Agent اصلی امضاشده با hash b422e8d4f0fe0cbcb2d106b455aa44d78eb3a4e173340f05e6cadac5091571b5 بازسازی شده‌اند؛ همه GET، طبقه مسیر tpr، بدنه کامل با طول صفر، query صفر و لایه plaintext_winsock_input. این بخش ورودی send روشن است؛ برای دیدن آن نیاز به کلید TLS نبود. این مشاهده API است، نه ضبط مستقل روی سیم یا اثبات دریافت سرور.

هدرهای ثبت‌شده فقط accept، host و range هستند؛ unknown_header_count صفر و User-Agent/Cookie/Authorization در این۲۶ درخواست دیده نشده‌اند. نام CPU مرجع در حافظه در دسترس بوده و تطبیق literal در requestها و رخدادهای پایه صفر است؛ field hints نیز خالی‌اند. هیچ‌کدام نبود همه اطلاعات شخصی را ثابت نمی‌کنند: مسیر کامل و مقادیر هدر عمداً صادر نشده‌اند و ID hashشده/encoded/ناشناخته با این گزارش رد نمی‌شود.

این درخواست‌ها با دریافت محتوای CDN سازگارند؛ محتوای پاسخ/recv و بایت دانلود ضبط نشده، پس تمام payload بازی یا بی‌نشان بودن همه فایل‌ها اثبات نشده است. سؤال fingerprint انتقال A→B همچنان آزمایش نشده است.

## نکته تعیین‌کننده: چهار اتصال HTTPS دیگر بدون مشاهده محتوا
همان گزارش چهار مقصد عمومی TCP/443 را برای process_index=6، battle.net.exe امضاشده نشان می‌دهد:

| مقصد | پورت | شاهد |
| --- | --- | --- |
| 52.29.86.120 | 443 | snapshot فرایند؛ محتوا/hostname نامعلوم |
| 2.21.23.89 | 443 | snapshot فرایند؛ محتوا/hostname نامعلوم |
| 54.149.134.39 | 443 | snapshot فرایند؛ محتوا/hostname نامعلوم |
| 192.178.24.142 | 443 | snapshot فرایند؛ محتوا/hostname نامعلوم |

این فرایند attached و hookها نصب‌شده گزارش شده، ولی input_events=0 دارد. از IP یا نبود رخداد نمی‌توان مقصد را telemetry/Google/Amazon/خرید یا بی‌ضرر نامید و نه علت دقیق فقدان پوشش را نتیجه گرفت. API/TLS دیگری ممکن است در کار باشد، اما استفاده از BoringSSL/OpenSSL یا علت دیگر هنوز اثبات نشده است. شمار snapshot نیز حجم upload/download یا تعداد درخواست نیست.

## کیفیت و محدودیت
- یک sampler_error و دو attach_failed (launcher و یک battle.net.exe)؛ علت‌ها از این گزارش معلوم نیستند. Agent اصلی attach شده و script_error ندارد.
- هیچ cap پایه/بافر audit فعال نشده و sampler پایان یافته است. این نبود cap برابر پوشش کامل نیست؛ late attach و پروتکل/APIهای پوشش‌نداده‌شده باقی‌اند.
- هر۱۸۷ stream برچسب parsed_to_end و gap=false دارد، اما فقط۲۶ درخواست صادر شده است. کد parser برخی Hostهای نامعتبر/پورتِ پشتیبانی‌نشده را بدون request row رد می‌کند؛ پس این برچسب را اثبات همه درخواست‌های parse/audit شده نگیریم. در داده پایه۱۸۰ send با host_hint loopback ثبت است؛ raw برای تعیین علت دقیق حذف requestها موجود نیست.
- requestهای بازسازی‌شده startup و پنجره update درهم‌اند و زمان کلیک Resume ثبت نشده است. رخدادهای پایه phase دارند؛ آن را زمان‌بندی دقیق تک‌تک requestهای audit جا نزنیم.
- نسخه‌نشانگر ابتدا/انتها12.1.5.70448 است؛ قبلاً هم همین بود و completion را ثابت نمی‌کند.
- profiler ردیف‌های metadata۲۶request،۱۹ duplicate ظاهری نشان می‌دهد. چون URL/مقادیر حذف شده‌اند و چند request از یک channel می‌آید، این metadata تکراری حذف نشد؛ نه تعداد فایل یکتا و نه ترافیک تکراری اثبات شده است. ثابت بودن ستون‌ها یافته همین subset است، نه خطای ورودی.

## گام بعد
تکرار همین تست Level3 یا تعویض BAT در این لحظه ضروری نیست. پیش از verdict «فقط آپدیت»، شکاف پوشش محتوای battle.net.exe دارای چهار TCP/443 باید بررسی شود: شناسایی فقط‌خواندنی کتابخانه/API شبکه همان فرایند و ابزار مناسب آن، با حفظ امضا/TLS و بدون تغییر hosts/فایروال/فرایند یا اجرای بازی. هیچ ابزار/runner تازه‌ای در پاسخ به این گزارش راه‌اندازی نشده است. فعلاً آپدیت Pause بماند؛ هیچ رضایت برای تکمیل/حذف/Repair/rollback از این گزارش نتیجه نمی‌شود.
