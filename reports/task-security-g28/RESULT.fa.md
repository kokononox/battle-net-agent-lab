# G28 — تشخیص فقط‌خواندنی هویت و مجوز Taskها

## نتیجه
علت خطای قابل بازتولید در ثبت G27 پیدا شد: `TaskPath` دارای بک‌اسلش انتهایی به `Schedule.Service.GetFolder` داده می‌شد. درخواست اصلی برای هر چهار Task در هر دو نمونه، در مرحلهٔ `get_folder` با HRESULT `8007007b` شکست خورد. همان درخواست با حذف جداکنندهٔ انتهایی، با حفظ مسیر ریشه، موفق شد. lookup مستقل از ریشه با مسیر کامل Task نیز XML یکسان را برگرداند.

ثبت مجوزها و binding/image اکنون در بررسی مستقل G28 موفق است؛ اما این شواهد مجوز معافیت یا اثبات عامل تغییر نیست.

| Task | فایل مرتبط | نتیجهٔ API امضا در VM آزمایش |
| --- | --- | --- |
| RefreshCache | wosc.dll | Valid؛ ناشر Microsoft Corporation |
| PrintJobCleanupTask | printercleanuptask.dll | Valid؛ ناشر Microsoft Corporation |
| Registration | sc.exe | Valid؛ ناشر Microsoft Corporation |
| SvcRestartTask | sppcext.dll | Valid؛ ناشر Microsoft Corporation |

## دامنهٔ بررسی
دو snapshot تحت SYSTEM روی یک Windows hosted VM گرفته شد. در هر دو، descriptor مجوزها با owner/group/DACL خوانده و parse شد؛ SACL درخواست نشد. هش مجوزها، binding، فایل، تعریف Actions و Principals بین دو نمونه ثابت بود. hash فایل قبل و بعد از `Get-AuthenticodeSignature` برابر بود. COM handler هیچ‌کدام فعال نشد؛ فقط binding رجیستری HKLM و فایل System32 بررسی شدند.

نصاب اجرا نشد، فایروال تغییر نکرد و چهار Task هدف اجرا/ویرایش/غیرفعال نشدند. برای دسترسی SYSTEM فقط یک Task موقت متعلق به آزمایش ساخته، اجرا و سپس unregister شد؛ بنابراین ادعای «هیچ تغییر مطلق در سیستم» مطرح نیست.

امضاها خارج از ایزوله‌سازی بررسی شدند. سیاست revocation این API جداگانه audit نشده، پوشش رویداد پیوسته نیست و ثابت‌بودن هش ACL به معنی ارزیابی معنایی امن‌بودن همهٔ ACEها نیست. این VM جدید، مجوزهای ثبت‌نشدهٔ G26/G27 را بازسازی نمی‌کند. فایل Microsoft امضاشده نیز به‌تنهایی صحت آرگومان Task، عامل تغییر Enabled یا مجازبودن تغییر را اثبات نمی‌کند.

## اصلاح ثبت و گزارش
در شاخهٔ پژوهشی، فقط لایهٔ مشاهدهٔ G27 اصلاح شد:
- حذف جداکنندهٔ انتهایی فقط در آرگومان GetFolder، بدون تغییر هویت یا Task ثبت‌شده؛
- ثبت stage و HRESULT خطا با فیلدهای محدود؛
- خروجی null برای مقایسهٔ مجوز/Actions/Principals در صورت نبود داده، به جای نتیجهٔ گمراه‌کنندهٔ false؛
- عدم معرفی زمان اسمی final=270 به‌عنوان زمان دقیق رویداد؛ زمان poll با مبنای watch مشخص می‌شود.

۱۵ آزمون واحد این خلاصه‌ساز موفق شدند. شکل normalized lookup روی Windows در G28 واقعاً آزموده شد؛ ادغام اصلاح با کل کنترل ۲۷۰ثانیه‌ای زیر گیت هنوز دوباره اجرا نشده است. امضای G28 به گزارش تاریخی G27 تزریق یا به آن منتسب نشده است. قواعد طبقه‌بندی، اجازهٔ خروجی شبکه و تصمیم بازیابی تغییر نکردند؛ نسخهٔ عمومی 0.9.10 و main دست‌نخورده‌اند.
