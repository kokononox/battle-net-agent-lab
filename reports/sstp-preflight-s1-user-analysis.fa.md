# نتیجهٔ پیش‌بررسی S1 دستگاه کاربر

## جمع‌بندی
VPN داخلی SSTP با پروفایل holand متصل است و مسیر هر 2 IP فعلی Level3 روی رابط همان VPN گزارش شده است؛ اما ایزولاسیون فقط‌آپدیت اعمال نشده است.

- هر 3 پروفایل فایروال روشن است، ولی DefaultOutboundAction همه Allow است. 121 قانون خروجی فعال: 100 Allow و 21 Block؛ همه در خلاصه Local، بدون truncation. این شمارش به‌تنهایی عبور هر برنامه یا عدم وجود فیلتر WFP/ابزار دیگر را ثابت نمی‌کند.
- برای گروه SSTP Kill Switch هیچ قانون خروجی فعال و فایل state در محل مورد انتظار دیده نشده است. این نتیجه مربوط به همین گروه/مسیر است؛ «هیچ نوع کیل‌سوییچی در سیستم نیست» نتیجه مجاز نیست.
- split_tunneling=true گزارش شده، ولی مسیرهای Level3 روی VPN و prefix /1 هستند. بنابراین فقط از flag نمی‌توان گفت دانلود از VPN عبور نمی‌کند. پوشش همه مقصدها از این نمونه معلوم نیست.
- یک اتصال Established متعلق به PID سرویس SSTP، TCP443 و مطابق DNS سرور مشاهده شده؛ binding اختصاصی به پروفایل ثابت نشده است. IP و نام سرور VPN کاربر عمداً در مخزن عمومی کپی نشده‌اند.
- default route برای IPv6 خارج از رابط VPN گزارش شده است. این یک شکاف طرح ایزولاسیون است، نه اثبات ترافیک/نشت IPv6 در همین نمونه. آزمون enforcement نداریم.
- query_errors=0 و review_blockers=0؛ خالی‌بودن فهرست blocker به معنای مجوز Apply نیست: ready_to_apply_isolation=false و independent_local_rollback_prepared=false باقی‌اند.

## تصمیم و گام بعد
گزارش برای طراحی بعد کافی است؛ تکرار S1، BAT99، Resume، Enable/Disable/EmergencyReset یا حذف/Repair بازی لازم نیست. فعلاً Pause و تنظیمات فعلی حفظ شوند.

گام بعدی عامل: طراحی Apply کوتاه و قابل‌بازیابی، ابتدا gateهای تست بدون تغییر شبکه کاربر. snapshot کامل policy و rollback مستقل محلی/زمان‌دار باید قبل default-deny آماده و تست شود؛ Allowهای قبلی باید موقت و قابل‌بازیابی مدیریت شوند. زیرلایه فقط endpoint معتبر SSTP، داخل تونل فقط مقصدهای مشخص آپدیت با interface/address constraints؛ IPv6، DNS/bootstrap، CRL/OCSP و reconnect جدا و بدون کاهش اعتبارسنجی TLS حل شوند. اگر وابستگی امن با allowlist محدود ناسازگار بود، توقف/بازیابی، نه خاموش‌کردن امنیت.

هیچ ابزار Apply در این نتیجه ساخته/تحویل/اجرا نشده؛ هیچ firewall/route/VPN/game تغییر نکرده است. اسم holand برای این مرحله کافی بود؛ IP دستی/رمز عبور نیاز نیست. نبود telemetry در مسیر مجاز و fingerprint فایل A→B همچنان باز است.

## منشأ و روش
یک JSON ارسال‌شده توسط کاربر، نه دسترسی زنده عامل. بازه: `2026-10-19T01:30:09.5821248Z` تا `2026-10-19T01:30:13.4095069Z`؛ SHA256 فایل اصلی `44f7daf99ca38a5e175eea33685ee267a95a04cecfbeba93ce53dc4c8a2e59bd`. raw report و endpoint VPN فقط محلی نگه داشته شدند.

profiler عمومی این JSON تو‌در‌تو را به دلیل طول متفاوت آرایه‌ها جدولی نخواند؛ grain یک snapshot است، نه سطرهای هم‌طول. همه مجموعه‌ها با parser JSON و cross-foot شمار قواعد بررسی شدند؛ هیچ رکوردی حذف نشد. ادعاهای اصلی با خواندن دوم و predicate مستقل کنترل شدند. نمودار برای این نتیجه تشخیصی categorical مفید نیست. شواهد redacted در فایل JSON همراه است؛ این گزارش موجودیت/امضای مستقل دستگاه را گواهی نمی‌کند.
