# نتیجهٔ G40 — پذیرش بومی Windows برای قرنطینهٔ مصنوعی

## نتیجه
در اجرای `40236707506` با source commit `b12967aa92157f48b6f16f1cf1b76d8c06aa91e2`، helper C# کامپایل شد و17از17آزمون بومی Windows2025 موفق شد. شواهد با run/source و hash فایل‌های checkout تطبیق داده شدند؛ برای فایل‌هایی که Git در Windows با CRLF checkout کرده، تبدیل پایان‌خط صریحاً در فایل verification ثبت شده است. این به معنی تغییر دلخواه کد در تطبیق هش نیست.

## چه چیزی واقعاً آزموده شد
- نوشتن و خواندن capture ساختگی با ACL محدود SYSTEM/Administrators؛ owner و DACL محافظت‌شده با handle بررسی شدند.
- رد تغییر ACL پوشه و فایل، hardlink فایل و junction ریشه، بدون ثبت تازه.
- سقف16رکورد بعد از بازکردن دوباره و زیر24ثبت هم‌زمان؛ نام تکراری/overwrite ایجاد نشد.
- مالک TCP واقعی در IPv4 وIPv6.
- child پایتون واقعاً عضو Job نام‌دار شد و درخواست HTTP ساختگی به endpoint loopback فرستاد. درخواست خصوصی ثبت شد، شناسهٔ دستگاهِ ساختگی در query خصوصی قابل بررسی ماند، Cookie حذف شد، رسید عمومی شناسهٔ دستگاه نداشت و client فقط403 گرفت.
- child خارج از Job، expiry گذشته، controller identity اشتباه و lease بسته، بدون capture رد شدند.
- تغییر lease و ACL بعد از admission و قبل از capture نیز مانع ثبت شد.
- تابع اتصال بالادست در آزمون sentinel بود و عدم فراخوانی‌اش assert شد؛ handler اصلاً مسیر forwarding ندارد.

30آزمون POSIX هم جداگانه روی Linux موفق‌اند؛ این شمارش را به نتیجهٔ اجرای Windows اضافه نمی‌کنیم.

## مسیر رفع خطا، بدون پنهان‌کردن شکست‌ها
1. اجرای اول پیش از VM به دلیل YAML `if` دارای colon نامعتبر شد؛ به block scalar اصلاح شد.
2. اجرای بعدی ورودی نسبی compiler را پیدا نکرد؛ مسیر absolute بومی Windows با Resolve-Path داده شد.
3. پس از کامپایل،17آزمون در init آداپتور متوقف شدند؛ probe نشان داد helper با محیط عادی کار می‌کند.
4. مقایسهٔ کنترل‌شدهٔ محیط‌ها نشان داد نبود SystemDrive عامل توقف init است: محیط minimal و افزودن فقط AllUsersProfile شکست خوردند، افزودن SystemDrive و محیط اصلاح‌شده موفق شدند. فقط متغیر مسیر سیستم اضافه شد؛ هیچ ACE، Job/owner rule، firewall یا مقصدی برای حل آن آزاد نشد.
5. اجرای نهایی هر17آزمون را پاس کرد. شکست‌ها و commit/run متناظر در attempts.json حفظ شده‌اند.

## محدودهٔ ادعا
این یک endpoint قرنطینهٔ پژوهشی با ترافیک ساختگی است، نه اصلاح فعال تمام مسیرهای پراکسی قبلی و نه محصول EXE آماده. gate سیستم و recovery به آن ادغام نشده‌اند. CI اینترنت مدیریتی عادی داشته و ادعای ایزوله‌سازی کل ترافیک VM نداریم. هیچ Setup، حساب یا payload واقعی Battle.net اجرا/دانلود نشد؛ هیچ فایروال، Windows task، CA یا TLS policy تغییر نکرد. فقط fixtureهای ACL/فایل/Job آزمون ساخته و پاک شدند.

private captureها در artifact یا commit منتشر نشده‌اند. فقط کد، تست و شواهد پالایش‌شده منتشر شده است. ثبت خصوصی موفق، تأیید بی‌خطر بودن درخواست یا صدور allowlist نیست. کنترل محتوا در HTTPS، فهرست payloadهای واقعی، سازگاری نصب دستی، اثر timing/IP و امنیت مقابل admin همچنان اثبات نشده‌اند. helper بومی در VM ساخته شد؛ آن را EXE نهاییِ پروژه تلقی نمی‌کنیم.

## قدم بعدی
یک کنترلر آزمایشیِ محدود باید endpoint قرنطینه، gate خروجی سیستم و recovery را به هم وصل کند؛ ابتدا همان fixtureهای مصنوعی، با ممنوعیت خروج مستقیم child و آزمون پایان/لغو/خطا. تنها پس از موفقیت این پذیرش یکپارچه، بررسی محدود درخواست‌های واقعی نصب مطرح شود. برای گرفتن نتیجه نباید HTTPS ناشناخته یا process خارج Job را خودکار مجاز کرد.
