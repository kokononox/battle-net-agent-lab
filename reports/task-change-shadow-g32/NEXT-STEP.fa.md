# مرز مرحلهٔ بعد

- نتیجهٔ shadow دو زمان‌بندی واقعی را پذیرفت، ولی enforcement عمداً تغییر نکرده است. هر فعال‌سازی آتی باید دقیقاً همین pinها و شرط‌ها را داشته باشد؛ نه تعمیم به همهٔ Taskها یا همهٔ فایل‌های Microsoft.
- PrintJobCleanupTask فقط برای همان true→false مشاهده شده است؛ false→true، تغییر action/args/principal/ACL، binding یا فایل همچنان مردود است. فعلاً هیچ قاعدهٔ runtime برای حتی این true→false فعال نشده است.
- لاگ عملیاتی موجود پس از فعال‌سازی، رخداد غیرفعال‌سازی را نشان داد اما caller PID را نداشت. برای انتساب دقیق‌تر، باید یک منبع شواهدِ دارای caller identity معتبر در همان VM انتخاب شود؛ provider PID یا تطبیق زمانی جای آن نیست. دربارهٔ Security log/4702 یا trace جدید بدون بررسی schema و وضعیت audit ادعایی نمی‌شود.
- معیار انتشار EXE همان قبلی است: بازیابی واقعی با fingerprint درست، نبود مؤلفهٔ خارج از زنجیره، بسته‌شدن Proxy و آزمون پس از بازیابی؛ موفقیت shadow جای آن نیست.
