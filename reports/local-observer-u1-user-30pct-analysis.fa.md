# اولین مشاهده واقعی U1 — دانلود جزئی با بلوک دامنه

## نتیجه
- کاربر می‌گوید Resume کرده و دانلود تا ۳۰٪ رسیده است؛ عدد درصد در گزارش ماشینی اندازه‌گیری نشده است. پاسخ نهایی داخل ابزار `reported_paused` است.
- READY ثبت شده و Agent اصلی PID 5712 با امضای معتبر Blizzard و هش `b422e8d4f0fe0cbcb2d106b455aa44d78eb3a4e173340f05e6cadac5091571b5`، دارای send/WSASend/EncryptMessage فعال بوده است.
- حالت `block_telemetry`، تغییر hosts، resolution فقط loopback پس از اعمال و در بررسی پایان، و `restored_exactly` ثبت شده‌اند. بررسی پایان پیش از restore است؛ loopback پایان به معنی تداوم بلوک پس از خروج ابزار نیست.
- نسخه خوانده‌شده از نشانگر نصب از `12.1.0.69933` به `12.1.5.70448` تغییر کرده است. حتی با دانلود ناقص ممکن است metadata نسخه عوض شود؛ این شاهد تکمیل/صحت کل بازی یا قابلیت Play نیست.

## آنچه نمونه واقعاً می‌گوید
- ۱۴۰۷ رویداد ورودی API با aggregate و مجموع process input_events تطبیق مستقل دارند؛ ۲۰ ورودی موفق محلی EncryptMessage ثبت شده است.
- هیچ host_hint برابر telemetry-in.battle.net و هیچ تطبیق رشته CPU مرجع در نمونه نیست؛ CPU مرجع در RAM ابزار موجود بوده است. اینها نبود سایر اطلاعات سخت‌افزاری، مسیر جایگزین یا دریافت/نگهداری داده در سرور را ثابت نمی‌کنند.
- Host header در همان بافر برای این نام‌ها دیده شده: `level3.blizzard.com`، `level3.ssl.blizzard.com`، `us.version.battle.net`، `distribution.version.battle.net`، `oauth.battle.net`، `breaking-news.support.blizzard.com` و loopback `127.0.0.1`.
- وجود oauth به‌تنهایی login کاربر را اثبات نمی‌کند. وجود خبر/سرویس OAuth نشان می‌دهد فعالیت قابل مشاهده فقط نام CDN بازی نیست، اما فهرست نام‌ها هدف و محتوای تمام تبادل را روشن نمی‌کند. loopback نیز داده ارسالی به سرور اینترنت نیست.
- شمارش API-input تعداد درخواست کامل، حجم دانلود یا حجم آپلود نیست. TCP samples را نمی‌توان با این Host hints به‌صورت قطعی متصل یا به همه مقصدها محتوای خاص نسبت داد.

## محدودیت‌های مهم
- ۱۲ پردازش attach شده‌اند؛ Agent دیگر PID 2036 با هش launcher دارای `attach_failed` است. به علت شکست، معنای مشخص‌تری نسبت نمی‌دهیم.
- `sampler_errors=1`؛ script_errors در پردازش‌ها صفر و limits_hit همگی false است. گزارش خطای شبکه جزئیات علت را ندارد؛ پوشش بی‌نقص ادعا نمی‌شود.
- همه پردازش‌ها late_attach هستند؛ رویدادهای آغاز کار و APIها/کدگذاری‌های پوشش‌نداده ممکن است از دست رفته باشند. هیچ TLS session key یا payload خام برای بررسی تازه در این گزارش وجود ندارد.
- ۲۹ رویداد برچسب before_user_update و ۱۳۷۸ رویداد user_update_window دارند. دومی از زمان READY تنظیم می‌شود، نه از زمان کلیک واقعی Resume؛ مرزبندی دقیق کلیک یا درصدها قابل استخراج نیست.
- بازه elapsed اولین/آخرین رویداد 14.92 تا 294.89 ثانیه است؛ زمان آخرین رویداد مدت کل آزمایش یا زمان دقیق Pause نیست.
- فایل کاربر امضای provenance ندارد؛ گزارش و کنسول با هم سازگارند ولی مشاهده زنده مستقل عامل نیستند.

## تصمیم و گام بعد
نتیجه فعلی «سازگاری جزئی دانلود با بلوک محدود این دامنه» است. هدف صفر بودن همه تبادل غیرآپدیت هنوز محقق/اثبات نشده؛ fingerprint فایل‌های A→B هم آزموده نشده است.

hosts در پایان دقیقاً بازیابی شده است؛ بلوک ابزار دیگر فعال نیست. اگر آزمایش فعلاً تمام است، کاربر Battle.net را دستی از tray Exit کند؛ Pause جلوی تمام فعالیت پس‌زمینه را نمی‌گیرد.

تکرار دانلود تا همان ۳۰٪، حذف بازی، Repair، Cancel یا کپی دوباره ۱۳۰GB لازم نیست. آزمون بعدی در صورت انتخاب کاربر: ادامه همان نصب تا تکمیل با پیش‌شرط‌ها و اجرای تازه U1، گزینه ۲/BLOCK و Resume فقط بعد از READY. پیش از اجرای تازه Battle.net/Agent/WoW باید بسته باشند. اگر بسته نشدند، خروجی تشخیص پردازش بررسی شود؛ ابزار برای دورزدن پیش‌شرط تغییر نکند.

یک خطای sampler و attach_failed باید در کد/محدودیت پوشش بازبینی شوند؛ بدون پیام تشخیصی علت‌سازی یا تضمین رفع نمی‌شود. هیچ runner/هزینه/تست جدیدی در این مرحله اجرا نشده است.
