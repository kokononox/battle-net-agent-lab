## شواهد مثبت
- baseline مستقیم دو مقصد و مقصد منفی سالم بود. زیر فایروال، TCP مستقیم ابزار آزمون به مقصدهای نامزد و مقصد منفی رد شد؛ TCP مستقیم ۴۴۳ هر دو نامزد نیز رد شد.
- از درگاه، HTTP ریشه `level3.blizzard.com:80` پاسخ ۴۰۳ مبدأ گرفت؛ این فقط شاهد رسیدن درخواست و برگشت پاسخ است، نه شاهد دانلود موفق.
- `us.version.battle.net:1119/agent/versions` از درگاه پاسخ HTTP ۲۰۰ گرفت. G6 پیش‌تر نشان داده بود HTTP روی پورت ۸۰ این مقصد پاسخ نمی‌دهد؛ بنابراین فرض اولیه ۸۰/۴۴۳ ناقص بود. این probe مستقل از نصاب است و هنوز پورت/مسیر واقعی نصاب را ثابت نمی‌کند.
- مسیرهای محلی IPv4 و IPv6 برای HTTP آزموده شدند. TLS سرتاسری هر دو نام با اعتبارسنجی گواهی از درگاه برقرار شد؛ CA یا اعتبارسنجی گواهی تغییر نکرد.
- authority نامرتبط و TLS SNI نامرتبط رد شدند.
- اعمال/بازبینی فایروال، هدایت hosts و بازیابی هر دو تأیید شدند. W3SVC فقط برای رفع تداخل پورت در ماشین تازه آزمایش متوقف شد و به Running برگشت.
- همه probeهای HTTP در G8 در تلاش نخست پاسخ موردانتظار داشتند. شکست baseline در G7 حفظ شده است؛ علت دقیق آن از گزارش آن اجرا مشخص نیست.

## مرز اعتبار
`installer_launched=false` و `all_traffic_blocked_proven=false` عمداً باقی‌اند. هیچ Setup در این اجرا دانلود/اجرا نشد. خروج مستقیم آزمایش‌شده مربوط به harness و IPv4 است؛ loopback IPv6 با آزمون جامع خروج خارجی IPv6/UDP/QUIC برابر نیست.

استثنای مدیریت فقط برای Runner.Listener/Worker گیت‌هاب است، نه مجوز نصب‌کننده. این مدل ادعای مقاومت در برابر نرم‌افزار مهاجم دارای دسترسی Administrator یا سوءاستفاده از فرایند مدیریتی مجاز نمی‌کند.

SNI و HTTP Host با محتوای HTTPS یکی نیستند. مسیرها، headerها و بدنه‌های رمز‌شده هنوز طبقه‌بندی نشده‌اند؛ موفقیت این درگاه اثبات «فقط نصب، بدون ارسال داده دیگر» نیست. خروجی اجرایی نهایی هنوز آماده نیست.
