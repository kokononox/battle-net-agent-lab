# بررسی اولین تلاش واقعی PSS — Snapshot 0.1.5

گزارش کاربر از 0.1.5، موفقیت سنجش native و 17,312,059,392 بایت فضای قابل‌استفاده روی G را نشان می‌دهد. ProcDump هم همین مقدار را ثبت کرده است. capture_started=true، خروج ProcDump برابر 1 و state=capture_failed است؛ هیچ analysis.json یا پنجرهٔ کد استخراج‌شده در ZIP نیست.

لاگ ProcDump، UTF-16LE بدون BOM است؛ نسخهٔ decoded این پوشه فقط تبدیل encoding همان لاگ است. پیام‌های اصلی: Target process no longer running و Error writing dump file: 0x8007001D. کاربر پس از همین تلاش تأیید کرده خود بازی عادی و قابل‌استفاده مانده است. پس بسته‌شدن بازی از پیام ProcDump اثبات نمی‌شود. سلامت دیسک، دخالت anti-cheat یا مرگ clone هم از این گزارش به‌تنهایی ثابت نمی‌شوند.

مستندات رسمی ProcDump می‌گویند -r از clone استفاده می‌کند و در Windows 8.1+ سازوکار PSS است. این زمینه، امکان متفاوت‌بودن وضعیت clone و بازی اصلی را مطرح می‌کند، نه تشخیص علت خطا. جست‌وجوی خطای مشخص، توضیح معتبر و مشخصی برای همین شکست نداد.

قدم بعد: پیش از capture دوباره، وجود و اندازهٔ snapshot.dmp محلی همان اجرا روشن شود. اگر artifact موجود و قابل بررسی باشد، مسیر فقط آفلاین است. فعلاً هیچ capture مجدد، debugger attach، تزریق، patch یا تغییر سیاست امنیتی تأیید/اضافه نشده است. فایل اصلی dump در مخزن نیست و درخواست ارسال کامل آن نشده است.

ارسال CPU/BIOS روی TCP/3724 همچنان نامعلوم است. main و GUI BIOS Path 0.2 دست‌نخورده‌اند.

منبع رسمی: https://learn.microsoft.com/en-us/sysinternals/downloads/procdump
