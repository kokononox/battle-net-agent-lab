# G50 — هر ۴۶ فهرست snapshot معتبر است؛ محل نمونه سوم پیدا شد

## نتیجه واقعی
هر ۱۶ GET ثابت metadata پاسخ HTTP 200 با Content-Length دقیق داد. مجموع بدنه‌های پذیرفته‌شده ۲۷۲٬۳۶۸ بایت بود. برای همه، اندازه و SHA256 footer با مشاهده G49 برابر بود؛ نام/MD5 footer، checksum footer، TOC، تمام بلوک‌ها، ترتیب یکتای کلیدها، تعداد رکورد و padding بررسی شد. همه ۱۶ index کامل معتبر شدند.

پس از بازاعتبارسنجی ۳۰ fixture قبلی G46 و اتصال رسیدها به برنامه‌های ثابت، پوشش این مجموعه مشخص به ۴۶ از ۴۶ رسید: ۴۵ archive index و یک loose-file index، جمعاً ۶۲۳٬۴۰۸ بایت snapshot عمومی. شناسه و کلیدهای مجموعه کامل، یکتا و بدون هم‌پوشانی بین ۳۰ قبلی و ۱۶ جدید هستند. این اعداد تعداد درخواست‌های همین گام نیستند: درخواست‌های جدید فقط ۱۶ GET بودند.

## محل نمونه سوم
- فهرست: `index_2`؛ کلید آرشیو: `11997641538a447ba9b7026a1145da9c`.
- EKey نمونه: `2f49790cbe4824363b14d37c9cb889d4`؛ CKey: `47af4d1649e32238b956e6c1ea9c722c`.
- offset: `65064708`؛ بازه شامل دو انتها: `65064708–65072168`.
- اندازه encoded برابر `7461` بایت و منطبق با برنامه G45؛ اندازه decoded مورد انتظار `12840` بایت است.
- SHA256 index کامل: `dddd859343761e559497340cc54aaf127e61f600f253b0dd04f2120e3731c3ee`.

اندازه decoded، hash payload و قابلیت اجرای فایل هنوز در این گام با دریافت خود نمونه بررسی نشده‌اند. محل تنها از index کامل معتبر به دست آمده است. اسکن دوم مستقلِ رکوردهای خام و هم‌تراز index_2 نیز همان کلید، اندازه و offset را یافت.

## مرز اعتبار و دامنه
پوشش کامل فقط مربوط به همان CDN-config پین‌شده bna در snapshot G43 است، نه همه نسخه‌ها، مناطق، محصولات یا patch archiveها. ثابت‌ماندن کلیدها و footerها در چند گام به معنی تازه‌بودن آخرین نسخه Battle.net نیست.

طول هر index جدید از footer تأییدشده می‌آید؛ برنامه جدید جایگزین مخفیانه رسید شکست G46 نشده و آن شواهد تغییر نکرده‌اند. علت اختلاف archives-index-size منبع قبلی همچنان تعیین نشده است؛ طول‌های تاریخی GETهای ردشده G46 هم ثبت نشده‌اند. برابری checksumهای TACT و SHA256 مشاهده‌شده، امضای ناشر یا اثبات نبود fingerprinting نیست. pin محلی نیز مانع تعویض کل زنجیره شواهد توسط مهاجم قادر به تغییر همه منابع نیست.

## ایمنی و محصول
این گام فقط metadata index دریافت کرد؛ نه Range، بدنه آرشیو، payload، نصب یا اجرای فایل. هیچ GET مستقلِ 404 گذشته تکرار نشد؛ این ۱۶ دریافت کامل، مرحله تشخیصی جدید با برنامه ثابت و اندازه‌های متصل به footer G49 بودند. retry خودکار، redirect، query، درخواست body، cookie یا Authorization وجود نداشت. اعتبارسنجی عادی TLS برقرار بود و proxy محیط استفاده نشد.

سقف خواندن بدنه با detector اضافه ۲۷۲٬۳۸۴ بایت بود، نه سقف کل ترافیک TCP/TLS/هدر. هر تلاش پیش از شبکه رزرو شد؛ خطا باعث بازپرداخت سهمیه یا fallback نمی‌شود. نشانگر یک‌بارمصرف همان پوشه کنترل پژوهشی است، نه ضد-replay سراسری محصول.

کاتالوگ deny-all با hash قبلی تطبیق داشت و مجوزهای runtime صفر ماندند. firewall، hosts، task، CA یا TLS policy تغییری نکردند؛ شاخه اصلی و محصول 0.9.10 منجمد باقی ماندند. مقصد پژوهشی به allowlist محصول افزوده نشد. metadata عمومی با فایل 0600 در پوشه 0700 ذخیره شد؛ این کنترل POSIX معادل private-store یا یکپارچه‌سازی ویندوز نیست.

## آزمون و بازتولید
۱۹ آزمون آفلاین پیش از شبکه موفق بود، شامل قرارداد HTTP، رد اندازه/encoding/Range/هدر تکراری و بازاعتبارسنجی ۳۰ index قبلی. پس از دریافت، ۴ آزمون آفلاین دیگر برای ۱۶ fixture واقعی، پوشش ۴۶‌تایی، اسکن مستقل نمونه سوم و ثابت‌ماندن کد/طرح بعدی موفق شد. کدهای دریافت و parser پس از preflight تغییر نکردند.

از ریشه checkout پژوهشی:

```sh
python -m unittest discover -s analysis-tools/complete-index-g50 -p 'test_offline.py' -v
python analysis-tools/complete-index-g50/locate.py
python -m unittest discover -s analysis-tools/complete-index-g50 -p 'test_live_evidence.py' -v
```

این فرمان‌ها شبکه ندارند و fixtureهای عمومی را می‌خوانند. `fetch_indices.py` کد دریافت واقعی است؛ برای بازتولید آفلاین اجرا نشود. فیلد executed=false در کپی proposal ورودی حفظ شده؛ اجرای واقعی G50 در رسید جداگانه ثبت شده است.

## قدم بعدی؛ فقط طرح و هنوز اجرا نشده
طرح یک Range ثابت برای sample_3 آماده است: `65064708–65072168`، معادل ۷٬۴۶۱ بایت encoded. باید پاسخ دقیق 206 و Content-Range/Length درست باشد؛ پاسخ 200 کل آرشیو پیش از خواندن بدنه رد شود. سپس BLTE، EKey، CKey، اندازه decoded و SHA256 واقعی بررسی و فایل صرفاً خصوصی و غیرقابل‌اجرا نگه‌داری شود.

در G50 این طرح اجرا نشده و هیچ مجوز runtime یا تأیید نصب کامل صادر نشده است. موفقیت دو نمونه کوچک G47 و یافتن محل سوم، نماینده همه ۱۹۶ نامزد ویندوز یا تضمین عدم آپلود داده نامرتبط نیست.
