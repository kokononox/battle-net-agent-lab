# G46 — دو محل آرشیوی پیدا شد؛ پوشش فهرست‌ها ناقص است

## نتیجه واقعی
- ۴۶ درخواست ثابت GET برای metadata index انجام شد؛ ۳۰ بدنه با اندازه مورد انتظار دریافت شد: جمعاً ۳۵۱٬۰۴۰ بایت بدنهٔ پذیرفته‌شده.
- هر ۳۰ فهرست، شامل فهرست loose، در بررسی آفلاین از کنترل نام/MD5 footer، checksum footer، TOC، بلوک‌ها، ترتیب کلیدها، تعداد و padding عبور کرد.
- ۱۶ پاسخ HTTP 200 به دلیل تفاوت Content-Length با برنامه، پیش از خواندن بدنه رد شدند. مقدار واقعی طول متفاوت ثبت نشده؛ علت دقیق تفاوت معلوم نیست. هیچ retry، تغییر سقف یا پذیرش پاسخ بزرگ‌تر انجام نشد.
- ۲۴ آزمون آفلاین موفق شد؛ موفقیت fixture مصنوعی به معنای موفقیت دانلود payload واقعی نیست.

چون ۱۶ فهرست بررسی نشده‌اند، نبودن نمونه سوم در مجموعه کامل اثبات نشده است.

## مرز شواهد و امنیت
فایل `fetch-evidence.json` رسید اصلی دریافت است و پس از اعتبارسنجی بازنویسی نشده. فلگ `parsed_or_authenticated:false` در آن مربوط به مرحله دریافت است؛ نتیجه parsing جداگانه در `index-verification.json` قرار دارد. hash کد دریافت پیش از اجرا در `preflight.json` اندازه‌گیری شد و با رسید و فایل فعلی برابر است. ابزار lookup آفلاین منابع، plan، ردیف‌های رسید و snapshotها را به هم متصل می‌کند؛ این pinها و MD5های TACT امضای ناشر یا تضمین در برابر مهاجم قادر به تعویض کل زنجیره نیستند.

کلید نام index، MD5 footer است؛ hash کل بدنه آرشیو نیست. محل و اندازه به دست آمده‌اند، نه سلامت payload داخل آرشیو. هیچ Range واقعی، بدنه آرشیو، payload، نصب یا اجرای Battle.net/Agent انجام نشده است. SHA256 واقعی payload هنوز نداریم.

این گام هیچ شاهدی بر نبود fingerprinting ایجاد نمی‌کند. GET، مقصد، TLS و زمان‌بندی خودشان تبادل شبکه دارند؛ «فقط دانلود» به معنای صفر داده خروجی نیست. هیچ host تازه‌ای در runtime مجاز نشده، و هیچ تغییری در firewall، hosts، task، CA یا سیاست TLS ایجاد نشده است. شاخه اصلی و محصول 0.9.10 منجمد باقی مانده‌اند. کاتالوگ deny-all همان hash پیشین را دارد؛ تعداد مجوزهای runtime صفر است.

## مرحله بعد؛ فقط طرح، اجرا نشده
1. دو Range ثابتِ یافته‌شده، مجموعاً ۴٬۳۱۰ بایت encoded، با الزام 206، Content-Range و طول دقیق. پاسخ 200 کل آرشیو باید پیش از خواندن بدنه رد شود. سپس BLTE، CKey، اندازه و SHA256 مشاهده‌شده بررسی شود. کاربر/کلاینت نباید offset دلخواه تعیین کند.
2. حداکثر ۱۶ HEAD ثابت برای مشاهده طول فعلی indexهای ردشده؛ بدون خواندن بدنه، retry یا GET جدید. مشاهده آینده مقدار هدر GET قبلی را بازسازی نمی‌کند و به‌تنهایی مجوز تغییر اندازه نیست.

هر دو طرح در فایل‌های `next-*.unexecuted.json` ثبت شده‌اند؛ در G46 اجرا نشده‌اند. برنامه پیشنهادی ورودی، کپی تغییرنیافته G45 است؛ `executed:false` آن سابقه پیشنهاد است، نه نفی درخواست‌های واقعی ثبت‌شده در رسید G46.

## بازتولید آفلاین
از ریشه checkout شاخه پژوهشی:

```sh
python analysis-tools/archive-index-g46/locate.py
python -m unittest discover -s analysis-tools/archive-index-g46 -p 'test_offline.py' -v
```

فقط این دو فرمان آفلاین‌اند. `fetch_indices.py` کد ثبت‌شده درخواست واقعی است؛ برای بازتولید نتایج آن را اجرا نکنید. fixtureها metadata عمومی‌اند، نه payload یا capture خصوصی. ابزار lookup در نبود فایل خام، فقط fixture ثبت‌شده را می‌خواند و fallback شبکه ندارد.
