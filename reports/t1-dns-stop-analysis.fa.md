# علت توقف T1 و محدوده اصلاح T1.1

گزارش DNS کاربر بررسی شد: هر۲۴ نام مورد انتظار blocked دارای ورودی0.0.0.0 در hosts و خطای resolver11004 بودند. تنها مقصد باز level3.blizzard.com پاسخ عمومی داشت. guard قبلی همه خطاهای resolver را unconfirmed می‌دانست؛ این حالت Windows را تفسیر نکرده بود.

اصلاح جدید هر خطای DNS را قبول نمی‌کند: تنها socket.gaierror11004 در Windows + entry صریح0.0.0.0 برای همان نام + نبود آدرس متعارض/نامعتبر. اگر resolver آدرس عمومی/مختلط بدهد، hosts به‌عنوان override شاهد استفاده نمی‌شود. نبود entry، error11001/11002/timeout، خطای مقصد باز و hosts ناخوانا همچنان مانع‌اند.

۹۹ تست محلی پاس، از جمله۲۰ regression و replay مقادیر گزارش با resolver مصنوعی و hosts موقت، با عدم تغییر فایل. این‌ها هنوز موفقیت اجرای اصلاح‌شده روی دستگاه کاربر نیستند؛ gate بومی ساخت جداگانه ثبت می‌شود. موفقیت DNS precondition هم اثبات enforcement شبکه یا فقط‌دانلود بودن محتوا نیست.

Nested JSON برای profiler ستونی مستقیم مناسب نبود؛۲۵ ردیف به CSV مشتق‌شده تبدیل و profile شد: host یکتا، duplicate صفر، null error_code فقط برای مقصد موفق انتظار می‌رود؛ هیچ ردیفی حذف نشد. شاهد اصلی با شمارش مستقل predicates خام دوباره کنترل شد. نمودار برای این تشخیص شاخه برنامه، ارزش اضافه ندارد.
