رصد وابستگی‌های WoW — نسخهٔ مستقل 0.1.0

هدف:
اجرای عادی بازی، بدون CDB و بدون تزریق؛ ثبت پردازش‌های وابسته، DLLهای بارگذاری‌شده و مقصدهای TCP/UDP قابل‌مشاهده با Microsoft Process Monitor.
این ابزار محتوای TLS را نمی‌خواند و ابزار جلوگیری از ارسال یا اثبات «فقط دانلود» نیست.

برای اولین اجرا — فقط وضعیت فعلی:
1) CDB و ابزارهای رصد قبلی را ببند. بازی و همهٔ پنجره‌های Procmon هم بسته باشند.
   تنظیمات ایزولاسیون، وایت‌لیست و فایل مسدودکننده را تغییر نده.
2) کل ZIP را در پوشهٔ جدید محلی و قابل‌نوشتن استخراج کن. روی Start.cmd راست‌کلیک و Run as administrator بزن.
   Python همراه بسته است. نصب Python یا تغییر ExecutionPolicy لازم نیست.
3) از پنجرهٔ انتخاب فایل، Wow.exe را بده؛ هنوز بازی را اجرا نکن.
4) برای برچسب آزمایش عدد 1 را بزن: current isolation.
   عددهای 2 و 3 فقط برچسب‌اند؛ برنامه ایزولاسیون را خاموش یا مقصدی را حذف نمی‌کند.
5) برای Procmon، یکی را انتخاب کن:
   LOCAL: فایل رسمی Procmon64.exe نسخهٔ 4.12 را از سیستم خودت انتخاب کن.
   DOWNLOAD: ابزار از ZIP رسمی مایکروسافت دریافت می‌شود؛ امضای معتبر Microsoft و SHA256 مشخص باید تأیید شوند.
   ابزار مایکروسافت داخل این بسته توزیع نشده است.
   اگر ایزولاسیون دریافت ابزار را مسدود کند، برنامه آن را دور نمی‌زند و قاعده‌ای اضافه نمی‌کند.
   در این صورت فایل رسمی را از قبل، یا با رایانهٔ دیگر، تهیه کن و LOCAL را انتخاب کن.
   نسخهٔ متفاوت/به‌روزشده با هش متفاوت اجرا نمی‌شود؛ برای آن هش را خودت غیرفعال نکن.
6) شرایط ضبط را بخوان. با نوشتن CAPTURE، ضبط محلی سیستمی و پذیرش EULA ابزار Procmon را تأیید می‌کنی.
7) فقط وقتی CAPTURE READY آمد، بازی را خودت عادی اجرا کن و تا صفحهٔ ورود برو؛ وارد حساب نشو.
   حدود 60 ثانیه ضبط می‌شود؛ بازی را عادی ببند. ثبت رویدادها و تبدیل XML ممکن است چند دقیقه زمان ببرد.
8) فقط فایل output\dependency-result-….json را بفرست. اگر خطا شد نیز همین JSON خلاصه کافی است.
   PML، XML و پوشهٔ خصوصی جلسه را ارسال نکن.

در این اجرا هیچ مقصد تازه‌ای را مسدود/آزاد نکن؛ ابتدا همین وضعیت را ثبت می‌کنیم.
اگر صفحهٔ گزارش خرابی آمد، روی Send/Submit نزن؛ از عنوان/پیام عکس بگیر و پنجره را عادی ببند.
اگر برنامه خیلی طول کشید یا ATTENTION/خطای مالکیت دیدی، Procmon را از پنجرهٔ خودش متوقف و ببند. بسته برای پایان مبهم، بازی را نمی‌کشد و فرآیندهای ناشناس را متوقف نمی‌کند.

چه چیزی از نتیجه می‌فهمیم؟
- مسیر انتخاب‌شدهٔ Wow.exe با جدول پردازش Procmon تطبیق داده می‌شود. فرزندان با ParentProcessIndex دنبال می‌شوند، نه فقط PID؛ تغییر/استفادهٔ دوبارهٔ PID با هم مخلوط نمی‌شود.
- EXEهای دیگر در همان پوشهٔ بازی، اگر در جدول ثبت باشند، با برچسب «نامزد هم‌پوشه؛ ارتباط ثابت نشده» جدا گزارش می‌شوند.
- برای DLLها، نام تصاویر بارگذاری‌شده و ماژول‌های دیده‌شده در stack رویداد ارسال گزارش می‌شود.
- دیده‌شدن یک DLL در stack نشانهٔ حضور در مسیر اجراست، نه اثبات اینکه آن DLL محتوای درخواست را ساخته یا مشخصات سخت‌افزار را آپلود کرده است.
- IP و پورت مقصدِ TCP Connect / TCP Send / UDP Send ثبت می‌شود. Receive برای حدس‌زدن مقصد ارسال به کار نمی‌رود.
- نام دامنه حدس زده نمی‌شود؛ اگر مقصد IP خوانا/پورت معتبر نداشته باشد، فقط شمارش «تجزیه‌نشده» افزایش می‌یابد.
- مقدار Length جمعِ گزارش‌شدهٔ عملیات موفق است، نه حجم یکتای واقعی روی سیم یا محتوای رمزگشایی‌شده.
- ممکن است کار به سرویسِ ازقبل‌فعال و خارج از این درخت/پوشه واگذار شده باشد؛ چنین ارتباطی الزاماً پوشش داده نمی‌شود.
- نبود رویداد/stack یا نرسیدن بازی به مرحلهٔ خاص، اثبات نبود ارتباط، نبود جمع‌آوری یا نبود صف ارسال نیست.

حریم خصوصی و تغییرات واقعی:
Procmon با دسترسی Administrator یک درایور هستهٔ مایکروسافت به کار می‌گیرد. DLL به بازی تزریق نمی‌شود و دیباگر به آن متصل نمی‌شود؛ اما اثر عملکرد/سازگاری صفر تضمین نشده است.
Procmon ممکن است تنظیمات رابط، فیلترها و تأیید EULA خودش را در ویندوز نگه دارد. ابزار با NoFilter ضبط را آغاز می‌کند؛ تنظیمات قبلی Procmon ممکن است تغییر کنند. هیچ تغییری در فایروال، وایت‌لیست، hosts، VPN، گواهی‌های اعتماد، تنظیمات بازی یا ExecutionPolicy درخواست نمی‌شود.
ضبط Procmon سیستمی است: فایل خام ممکن است مسیرها، command line، محیط پردازش‌ها و داده‌های رجیستری برنامه‌های دیگر را داشته باشد. این داده‌ها به JSON کپی نمی‌شوند. نام فایل‌های EXE/DLL، PID/index و مقصدهای ارتباطی در خلاصه باقی می‌مانند؛ پیش از اشتراک خودت بررسی کن.
هیچ فایل یا لاگی خودکار آپلود نمی‌شود. دریافت اختیاری ابزار و بررسی اعتماد امضا، قبل از ضبط انجام می‌شوند و ممکن است ارتباط شبکهٔ مایکروسافت/Windows trust ایجاد کنند.
فایل‌ها زیر %LOCALAPPDATA%\WoWDependencyObserver\<شناسه> با ACL کاربر جاری و SYSTEM می‌مانند. پس از خروج همهٔ Procmonها می‌توان پوشهٔ همان جلسه را دستی حذف کرد. برنامه پاک‌سازی/ارسال خودکار ندارد.

سقف‌ها و محدودیت‌ها:
مدت 60 ثانیه به خود Procmon درخواست می‌شود. بودجهٔ نرم PML برابر 512MiB و فضای آزاد لازم 3GiB است. توقف زودتر با /Terminate فقط وقتی درخواست می‌شود که تنها PID مشاهده‌شدهٔ Procmon همان پردازش ایجادشدهٔ بسته باشد؛ هم‌زمان Procmon دیگری اجرا نکن. بین بررسی‌ها رشد فایل ممکن است از بودجه بیشتر شود؛ این سقف سخت دیسک یا تضمین مطلق در خرابی سیستم نیست.
تبدیل XML حداکثر 240 ثانیه انتظار دارد؛ پایان‌نیافتن به‌معنای مجازبودن ارسال فایل خام نیست. در چنین حالتی Procmon را خودت بررسی کن.
تحلیل حداکثر XML با حجم 768MiB، تعداد 750000 رویداد و 20000 پردازش را می‌خواند؛ محدودیت‌ها و نبود دسته‌های Network/Load Image/Process در JSON علامت می‌خورند. تنظیمات capture/advanced output قبلی Procmon می‌توانند بر پوشش اثر بگذارند؛ بسته کامل‌بودن stackها را تضمین نمی‌کند.

اعتبارسنجی:
34 آزمون ساختگیِ تحلیل XML، فرزند/نواده، PID reuse، IPv4/IPv6، جهت Send/Receive، جمع Length، حذف دادهٔ خام و XML نامعتبر/ENTITY موفق شده‌اند. بررسی نحوی Python انجام شده و فرمان‌های CLI از خود Procmon64 رسمی بررسی شده‌اند.
اجرای واقعی این بسته روی Windows/Procmon/بازی در محیط توسعه انجام نشده است. نتیجهٔ نخست برای تأیید سازگاری لازم است؛ موفقیت تست ساختگی جای آن را نمی‌گیرد.
