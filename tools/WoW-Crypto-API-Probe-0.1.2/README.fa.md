# WoW Crypto API Probe 0.1.2

## اصلاح مورد فعلی

CDB روی سیستم آزمایشی کاربر نصب است و کنترل سادهٔ نسخهٔ قبلی موفق شد. ولی بازی پیش از نمایش پنجره روی int3 در wow_loader.dll متوقف شد؛ تنظیم breakpoint مربوط به SSPI نیز خطا داد. بنابراین نتیجهٔ قبلی هیچ حکمی دربارهٔ نبود TLS یا تله‌متری نمی‌دهد.

این نسخه دو اصلاح محدود دارد:

1. دستور SSPI دیگر داخل بلوک شرطی تو در تو نیست. Windows GetProcAddress در خود ابزار، نشانی واقعی EncryptMessage و DLL مالک آن را پیدا می‌کند؛ breakpoint با **نام ماژول + RVA** درخواست می‌شود، نه با دنبال‌کردن نام نماد forwardشده در CDB. نام، RVA و هش فایل DLL سیستم در JSON می‌آید؛ مسیر کاربر یا نشانی مطلق حافظه نمی‌آید. این تطبیق، گواهی مستقل حافظهٔ پردازش بازی نیست.
2. فقط برای **همان نشانی int3 گزارش‌شده** در loader قبلی، یک breakpoint یک‌بارمصرف با فرمان **gN** قرار می‌گیرد. gN استثنا را «هندل‌شده» اعلام نمی‌کند؛ فرصت بررسی را به handler خود برنامه می‌دهد. استثنا بلعیده نمی‌شود، دستور بازی NOP یا حذف نمی‌شود و RIP دستی جلو برده نمی‌شود. سیاست عمومی استثناها شل نمی‌شود. اگر برنامه آن را هندل نکند یا جای دیگری متوقف شود، ابزار ادامهٔ اجباری نمی‌دهد.

فایل‌های Wow.exe و wow_loader.dll باید با هش نسخه‌های قبلاً بررسی‌شده تطبیق کنند. نشانی انتخاب‌شده از توقف اجرای قبلی و بایت int3 در فایل آفلاین همان loader به دست آمده است؛ بایت‌های بارگذاری‌شدهٔ اجرای جدید و اجرای واقعی handler بازی مستقلاً گواهی نمی‌شوند.

## کنترل پیش از بازی

ProbeControl.exe یک برنامهٔ کوچک از منبع Control.cs است. این برنامه روی خودش handler استثنا نصب می‌کند و DbgBreakPoint را فراخوانی می‌کند. CDB باید همان سازوکار یک‌بارمصرف gN را روی این برنامه اجرا کند؛ برنامه تنها وقتی خروج صفر دارد که handler خودش دقیقاً یک breakpoint را دریافت کرده باشد.

**فقط با خروج صفر و مشاهدهٔ هر دو نشانهٔ کنترل، بازی اجرا می‌شود.** این کنترل به پردازش بازی handler تزریق نمی‌کند. موفقیت آن هنوز تضمین سازگاری loader یا محافظت‌های بازی نیست.

## اجرا

1. بسته را در **پوشهٔ جدید قابل‌نوشتن** استخراج کن؛ فایل‌های نسخه‌های قدیمی را قاطی نکن. تمام نمونه‌های بازی را عادی ببند.
2. Start.cmd را اجرا کن. نیازی به تغییر ExecutionPolicy یا غیرفعال‌کردن حفاظت ویندوز نیست. راه‌انداز دو EXE خود ابزار و کنترل را از منبع C# می‌سازد.
3. همان cdb.exe رسمی نسخهٔ x64 و Wow.exe را انتخاب کن و Start lab probe را بزن. CDB نصب‌شدهٔ تو کافی است؛ دوباره نصبش نکن.
4. ابتدا کنترل اجرا می‌شود؛ اگر موفق شد بازی خودکار اجرا می‌شود. فقط تا صفحهٔ ورود برو، نه دانلود یا بازی طولانی. **ورود به حساب لازم نیست.** سپس بازی را عادی ببند.
5. ابزار می‌پرسد آیا در همین اجرا واقعاً به صفحهٔ ورود رسیدی. اگر باز نشد یا در دیباگر متوقف شد، **No** را بزن. فقط **crypto-api-result-….json** کنار Start.cmd را بفرست.

اگر کنترل یا اجرای بازی باز هم در prompt CDB متوقف ماند، **qd** و Enter بزن. اگر هنوز در حال اجراست ولی گیر کرده، پنجرهٔ CDB را فعال کن، Ctrl+C و سپس qd و Enter بزن. qd دیباگر را جدا می‌کند؛ ممکن است بازی باز بماند، خودت آن را عادی ببند. با دستور q یا ضربدر CDB خارج نشو، چون ممکن است بازی را خاتمه دهد. بستن پنجرهٔ خود ابزار، دیباگر را جدا نمی‌کند. خطای ناشناخته را با g/gh/gN دستی رد نکن.

## داده و محدودیت

- این مرحله هنوز فقط ورود به API را رصد می‌کند، نه محتوای آپلود، مقصد ارتباط یا ارسال CPU/BIOS را. رسیدن به SSPI EncryptMessage به‌تنهایی اثبات Schannel/TLS یا ارسال موفق نیست.
- مسیرهای OpenSSL هنوز محدود به اسکن نمادهای اولیه و نام‌های deferred رایج/نامزد هستند. لینک استاتیک، نمادهای مخفی، DLL بعدی با نام دیگر یا پردازش فرزند ممکن است پوشش داده نشود. «کلید/API ندیدیم» به معنی «اطلاعاتی ارسال نمی‌شود» نیست.
- در صورت خطای نحوی، لاگ ناقص یا بازنشدن بازی، خروجی این محدودیت را جداگانه اعلام می‌کند و صرفاً نتیجهٔ منفی API نمی‌دهد.
- گواهی، پروکسی، فایروال، hosts و ExecutionPolicy تغییر نمی‌کنند؛ هیچ روش مخفی‌کردن دیباگر یا غیرفعال‌کردن حفاظت بازی وجود ندارد. ابزار بازی را زیر دیباگر اجرا می‌کند و breakpointهای نرم‌افزاری API در حافظه می‌گذارد؛ کاملاً منفعل یا بدون اثر بر اجرا نیست. بازی و برنامهٔ کنترل ممکن است موقتاً توسط دیباگر متوقف شوند.
- ابزار حافظهٔ بافر شبکه، رمز عبور یا کلید TLS را dump نمی‌کند. برای شناسایی ماژول SSPI فقط آدرس تابع و header ماژول Windows در خود ابزار بررسی می‌شوند. هیچ محتوای خام خودکار آپلود نمی‌شود.
- دیباگر می‌تواند در لاگ محلی پیام‌های debug و مسیرهای خصوصی بنویسد. **فایل‌های *-debugger-local.log یا پوشهٔ خصوصی را نفرست.** JSON فقط نشانه‌ها، وضعیت، مشخصات فنی محدود و هش‌ها را دارد.
- فایل‌های محلی در `%LOCALAPPDATA%\WowCryptoProbe\<session>` با ACL اختصاصی کاربر و SYSTEM ساخته می‌شوند. حداکثر ۴ MiB ابتدای لاگ بررسی می‌شود، اما سقف سخت حجم خام یا زمان وجود ندارد. آزمون را کوتاه نگه دار. بعد از خروج/جداسازی CDB و بسته‌شدن بازی، پوشهٔ همان جلسه را دستی پاک کن.
- فقط مسیر نماد محلی تعیین می‌شود و تنظیم symbol server ارث‌بری نمی‌شود؛ این به معنی فایروال یا تضمین قطع همهٔ شبکهٔ دیباگر/بازی نیست.
- اجرای دیباگر می‌تواند رفتار بازی را تغییر دهد یا راه‌اندازی را خراب کند. تضمین نبود ریسک حساب/محدودیت داده نمی‌شود. فقط آزمایشگاهی و بدون حساب ارزشمند استفاده کن.

## وضعیت آزمون

۳۰ آزمون هسته موفق‌اند و رابط، binding و برنامهٔ کنترل با C#5 و مراجع .NET Framework 4.8 برای x64 کامپایل شده‌اند. **اجرای واقعی CDB، P/Invokeهای Windows، VEH و بازی در محیط توسعهٔ Linux انجام نشده است.** کنترل جدید روی سیستم آزمایشی باید این مسیر را ابتدا بررسی کند؛ موفقیت بازی پیشاپیش ادعا نمی‌شود.
