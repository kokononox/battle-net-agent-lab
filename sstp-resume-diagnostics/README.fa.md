# تشخیص علت رد ساخت IPv6؛ نه رفع قطعی

گزارش دستگاه کاربر: resume_v6_create_failed، CimException، HRESULT=-2146233088 و StatusCode/NativeErrorCode=1. این اعداد علت دقیق را مشخص نمی‌کنند. نمایش جایگزین CIDR نیز روی دستگاه کاربر موفق نشده است؛ علت به‌طور قطعی به قالب آدرس نسبت داده نمی‌شود.

## اقدام
۱. پنجره‌های قبلی ابزار را ببندید. این ZIP را کامل در پوشه‌ای جدید خارج کنید.
۲. فقط Diagnose-Prepare.cmd را اجرا کنید و درخواست Administrator مربوط به همین ابزار و تأیید تلاش آماده‌سازی را بررسی و تأیید کنید.
۳. اگر خطا داد، startup-error.json تازهٔ همین پوشه را پیش از ارسال بررسی کنید و سپس ارسال کنید. این بار native_codes[].message نیز ثبت می‌شود. journal یا فایل فهرست خصوصی را ارسال نکنید. اگر موفق شد، resume-result.json را ارسال کنید.
۴. فعلاً Prepare/Enable نکنید. journal موجود ProgramData را حذف نکنید و از EmergencyReset استفاده نکنید.

این فرمان خواندنیِ صرف نیست: همان تلاش محدود قبلی برای ایجاد قانون IPv6 **غیرفعال** را یک بار تکرار می‌کند. قواعد قبلی guard/v4 باید همچنان دقیق و غیرفعال باشند. اگر قانون v6 موجود و ثبت‌نشده باشد، بدون تصاحب یا حذف آن متوقف می‌شود. در موفقیت، آماده‌سازی فقط به prepared می‌رود؛ Enable خودکار ندارد.

موتور و شرط‌های بازیابی همان نسخهٔ ۰.۱.۲ هستند. تغییر فقط در گزارش خطاست: متن Exception.Message با سقف طول و حذف آدرس‌ها، شناسهٔ قواعد، دامنه‌ها، مسیرها و مقادیر خصوصی شناخته‌شده ثبت می‌شود؛ کل ErrorRecord، stack یا journal ذخیره نمی‌شود. حذف اطلاعات با الگوها تضمین حذف همهٔ داده‌های احتمالی نیست؛ فایل را پیش از ارسال بررسی کنید. کدهای عددی قبلی هم حفظ می‌شوند.

پنجرهٔ فرمان برای دیدن نتیجه منتظر کلید می‌ماند و سپس بسته می‌شود؛ سرویس، تایمر، task یا نگهبان دائمی ساخته نمی‌شود. کیل‌سوییچ، اتصال VPN، پروفایل‌های فایروال و قواعد نامرتبط تغییر نمی‌کنند. هیچ محافظتِ نبود نشتی، IPv6 packet یا دستگاه کاربر در این مرحله تأیید نشده است.

## محدودهٔ آزمون
RecoveryEngineReceipt.json مربوط به موتور پایهٔ قبلی است: pure257، CIDR28، recovery46 و native40 روی Windows CI؛ نه موفقیت دستگاه کاربر.
DiagnosticBuildReceipt.json فقط parse و ۱۵ بررسی حذف اطلاعات خصوصی را روی Windows PowerShell آزمون می‌کند؛ اجرای بومی بازیابی یا UAC تعاملی برای این تغییر تشخیصی در CI تکرار نشده است. تمام شرط‌های ایجاد/تطبیق/ثبت/توقف موتور پایه بدون تغییر حفظ شده‌اند؛ فقط helper و بخش گزارشِ catch تفاوت دارند.
