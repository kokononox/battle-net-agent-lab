# P7C — کنترل فقط‌خواندنی اختلاف قواعد Windows
سؤال: آیا بدون هیچ mutation از طرف کد ما، همان اختلاف Description/DisplayGroup/DisplayName در بازه هم‌مدت ظاهر می‌شود؟

یک Windows-2025 استاندارد؛ اجرای یک‌باره، ۶۶۰ثانیه مشاهده با۱۳snapshot: مبنا، تکرار فوری، سپس هر۶۰ثانیه تا دقیقه۱۱. همین منطق property-level P7 (حذف همان runtime-statusها، نه حذف فیلدهای اختلاف‌دار) استفاده می‌شود. هم baseline و هم snapshot قبلی مقایسه می‌شوند؛ union شناسه‌های تغییرکرده فقط در حافظه شمارش می‌شود.

فقط Get-NetFirewallRule/Get-NetFirewallProfile؛ هیچ ماژول دارای setter وارد نمی‌شود، هیچ fixture/policy/rule ساخته نمی‌شود و هیچ DNS/اتصال آزمایشی وجود ندارد. runner و agentهای GitHub خودشان همچنان فعال‌اند؛ این کنترل علت احتمالی بیرونی یا اثر خواندن provider را از هم جدا نمی‌کند. برای اثبات منشأ دقیق هر تغییر، trace مستقل بیشتری ممکن است لازم شود.

خروجی محدود: شمارش تغییرها، نام propertyهای متفاوت و دسته متن (خالی/ارجاع resource با @/literal). نام قواعد، مقدار توضیح و برچسب، مسیر برنامه و IP/GUID/SID صادر نمی‌شود. اینکه یک متن با @ شروع می‌شود، به‌تنهایی اثبات localization یا علت تغییر نیست. تنها محتوای artifact رسید محدود و hash منبع است.

completed=true یعنی مشاهده کامل شد، نه اینکه policy ثابت بوده یا کیل‌سوییچ پاس شده باشد. نتیجه مثبت کنترل صرفاً نشان می‌دهد تغییر مشابه بدون setter ما هم رخ داده؛ تغییرات دو اجرای قبلی را قطعاً به همان علت نسبت نمی‌دهد. نتیجه منفی هم اثبات نمی‌کند setter مقصر بوده است. معیار ایمنی P7 عوض نشده، ready_for_user_apply=false و دستگاه کاربر دست‌نخورده می‌ماند.

انتظار زمانی فقط برای این آزمایش CI است؛ محصول نهایی هیچ timer/resident/expiry نمی‌گیرد. این فایل برای اجرای کاربر بسته‌بندی نشده است.
