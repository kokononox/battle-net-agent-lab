# هستهٔ سیاست Allowlist + کیل‌سوییچ SSTP — هنوز برنامهٔ Enable نیست

این بخش فقط config و تصمیم‌گیری خالص است. هیچ firewall، hosts، VPN، route، DNS، task یا سرویس را تغییر نمی‌دهد. نوشتن فایل تنها در Test-Policy.ps1 برای رسید محدود آزمون CI است. هیچ برنامهٔ همیشه‌روشن یا زمان انقضا ندارد. توابع EditPolicyConfig فهرست جدید برمی‌گردانند؛ هنوز ذخیره‌سازی/ویرایش فایل hosts یا رابط کاربری نهایی نیستند.

## نیاز قطعی کاربر، بر اساس آخرین توضیح
- **Allowlist واقعیِ مقصدها**، نه فقط denylist BAT۶ و نه صرفاً «همه ترافیک از VPN».
- فقط مقصدهای مجاز از رابط SSTP انتخاب‌شده؛ ترافیک عادی خارج تونل و مقصدهای خارج فهرست بسته بمانند. LAN عادی باز نشود و قطع/اتصال مجدد/IPv6/DNS/boot باید fail-closed آزموده شوند.
- پروفایل SSTP فعالِ یکتا اولویت دارد، وگرنه موجودِ یکتا؛ holand نام ترجیحی در حالت چند پروفایل غیرمتصل است، نه نام hardcode اجباری. چند اتصال SSTP فعال یا دو scope هم‌نام بدون انتخاب روشن، خطاست. اتصال دستی است.
- Enable تنظیمات پایدار را بگذارد و خارج شود؛ Disable فقط تغییرات خودش را از journal بازگرداند و خارج شود. هیچ monitor/service/process یا task دوره‌ایِ اختصاصی نباید لازم باشد. محدودیت بدون انقضا و پس از reboot حفظ شود. وظیفه/انقضای CI مربوط به محصول نیست.
- فهرست مقصدهای مجاز قابل افزودن/حذف است. نمونهٔ شروع level3.blizzard.com است، نه IP واقعی hardcode. IPهای fixture ساختگی‌اند و DNS یا ترافیک واقعی برای آن‌ها تولید نمی‌شود.

## طرح و مرزهای اثبات
Policy.ps1 دامنه و host-IP را اعتبارسنجی، config را ویرایش، پروفایل را انتخاب و از snapshot ورودی یک policy-plan تولید می‌کند. CIDR، Any، wildcard و URL به عنوان مقصد عادی پذیرفته نمی‌شوند؛ config کلید اضافه برای تضعیف سیاست ندارد. Snapshot حل‌نام توسط caller آینده با کنترل مسیر DNS تهیه خواهد شد؛ این هسته خود DNS query ندارد.

**نام دامنه مساوی هویت انحصاری IP نیست:** این طرح IP-allowlist است؛ سرویس‌های روی IP مشترک با فایروال IP از هم تفکیک نمی‌شوند. تغییر DNS/CDN بدون resident نیاز به Refresh صریح دارد؛ IP جدید تا refresh باید بسته بماند. نبود تله‌متری در مقصد مجاز یا نبود fingerprint محتوای فایل تضمین نمی‌شود.

ارتباط محدود لازم برای برقراری خود SSTP با سرور، استثنای صریح transport است، نه راه عمومی خروج اینترنت. طرح نام سرویس SstpSvc/TCP443 را پیشنهاد می‌دهد؛ binding سرویس/فرایند و رابط باید از اجرای واقعی qualification بگیرد. DNS در صورت نیاز فقط به resolverهای مشخص داخل تونل مجاز خواهد بود؛ DNS بیرون تونل در طرح باز نمی‌شود. CRL/OCSP یا bootstrap ناسازگار باید به توقف منجر شوند، نه غیرفعال‌کردن TLS یا Allow وسیع.

انتخاب پروفایل/تولید plan **اثبات binding امن interface پس از reconnect/boot نیست**. selected_interface_binding_qualified=false، enforcement_tested=false و ready_for_user_apply=false ثابت‌اند. backend اجرایی Enable/Disable هنوز اینجا وجود ندارد؛ هیچ فایل آمادهٔ فعال‌سازی به کاربر تحویل نشده است.

قبل backend باید موارد زیر روشن/آزموده شوند: حفظ اتصال خود SSTP در fail-closed، مدیریت Allowهای محلی قبلی و توقف در GPO/Allow غیرقابل‌کنترل، transition guard برای جلوگیری از پنجره باز بین چند فرمان، journal خصوصی و بازیابی فقط تغییرات خود، binding رابط پس از قطع/وصل و reboot، DNS/IPv6/LAN. برنامهٔ قدیمی v1.2 صرفاً مبناست و با Allow همه RemoteAccess، DNS از همه رابط‌ها، DHCP عمومی و باقی‌گذاشتن Allowهای موجود، معادل این هدف نیست. EmergencyResetِ تحمیل Allow در محصول جدید نباید وجود داشته باشد.

فایل‌های Connect-rus و BATهای کاربر اجرا یا تغییر نشده‌اند. اتصال دستی، BAT۶ و Pause فعلی محفوظ‌اند. وظایف timer/استثناهای runner که قبلاً برای CI استفاده شدند به محصول منتقل نمی‌شوند. هیچ تضمین مطلق «بدون نشتی» قبل آزمون دستگاه واقعی داده نشده است.
