# P7 — قرنطینه و بازیابی واقعی Enabled قوانین Allow
این کتابخانه داخلی است، نه Enable/Disable محصول و نه فایل قابل اجرای کاربر.

## پیاده‌سازی
- snapshot کامل هر قانون شامل CIM و هفت فیلتر از P3؛ فقط قوانین محلیِ موجود، فعال، Outbound/Allow پذیرفته می‌شوند.
- تنها تغییر واقعی کتابخانه: Set-NetFirewallRule -InputObject ... -Enabled False/True. نام قوانین موجود wildcard تفسیر نمی‌شود. هیچ قانون یا فیلتر موجودی بازسازی، حذف یا گسترده نمی‌شود.
- snapshot اصلی تغییر نمی‌کند. تصویر مورد انتظار پس از تغییر فقط از Enabled عددی CIM و نمای خوانا مشتق می‌شود؛ readback کامل باید همان hash را داشته باشد. تفاوت‌های ناشناخته provider پذیرفته نمی‌شوند.
- journal و ACL و flush/revision از P2؛ قفل کل فراخوانی، write-ahead قبل از تک‌تک تغییرها؛ بررسی کل frontier قبل/بعد هر تغییر.
- فرایند جدید فقط قبل/بعد دقیق همان تغییر معلق را می‌پذیرد. تغییر بیرونی، قانون گمشده، journal گمشده/خراب یا snapshot نامعتبر موجب توقف است، نه reset.
- Restore از قرنطینه ناقص هم ممکن است و تنها Enabled اصلی snapshot را برمی‌گرداند. هیچ Force-Allow عمومی، EnableAll یا reset وجود ندارد.
- سقف ۵۱۲ قانون و سقف واقعی ۱MiB journal؛ پر شدن journal اولیه قبل از نخستین تغییر فایروال متوقف می‌شود. ظرفیت واقعی صد قانون دستگاه کاربر هنوز اندازه‌گیری نشده است.

## مرزهای ایمنی و آزمایش
این کتابخانه guard ندارد؛ فراخوانی مستقل آن روی قوانین واقعی دستگاه کاربر مجاز/ایمن اعلام نشده است. coordinator نهایی باید guard پایدار و تأییدشده را پیش از آن برقرار کند، هم‌زمانی و موجودی کامل policy را بسنجد و پیش از برداشتن guard دوباره همه‌چیز را بخواند. قفل فقط عامل‌های همکار همین journal را سریالی می‌کند، نه مدیر محلی هم‌زمان یا GPO. check و syscall اتمیک نیستند.

CI فقط قوانین ساختگی متعلق به همان اجرای تست را تغییر می‌دهد: executable تصادفیِ ناموجود، IPهای مستندسازی IPv4/IPv6 و TCP/65534. این Allowهای فعال، آزمون عبور بسته یا تضمین عدم نشتی نیستند. defaultهای پروفایل‌ها و قوانین قبلی runner تغییر نمی‌کنند. پاک‌سازی fixtureها جدا از Restore محصول و با hash کامل و هویت دقیق انجام می‌شود. فایل‌های journal و snapshot خصوصی به artifact ارسال نمی‌شوند.

تست شامل قطع واقعی فرایند پیش/پس از هر دو تغییر در Quarantine و Restore، بازیابی از فرایند تازه، Restore مستقیم از Quarantine ناقص، تداخل فیلتر خارجی و frontier، snapshot جعلی/تکراری، journal خراب/گمشده، idempotency و قفل است. فقط receipt محدود و hash کد منتشر می‌شود.

هیچ DNS، سرویس، scheduled task، انقضا یا برنامه resident ساخته نمی‌شود. وضعیت محصول همچنان ready_for_user_apply=false است. صد Allow واقعی دستگاه، guard، default=Block، اتصال فیلتر SSTP، قطع/وصل VPN، reboot و بسته‌ها در این مرحله تست نمی‌شوند.

## اصلاح پس از نخستین اجرای بومی
اجرای اول با۸۷بررسی و۱۰recovery و باقی‌مانده صفر، در تطبیق propertyهای قوانین نامرتبط failed شد؛ علت از رسید اول قابل تشخیص نیست. نه حذف این شرط و نه نسبت‌دادن بی‌شاهد آن به Windows مجاز است. اجرای بعد تعداد افزوده/حذف/اصلاح و فقط نام propertyهای متفاوت را گزارش می‌کند؛ هیچ نام قانون یا مقدار خصوصی صادر نمی‌شود. lookup الزامیِ قانون موجود از query دقیق escaped Name استفاده می‌کند و تمام خطاهای provider/not-found متوقف‌کننده‌اند؛ خطا هرگز «قانون وجود ندارد» تلقی نمی‌شود. snapshot کامل و معیار baseline ثابت مانده‌اند.
