# ممیزی پچ WoW — آزمایش مستقل، نه آپدیتر آماده

> تازه‌ترین milestone: [مدیر/cache اصلی و مسیر CreateFile](research/archive-cache-9824/README-fa.md): ۲۳ تابع/۲۴۲۳ بایت اصلی، ۱۵۴۱ بردار مطابق، ۳۲ بازخوانی واقعی، cache hit/collision و retain/list/release اصلی، ۹ توقف/resume، ۸۱۴ آزمون/صفر skip. constructor/درج cache هنوز adapter؛ CreateFile/ReadFile مرز Linux فقط‌خواندنی دارند و حالت write/create رد می‌شود. نه Windows یا Agent کامل و نه writer نصب اصلی.


## به‌روزرسانی مرحلهٔ دوم: اتصال به شواهد قبلی

راهنمای فعلی برای تست آفلاین Lab در **SOURCE-BINDING-fa.md** است. ورودی ساده `START-SOURCE-CHECK.cmd` اضافه شده؛ مرحلهٔ دوم شبکه ندارد و محتوای آرشیو بازی را نمی‌خواند. مانیفست PA و BuildConfig عمومی داخل `pinned_metadata/` همراه بسته‌اند. تعداد کل تست‌های فعلی ۹۹ است؛ اعداد ۵۸تستی پایین، نتیجهٔ تاریخی مرحلهٔ اول‌اند. خواندن دستورهای اجرای زندهٔ مرحلهٔ اول برای تست Lab لازم نیست.


## نتیجهٔ این مرحله

- زنجیرهٔ رسمی HTTPS برای EU و Build ثابت `12.1.5.70391` بازتولید شد؛ BuildConfig و CDNConfig با شناسهٔ MD5 خود تطبیق داده شدند. MD5 در اینجا شناسه/کنترل یکپارچگی TACT است، نه امضای دیجیتال ناشر.
- مانیفست PA2 دارای ۲۸ بلوک، ۲۷٬۱۵۴ هدف و ۲۷٬۹۹۴ گزینهٔ پچ خوانده شد. هش هدر+جدول و تمام بلوک‌ها تأیید شد. این تعداد به معنی تعداد فایل لازم برای نصب کاربر نیست.
- `patch-index` واقعی BLTE با هر ۷ هش chunk و EKey/CKey تأیید شد؛ parser معنایی patch-index هنوز پیاده نشده است.
- ایندکس رسمی patch-file-index کامل اعتبارسنجی شد. دو گزینهٔ پچ دارای مسیر مستقیم معرفی‌شده پیدا شد؛ این نتیجه همهٔ patch archives را پوشش نمی‌دهد.
- یک پچ `ZBSDIFF1` با اندازهٔ دقیق ۲٬۲۷۳٬۹۶۹ بایت و شناسهٔ `a56b3fe67a775fe9f4e86d6cbb688b5d` دریافت شد. ۳۷۰ دستور آن با خروجی اعلام‌شدهٔ ۷٬۰۶۷٬۰۵۰ بایت سازگار بود؛ ۱۲۲ دستور seek منفی داشت.
- پنج مجموعهٔ عمومی مرجع WoW Classic از commit ثابت دریافت شد. هر بازسازی دقیقاً با فایل expected مستقل از خروجی برنامه برابر شد و CKey نهایی هم تأیید شد. این نتیجه اثبات اعمال پچ روی Retail یا نصب کاربر نیست.
- ۵۸ آزمون محلی روی Linux/Python 3.13 گذشت. Windows در این مرحله آزمایش نشده است؛ ۴۴۶ تست هستهٔ قبلی هم در این محیط دوباره اجرا نشده‌اند.

## محدودیت تعیین‌کننده

پچ Retail هنوز روی ورودی واقعی خودش اعمال نشده است. Source EKey آن با CKey فایل decoded یکی نیست؛ نمی‌توان MD5 فایل decoded را با EKey مقایسه کرد و نتیجهٔ درست گرفت. فایل encoded قدیمی باید بر اساس شواهد معتبر پیدا و تأیید، سپس decode شود. ترتیب/معنای ordinal و نیاز به chain هنوز اثبات نشده است. صفر تا چهار در داده دیده شد؛ از توضیح قدیمی «۱-based» قاعدهٔ قطعی نساخته‌ایم.

مقادیر `required_network_download_bytes = null` و `installation_ready = false` حفظ شده‌اند. از اندازهٔ پچ آزمایشی، حجم آپدیت یا صرفه‌جویی نصب کاربر استنتاج نمی‌شود. برنامه CASC writer، تغییر build.info، راه‌اندازی Agent، دریافت حساب، تعمیر واقعی یا فعال‌سازی نسخه ندارد.

## تصمیم برای ادامه

1. نتایج اسکن کامل قبلی و Lab حفظ شوند؛ نه metadata prepare و نه اسکن ۱٫۵میلیونی تکرار نشود.
2. فقط گزینهٔ پچی انتخاب شود که Source EKey آن در شواهد کامل موجودی قبلی ثابت شده باشد؛ اجرای بعدی باید با index/proof قبلی و خواندن هدفمند همان شیء کار کند.
3. منبع encoded دوباره به‌صورت هدفمند بررسی و decode شود؛ fingerprint تغییرکرده توقف می‌دهد. نبود proof به معنی نبود یا خرابی فایل نیست.
4. معنای ordinal/chain با مرجع اجرایی و نتیجهٔ واقعی روشن شود؛ سپس خروجی یک پچ Retail در staging جدا با CKey هدف تأیید شود.
5. حتی پس از بازسازی، نصب CASC و crash recovery پروژهٔ جدا می‌مانند. در بازی و Lab کاربر چیزی ننویسید.
6. هدف اصلی همچنان اثبات «فیلد سیستم → درخواست واقعی → مقصد → مرحلهٔ زمانی» است؛ دانلودر جای آن را نمی‌گیرد.

## اجرای توسعه‌دهنده — فعلاً از کاربر اجرای تازه‌ای نمی‌خواهیم

Python 3.9+، تنها کتابخانهٔ استاندارد؛ هیچ بسته‌ای نصب نمی‌شود. از پوشهٔ همین ابزار:

```sh
python -m unittest discover -s tests -v
python patch_audit.py --output ./NEW-OFFICIAL-AUDIT
python reference_fixtures.py --output ./NEW-REFERENCE-TEST
```

دستور اول آفلاین است. دو دستور دیگر شبکه دارند و فقط پوشهٔ جدید می‌سازند؛ پوشهٔ بازی یا Lab قبلی را انتخاب نکنید. اجرای دوبارهٔ زنده دانلود را دوباره انجام می‌دهد؛ این ابزار deliberately کش یا resume تولیدی ندارد. برای بازخوانی نتیجهٔ موجود کافی است JSONها را بخوانید، نیازی به اجرای مجدد نیست. Target پین‌شده است؛ اگر پاسخ رسمی تغییر کند، برنامه متوقف می‌شود و بی‌خبر سراغ Build جدید نمی‌رود.

ممیزی زندهٔ موفق، ۵٬۸۳۳٬۲۷۷ بایت body HTTP گرفت؛ آزمون پنج نمونهٔ مرجع ۸۸٬۰۸۳ بایت. این‌ها فقط همان دو اجرای نهایی‌اند، نه کل مصرف توسعهٔ جلسه، overhead شبکه یا حجم دانلود بازی. سقف کل body ابزار رسمی ۱۲ MiB است؛ هر metadata حداکثر ۸ MiB و پچ حداکثر ۴ MiB. برای تشخیص عبور از سقف ممکن است یک بایت اضافی خوانده و سپس اجرا رد شود. Redirect، HTTP، پاسخ Range ناخواسته، Content-Encoding، سایز نامعتبر و checksum نادرست رد می‌شوند. فایل موجود بازنویسی نمی‌شود. در اجرای رسمی، ورودی محلی بازی پذیرفته نمی‌شود.

## نکات قالب که با دادهٔ واقعی تأیید شدند

- PA2: هش شناسهٔ manifest فقط header + جدول بلوک‌ها را پوشش می‌دهد، نه کل فایل.
- هش هر بلوک روی رکوردهای استفاده‌شده به‌علاوهٔ بایت صفر پایان است؛ padding صفر جدا کنترل می‌شود. تمام ۲۸ بلوک نمونه با این قرارداد تطبیق داشتند. سایر variantها fail-closed هستند.
- ZBSDIFF1: سه stream مستقل zlib؛ control در tripleهای ۲۴بایتی؛ عددها little-endian **sign-magnitude** هستند، نه two's complement. جمع diff با بایت قدیمی modulo 256 است، نه XOR.
- SHA256 ورودی نمونه‌های مرجع فقط همان bytes ثابت را به تست متصل می‌کند؛ اثبات EKey نصب کاربر نیست.

## فایل‌ها

- `patch_audit.py`: ممیزی رسمی و تابع خالص اعمال پچ در حافظه؛ بدون نصب یا دسترسی به فرایند.
- `cdn_catalog.py`: کد اعتبارسنجی ایندکس از مخزن موجود، بدون تغییر.
- `reference_fixtures.py`: آزمون اختیاری پنج نمونهٔ عمومی با commit و Git blob manifest ثابت.
- `tests/test_patch_audit.py`: ۵۸ آزمون؛ دادهٔ خراب، عددهای منفی، کنترل سایز، فشرده‌سازی مخرب، هش‌ها، ورودی اشتباه، path traversal و عدم بازنویسی.
- `PATCH-AUDIT.json`، `REFERENCE-FIXTURE-RESULTS.json`، `TEST-RESULTS.json` و `TEST-LOG.txt`: شواهد همین اجرا.
- `PACKAGE-MANIFEST.json`: SHA256 فایل‌های تحویل‌شده، به‌جز خودش.

هیچ باینری بازی، پچ دریافتی، فایل PRIVATE، دادهٔ حساب یا ضبط شبکه در بسته نیست. فایل‌های مرجع دریافت می‌شوند ولی اجرا نمی‌شوند و در بسته توزیع نشده‌اند.
