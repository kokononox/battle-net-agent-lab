# اصلاح ذخیرهٔ گزارش Windows بدون نیاز به hardlink

## شواهد واقعی و حد نتیجه‌گیری

کاربر بستهٔ `local-review-diag-2` را روی Windows و Python 3.13.16 اجرا کرد. خروجی: `OSError`, مرحلهٔ `publish_report_noreplace`, `errno=22`, `winerror=1` و trace مربوط به خط `os.link(temp,final)` در `local_update_review.publish`. این مرحله پس از بازبینی ورودی‌ها و نوشتن گزارش موقت است. پیام مذکور به معنی خرابی/ناقص‌بودن بازی نیست؛ `installation_ready=false` همچنان درست است.

فراخوانی ردشده مشخص است، اما نوع فایل‌سیستم یا علت زیرین پشتیبانی‌نشدن عملیات مشخص نیست. حدس exFAT، نیاز به administrator یا تغییر مجوز از این داده ثابت نمی‌شود. هیچ‌کدام به کاربر توصیه نشده است.

## تغییر محدود

نسخهٔ `local-review-diag-3`: تابع `publish_report_noreplace` در Windows مستقیماً `os.rename(temp,final)` را فراخوانی می‌کند؛ طبق قرارداد Windows در Python، اگر مقصد موجود باشد `FileExistsError` می‌دهد و بازنویسی نمی‌کند. در POSIX همان `os.link` حفظ می‌شود چون `rename` آن می‌تواند فایل موجود را جایگزین کند. فایل موقت و مقصد در همان پوشهٔ جدید خروجی‌اند. `os.replace` یا fallback بازنویس اضافه نشده است.

کنترل‌های خروجی خارج از Lab/بازی/ورودی‌ها، کنترل مجدد snapshot و sidecar، حذف فایل نهایی خود برنامه هنگام شکست پس از انتشار و پاک‌کردن pending حفظ شده‌اند. هیچ سقف خواندن، شرط binding یا معیار اثبات محتوا تغییر نکرده است. کد scanner، downloader یا writer بازی اضافه نشده است.

## تست‌ها و محدودیت

جزئیات قابل بازاجرا در `run_experiments.py` و `TEST-RESULTS.json` همین پوشه ثبت می‌شود. ۲۳۷ تست هسته/برنامه‌ریز/بازبینی، ۲۵ تست تشخیص خطا و ۱۶ تست انتشار: مجموع ۲۷۸ تست. نشانگر نسخه در دو assertion قدیمی از diag-2 به diag-3 به‌روز شده؛ منطق تست‌های قبلی حذف نشده است.

۱۶ تست تازه dispatch سیستم‌عامل، عدم استفاده از hardlink در مسیر production ویندوز، نبود fallback یا replace، حفظ فایل رقیب، پاک‌سازی هنگام خطا، تغییر snapshot/sidecar، حفاظت Lab/آرشیو/بازی و تشخیص خطای 22/1 را پوشش می‌دهند. قرارداد rename ویندوز با مدل صریح فقط در تست شبیه‌سازی شده؛ این مدل از hardlink واقعی Linux کمک می‌گیرد و آزمون فایل‌سیستم Windows یا محیط بدون hardlink نیست. خطای گزارش‌شده نیز در Linux تزریق شده، نه روی دستگاه کاربر بازتولید شده است.

دو حالت مستقل CLI قبلی و انتشار واقعی گزارش با primitive لینوکس، خارج از PYTHONPATH مخزن، اجرا می‌شوند. کد Windows، CMD و انتخابگر گرافیکی روی Windows در این محیط اجرا نشده‌اند؛ موفقیت روی سیستم کاربر هنوز باید با بستهٔ جدید تأیید شود. این اصلاح آپدیتر کامل یا اجازهٔ نصب بازی محسوب نمی‌شود.

## مبنای قرارداد

[Python 3.13 os.rename](https://docs.python.org/3.13/library/os.html#os.rename) — در Windows مقصد موجود همواره خطای FileExistsError می‌دهد؛ این رفتار با POSIX متفاوت است.

## اجرای کاربر

بستهٔ `Local-Update-Review-Windows-Fix.zip` را در پوشه‌ای تازه خارج از بازی و Lab استخراج کنید. Lab قبلی را جابه‌جا نکنید. بازی و Battle.net بسته باشند. `RUN-LOCAL-REVIEW.cmd` را اجرا و نشانگر `Diagnostic build: local-review-diag-3` را کنترل کنید. همان Lab قبلی را انتخاب کنید. فقط `LOCAL-UPDATE-REVIEW-to-share.json` را از مسیری که ابزار اعلام می‌کند ارسال کنید. اگر متوقف شد، JSON تشخیصی را ارسال کنید. اسکن/دانلود مجدد، حذف Lab، اجرای administrator یا تغییر مجوز لازم نیست.
