# تشخیص امن خطای سیستم‌عامل — local-review-diag-2

گزارش کاربر از بستهٔ قبلی فقط `OSError` داشت. از آن پیام نمی‌توان فهمید خطا هنگام خواندن Lab/آرشیو، بررسی snapshot، یا ساخت گزارش بوده است. **علت خطای واقعی Windows هنوز مشخص یا رفع‌شده اعلام نمی‌شود.**

این تغییر فقط قابلیت تشخیص را اضافه می‌کند؛ کنترل‌های binding/snapshot، حالت فقط‌خواندنی، سقف خواندن، رد symlink/reparse و انتشار بدون overwrite تغییر نکرده‌اند. هیچ fallback ناامن، درخواست Administrator، تغییر permission، migration، اسکن دوباره یا دانلودی اضافه نشده است.

## خروجی خطا

- `diagnostics_version`: برای تشخیص اجرای بستهٔ جدید؛ مقدار `local-review-diag-2`.
- `stage`: نام ثابت مرحله، مثل `bind_saved_checkpoint`، `verify_target_payloads` یا `publish_report_noreplace`.
- `errno` و `winerror`: فقط عدد، اگر خود exception آن‌ها را داشته باشد.
- سیستم‌عامل عمومی و نسخهٔ Python؛ بدون نام سیستم یا حساب کاربر.
- `safe_trace`: فقط نام ماژول‌های مجاز، نام تابع و شمارهٔ خط؛ حداکثر ۱۲ frame.

متن exception، filename، مسیر پوشه، خط کد و متغیرهای محلی چاپ نمی‌شوند. خطاهای ناشناخته همچنان موجب توقف می‌شوند؛ diagnostic به معنی تأیید یا تعمیر فایل نیست.

## اجرا برای کاربر

1. ZIP جدید را در **پوشه‌ای جدید و خارج از بازی و Lab** استخراج کنید؛ Lab را جابه‌جا یا بازنویسی نکنید.
2. بازی و Battle.net بسته بمانند.
3. `RUN-LOCAL-REVIEW.cmd` را اجرا کنید. ابتدا باید `Diagnostic build: local-review-diag-2` دیده شود.
4. همان Lab موجود را انتخاب کنید. در صورت خطا، خروجی JSON جدید را ارسال کنید. در صورت موفقیت، فقط `LOCAL-UPDATE-REVIEW-to-share.json` را ارسال کنید.

Python 3.10+ لازم است. این نسخه نیز آپدیتر یا نصب‌کنندهٔ بازی نیست. تا دریافت کد واقعی خطای Windows، تغییر در مسیر فایل‌ها/دسترسی‌ها یا حذف Lab توصیه نمی‌شود.

## شواهد

۲۵ تست جدید برای عددهای خطای تزریق‌شدهٔ Windows، عدم نشت مسیر/پیام، stage درست در خطای bind/خواندن payload/ساخت پوشه/نوشتن/انتشار گزارش، پاک‌سازی فایل موقت و خروجی launcher با folder picker شبیه‌سازی‌شده. ۲۳۷ تست قبلی نیز دوباره اجرا شده‌اند؛ جمع ۲۶۲ تست بدون شکست/خطا/skip.

خطاهای `WinError` این تست‌ها روی Linux **تزریق** شده‌اند؛ اجرای واقعی Windows، تشخیص علت خطای کاربر یا رفع آن اثبات نشده است. بستهٔ مستقل دوباره در دو حالت موفق CLI و یک مسیر خطای محلی روی Linux بررسی شده است. در مسیر خطا، stage/errno و trace امن بررسی شده و مسیر خصوصی در خروجی نبوده است.
