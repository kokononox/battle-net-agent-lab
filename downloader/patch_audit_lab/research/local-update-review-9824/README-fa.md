# بازبینی تازهٔ محلی — فقط‌خواندنی و محدود

این مرحله، برنامه‌ریز را به **inventory ذخیره‌شدهٔ موجود** وصل می‌کند و فایل‌های نامزد را دوباره می‌خواند. این ابزار آپدیتر کامل یا نصب‌کننده نیست؛ هیچ patch یا دانلودی روی نصب واقعی اجرا نمی‌کند.

## کنترل‌های اصلی

- تمام کنترل‌های قبلی `source_binding.bind` برای build/Download، plan، صف، checkpoint، snapshot و fingerprint دوباره اجرا می‌شوند.
- موفقیت قدیمی صف یا evidence، به‌تنهایی اثبات نیست. برای reuse باید EKey کامل، جدول و checksum قطعه‌های BLTE، اندازهٔ decoded و CKey کامل هدف با خواندن تازه تأیید شوند. prefix نه‌بایتی کافی نیست.
- ابتدا هدف‌های منتخب بررسی می‌شوند، سپس فقط مبدأهای PA مرتبط با هدف‌های هنوز استفاده‌نشده. خواندنِ یک محدودهٔ مشترک دوباره محاسبه نمی‌شود.
- به‌صورت پیش‌فرض: حداکثر ۲۵۶ هدف، ۳۲ مگابایت payload آرشیو، ۳۲ فراخوانی خواندن و ۲۵۶ بررسی نامزد. هر شیء حداکثر ۸ مگابایت encoded/decoded. سقف هدف‌ها ۴۰۹۶ است. فراتر از حد، ناشناخته می‌ماند، نه مفقود یا خراب.
- محدودیت ۳۲ مگابایت فقط برای payload آرشیوهای موجود است؛ خواندن DB/PA جداست. گزینهٔ اختیاری Portable، بسته و Encoding حدود ۲۰۰مگابایتی آن را کامل بررسی می‌کند و جزء بودجهٔ آرشیو نیست.
- روی هیچ ورودی index ساخته یا migration اجرا نمی‌شود؛ هیچ اسکن تازهٔ بازی و هیچ درخواست شبکه‌ای وجود ندارد.
- موجود بودن مبدأ PA اجازهٔ اجرای پچ عمومی نیست. فقط با `--portable`، همان رابطهٔ دقیق پین‌شده و encoding تأییدشده می‌تواند نامزد پچِ موجودِ محلی شود. حتی در این حالت `apply_authorized=false` می‌ماند و چیزی نوشته نمی‌شود.

## خروجی و حریم خصوصی

`LOCAL-UPDATE-REVIEW-to-share.json` گزارش عمومی است. مسیر آرشیو، مسیر Lab، provenance خصوصی و برچسب‌های دلخواه/account وارد آن نمی‌شوند. سیاست انتخاب فقط با فیلدهای شناخته‌شده گزارش می‌شود. هیچ فایل PRIVATE برای ارسال تولید نمی‌شود.

گزارش فقط در پوشهٔ جدید، خارج از Lab/بازی/متادیتا منتشر می‌شود. قبل از انتشار، هویت ورودی‌ها و نبودن journal/WAL دوباره بررسی می‌شود. انتشار فایل نهایی بدون overwrite است؛ اگر تغییر ورودی هنگام انتشار کشف شود، گزارش نهایی خود ابزار حذف می‌شود. فایل ازپیش‌موجود یا فایل برندهٔ رقابت جایگزین نمی‌شود.

مدل سازگاری، fingerprint و مجموعهٔ نام فایل‌هاست؛ OS snapshot و دفاع در برابر نویسندهٔ مهاجم ادعا نمی‌شود. بازی و Battle.net را قبل از بررسی ببندید. خطای unsupported یا snapshot قدیمی، مجوز حذف فایل‌ها یا شروع مجدد دانلود/اسکن نیست.

## اجرای بستهٔ مستقل

بسته را **خارج از بازی و Lab** روی فایل‌سیستم معمولیِ دارای hardlink (مثلاً NTFS) استخراج کنید. Python 3.10 یا جدیدتر لازم است؛ آزمایش حاضر با Python 3.13/Linux انجام شده است. هیچ پکیج pip یا دسترسی Administrator لازم نیست. راه‌انداز CMD و folder picker ارائه شده‌اند، اما اجرای واقعی روی Windows هنوز آزمایش نشده است؛ این یک فایل EXE یا نسخهٔ نهایی ویندوز نیست.

1. بازی و Battle.net را ببندید.
2. `RUN-LOCAL-REVIEW.cmd` را اجرا کنید و **پوشهٔ Lab موجود** را انتخاب کنید، نه پوشهٔ بازی.
3. پس از اتمام، فقط `Results/Local-Review-.../LOCAL-UPDATE-REVIEW-to-share.json` را ارسال کنید.
4. اگر متوقف شد، کد خطای امن را ارسال کنید؛ فایل بازی یا Lab را تغییر ندهید.

روش خط فرمان، از پوشهٔ بسته:

```bash
python -B local_update_review.py --lab "PATH_TO_EXISTING_LAB" \
  --audit-dir "PATH_TO_BUNDLE/pinned_metadata" \
  --out-new "NEW_RESULTS_FOLDER_OUTSIDE_INPUTS"
```

برای بررسی اختیاری همان Portable موجود، `--portable "PATH_TO_EXTRACTED_PORTABLE"` را اضافه کنید. نبودن این گزینه باعث توقف بررسی reuse نمی‌شود، ولی قابلیت اختصاصی پچ نمونه فعال نمی‌شود.

در لینوکس، مسیرهای دارای symlink از جمله alias محیطی `/data` را با مسیر فیزیکی حاصل از `realpath` جایگزین کنید. ذخیرهٔ stdout با redirection داخل ورودی‌ها مجاز نیست؛ گزینهٔ `--out-new` کنترل‌های محل خروجی را اعمال می‌کند.

## شواهد این مرحله

۴۹ تست جدید و اجرای مجدد ۱۸۸ تست قبلی، مجموعاً ۲۳۷ تست بدون شکست/خطا/skip. تست‌های تازه شامل سقف خواندن، نادیده‌گرفتن ادعاهای موفقیت قدیمی، محتوای تغییرکرده، CKey ناهماهنگ، binding نامعتبر، snapshot تغییرکرده، sidecar، حریم خصوصی و رقابت هنگام انتشار گزارش‌اند.

برای آزمون اتصال، DBهای Lab **مصنوعی** ساخته شده‌اند و دو محتوای واقعیِ Portable در آرشیو owned مرحلهٔ قبل خوانده شده‌اند. این‌ها inventory یا انتخاب Download واقعی کاربر نیستند:

- مبدأ موجود و مقصد نامشخص، بدون Portable: یک reuse و یک دریافت کامل مشروط.
- همان ورودی با Portable تأییدشده: یک reuse و یک پچِ موجودِ محلی.
- آرشیو owned دارای هر دو محتوا: دو reuse با ۳۱۶ بایت خواندن payload.

بستهٔ ZIP پس از ساخت در یک پوشهٔ جدید استخراج و **بدون PYTHONPATH مخزن** در دو حالت عادی و Portable اجرا شده است. این آزمایش، کامل بودن وابستگی‌های CLI مستقل را روی Linux نشان می‌دهد؛ نه تأیید Windows/CMD/Tkinter یا نصب واقعی.

کدهای قبلی، native oracleها، Agent.exe، فایل‌های بازی و payloadهای نمونه در بستهٔ بازبینی توزیع نمی‌شوند. متادیتای پین‌شده، کدهای بررسی و راهنما همراه آن‌اند.

## مانع باقی‌مانده برای آپدیتر کامل

فهرست/شواهد واقعی نصب کاربر و تشخیص build نصب‌شده در این محیط موجود نیست. Encoding و PA به‌تنهایی فهرست کامل فایل‌های لازم بازی نیستند. ابتدا گزارش فقط‌خواندنی از Lab موجود لازم است؛ پس از آن می‌توان شکاف داده‌ها را دقیق تعیین کرد. دریافت شبکه، اجرای عمومی patch/fallback، چند payload واقعیِ آپدیت‌شونده، فعال‌سازی نصب و تست Windows/قطع برق هنوز تأیید نشده‌اند. مجموعهٔ تاریخی ۸۱۴تستی نیز در این مرحله بازاجرا نشده است.
