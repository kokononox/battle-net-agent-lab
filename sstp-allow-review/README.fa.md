# بررسی محدودیت Allowهای خروجی — فقط‌خواندنی

۱. ZIP را کامل در پوشه‌ای جدید استخراج کنید و فقط Read-Allows.cmd را اجرا کنید.
۲. درخواست Administrator مربوط به همین ابزار را بررسی و تأیید کنید.
۳. outbound-allow-report.json تازهٔ همان پوشه را پیش از ارسال بررسی و سپس ارسال کنید. در خطا، allow-review-error.json را ارسال کنید. journal، hosts یا backup خصوصی را نفرستید.
۴. فعلاً Enable، Prepare، Resume، Diagnose، فایل۹۹ یا EmergencyReset را اجرا نکنید.

هیچ قاعده، profile فایروال، hosts، DNS، route، VPN، IPv6، registry، سرویس یا task تغییر نمی‌کند. ابزار فقط فایل گزارش خود را کنار برنامه می‌نویسد و نسخهٔ قبلی همان گزارش را جایگزین می‌کند. پنجرهٔ فرمان پس از نتیجه منتظر کلید می‌ماند و سپس بسته می‌شود؛ پردازش نگهبان/سرویس نصب نمی‌شود. DNS lookup یا اتصال آزمایشی عمدی ندارد.

## دامنهٔ گزارش
این بار ActiveStore خوانده می‌شود: Allowهای Enabled و Outbound. بنابراین تعداد ممکن است با گزارش قبلی PersistentStore فرق کند. Enabled به‌تنهایی ثابت نمی‌کند قاعده در پروفایل جاری واقعاً اجرا می‌شود؛ statusهای عددی provider و profileهای قاعده هم گزارش می‌شوند، نه تست packet-level.

برای هر قاعده، interface type و محدودیت alias، دستهٔ برنامه، پورت/پروتکل، دسته/شمار مقادیر local/remote address و بخشی از شروط امنیتی خوانده می‌شوند. نام شش قاعدهٔ شناخته‌شدهٔ کیل‌سوییچ قبلی فقط در صورت تطابق دقیق label و Group نشان داده می‌شود؛ این تطابق اثبات مالکیت یا اصالت قاعده نیست. نام دیگر قواعد و برنامه‌ها و سرویس‌های ناشناخته، مسیرها، aliasها، IPها و SIDها به‌صورت خام صادر نمی‌شوند؛ به‌جایش دسته یا SHA256 استفاده می‌شود. نام پایهٔ چند فایل شناخته‌شده فقط برای رشتهٔ مسیرِ شروع‌شده با پوشهٔ Windows نشان داده می‌شود؛ مسیر canonical، امضا یا اصالت فایل تأیید نشده است.

مقصدها بدون خروج IP، با IPهای snapshot ذخیره‌شدهٔ کیل‌سوییچ و DNS فعلی ویندوز مقایسه می‌شوند. snapshot قدیمی، سرور اتصال جاری را اثبات نمی‌کند و DNS فعلی به معنی DNS داخل VPN نیست. context unavailable/absent با نبود مقصد یکی نیست.

remote_access_type_only فقط یعنی interface-type filter به RemoteAccess محدود است؛ نه پروفایل SSTP خاص. candidate_for_non_vpn_review یعنی از روی interface-type نمی‌توان رابط‌های غیرVPN را منتفی کرد؛ نه اثبات نشتی. aliasهای صریح، شرایط امنیتی اضافه و Blockهای متعارض هنوز ممکن است اثر قاعده را محدود کنند. عدد candidate را نباید تعداد نشتی یا تعداد قواعد قابل‌حذف دانست.

نام/هش/label این گزارش مجوز حذف یا غیرفعال‌سازی قاعده نیست. is_proven_leak و is_proven_safe و activation_approved عمداً false هستند. هیچ Allow به‌طور خودکار «بی‌خطر» یا «نشتی قطعی» نامیده نمی‌شود.

## محدودیت‌ها
snapshot اتمیک نیست. header قواعد قبل/بعد مقایسه می‌شود، ولی filterها در پایان دوباره خوانده نمی‌شوند. نبود تغییر header، نبود تغییر همزمان همهٔ داده‌ها را اثبات نمی‌کند. حد۱۰۰۰Allow و۴۰۰۰۰filter برای هر کلاس و فایل خروجی۲٫۲میلیون‌کاراکتری وجود دارد؛ در عبور از حد یا join ناقص/تکراری ابزار خطا می‌دهد، نه گزارش ناقص با ادعای کامل‌بودن.

Blockها و تقدم تعارض‌ها، جزئیات همهٔ شرایط IPsec/authenticated bypass، WFP ثالث، مسیر واقعی packets و قطع‌وصل/reboot بررسی جامع نمی‌شوند. مقدار نامفهوم Unknown/null باقی می‌ماند؛ صفر یا false فرض نمی‌شود. هش، تضمین ناشناس‌ماندن نیست؛ فایل را پیش از ارسال بررسی کنید. برای داده‌های user-scoped، در UAC با حساب دیگر، محدوده همان حساب elevated است.
