# F2 — تشخیص شکاف ثبت HTTP

## یافتهٔ آفلاین پیش از اجرا
در F1، بسته پیش از بازسازی HTTP فقط در صورتی بررسی می‌شد که tuple آن در نمونه‌برداری دوره‌ای IP Helper دیده شده باشد. یک نمونهٔ PCAP مصنوعی دارای درخواست کامل و بدون رکورد PID، در F1 حذف و در F2 با attribution=unattributed حفظ می‌شود. این مسیر نقص در کد بازتولید شد؛ علت قطعی تک‌تک شکاف‌های تاریخی F1 هنوز معلوم نیست.

## تفاوت مشخص، نه تکرار کور
- بازسازی همهٔ TCP مقصد عمومی پورت ۸۰ تا سقف‌ها، سپس انتشار فقط چهار Host تأییدشدهٔ F1.
- درخواست با PID نامعلوم حذف نمی‌شود و به Agent نسبت داده نمی‌شود؛ pid و process_name آن null هستند.
- نمونه‌های دارای انتساب فقط sampled_tcp_tuple نام دارند؛ گواه رمزنگاری‌شدهٔ PID نیستند.
- شمارندهٔ لایهٔ Ethernet/IP/TCP، اندازه‌های نامعتبر، fragment، طول IP صفر، جریان بدون payload، شکاف، conflict، نبود انتساب و محدودیت حافظه افزوده شد.
- طول صفر IP به طول حدسی تبدیل نمی‌شود. احتمال offload فقط فرضیه است تا دادهٔ واقعی خلاف یا تأییدش را نشان دهد.
- هیچ دادهٔ Hostهای نامرتبط، packet خام یا پاسخ HTTP منتشر نمی‌شود. شمارنده‌های کلی VM شامل ترافیک سایر پردازش‌ها نیز می‌شوند و نباید به Battle.net نسبت داده شوند.

## اجرا و ایمنی
همان bootstrap دارای هش pin و امضای معتبر، محیط child بدون توکن، مشاهدهٔ ۱۲۰ثانیه‌ای راه‌اندازی و فقط ادامهٔ زبان؛ بدون login، نصب، درخواست بازی، تغییر hosts یا Frida. همان runner استاندارد windows-2025 و ناشر Ubuntu جداگانه. larger runner یا گروه پولی فعال نمی‌شود؛ سهمیه و تعرفهٔ عادی حساب GitHub مستقل از این انتخاب است.
تمام سقف‌های F1 حفظ شده‌اند: ۳۲ MiB ETL حلقوی، پردازش ETL حداکثر۶۴ MiB و PCAP حداکثر۱۲۸ MiB، ۱۲۸ stream و کل۱۶ MiB دادهٔ segment، ۶۴ درخواست و حدود۵۱۲ KiB export، نمونهٔ بدنه۶۴ KiB. دانلود child سقف سخت شبکه ندارد، اما دانلود بازی درخواست نمی‌شود.

## آزمون پیش از اجرای زنده
۳۶ آزمون HTTP و validator و ۲۱ آزمون قبلی بسته‌ها پاس شدند. یک ناسازگاری bytearray در fixture قبل از هر اجرای زنده پیدا و با تبدیل صریح bytes اصلاح شد. نمونه‌ها مصنوعی‌اند، نه evidence واقعی. شرط پیام commit دقیق و run_attempt=1 از تکرار ناخواسته جلوگیری می‌کند. گزارش‌های F1 و منبع ثابت آن تغییر نمی‌کنند.

گزارش اجرای جدید پس از پایان: reports/startup-http-f2.json و reports/startup-http-f2-bootstrap.json.
مقایسهٔ تعداد درخواست‌ها بین VMهای F1 و F2 به‌تنهایی مقایسهٔ کنترل‌شده نیست؛ قضاوت اصلی باید از attribution و شمارنده‌های همان اجرای F2 باشد.
