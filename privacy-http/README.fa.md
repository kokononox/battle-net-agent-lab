# بررسی درخواست‌های HTTP مقصدهای باقی‌مانده — F1

## سؤال و تفاوت با E2
در اجرای پیشین بدنهٔ TLS از ورودی EncryptMessage ثبت شد، اما برای
nydus.battle.net، level3.blizzard.com، us.cdn.blizzard.com و ocsp.digicert.com
محتوای HTTP معمولی باقی نماند. این اجرا فقط شکاف درخواست‌های خروجی HTTP را هدف می‌گیرد.
پاسخ‌ها یا فایل‌های دانلودی طبقه‌بندی نمی‌شوند؛ آزمون آپدیت WoW یا انتقال A→B نیست.

## اجرا و هزینه
- فقط همان شاخهٔ پژوهشی، پیام commit دقیق، run_attempt=1 و رانر استاندارد windows-2025.
- هیچ larger runner، runner group سازمانی یا قابلیت پولی جدیدی فعال نمی‌شود.
- استاندارد بودن به معنی تضمین صفر هزینهٔ مصرف نیست؛ محدودیت و سهمیهٔ حساب GitHub اعمال می‌شود.
- اجرای کل job حداکثر ۱۰ دقیقه؛ مشاهدهٔ راه‌اندازی ۱۲۰ ثانیه.
- بدون Frida، بدون نصب وابستگی جدید، بدون تغییر hosts، بدون محدودسازی مقصدها.
- فقط ادامهٔ انتخاب زبان همان ابزار تأییدشده؛ نه ورود، پذیرش شرایط، کلیک نصب یا درخواست بازی.
- بررسی امضای Blizzard و هش ثابت bootstrap پیش از اجرا.
- محیط child فاقد توکن گیتهاب است. ویندوز توکن فقط read؛ انتشار از job جداگانهٔ Ubuntu.

## داده و محدودیت
- pktmon NIC با pkt-size=0 (درخواست ثبت کامل packet)، ETL حلقوی ۳۲ MiB،
  سقف پردازش ETL=64 MiB و pcapng=128 MiB؛ فایل خام از VM خارج نمی‌شود.
- فقط TCP پورت ۸۰ که tuple آن توسط IP Helper به پردازش‌های شناخته‌شده منتسب شده است.
- فقط چهار Host بالا منتشر می‌شوند؛ نام DNS به‌تنهایی مجوز انتساب محتوا نیست.
- سرهم‌بندی sequence با reorder/retransmit و تشخیص overlap متعارض؛ از شکاف عبور نمی‌کند.
- tuple با SYN متفاوت دوباره‌استفاده‌شده کنار گذاشته می‌شود. FIN/RST و تمام حالت‌های TCP
  مدل‌سازی نشده‌اند؛ انتساب tuple به PID گواه رمزنگاری‌شده نیست.
- حداکثر ۱۲۸ stream، هرکدام ۲۵۶ KiB دادهٔ segment شامل تکرارها، کل ۱۶ MiB.
- حداکثر ۶۴ درخواست، نمونهٔ بدنه ۶۴ KiB، مجموع export حدود ۵۱۲ KiB.
- مسیر و هدرهای واقعی VM و بدنهٔ base64 ثبت می‌شوند؛ auth/cookie headers ماسک می‌شوند.
  مسیر و بدنه برای محتوای arbitrary ناشناخته scrub نمی‌شوند؛ VM حساب شخصی ندارد.
- complete بودن بدنه فقط نسبت به framing ثبت‌شده است؛ اثبات تحویل یا ذخیرهٔ سرور نیست.
- HTTP/2، QUIC، ترافیک TLS، IPv6 extensions و IP fragments در این parser پوشش داده نمی‌شوند.
- نبود درخواست یا نبود رشتهٔ CPU، اثبات عدم ارسال مشخصات سخت‌افزاری نیست.
- سقف سخت دانلود شبکهٔ child وجود ندارد؛ درخواست دانلود بازی نداریم.

## آزمون‌ها
قبل از bootstrap، آزمون‌های safety قبلی و آزمون‌های parser اجرا می‌شوند.
نمونهٔ PCAP مصنوعی شامل HTTP چندقطعه‌ای، reorder، retransmit و بدنه است.
این داده‌ها هرگز evidence واقعی تلقی نمی‌شوند.
پس از اجرا گزارش `reports/startup-http-f1.json` و receipt bootstrap منتشر می‌شود.
خرابی capture مانع اجرای client می‌شود؛ pin mismatch مانع اجرای bootstrap می‌شود.
