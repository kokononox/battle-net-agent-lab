## تغییر هدفمند
به صورت opt-in، برای رکورد capture نوع IPv4/TCP دارای total length صفر، انتهای frame ثبت‌شده مرز حداکثر داده فرض می‌شود؛ نه یک IP packet معتبر روی سیم. offset و fragmentation همچنان بررسی می‌شوند. داده تنها وقتی صادر می‌شود که parser HTTP از ابتدای stream درخواست یکی از چهار Host مجاز را استخراج کند. هیچ resync دلخواه به رشتهٔ GET در بدنه انجام نمی‌شود.
هر stream دارای این نوع رکورد پسوند `_capture_bounds` می‌گیرد؛ هر درخواست به آن stream لینک دارد. schema=3 و پرچم zero_ip_length_capture_bounds_inference اجباری‌اند؛ شمارنده‌های مستقل پوشش این نوع بازیابی را نشان می‌دهند. خروجی غیر برچسب‌دار برای این داده توسط validator رد می‌شود.
این استنباط ممکن است محدودیت offload/capture داشته باشد؛ وجود چنین رکوردی علت خاص NIC یا رسیدن به سرور را ثابت نمی‌کند. Capture خام، دیگر Hostها و پاسخ‌ها خارج نمی‌شوند.

## آزمون و اجرای محدود
۴۰ آزمون HTTP/validator پاس شدند؛ شامل نمونهٔ مصنوعی total-length صفر که در حالت عادی رد، و فقط در حالت opt-in با برچسب قابل استخراج است. fixture دادهٔ واقعی نیست. آزمون‌های ایمنی پیشین و packet parser نیز در workflow قبل از اجرای bootstrap برقرارند.
