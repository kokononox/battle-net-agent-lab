# ابزار مستقل فهرست مجاز — نسخهٔ توسعه

**این نسخه فقط ویرایش فهرست و پیش‌نمایش سازگاری است؛ فایروال را تغییر نمی‌دهد و کیل‌سوییچ آمادهٔ استفاده نیست.**

## محدودهٔ ثابت
- اتصال SSTP با شورتکات فعلی کاربر مستقل باقی می‌ماند؛ این ابزار rasphone/rasdial را اجرا نمی‌کند.
- هیچ سرویس اختصاصی، پردازش پس‌زمینه، task، watchdog یا زمان انقضا ساخته نمی‌شود. بعد از هر فرمان فرایند تمام می‌شود.
- فرایندهای بومی Windows/SSTP خارج از ابزار هستند و برای شبکه لازم‌اند.
- اعمال نهایی فقط پس از آماده‌شدن تغییر guarded و بازگردانی دقیق ارائه خواهد شد. فعلاً Actionهای Enable، Disable و EmergencyReset اصلاً وجود ندارند.

## آنچه نوشته شده
`SstpAllowlist.ps1` ورودی مستقل با پنج فرمان Init، List، Add، Remove و Plan است. `Core.ps1` از نسخهٔ همراه `Policy.ps1` برای اعتبارسنجی استفاده می‌کند؛ این فایل همان کتابخانهٔ سیاست قبلی است و هیچ تغییر فایروالی انجام نمی‌دهد. این پوشه مستقل از شاخه‌های آزمایشی قبلی نگهداری می‌شود.

Init فایل جدید را با تنها مقصد level3.blizzard.com می‌سازد و فایل موجود را overwrite نمی‌کند. Add و Remove دامنه/تک-IP را canonical می‌کنند؛ wildcard، URL، CIDR، مقصد تهی، schema ناشناخته و حذف آخرین مقصد رد می‌شوند. نوشتن در فایل موقتِ همان پوشه و Replace انجام می‌شود؛ lock فقط ویرایشگرهای همکار همین ابزار را سریالی می‌کند. مسیر دارای reparse point رد می‌شود. این فایل پیکربندی **journal مالکیت یا مرز امنیتی در برابر مدیر محلی مهاجم نیست**. ورودی کاربر در DNS resolve نمی‌شود.

Plan فایل را می‌خواند و فقط با Get-NetFirewallProfile و Get-NetFirewallRule از ActiveStore پیش‌نمایش می‌سازد؛ فعلاً شروط هفت‌گانهٔ filter هر rule را تحلیل نمی‌کند. حتی نبودن مانع در این پیش‌نمایش مجوز Apply نیست. این فرمان فعلاً برای توسعه است و خروجی محلی می‌تواند نام واقعی قواعد را داشته باشد؛ خروجی نباید عمومی upload شود. هیچ inventory زنده‌ای در این مخزن ثبت نشده است.

گروه SSTP Kill Switch صرفاً سرنخ نمایش برای review است، نه اثبات مالکیت؛ قواعد آن adopt/delete/disable نمی‌شوند. Allowهای دیگر و Blockهای موجود برای بررسی جدا می‌شوند؛ GPO با برچسب گروهِ مشابه قانون خودی محسوب نمی‌شود. Profile خاموش یا default مؤثر غیر Block مانع گزارش می‌شود؛ هیچ مقدار NotConfigured به Allow تبدیل نمی‌شود.

## قرارداد یکپارچه‌سازی با کیل‌سوییچ v1.2
1. شورتکات Connect-rus-v1.3 بدون تغییر باقی بماند.
2. قانون عمومی Allow روی RemoteAccess باید در مسیر اعمال نهایی با قواعد مقصد محدود جایگزین شود؛ افزودن Allowهای محدود کنار آن کافی نیست.
3. DNS آزاد از همهٔ رابط‌ها باید جدا بررسی و محدود شود. DHCP، bootstrap TCP443، DNS داخل تونل و سرویس‌های ضروری شبکه یک چیز نیستند و نباید حذف/گسترش کورکورانه شوند.
4. Allowهای موجود روی ویندوز و GPO باید در سیاست مؤثر حسابرسی شوند؛ default Block به‌تنهایی آن‌ها را خنثی نمی‌کند. Blockهای صریحِ متعارض نیز باید بررسی شوند؛ BlockAll + Allow استثنا طراحی صحیحی نیست.
5. اجرای دوبارهٔ Enable فایل قدیمی، اجازهٔ عمومی را دوباره می‌سازد؛ دو ابزار نباید همزمان مالک سیاست مشترک باشند. سازگاری نهایی باید وضعیت این تداخل را صریح کند، نه فایل قدیمی را بی‌خبر تغییر دهد.
6. Disable فایل قدیمی profile defaults را بازمی‌گرداند و EmergencyReset آن‌ها را به Allow می‌برد؛ هنگام فعال‌بودن وایت‌لیست، اجرای این مسیرها مستقل و ایمن فرض نمی‌شود. ابزار جدید نباید چنین resetی اضافه کند.
7. journal، baseline کامل شروط، transition guard و بازگردانیِ دقیق باید پیش از اولین تغییر واقعی برقرار باشند. خطا مجوز Force-Allow یا حذف قواعد براساس DisplayName/Group نیست.
8. اعمال نهایی باید مقصدها را به مسیر VPN محدود کند و رفتار قطع‌وصل/راه‌اندازی مجدد را بررسی کند؛ برنامهٔ اتصال یا نگهبان مقیم برای این منظور اضافه نخواهد شد. این مورد هنوز تأیید نشده است.

## آزمون انجام‌شده
- PowerShell 7.4.6 روی Linux: ۳۵ بررسی parser، پیکربندی، lock، نگهداری فایل اصلی هنگام خطا و تصمیم‌های پیش‌نمایش موفق شد.
- ده اجرای مستقل CLI شامل Init/Add/Remove/List، ورودی نامعتبر و رد Enable/Disable موفق شد.
- اجرای اول در check ششم به‌علت تبدیل null در آرگومان File.Replace متوقف شد؛ استفاده از NullString برای null واقعی اصلاح شد. رسید اول نگهداری شده؛ ادعای موفقیت به آن اجرا تعمیم داده نشده است.
- Windows PowerShell 5.1، cmdletهای زندهٔ NetSecurity، Windows Forms و اجرای واقعی روی دستگاه کاربر **آزموده نشده‌اند**. سازگاری PS7/Linux جای آن‌ها را نمی‌گیرد.
- هیچ firewall/VPN/DNS mutation در این نسخه وجود ندارد. Apply و آزمون ترافیک انجام نشده‌اند؛ ready_for_user_apply=false.
