# انتخاب آزمایشی مجموعه و کنترل مسیرها — ۰٫۱۳

## نتیجهٔ این مرحله
مرحلهٔ اولِ انتخاب مجموعه آغاز شد، نه تکمیل یک اپدیتر نصب‌کننده. هیچ درخواست شبکه، خواندن نصب زنده یا تغییر بازی در این مرحله انجام نشد.

- required_set.py یک فیلتر صریح و نسخه‌مستقل دارد: AND داخل هر clause، OR بین clauseها و رسید برای tag اختیاریِ غایب. این تفسیر فعلاً candidate است؛ سیاست واقعی Agent، qualifierهای خصوصی و رفتار همهٔ tagهای آینده مستقلاً qualification نشده‌اند.
- تعداد واقعی رکوردها هنگام پردازش bitmap رعایت می‌شود؛ بیت‌های padding، که در متادیتای تاریخی می‌توانند یک باشند، فایل اضافی ایجاد نمی‌کنند. MSB-first صریح است؛ نوع یا نام tag ناشناخته به معنی خرابی بازی نیست.
- Windows path gate فقط رشتهٔ مسیر نسبی را بررسی می‌کند؛ traversal، absolute/UNC، ADS، کنترل‌ها، نام دستگاه رزروشده، مؤلفهٔ غیرمجاز، تعارض case و تعارض file/directory رد می‌شوند. هیچ label متادیتا باز یا اجرا نمی‌شود. این gate جای امن‌سازی نویسندهٔ Windows و دفاع در برابر junction/reparse در زمان اعمال را نمی‌گیرد.
- آزمون آفلاین روی Install و Download تاریخیِ 12.1.5.70391 انجام شد؛ اندازه و CKey هر دو با build config همان نسخه تطبیق داشتند. ۳۹ مسیر Install آزمایشی کنترل شد. این داده جای مقصد 12.1.5.70448 استفاده نشد و هیچ required-set تولیدی اعلام نشد.
- متادیتا شمارش و جمع اندازهٔ candidate را می‌دهد، اما required_network_download_bytes عمداً null است: انتخاب قطعی و reuse هنوز اثبات نشده‌اند.
- MetadataSession پیش از بدنه Content-Length دقیق می‌خواهد، read اضافه برای آزمون EOF نمی‌کند، retry خودکار ندارد، partial-byte خطا را می‌شمارد و HTTPError را بدون خواندن بدنه می‌بندد. همهٔ آزمون‌های تازهٔ transport mock هستند، نه دانلود تازه.

## کنترل کیفیت
۳۴۵ تست Linux پاس شدند: ۳۴۱ مصنوعی و ۴ fixture متادیتای واقعی (سه ایندکس عمومی و Install تاریخی ارسالی). ۲۹ تست انتخاب و مسیر، ۹ تست transport مصنوعی و یک fixture واقعی در این نسخه اضافه شد. اجرای Download تاریخی جداگانه در reports/HISTORICAL-CANDIDATE-SELECTION-to-share.json ثبت شده و جزو شمارش تست‌های fixture کوچک نیست.

## مرز فعلی؛ نیازمند تأیید تازه
رسیدها، هویت‌ها و کد مقصد قبلی باقی‌اند، ولی فایل‌های بزرگِ decoded مقصد و بانک TARGET-CATALOGUE.sqlite در محیط فعلی یافت نشدند. به‌جای جایگزین کردن آن‌ها با نسخهٔ تاریخیِ متفاوت یا مصرف مجدد مجوز بسته‌شده، NEXT-METADATA-RECOVERY-PERMISSION.json یک درخواست جدید و هنوز approved=false ثبت می‌کند:

- فقط سه URL دقیق و متصل به config مقصد pinned: Install، Download و Encoding.
- حداکثر سه درخواست و مجموع 251510113 بایت بدنه (حدود 239.86 MiB).
- بدون retry، redirect، عوض کردن host/target، دانلود asset بازی، دسترسی به نصب کاربر، repair، تغییر permission یا نصب.
- در صورت موفقیت، اعتبارسنجی کامل N/Z BLTE و کلیدها، بازسازی catalogue و انتخاب آزمایشی آفلاین. این مجوز نه سیاست ناشناخته را معتبر می‌کند و نه اجازهٔ نصب می‌دهد.
- هیچ‌کدام از این سه درخواست در مرحلهٔ ۰٫۱۳ اجرا نشده‌اند.

هدف pinned یک نمونهٔ پژوهشیِ حفظ‌شده است، نه ادعای تازه‌ترین نسخهٔ امروز. معماری همچنان باید نصب موجود و انتشار سازگار را در زمان اجرا تشخیص دهد.

## ترتیب بعدی
۱. بازیابی ورودی‌های مقصد و qualification سیاست انتخاب؛ سپس تعیین required-set واقعی.
۲. تشخیص نسل فعال، بررسی شواهد reuse و بعد محاسبهٔ حجم دانلود؛ رسید تاریخی سلامت فعلی نیست.
۳. یکپارچه‌سازی transport و staging مقیاس‌پذیر و آزمون بومی Windows.
۴. نویسندهٔ تراکنشی CASC، rollback/activation روی کپی جداگانهٔ آزمایشی.
۵. UI، بسته‌بندی و end-to-end چند baseline/target.

برای مرجع ساختار manifest و tagها از https://wowdev.wiki/TACT استفاده شده است؛ این مرجع به‌تنهایی اثبات سیاست انتخاب proprietary Agent نیست. کد selection این بسته بازنویسی مستقلی است که محدودیت qualification را صریح نگه می‌دارد.

```sh
python -m unittest discover -v
```

# سابقهٔ مرحلهٔ ۰٫۱۲

این بسته checkpoint کد، تست و رسید است؛ اپدیتر آمادهٔ نصب نیست. لازم نیست آن را روی Windows یا پوشهٔ بازی اجرا کنید.

## نتیجهٔ واقعی محدودهٔ تازهٔ تأییدشده
- مجوز شامل حداکثر ۶۹۴ ایندکسِ قبلاً خوانده‌نشده و فقط پس از یافتن مسیر معتبر، دو Range برای یک شیء ۵۲ بایتی بود.
- ۱۹۷ ایندکس درخواست و با کلید نام، footer، TOC، checksum صفحات، ترتیب، padding و تعداد رکوردها تأیید شدند؛ ۲۷۳۲۵۲۳۶ بایت بدنه. در اولین مسیر معتبر متوقف شدیم: ۴۹۷ URL درخواست نشدند.
- ایندکس آرشیو 5794b0453d6a92824695d862abb25a31 رکورد کامل EKey/اندازه را در offset فیزیکی 268435404 نشان داد. این offset مستقل از offset فایل محلی است.
- دو درخواست Range دقیقاً ۲۶+۲۶ بایت دریافت کردند. بین دو مرحله process جدا اجرا شد؛ مرحلهٔ دوم checkpoint ذخیره‌شده را با همان target/source، ETag و اندازهٔ کل آرشیو بازیابی کرد. هر دو پاسخ 206 بودند. نه retry، نه redirect، نه دانلود کل آرشیو.
- پس از دریافت ۵۲ بایت، EKey، checksumهای BLTE، CKey و اندازهٔ decoded=64 تأیید شدند. SHA-256 دادهٔ بازشده با گزارش تاریخی کاربر یکسان بود. raw یا decoded payload در ZIP نیست.
- جمع محدودهٔ تازه: ۱۹۹ درخواست، ۲۷۳۲۵۲۸۸ بایت بدنهٔ کاربردی. سربرگ و سربار شبکه در این عدد نیست.
- baseline از دادهٔ تاریخی ارسال‌شده است، نه بازاعتبارسنجی نصب فعلی. از این نمونهٔ کوچک، سلامت کل نصب یا حجم لازم برای به‌روزرسانی نتیجه نمی‌گیریم.

## اصلاح ایندکس و سابقه
در محدودهٔ قبلی ۱۴۲۴ URL یک‌بار درخواست شد؛ ۷۳۰ ایندکس تأیید و ۶۹۴ بدنه خوانده نشدند. فرضِ جفت‌سازی ردیفی archives-index-size با archives مانع خواندن شد؛ این خطای فرض ابزار بود، نه خطای کاربر یا اثبات خرابی بازی. در محدودهٔ تازه سقف خواندن صریح از مجوز می‌آید و هویت همچنان با کنترل کامل ایندکس اثبات می‌شود. خود جفت‌سازی ردیفی هنوز qualification نشده است.

رسیدهای قدیمی reports برای سابقه نگه داشته شده‌اند؛ وضعیت جاری در QA.json و رسیدهای UNREAD-PASS، ARCHIVE-FIRST/SECOND و SEGMENT-STAGE است. فایل NEXT-UNREAD-INDEX-PERMISSION.json اکنون اجرای مصرف‌شده و بسته‌شده را ثبت می‌کند؛ مجوز اجرای تازه نیست. scanner نیز مجوز صریح مصرف‌نشده می‌خواهد و روی این فایل بسته‌شده توقف می‌کند. runnerهای شبکه پژوهشی و وابسته به محیط و ledger همین اجرا هستند، نه ابزار نصب قابل‌اجرای کاربر.

## توسعهٔ آفلاین بعد از موفقیت دریافت
segment_stage.py جایگزین آزمایشی نگه‌داری payload در JSON است:
- قطعات immutable در پوشهٔ scratch تازه و مستقل؛ journal فقط نام قطعات، طول، hash، هویت target/baseline/source و وضعیت entity دارد.
- ابتدا فایل قطعه و سپس journal موقت fsync می‌شوند؛ جایگزینی journal با os.replace و fsync پوشه انجام می‌شود.
- در بازیابی، همهٔ قطعات ثبت‌شده دوباره از نظر طول و SHA بررسی می‌شوند. قطعهٔ orphan خودکار پذیرفته یا حذف نمی‌شود. lock باقی‌مانده خودکار شکسته نمی‌شود.
- تغییر نصب مرجع/هدف/مسیر/CDN entity، writer قدیمی، خرابی یا فقدان قطعه و symlink/hardlink فایل‌ها رد می‌شوند. مسیر والد باید scratch مورد اعتماد باشد؛ دفاع در برابر process مهاجم ادعا نمی‌شود.
- ۲۷ تست مصنوعی شامل وقفهٔ شبیه‌سازی‌شده پس از قطعه، پیش از replace و پس از replace. این‌ها آزمایش قطع برق واقعی نیستند.
- همان نمونهٔ دریافت‌شده در دو process آفلاین روی این staging بازپخش و هویت کامل دوباره تأیید شد؛ درخواست شبکهٔ اضافی صفر بود. مسیر دریافت شبکه هنوز با staging جدید یکپارچه نشده است.
- این prototype مخصوص POSIX است، نه Windows. حداکثر شیء encoded فعلی ۴ MiB، هر قطعه ۱ MiB و حداکثر ۶۴ قطعه است. verifier نهایی هنوز فایل کوچک را در RAM می‌خواند؛ staging بزرگ و verification streaming تولیدی تکمیل نشده‌اند.

## الزام نسخه‌های آینده
منطق baseline و target پویاست؛ شمارهٔ 12.1.5.70448 و کلیدهای بالا فقط snapshot تاریخی این آزمایش‌اند، نه نسخهٔ ثابت محصول یا ادعای آخرین نسخهٔ امروز. انتشار تازه وسط دانلود نباید target ثابت را عوض کند. قالب ناشناخته باید ایمن رد شود؛ سازگاری با تمام فرمت‌های آینده تضمین نمی‌شود.

## باقی‌مانده تا اپدیتر قابل‌استفاده
۱. انتخاب معتبر required-set بر مبنای زبان/پلتفرم/اجزای نصب؛ نگاشت مسیرها و تشخیص نسل فعال.
۲. اثبات reuse و محاسبهٔ حجم و فضای لازم؛ هنوز عدد معتبری برای دانلود کامل نداریم.
۳. یکپارچه‌سازی شبکه با staging، verifier جریانی و journal مقیاس‌پذیر، سپس qualification بومی Windows.
۴. نویسندهٔ تراکنشی CASC، rollback و activation؛ آزمون روی کپی جداگانهٔ نصب، نه بازی اصلی.
۵. UI، بستهٔ Windows و end-to-end برای چند baseline و چند target بدون تغییر کد.

این مرحله هیچ خواندن یا نوشتنی روی دستگاه کاربر، نصب/repair، تغییر permission یا درخواست دسترسی admin نداشت. برای مراحل فعلیِ کدنویسی آفلاین مجوز بیشتری لازم نیست؛ هر آزمون محلی یا اعمال روی نصب بعداً باید با محدودهٔ مشخص تأیید شود.
