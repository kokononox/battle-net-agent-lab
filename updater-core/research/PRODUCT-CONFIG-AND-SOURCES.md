# ProductConfig and independent selection implementations — 0.24

## What was recovered, exactly
The pinned historical EU 12.1.5.70448 versions bytes already retained in the project contain ProductConfig `53020d32e1a25648c8e1eafd5771935f`. This field was not represented in the legacy TargetSnapshot shape. We found the exact content-addressed config without any new game-CDN request:
- [mdX7 mirror, pinned commit](https://github.com/mdX7/tact_configs/blob/04cce332a107ca0e303c570fc86b4690d1d51b38/tpr/configs/data/53/02/53020d32e1a25648c8e1eafd5771935f)
- [Arctium mirror, pinned commit](https://github.com/Arctium/bnet-tact-channel-configs/blob/e0ae5fcca1b6878ea8d79e6242e994cc7b454f3a/wow/data/53/02/53020d32e1a25648c8e1eafd5771935f)

Both raw UTF-8 files are 15764 bytes, MD5 exactly the advertised ProductConfig key; SHA256 `0909c89b6e5808a26791197dd722364d4b94d4b01ac64437b81bcde37d5c7519`. Python hashes and independent md5sum/sha256sum agree. We did NOT append a newline (that would change the content key). Both mirrors may share provenance: their agreement is not two independent official observations. No publisher signature was verified; MD5 content-key equality is not a modern authenticity guarantee.

The retained versions fixture SHA256 is `88824e3367bc0c446e0c2877990fc6170169b3cd56b9a7754034bb095adad407`, matching the existing pinned target. The config declares Windows/x86_64/arm64 mappings, supported/replacement locales, `_retail_`, `ngdp`, and `cn.config.extra_tags=[Alternate]`. There is no applicable extra_tags declaration for the public EU/enUS profile. That absence does NOT establish exclusion of Alternate, Talebound or HighRes. enable_block_copy_patch=true advertises a capability, not a patch recipe or correctness proof. Windows executable/registry/uninstall/delete fields are NOT executed or treated as paths by this feature.

## Code and integration
product_policy_facts.inspect_product_config checks the exact table SHA, unambiguous region row and all target identity fields before accepting the config's MD5. It strictly parses bounded JSON, supports explicit known Windows mappings, validates aliases including unused cycles, keeps text/speech separate, and reports scoped extra-tag declarations without selecting files. Future versions are not hardcoded; a synthetic 20.2.1.91234 case passes. Unknown schemas/mappings/locales fail closed. The legacy release/checkpoint format is intentionally unchanged; these facts are a separate release-table-bound review, NOT an end-to-end latest-target policy lifecycle.

review_candidate_product_facts calls the existing full candidate identity review first. Actual historical copied metadata/SQLite hashes were reverified; output is reports/PRODUCT-CONFIG-FACTS-to-share.json. No candidate change; no profile inferred from live installation. Alias changes are flagged for replan review, not silently applied. CLI reads only explicit owned files, has byte caps, exclusively creates a new output and never fetches data. It has no writer/install authority.

## Independent code: useful evidence, NOT a substitute official policy
1. [battlenet.nix selected(), pinned](https://github.com/DzmingLi/battlenet.nix/blob/299cc257767f1f71d7439a4a50859ee761d759b7/tact.py): groups same-type selected tags with OR, combines categories with AND; an explicitly selected 0x4000 group also retains files untagged by all such tags; unspecified groups are not filtered. [Update orchestration](https://github.com/DzmingLi/battlenet.nix/blob/299cc257767f1f71d7439a4a50859ee761d759b7/update.nu) reads verified ProductConfig and regional extra_tags. However [wow.nix at this revision](https://github.com/DzmingLi/battlenet.nix/blob/299cc257767f1f71d7439a4a50859ee761d759b7/games/wow.nix) is release metadata only, NOT a completed WoW installation/defaults/official-client reference plan. Do not claim it proves an actual Retail install.
2. [steed install manifest selector](https://github.com/steed-rs/steed/blob/d9cee6562d6acb234686c0d8a4ab89a6d9243be6/crates/ngdp/src/tact/install.rs): ANDs each selected bitmap and loops `0..maximum_type`, excluding the highest type. With 0x4000 present that type is never filtered; without it the highest normal category can be skipped. This is a concrete reason NOT to copy the prototype as policy.
3. [TACT.Net type helper](https://github.com/wowdev/TACT.Net/blob/57618c47dc0cfef1bfc0e7585bf335ced7218389/TACT.Net/SystemFiles/Tags/TagTypeHelper.cs) names 0x4000 Alternate for its recent-build mapping, but names/build-range lookups do not specify complete installer behavior.

Our differential investigation translates these small algorithm semantics into owned offline models, not executed external programs. With the historical enUS text+speech profile the battlenet.nix model equals our candidate bitmap for both manifests. The steed model agrees on Install but differs on Download. A four-row synthetic two-locale counterexample shows why agreement for one language is not general semantics: paired clauses choose enUS/text + deDE/speech; same-type OR permits the cross-product; the AND/exclusive-max model chooses none. None of these facts identifies the correct official multi-locale policy by itself. Report values/conditions and immutable sources are in reports/INDEPENDENT-POLICY-SOURCES-to-share.json. Counts were independently checked with a per-ordinal implementation. No statistical chart was warranted for software identity assertions and this Boolean counterexample.

Profiling the hierarchical ProductConfig JSON produces flattened sparse/null columns. These are structural artifacts of nested all/region/platform/locale sections, not missing file rows; no data was imputed/dropped. The typed structural parser validates actual section objects directly. Raw files remain immutable in the research workspace.

## Scope, progress and what genuinely remains
This resolves the previously missing **release-bound configuration facts**, not all of milestone 1. Still open: applicable complete feature/variant/dependency selection; freshly captured actual installation preferences; coherent active-generation proof; qualified required set/reuse/download bytes. No new user action is requested. Continue source-level research with concrete missing semantics; do not ask the user for an unspecified 'official plan' or more arbitrary uploads. A future official-client comparison, if necessary, must first be designed as a bounded test on an isolated copy, with explicit network/write/privacy scope and separate approval. No live capture tool is shipped in 0.24.
