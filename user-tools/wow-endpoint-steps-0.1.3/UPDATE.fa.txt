اصلاحیهٔ 0.1.3 — رفع اختلاف نام فایل آماده‌بودن پایشگر

نقص بازتولیدشده: عبارت ChangeExtension(path,$null) در PowerShell رسمیِ آزمایش‌شده یک نقطهٔ انتهایی باقی می‌گذاشت. افزودن .monitor-ready نامی با دو نقطه می‌ساخت، درحالی‌که Python نام یک‌نقطه‌ای را انتظار داشت. نام‌های stop/result نیز همین مشکل را داشتند. مسیر با GetDirectoryName + GetFileNameWithoutExtension بازسازی شد تا هر دو بخش دقیقاً یک نام داشته باشند. زمان انتظار صرفاً افزایش نیافته است.

آزمون واقعی با PowerShell رسمی روی Linux انجام شد: بازتولید عبارت قبلی، parse هر دو PS script، ساخت فایل آمادگی، دریافت stop از Python و نوشتن/خواندن JSON نتیجه. در آزمون هماهنگی، فقط منابع Windows یعنی Get-NetTCPConnection و Get-WinEvent mock بودند. این آزمون اجرای واقعی Windows Firewall/پایش شبکهٔ بازی نیست.

نصب:
۱. کنسول قبلی را ببندید. اگر مرحله‌ای فعال/ناموفق بوده و حذف هنوز تأیید نشده، تا پایان مهلت نگهبان صبر کنید و بعد Restore.cmd را اجرا کنید. گزارش قبلی کاربر برای هر دو تلاشِ شکست‌خورده rule_absence_verified=true داشت؛ برای تلاش‌های بعد از آن تضمینی از این گزارش نداریم.
۲. محتوای ZIP Update را مستقیماً روی همان پوشهٔ قبلی کنار Start.cmd استخراج و فایل‌ها را جایگزین کنید. runtime، private-state و output را حذف/جابه‌جا نکنید. بسته مستقل نیست و runtime قبلی را لازم دارد.
۳. Restore.cmd را با Administrator اجرا کنید و فقط پس از Verified: no rules from this package journals remain ادامه دهید. بازگشت رفتار عادی بازی را هم بررسی کنید؛ نبود قانون به‌تنهایی جای این بررسی نیست.
۴. Start.cmd را با Administrator اجرا و فقط اولین مقصد 3.124.215.108:443 را تست کنید. بعد از «آزمایش فعال»، بازی را عادی کامل ببندید و همان نصب را باز کنید؛ فقط یک بار برای ورود اقدام کنید. کادر بازگشایی را در صورت انجام تیک بزنید. رمز فقط داخل بازی وارد شود.
۵. پایش تا ۹۰ ثانیه است؛ اقدام را همان ابتدا شروع کنید. اگر دیرتر به محیط بازی رسیدید نتیجه را نامشخص بزنید. سپس نتیجه، حذف قانون و رفتار عادی را بررسی و JSON جدید endpoint-results را بفرستید. مرحلهٔ بعد را فعلاً شروع نکنید.

حدود قبلی پابرجا هستند: audit policy، hosts، VPN، وایت‌لیست، گواهی و تنظیم بازی تغییر نمی‌کنند. WFP فقط از رویدادهای موجود خوانده می‌شود. نبود رویداد دلیل قطع ترافیک نیست و قانون مسئول WFP مشخص نشده است. TLS/CPU/BIOS خوانده نمی‌شوند. نگهبان پنج‌دقیقه‌ای و journal بازیابی حفظ شده‌اند.

این نقص نام‌گذاری برطرف و handoff واقعی آزموده شده است؛ موفقیت خواندن شبکه/لاگ روی Windows کاربر هنوز تأیید نشده است. هیچ نیازی به غیرفعال‌کردن تنظیم امنیتی یا تغییر سیاست اجرای Windows نیست.
