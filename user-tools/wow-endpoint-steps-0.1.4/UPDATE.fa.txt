WoW Endpoint Steps 0.1.4 — تک‌مقصد یا گروه پنج‌تایی

اجرای Windows x64، با Administrator. Python همراه بسته است؛ نصب Python یا تغییر ExecutionPolicy لازم نیست.
ارتقا: ابتدا در ابزار قبلی توقف/بازیابی را بزنید و نبود قوانین را تأیید کنید. کنسول قبلی را ببندید. در صورت شک Restore.cmd همان پوشه را با Administrator اجرا کنید و تا تأیید حذف، ادامه ندهید. ZIP کامل جدید را در همان پوشه استخراج/جایگزین کنید؛ private-state و output را پاک یا جابه‌جا نکنید.

Start.cmd را با Run as administrator اجرا کنید. Wow.exe همان نصب بازی را انتخاب کنید. در بخش ۲، حالت «هم‌زمان: پنج مقصد تست‌شده» را انتخاب کنید. فهرست پنج مقصد نمایش داده می‌شود. رضایت گروهی را تیک بزنید و «پنج مقصد را محدود کن و شروع کن» را بزنید. ساخت قوانین ترتیبی است، نه اتمیک؛ فقط وقتی همه تأیید و پایش آماده شد، مرحلهٔ ۳ باز می‌شود. اگر ساخت یکی شکست بخورد، بازیابی همه درخواست می‌شود.

گروه ثابت، فقط TCP و خروجی همان Wow.exe انتخابی:

3.75.62.211:443
35.204.95.176:1119

37.244.29.11:3724 (ورود قبلاً مختل شد)، 37.244.62.60:3724 و تمام UDPها خارج گروه‌اند.

پس از نمایش مرحلهٔ ۳، بازی را عادی کامل ببندید و همان نصب را دوباره باز کنید. فقط یک بار برای ورود اقدام کنید؛ اگر خطای احراز هویت دیدید، تکرار نکنید و نتیجه/توقف را بزنید. پس از ورود به محیط، حدود ۳۰ ثانیه بررسی کنید. تیک اجرای تازه را فقط اگر واقعاً انجام دادید بزنید؛ نتیجه را انتخاب کنید. ابزار بازی یا حساب را کنترل نمی‌کند.

مهلت مشترک ۳۰۰ ثانیه از شروع آماده‌سازی است، نه ۵ دقیقه برای هر IP. برای هر قانون journal پیش از ساخت و نگهبان مستقل با همان deadline وجود دارد. صرف بستن مرورگر پایان تست نیست. قوانین PersistentStore ذاتاً زمان‌دار نیستند؛ نگهبان/ابزار باید حذفشان کنند. sleep، خاموشی یا خطای سیستم می‌تواند حذف را عقب بیندازد. تا تأیید نبود قوانین، پوشه را حذف نکنید. Restore.cmd مسیر دستی است. نگهبان یا حذف ناموفق یک عضو، ادامهٔ گروه را متوقف می‌کند.

توقف یا ثبت نتیجه، ابتدا مرز توقف پایش را علامت می‌زند، سپس برای حذف هر پنج عضو تلاش می‌کند، حتی اگر حذف یکی خطا دهد. جمع‌آوری نتیجهٔ پایش مانع آغاز حذف قوانین نیست. تا حذف همه تأیید نشود، گزارش موفقیت گروه و مرحلهٔ بعد نداریم و journalها می‌مانند. پس از حذف، عادی‌بودن بازی را جدا تأیید کنید.

در حالت گروهی یک پایشگر فقط‌خواندنی برای کل گروه تا پایان مهلت کار می‌کند؛ در حالت تک‌مقصد همان ۹۰ ثانیه حفظ شده است. خلاصهٔ هدف در پایش گروهی any_group_target یعنی یکی از پنج هدف است، نه نتیجهٔ جدا برای هر IP. صفر رویداد یا ندیدن سوکت اثبات مسدودسازی/نبود ترافیک نیست. WFP موجود می‌تواند تصمیم Windows برای block را نشان دهد ولی قانون مسئول را مشخص نمی‌کند. packet_block_verified و rule_causality_proven false می‌مانند. TCPهای کوتاه ممکن است دیده نشوند. محتوای TLS، CPU/BIOS و نقش CDN تشخیص داده نمی‌شوند.

فقط endpoint-results-….json و در صورت خطا firewall-error-….json از output را بفرستید؛ private-state را نفرستید. گزارش گروهی یک record با mode=group و endpoints دارد؛ آن را به پنج نتیجهٔ تک‌مقصد تبدیل نکنید. مسیر بازی و اطلاعات ورود در گزارش نیست. hosts، VPN، سایر قوانین فایروال، audit policy، گواهی و تنظیمات بازی دست‌نخورده‌اند.

۸۴ تست پاس شده‌اند؛ شامل rollback نیمه‌کاره، خطای حذف یک عضو، ادامهٔ تلاش حذف بقیه، نگهبان‌ها، رضایت، API و handoff واقعی PowerShell/Python روی Linux. APIهای Windows در تست‌ها شبیه‌سازی شده‌اند؛ گروه پنج‌تایی هنوز روی Windows واقعی/بازی توسط سازنده اجرا نشده است. runtime PowerShell QA وارد بسته نشده است.
