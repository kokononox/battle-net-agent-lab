# WLab Control 0.1.0

آزمون تشخیصی **فقط روی پردازش جدیدِ خود WLab**؛ این نسخه snapshot دیگری از بازی نمی‌گیرد. بازی لازم نیست باز باشد و می‌توانی آن را ببندی.

## چرا این آزمون؟

در تلاش Snapshot 0.1.5، فضای خروجی و آماده‌سازی درست بودند، اما ProcDump با `Target process no longer running` و `0x8007001D` شکست خورد. کاربر تأیید کرد بازی عادی ماند و `snapshot.dmp` وجود ندارد. بنابراین هیچ artifact قابل‌تحلیلی نداریم و تکرار همان تلاش روی بازی قدم مناسبی نیست.

این کنترل بررسی می‌کند آیا همان ابزار Microsoft و همان مسیر ذخیره روی یک هدف ساده نیز شکست می‌خورند یا نه. هیچ نتیجه‌ای از آن به‌تنهایی پشتیبانی از capture بازی، رفتار anti-cheat، سلامت کامل دیسک یا ارسال CPU/BIOS روی TCP/3724 را ثابت نمی‌کند.

## اجرا

1. ZIP را در پوشه‌ای تازه Extract کن و **WLab-Control-0.1.0.exe** را اجرا کن.
2. مسیر پیش‌فرض **G:\WLabControl** است؛ در صورت نیاز Browse را بزن و پوشه‌ای روی درایو دارای فضا انتخاب کن. هیچ بازگشت پنهانی به C وجود ندارد.
3. شرایط Microsoft را با View EULA بخوان؛ در صورت پذیرش تیک بزن.
4. **Run control tests once** را فقط یک بار بزن. برنامه دو آزمونِ از پیش مشخص‌شده را پشت سر هم انجام می‌دهد؛ نه تلاش مجدد خودکار روی بازی.
5. پس از پایان، فقط **READY-TO-SEND.zip** را بفرست، حتی اگر خطا داشت. فایل‌های `.dmp` محلی را نفرست.

نیازی به نصب Python، debugger یا واردکردن PID نیست. خود WLab امضای ناشر تجاری ندارد. ابزار Microsoft به‌صورت مستقیم از Microsoft دریافت یا از cache دارای هش صحیح استفاده می‌شود؛ hash و امضای معتبر Microsoft پیش از اجرای آن الزام می‌شوند. فایل اجرایی Microsoft در این ZIP بازتوزیع نشده است. تنظیمات امنیتی/فایروال تغییر نمی‌کنند.

## دقیقاً چه می‌کند؟

- پوشهٔ timestampدار مستقل روی G یا پوشهٔ انتخاب‌شده ایجاد می‌کند. cache کوچک، قفل مشترک با Snapshot و لاگ شروع همچنان در LocalAppData هستند.
- فضای قابل‌استفادهٔ همان پوشه را از GetDiskFreeSpaceExW می‌خواند. حداقل ۱ GiB فقط برای این آزمونِ هدف کوچک است؛ حداقل ۸ GiB ابزار capture بازی تغییر نکرده است. کفایت همهٔ عملیات با یک عدد تضمین نمی‌شود.
- یک فایل ۱ MiB با CreateNew می‌نویسد، flush/readback/hash را می‌سنجد و همان فایل ساخته‌شده را حذف می‌کند. این آزمون سلامت کامل دیسک یا ظرفیت full dump را ثابت نمی‌کند.
- دو probe خروج 0/7 متعلق به WLab را برای کنترل ثبت خروج و لاگ اجرا می‌کند. خروج 7 در این آزمون عمدی است.
- یک **پردازش جدید WLab** با `--control-worker` می‌سازد. این فرایند ۲ MiB دادهٔ آزمایشی را در حافظه نگه می‌دارد و پس از ۱۵۰ ثانیه خودبه‌خود خارج می‌شود؛ ممکن است در پایان آزمون زودتر توسط والد خودش بسته شود. مصرف کل runtime و اندازهٔ dump بزرگ‌تر از آن ۲ MiB است.
- PID فقط از Process.Start همان فرزند به دست می‌آید و با ready JSON آن تطبیق می‌یابد. هیچ کادر PID دلخواه یا انتخاب بازی وجود ندارد.
- آزمون اول: `-accepteula -ma -r 1 -n 1 -at 30 OWN_WORKER_PID control-clone.dmp`.
- آزمون دوم: `-accepteula -ma -n 1 -at 30 OWN_WORKER_PID control-direct.dmp`. این آزمون **بدون clone فقط روی فرزند خود WLab** انجام می‌شود و مجوز یا پیشنهادی برای attach مستقیم به بازی نیست. در این روش ProcDump می‌تواند هدف آزمایشی را موقتاً متوقف کند.
- هر آزمون timeout و لغو مستقل دارد؛ در توقف/timeout، ابتدا لغو مستند `-cancel` برای PID هدف **متعلق به همین آزمون** درخواست می‌شود. اگر لازم شود، فقط فرایندهای فرزند ایجادشده توسط این ابزار بسته می‌شوند؛ نه بازی، نه PowerShell یا ProcDumpهای از قبل موجود. اگر ProcDump دیگری از ابتدا فعال باشد، آزمون شروع نمی‌شود.
- وجود/اندازهٔ dump، ۳۲ بایت header، signature و bounds فهرست stream بررسی می‌شوند. این فقط بررسی ابتدایی است، نه parser کامل یا اثبات محتوای حافظهٔ بازی.
- لاگ اصلی ProcDump بدون تغییر حفظ و نسخهٔ decoded UTF-16LE آن نیز در گزارش گذاشته می‌شود. ZIP کوچک شامل dumpها نیست و هیچ آپلود خودکاری ندارد.

Dump حتی از فرایند خود ابزار ممکن است محیط اجرای آن را داشته باشد؛ آن را محلی نگه دار. این ابزار به حافظهٔ Wow دسترسی درخواست نمی‌کند، بازی را اجرا/بسته نمی‌کند، تزریق یا patch ندارد و از capture شکست‌خوردهٔ قبلی چیزی استخراج نمی‌کند.

## خواندن نتیجه

- **clone موفق روی هدف کنترل:** نشان می‌دهد این مسیر در همین شرایط برای هدف کنترل کار کرده؛ علت شکست قبلی روی بازی هنوز باید جدا بررسی شود.
- **clone شکست، direct موفق:** اختلاف را به مسیر clone/PSS در این آزمون محدودتر می‌کند؛ به‌تنهایی علت فنی یا راه‌حل بازی را ثابت نمی‌کند.
- **هر دو شکست:** باید خطاهای هر مرحله و write probe بررسی شوند؛ از این نتیجه به‌تنهایی نمی‌توان anti-cheat یا خرابی دیسک را مقصر دانست.
- **توقف پیش از capture کنترل:** گزارش مرحلهٔ آماده‌سازی/امضا/فضا مهم است؛ هیچ نتیجه‌ای دربارهٔ بازی نمی‌دهد.

## محدودیت آزمون سازنده

ساخت Windows x64 GUI، vet، آزمون‌های Go، parse پنج فایل PowerShell، پردازش‌های واقعی probe در Linux و fixtureهای header/encoding/write-probe بررسی شده‌اند. **Windows PowerShell 5.1، WinForms، PSS و ProcDump واقعی در محیط Linux ساخت اجرا نشده‌اند.** این بسته برای اولین آزمون کنترل روی Windows است، نه اعلام حل مشکل.

## منبع و بازسازی

منبع کامل در source است. با Go منطبق با PROVENANCE.json:

```sh
cd source
sh build.sh
```

آزمون helperها فقط برای توسعه‌دهنده به PowerShell/Python نیاز دارد؛ استفاده‌کنندهٔ Windows به نصب آن‌ها نیاز ندارد. بخش capture بازی، استخراج Wow و CLI `--extract` در این ابزار وجود ندارند. main مخزن و GUI BIOS Path 0.2 تغییر نکرده‌اند.

منبع رسمی سازوکار clone و لغو ProcDump: https://learn.microsoft.com/en-us/sysinternals/downloads/procdump
