نسخهٔ آزمایشی 0.1.8 — شروع اتصال با Enter پس از صفحهٔ ورود

این پچ رفع قطعی ProcessNotRespondingError نیست؛ فقط اتصال هنگام بارگذاری اولیه را کنار می‌گذارد.
هیچ کنترل دسترسی یا ضدتقلبی دور زده نمی‌شود و زمان/روش پایهٔ تزریق تغییر نکرده است.

پچ تجمعی را داخل پوشهٔ اصلی Content Check، کنار runtime و Start.cmd استخراج و Replace کنید.
بستهٔ کامل قبلی با runtime لازم است. پچ‌های 0.1.1 تا 0.1.7 پشتیبانی می‌شوند.

اجرای ساده:
1) بازی می‌تواند از قبل باز باشد و در صفحهٔ ورود بماند؛ برای این تست نیازی به واردکردن نام کاربری/رمز نیست.
2) Start-Game-Content.cmd را با Run as administrator اجرا کنید.
3) EXE واقعی همان بازی (_retail_\Wow.exe) را انتخاب کنید و START بنویسید.
4) تأیید امضا و خودآزمایی را تمام کند. هنوز هیچ هوکی به بازی متصل نشده است.
5) اگر بازی بسته است خودتان بازش کنید؛ صبر کنید صفحهٔ ورود ثابت و پاسخ‌گو باشد.
6) وقتی پیام At stable login screen را دیدید، Enter بزنید. فقط از این لحظه تلاش اتصال به بازی شروع می‌شود.
   Q در همین مرحله بدون اتصال لغو می‌کند.
7) پس از READY حداکثر دو دقیقه ثبت می‌کند؛ Q پایان زودتر است. پایان ابزار بازی را نمی‌بندد.
8) game-content-....json داخل output را ارسال کنید.

محدودیت مهم: این روش ترافیک اولیهٔ اجرای بازی را پوشش نمی‌دهد؛ نبودن تله‌متری در گزارش، نبودن آن هنگام شروع بازی را ثابت نمی‌کند.
اگر دوباره ProcessNotRespondingError رخ دهد، مشکل صرفاً با تغییر زمان اتصال رفع نشده؛ همان گزارش مرحله/نوع خطا را نگه می‌دارد.
۶ آزمون ایستای ترتیب شروع/لغو و ۲۲ تست محتوایی محلی گذشت؛ اجرای واقعی این نسخه روی ویندوز تأیید نشده است.

چیزی که ثبت می‌شود:
- فراخوانی نام‌ها در getaddrinfo/GetAddrInfoW و DnsQuery_A/W و هدف WinHttpConnect، در صورت استفادهٔ برنامه از آن مسیر.
- SNI قابل‌مشاهدهٔ ClientHello، اگر رکورد کامل در یک بافر Winsock مشاهده شود.
- Host درخواست HTTP/1 و، در صورت شواهد مستقیم، IP/پورت همان سوکت.
- ورودی قابل‌مشاهدهٔ EncryptMessage (SSPI)، به‌صورت بهترین تلاش؛ این به معنی پوشش همهٔ TLS نیست.
- روش درخواست، نام هدرهای شناخته‌شده، اندازه/کامل‌بودن بدنه، شکل JSON یا فرم و نام فیلدهای مجاز؛ مقادیر بدنه صادر نمی‌شوند.
- تطابق لفظی با مقادیر محلی CPU و نسخه/سازنده/تاریخ BIOS و مدل سیستم/برد، فقط برای دسته‌های واقعاً موجود.
- بررسی محدود پیشوند داده‌های send/WSASend و EncryptMessage برای همین نشانه‌ها، حتی اگر HTTP نباشند.

حریم خصوصی و تفسیر:
توکن، کوکی، Authorization، مقادیر بدنه، آدرس کامل URL و مقادیر واقعی سخت‌افزار در گزارش صادر نمی‌شوند.
نام دامنه، نام فایل انتخابی، SHA256 فایل و نام برخی فیلدهای JSON در گزارش می‌آیند. قبل از اشتراک آن را مرور کنید.
گزارش «شکل/فیلدهای محتوای قابل‌خواندن» است، نه دامپ کامل متن بسته‌ها.
مشاهدهٔ نام در یک فراخوانی DNS به‌تنهایی ثابت نمی‌کند کدام IP/سوکت از آن استفاده کرده است.
فقط SNI/سوکت یا Host/سوکت با شواهد مستقیم به‌عنوان اتصال دامنه به IP ثبت می‌شوند.
SNI ممکن است با ECH فقط نام بیرونی باشد؛ رکورد شکسته/چندبافری ممکن است دیده نشود.
نام هدف WinHttpConnect هم بدون اتصال مستقیم به سوکت برچسب می‌خورد، نه اثبات اتصال به یک IP.
دیدن نام فیلد cpu/bios با دیدن مقدار واقعی محلی تفاوت دارد؛ تطابق لفظی هم لزوماً شناسهٔ یکتا نیست.
مقادیر کوتاه، مانند تاریخ BIOS، ممکن است تطابق اتفاقی داشته باشند و باید با بافت بررسی شوند.
دیدن ورودی API، به‌خصوص پیش از بازگشت، اثبات ارسال روی شبکه یا دریافت سرور نیست.

محدودیت‌ها:
فقط فایل انتخابی و فرزندانِ واقعاً مشاهده‌شده با امضای معتبر Blizzard بررسی می‌شوند.
پردازش‌های والد، Agent/سرویس ازقبل‌باز و فرزندان کوتاه‌عمرِ دیده‌نشده ممکن است پوشش داده نشوند.
اتصال به پردازش پس از شروع آن است؛ اولین درخواست‌ها ممکن است قبل از اتصال هوک ارسال شوند.
رمزگشایی عمومی TLS، OpenSSL/BoringSSL داخلی، پروتکل اختصاصی بازی، HTTP/2 و UDP/QUIC انجام نمی‌شود.
TLS خصوصی یا رمزگذاری/کدگذاری/هش‌شدن داخل برنامه می‌تواند داده را ناخوانا کند؛ عدم تطابق به معنی عدم ارسال نیست.
حداکثر پیشوند هر ورودی 16KiB است. بافر بازسازی HTTP و بودجهٔ بررسی پیشوندها هرکدام محدودند؛ محدودیت‌ها گزارش می‌شوند.
گزارش هیچ نتیجهٔ «فقط دانلود/هیچ مشخصاتی ارسال نشد/بدون نشتی» صادر نمی‌کند.
هیچ فایل ضدتقلب، کنترل امنیتی یا نتیجهٔ اعتماد دور زده نمی‌شود؛ اگر امضا یا دسترسی رد شد، ابزار متوقف می‌شود.
هیچ قانون شبکه، DNS، گواهی، پروکسی یا تنظیم TLS تغییر نمی‌کند. خود مشاهده‌گر DNS آنلاین درخواست نمی‌کند.
تأیید امضای ویندوز ممکن است برای بررسی گواهی به شبکه مراجعه کند.
خودآزمایی فقط یک پردازش متعلق به ابزار را روی loopback اجرا می‌کند؛ مثبتِ TLS/SSPI واقعی نیست.
امکان نمونه‌برداری حافظه توسط سیستم‌عامل/صفحه‌بندی وجود دارد؛ پاک‌سازی تضمین‌شدهٔ RAM ادعا نمی‌شود.

حالت‌های قبلی:
Start-Launcher.cmd همچنان مقصدخوان بدون تزریق است.
Start.cmd همچنان Content Check قدیمیِ مخصوص وایت‌لیست Level3 است.
برای این تست فقط Start-Game-Content.cmd را اجرا کنید؛ نیاز به Apply کردن وایت‌لیست نیست.

آزمون‌های سازنده:
22 تست محلی محتوایی + 28 تست رگرسیون پایتون و 40 بررسی mock جاوااسکریپت گذشت.
پنجرهٔ انتخاب فایل، تزریق واقعی و مسیرهای دامنه/SSPI روی ویندوز توسط سازنده آزمایش نشده‌اند.
خودآزمایی زمان اجرا تلاش می‌کند HTTP/نشانه‌های سخت‌افزاری و SNI ساختگی را روی loopback تأیید کند؛ در صورت شکست متوقف می‌شود.
