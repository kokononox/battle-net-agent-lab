# بررسی محتوای خروجی Level3 — نسخهٔ آزمایشی 0.1.3

هدف: بررسی یک نمونهٔ کوتاه از درخواست‌های خروجی آپدیتر رسمی WoW Retail، در وضعیت وایت‌لیست فعلی. این بسته مستقل و همراه Python/Frida قابل‌حمل است؛ Python نصب نمی‌کند و اینترنت برای نصب وابستگی لازم نیست. حدود ۶۵ مگابایت فشرده و حدود ۱۷۵ مگابایت پس از استخراج است.

## اجرای کوتاه

۱. فقط روی همان ویندوز آزمایشی اجرا کنید، نه هم‌زمان روی ۲۵ سیستم. VPN SSTP وصل و وایت‌لیست نسخهٔ 0.1.x در حالت Apply باشد. ابزار وایت‌لیست و همهٔ مشاهده‌گرهای قبلی بسته باشند. این ابزار هیچ Restore یا Apply انجام نمی‌دهد.
۲. WoW را بسته نگه دارید؛ آپدیت را Pause، آپدیت خودکار را خاموش و Battle.net را از کنار ساعت کامل Exit کنید. اگر Agent باقی مانده، تا بسته‌شدنش صبر کنید. ابزار هیچ فرایند Blizzard را نمی‌بندد. اگر بکاپ لازم ندارید/ندارید، قبل از تأیید اجرای آپدیت ریسک تغییر فایل‌ها را بررسی کنید.
۳. ZIP را کامل در پوشه‌ای تازه و محلی Extract کنید. روی Start.cmd راست‌کلیک → Run as administrator. ویندوز x64، Windows PowerShell 5.1 و کامپایلر داخلی .NET Framework لازم است. اگر ابزار یا حفاظت Windows خطا داد، حفاظت یا بررسی گواهی را خاموش نکنید؛ گزارش خطا را ارسال کنید.
۴. برای پذیرفتن مشاهده، START تایپ کنید. ابتدا وضعیت ذخیره‌شدهٔ وایت‌لیست، قواعد متعلق به آن در PersistentStore/ActiveStore، اتصال SSTP و یک آزمایش داخلی روی loopback بررسی می‌شود. این تست TLS را به‌طور کامل آزمایش نمی‌کند. اگر STOP دیدید برای دورزدن آن Resume نکنید.
۵. وقتی ابزار خواست، Battle.net را دستی باز کنید؛ تا READY آپدیت را Resume نکنید. اگر بدون ورود به حساب آپدیت ممکن است، signed out بمانید. بعد از READY، خودتان Resume کنید و به پنجره ابزار برگردید و Enter بزنید.
۶. حدود ۶۰ ثانیه کافی است. ابتدا خودتان آپدیت را Pause کنید، بعد در پنجرهٔ ابزار Q بزنید. مهلت ۱۲۰ ثانیه از علامت دستی Enter شروع می‌شود و فقط مشاهده را متوقف می‌کند؛ دانلود را Pause نمی‌کند. پس از توقف، وضعیت Paused/Finished/Error را پاسخ دهید.
۷. فقط فایل output/content-result-....json را ارسال کنید. هیچ ارسال خودکاری وجود ندارد. بعد از تست Battle.net را کامل Exit کنید؛ بازی را هنگام اتصال hook اجرا نکنید. وایت‌لیست قبلی دست‌نخورده باقی می‌ماند.

## چه چیزی بررسی می‌شود؟

- امضای معتبر و ناشر Blizzard، هویت PID و فایل اجرایی پیش از attach. بررسی امضا با سیاست revocation قبلی حفظ شده و ممکن است سرویس‌های گواهی را از طریق شبکه فراخوانی کند. ابزار DNS آنلاین برای Level3 اجرا نمی‌کند و DNS/hosts/VPN/فایروال/TLS را تغییر نمی‌دهد.
- فقط send و WSASend و ورودی پیش از TLS در EncryptMessage؛ attach-only بدون spawn/resume/terminate برای فرایندهای Blizzard. تزریق حتی وقتی فقط می‌خواند، ممکن است روی پایداری و زمان‌بندی اثر بگذارد.
- بازسازی محدود HTTP/1 در RAM: method، hostname، طبقهٔ مسیر، نام‌های شناخته‌شدهٔ هدر/فیلد، اندازه/کامل‌بودن بدنه و وجود Cookie/Authorization. مقدار هدر، بدنه، query، URL کامل، هش محتوای درخواست و کلید TLS در گزارش نیست.
- برای HTTP ساده، getpeername همان socket alias برای IP/port واقعی مقصد ثبت می‌شود. این به معنی اثبات مالکیت دامنه یا دریافت سمت سرور نیست. اتصال دارای IP/port نامشخص، تغییر مبهم alias یا SSPI به IP نسبت داده نمی‌شود.
- در send/WSASend شمارش محدود فراخوانی/اندازهٔ ورودی/پذیرش محلی API حتی برای دادهٔ غیرقابل‌خواندن نگهداری می‌شود، بدون صادرکردن ciphertext. موفقیت API با دریافت سرور فرق دارد. پذیرش asynchronous نامعلوم، نامعلوم می‌ماند.
- نام CPU و در صورت موجودبودن BIOS version/vendor/date، مدل/سازنده سیستم و مدل برد، از رجیستری فقط برای تطبیق محلی خوانده می‌شوند. مقادیر واقعی صادر نمی‌شوند. رشته‌های خیلی کوتاه یا placeholder کنار گذاشته می‌شوند؛ BIOS serial، GPU/RAM واقعی و تمام شناسه‌های دیگر استخراج نمی‌شوند. دسته‌های مرجع موجود در گزارش می‌آیند. نام فیلد به‌تنهایی اثبات مقدار نیست؛ رشتهٔ مدل/سازندهٔ مشترک یا تاریخ BIOS هم به‌تنهایی ثابت نمی‌کند دستگاه منشأ آن بوده است.
- جست‌وجوی literal روی نمونهٔ محدود raw، UTF-8/UTF-16LE و URL-decoded و gzip/deflate محدود انجام می‌شود. همهٔ encodingها، hashها یا schemaهای اختصاصی پوشش ندارند.

## نتیجه‌گیری مجاز

findings.target_finding یکی از این‌هاست:
- local_hardware_literal_observed: یک مقدار مرجع محلی در درخواست بازسازی‌شده پیدا شد؛ دستهٔ تطبیق را بررسی کنید، نه ادعای خودکار دریافت سرور.
- known_field_names_observed: نام فیلد شناخته‌شده دیده شد؛ لزوماً مقدار واقعی سخت‌افزار در آن نیست.
- no_known_markers_in_inspected_requests: در بخش بررسی‌شده نشانگر شناخته‌شده دیده نشد؛ به معنی «هیچ اطلاعاتی ارسال نشد» نیست.
- no_readable_target_requests: درخواست قابل‌خواندن برای Level3 پیدا نشد؛ نتیجهٔ امن/پاک صادر نمی‌شود.

target_requests_bound_to_allowed_ip تعداد درخواست‌هایی است که هم Host برابر Level3 داشتند و هم به IP ذخیره‌شدهٔ مجاز نسبت داده شدند. hostname و IP مشترک CDN انحصاری نیستند. وایت‌لیست IP هویت hostname را تضمین نمی‌کند. تنظیمات باید دقیقاً تنها دامنهٔ level3.blizzard.com داشته باشد؛ IPهای دستی عمومی نیز در نسخهٔ 0.1.3 پذیرفته و جدا علامت‌گذاری می‌شوند، مشروط به اینکه تنظیمات با ژورنال فعال و متمم آدرس‌های قواعد فایروال تطابق داشته باشد. هیچ IP دستی حذف یا اضافه نمی‌شود. تعلق IP دستی به دامنه تأیید نشده است.

coverage_verdict همواره incomplete_no_global_privacy_verdict است. HTTP2/QUIC/UDP، TLS اختصاصی/CEF و همهٔ برنامه‌ها/رابط‌ها پوشش کامل ندارند. pre-TLS SSPI به مقصد شبکه bind نشده و local_api_success فقط موفقیت محلی است. شروع برنامه پیش از attach و اتصال‌های کوتاه ممکن است از دست بروند. همزمانی و reuse context هم محدودیت دارد. رویدادهای startup و بعد از علامت دستی Resume برای شمارش پایه جدا هستند؛ درخواست بازسازی‌شده برچسب دقیق لحظهٔ Resume ندارد.

قواعد انتخاب‌شده و هویت SSTP ابتدا/انتها خوانده می‌شوند، نه پیوسته. این نه تست نشتی همهٔ سیستم است و نه تضمین بیرون VPN. خروجی مشاهده‌گر نشان نمی‌دهد همهٔ Allowهای دیگر یا مسیرهای IPv6 امن هستند. مقایسهٔ دو snapshot نبود تغییر موقت را ثابت نمی‌کند.

## محدودیت‌های اجرایی و حریم خصوصی

- مشاهده پس از وقوع فراخوانی جلوی اولین افشای اطلاعات را نمی‌گیرد. این ابزار فایروال محتوایی نیست؛ اگر افشای حتی آزمایشی قابل‌قبول نیست، START نکنید.
- حدود نمونه: ورودی تا ۱۶KiB، RAM خام تا ۳۲MiB/۳۲۷۶۸ رخداد، stream تا۲۵۶KiB و۶۴ درخواست، خروجی تا۲۰۴۸ درخواست. gap/cap/خطاها باید در تحلیل لحاظ شوند. parser بعد از دادهٔ خراب resync نمی‌کند و نبود داده را پاک تلقی نمی‌کند.
- raw در فایل گزارش ذخیره نمی‌شود، اما پاک‌سازی قطعی حافظه/paging/crash dump سیستم‌عامل تضمین نمی‌شود. گزارش هنوز حاوی hostnameهای مشاهده‌شده، IPهای عمومی مقصد، PID، هش فایل اجرایی و نشانگر هش‌شدهٔ نشست SSTP است؛ قبل از انتشار عمومی بازبینی شود.
- هیچ سرویس، Scheduled Task، certificate، proxy، درایور شبکه یا جزء دائمی نصب نمی‌شود. hookها در پایان تلاش می‌کنند unload/detach شوند. وضعیت توقف thread در گزارش ثبت می‌شود. برای پایان روشن آزمایش Battle.net را دستی Exit کنید.
- فایل AuthVerify.exe هنگام اجرا از سورس همراه در پوشهٔ همین ابزار کامپایل می‌شود؛ فایل اجرایی Blizzard دست‌کاری نمی‌شود. فقط worker آزمایشیِ متعلق به ابزار در صورت گیرکردن ممکن است terminate شود، نه فرایند Blizzard.

## آزمون و منشأ

هسته از مخزن kokononox/battle-net-agent-lab، commit 7eacb50b04ffe4676ff85a8c37df9f5e03d1a97e، مسیر level3-request-audit-t1/app گرفته شده و کنترل BAT/DNS/hosts قدیمی وارد این بسته نشده است. کنترل خواندنی SSTP از نسخهٔ فعلی Sstp-Whitelist 0.1.2 در همین گفتگو بازاستفاده شده است. سورس قابل‌بررسی همراه بسته است؛ این فایل‌ها در GitHub push نشده‌اند و CI اجرا نشده است.

آزمون‌های انجام‌شده در Linux: ۲۸ آزمون Python، ۲۸ assertion شبیه‌سازی hook با Node، syntax Python/JavaScript/PowerShell، compile کد C# Authenticode روی .NET موجود. این‌ها تأیید اجرای بومی ویندوز، Agent واقعی یا TLS واقعی نیستند. تست داخلی Windows در زمان اجرا روی worker loopback انجام می‌شود؛ SSPI/TLS مثبت واقعی در آن تأیید نمی‌شود. قبل از دریافت نتیجهٔ دستگاه آزمایشی، برای ۲۵ سیستم توصیه نمی‌شود.

هش‌های PyPI برای wheelها تطبیق داده شده‌اند. Python embedded از HTTPS رسمی دریافت شده؛ امضای ناشر آن در این محیط Linux تأیید نشده است. MANIFEST برای کشف خرابی فایل است، امضای دیجیتال بسته نیست. به جای خاموش‌کردن حفاظت Windows، در صورت خطا توقف کنید.

## اصلاح 0.1.1

انتقال آرایهٔ نام قواعد به Windows PowerShell اکنون Base64 است تا نقل‌قول JSON در مرز فرایند از دست نرود. گزارش قبلی فقط effective_policy_read_failed داشت؛ علت دقیق آن از آن گزارش معلوم نبود و خطای نقل‌قول یک علت محتمل است، نه تشخیص قطعی. خطای جدید شامل مرحله، نوع exception، HResult و دستهٔ خطاست، بدون پیام خام یا مسیرهای شخصی. شروط فایروال/هویت SSTP و hookها ضعیف یا حذف نشده‌اند. ابزار هنوز آزمایشی و فاقد تأیید بومی Windows در محیط سازنده است.

## اصلاح 0.1.2 — سازگاری Windows PowerShell 5.1

گزارش کاربر argument_count_invalid در decode_rule_names بود. Windows PowerShell 5.1 آرایهٔ خروجی ConvertFrom-Json را در pipeline یک شیء می‌فرستد؛ @(...pipeline...) آرایهٔ تودرتوی یک‌عضوی ایجاد می‌کرد. تخصیص مستقیم خروجی ConvertFrom-Json بدون wrapper، با بررسی صریح نوع array و شمارش و اعتبارسنجی هر سه نام، جایگزین شد. هیچ پیش‌شرط شبکه یا فایروال حذف نشده است. اجرای اول گزارش کاربر run_start_as_administrator بود و اجرای دوم از آن مرحله عبور کرده بود. این اصلاح هنوز روی ویندوز کاربر تأیید نشده است.

## اصلاح 0.1.3 — IPهای دستی موجود

رد شدن تنظیمات با IP دستی محدودیت خود مشاهده‌گر بود، نه اثبات ایراد وایت‌لیست. IPهای صریح عمومی اکنون پذیرفته می‌شوند؛ نوع، قالب، تعداد، تکراری‌نبودن و عضویت در snapshot فعال کنترل می‌شود. هش تنظیمات از همین آرایهٔ واقعی بازسازی و با ژورنال مقایسه می‌شود؛ اختلاف تنظیمات ذخیره‌شده و Apply قبلی همچنان موجب توقف است. تطبیق قواعد PersistentStore/ActiveStore با متمم تمام IPهای فعال حذف نشده است. configured_manual_ips و peer_in_configured_manual_ips منشأ تنظیماتی را نشان می‌دهند، نه مالکیت دامنه یا اثبات امن‌بودن مقصد. هیچ DNS تازه‌ای انجام نمی‌شود و تنظیمات تغییری نمی‌کند.
