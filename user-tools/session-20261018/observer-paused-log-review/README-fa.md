# بررسی محدود لاگِ اجرای متوقف‌شده

**آپدیت را روی Pause نگه دارید.** این ابزار Update، Resume، Repair، ورود حساب یا بازیابی انجام نمی‌دهد. بازی، CASC و پوشهٔ اکسترنال خوانده یا تغییر داده نمی‌شوند. هدف فقط استفاده از لاگ‌های باقی‌ماندهٔ همان اجرای قبلی است؛ آپدیت را تکرار نکنید.

## اجرا
1. بسته را کامل در پوشه‌ای تازه، بیرون از بازی و Lab استخراج کنید. با بسته‌های دیگر مخلوط نکنید.
2. فقط RUN-PAUSED-REVIEW.cmd را اجرا کنید؛ Python و Administrator لازم نیست. مسیر بازی یا رمز نمی‌پرسد.
3. پس از پایان، فقط Results/run-…/PAUSED-REVIEW-to-share.json را پس از بازبینی بفرستید؛ نه فایل‌های لاگ خام.
4. اگر ابزار خطا داد، هیچ سیاست امنیتی یا دسترسی را تغییر ندهید؛ پیام کوتاه را بفرستید. اگر گزارش خالی/بدون تطبیق بود، بدون بررسی علت دوباره اجرا نکنید.

اگرچه برای تست جدید لازم نیست Battle.net را ببندید یا باز کنید، این ابزار مانع نوشتن یا چرخش لاگ توسط Battle.net هم نیست. نسخهٔ مرجع اکسترنال همچنان جدا بماند. تغییر وضعیت Pause را از این ابزار انتظار نداشته باشید.

## دقیقاً چه می‌خواند؟
- فقط فایل‌های .log در پوشه‌های مشخص Logsِ Battle.net/Agent/Blizzard؛ همان resolver محدود نسخهٔ ۱٫۲، بدون جست‌وجوی کش‌ها یا بازی.
- حداکثر ۳۲ فایل با آخرین تغییر از ۲ دقیقه قبلِ شروع اجرای قبلی به بعد، به ترتیب آخرین تغییر.
- حداکثر ۱ MiB از انتهای هر فایل، و سقف کل ۸ MiB شامل probe مربوط به BOM. فایل بزرگ‌تر کامل خوانده نمی‌شود.
- بازهٔ زمانی مورد بررسی ثابت است: **2026-10-18 17:44:36.1659425Z تا 17:52:27.1659425Z**؛ از گزارش قبلی آمده و زمان پاسخ‌دادن به منوها را هم شامل می‌شود، نه زمان دقیق کلیک Update/Pause.
- این بار بررسی بخش کوچکی از لاگ تاریخی صریحاً لازم است؛ مثل observer قبلی فقط append نیست. بازی/CASC خوانده نمی‌شوند.

## چه چیزی صادر می‌شود؟
فقط شمارنده‌ها، نام‌های مستعار مثل log_01، نوع مسیر Agent/Client، اندازه‌های خواندن، زمان‌های قابل تشخیص، برچسب ثابت کلیدواژه و تعداد محدودی کدِ مطابق الگوی BLZ. متن کامل یا تکه‌ای از خط، نام فایل، مسیر نصب/شخصی، ایمیل، token/cookie یا مقادیر عمومی فیلدها صادر نمی‌شوند. بررسی منفی خروجی با token، ایمیل و مسیر ساختگی انجام شده است؛ این ابزار سیاست sandbox در برابر تغییر مسیر توسط فرایند مهاجم نیست.

کلیدواژهٔ initialization به‌تنهایی به معنی مرحلهٔ Initializing بازی نیست؛ ممکن است initialization داخلیِ یک جزء، محصول دیگر یا فعالیت پس‌زمینه باشد. wow_literal نیز فقط وجود واژهٔ wow در همان خط است و انتساب قطعی عملیات را اثبات نمی‌کند. کدِ مطابق الگو هم فقط سرنخ است، نه خطای تأییدشده.

Timestamp باید تاریخ کاملِ شبیه ISO در ۹۶ نویسهٔ اول خط داشته باشد. زمانِ دارای offset صریح مستقیماً تبدیل می‌شود. بدون offset، تفسیر UTC و timezone محلی سیستم بررسی می‌شود و تنها تطبیق یکتای بازه نگه داشته می‌شود؛ این **فرض زمان‌بندی** است، نه اثبات timezone. زمان نامفهوم/مبهم به همان اجرا نسبت داده نمی‌شود. خط‌های بدون تاریخ کامل، قالب ناشناخته، چرخش لاگ یا tail محدود ممکن است شاهد لازم را از دست بدهند. صفر بودن نتیجه، نبود Initializing را ثابت نمی‌کند.

## ایمنی و تست
اسکریپت شبکه، آپلود، تغییر registry، توقف پردازش، تغییر بازی/اکسترنال، دانلود بازی یا فرمان محلی Agent ندارد. فقط گزارش تازه کنار خودش می‌نویسد. launcher از ExecutionPolicy Bypass فقط برای پردازش Windows PowerShell داخلی استفاده می‌کند؛ تنظیم دائمی عوض نمی‌شود. اگر سیستم سازمانی/امنیتی مانع است، آن را غیرفعال نکنید.

۱۰ تست پارسر/برچسب‌گذاری روی PowerShell 7.4.6 در Linux پاس شده‌اند. آزمون سرتاسری نیز با ریشه‌های ساختگی و مدل‌کردن guard سیستم‌عامل انجام شده است؛ **اجرای بومی Windows این ابزار جدید هنوز تأیید نشده**. نتایج از پیش‌ساخته در بسته قرار نگرفته‌اند تا با گزارش واقعی شما اشتباه نشوند.

این بسته ابزار بررسی شاهد است، **نه موتور اپدیتر و نه ادعای حل الگوریتم patch**. به داده‌های Lab، نسخهٔ مرجع و نصب نیمه‌آپدیت‌شده دست نمی‌زند.
