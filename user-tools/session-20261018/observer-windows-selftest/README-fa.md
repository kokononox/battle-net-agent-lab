# خودآزمایی ویندوز — بدون آپدیت و بدون دسترسی به بازی

این بسته فقط همان توابع اصلی خواندن نسخه/لاگِ Observer 1.2 را با فایل‌های ساختگی آزمایش می‌کند. هدف، تأیید IO روی ویندوز شماست، نه دریافت اطلاعات از بازی. بازی واقعی، G:، اکسترنال، لاگ واقعی Battle.net و Lab در این تست باز یا جست‌وجو نمی‌شوند. شبکه، حساب، registry، پردازش Battle.net و تنظیم‌های بازی تغییر نمی‌کنند.

## اجرا؛ فقط همین مرحله
1. Battle.net را در حالت توقف آپدیت نگه دارید. هنوز Update نزنید. نسخهٔ مرجع اکسترنال را با خروج ایمن جدا کنید.
2. ZIP را کامل در یک پوشهٔ تازه و قابل‌نوشتن، بیرون از بازی و Lab استخراج کنید؛ با نسخه‌های قبلی مخلوط نکنید.
3. فقط **RUN-SELFTEST.cmd** را اجرا کنید. فایل Core یا اسکریپت‌های دیگر را جداگانه اجرا نکنید.
4. ابزار خودکار تمام می‌شود؛ مسیر بازی نمی‌پرسد، Administrator نمی‌خواهد و روی ویندوز از مدل/جایگزین تست استفاده نمی‌کند.
5. فقط **SELFTEST-to-share.json** را از پوشهٔ تازهٔ SelfTest-Results/run-… بفرستید. لازم نیست فایل‌های ساختگی یا پوشهٔ بازی را بفرستید.

اگر SELFTEST PASSED دیدید هم هنوز Update نزنید. اگر STOPPED یا NOT PASSED دیدید، هیچ دسترسی/سیاست امنیتی را تغییر ندهید؛ گزارش ساخته‌شده یا آخرین پیام کوتاه بدون اطلاعات شخصی را بفرستید. اگر هیچ گزارشی ساخته نشد، تکرار مداوم نکنید.

launcher، Windows PowerShell داخلی را با ExecutionPolicy Bypass فقط برای همان پردازش اجرا می‌کند؛ تنظیم دائمی سیستم عوض نمی‌شود. اگر سیاست سازمانی یا ابزار امنیتی مانع است، آن را غیرفعال نکنید.

## چه چیزی آزمایش می‌شود؟
۱۶ بررسی: نسخهٔ ساختگی Retail و حذف فیلدهای اضافی، دست‌نخوردن فایل ساختگی، نخواندن تاریخچهٔ لاگ، خواندن افزودهٔ واقعی در فایل ساختگی، رفتار شناخته‌شدهٔ حذف خط اول، خط ناقص و تکمیل آن، خواندن با handle نویسندهٔ باز، truncate، UTF-16، محدودیت طول خط، سقف خواندن، حذف متن و مسیر ساختگی از گزارش، ذخیره و بازخوانی JSON و نبود خطاهای IO در همین fixture.

گزارش خواندن همزمان به معنی شبیه‌سازی کامل زمان‌بندی Battle.net نیست؛ نویسنده در تست handle را باز نگه می‌دارد و داده flush می‌شود، نه اینکه رفتار واقعی تمام پردازش‌های vendor بازسازی شود. آزمون سقف از شمارندهٔ ساختگی استفاده می‌کند؛ دانلود یا خواندن ۳۲ MiB واقعی لازم نیست.

## مرز مهم نتیجه
قبولی این تست فقط کارکرد محدود توابع روی فایل‌های ساختگی ویندوز است. تضمینِ لاگ واقعی، پوشش همهٔ مراحل آپدیت، rotation بدون فقدان، ثبت crash-safe، الگوریتم کامل patch، صحت نصب یا Rollback نیست.

هستهٔ فعلی محدودیت شناخته‌شده دارد: اولین خط پس از baseline غیرخالی را کنار می‌گذارد؛ شمارندهٔ واژه، گزارش رویداد کامل نیست؛ گزارش اصلی تنها در توقف عادی ذخیره می‌شود و بستن ناگهانی پنجره ممکن است آن را از دست بدهد. این‌ها نباید زیر عبارت READY یا PASSED پنهان شوند.

بعد از این تست، گام بعد صرفاً آزمون غیرفعالِ نوشتن لاگ واقعی بدون Update و تعیین هدف/شواهد موردنیاز خواهد بود. برای آزمایش تغییر نصب، کپی کامل و مستقل اکسترنال باید محفوظ باشد و بازیابی مستلزم کپی مجدد است، نه Rollback نرم‌افزاری.

## حریم خصوصی و بازتولید
خودآزمایی هیچ خروجی خام لاگ واقعی، مسیر بازی یا مشخصات حساب ندارد. فقط نتیجهٔ بررسی‌ها، نسخهٔ PowerShell، نوع محیط و SHA-256 هسته صادر می‌شود. فایل‌ها فقط در پوشهٔ تازهٔ نتایج کنار همین بسته ساخته می‌شوند و حذف خودکار هیچ فایل کاربر انجام نمی‌شود.

برای توسعه در محیط دستیار، تست روی Linux/PowerShell 7.4.6 با مدل صریح CreationTime اجرا شده است؛ مدل فقط تفاوت ctime لینوکس با CreationTime پایدار ویندوز را پوشش می‌دهد. این، اجرای بومی ویندوز نیست. گزینهٔ مدل در ویندوز رد می‌شود. تست واقعی ویندوز باید از launcher و بدون هیچ گزینهٔ اضافی اجرا شود.
