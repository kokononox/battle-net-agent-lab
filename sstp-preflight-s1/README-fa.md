# S1 — پیش‌بررسی فقط‌خواندنی ایزولاسیون SSTP و Level3

هدف انتخاب‌شده: **کل Windows**، VPN داخلی Windows با نام دقیق `holand`. این بسته **ایزولاسیون را فعال نمی‌کند**؛ قبل از نوشتن هر rule و آماده‌سازی بازیابی محلی، وضعیت واقعی را جمع می‌کند.

## اجرا
1. بسته را در یک پوشه تازه Extract کنید؛ به Python یا بسته‌های T1/N1 نیاز ندارد.
2. WoW بسته، دانلود بازی Pause و automatic updates خاموش بماند. اگر VPN الان وصل است، وضعیت فعلی را نگه دارید؛ ابزار آن را قطع/وصل نمی‌کند. اسکریپت‌های Enable/Disable/EmergencyReset موجود را برای این مرحله اجرا نکنید.
3. `Start-Preflight.cmd` را با Run as administrator اجرا کنید. این نسخه فقط پروفایل `holand` را از user/all-user می‌جوید؛ اگر دو پروفایل هم‌نام باشد، خودسرانه انتخاب نمی‌کند.
4. فایل `output/sstp-preflight-....json` را بفرستید. هیچ دستور Resume یا تغییر فایروال صادر نمی‌شود؛ در STOP متن خطا را بفرستید.

IP را لازم نیست دستی وارد کنید؛ آدرس از خود پروفایل و IPهای snapshot DNS خوانده می‌شود و با اتصال‌های احتمالی سرویس SSTP مقایسه می‌شود. تطابق IP یک سرویس اشتراکی svchost، اثبات اختصاصی binding به این پروفایل نیست. پورت443 برای SSTP پیش‌فرض است مگر آدرس صریح پورت داشته باشد؛ اتصال زنده باید جدا کنترل شود.

## داده‌های خوانده‌شده
- فقط metadata انتخاب‌شدهٔ پروفایل `holand`، بدون username/password/PSK یا certificate/private key.
- DNS آدرس VPN و `level3.blizzard.com`؛ **این lookupها ممکن است به resolver فعلی درخواست شبکه بفرستند**. صرف snapshot است، نه فهرست دائمی همه IPهای CDN.
- رابط هم‌نام VPN، default routeها و نتیجه Find-NetRoute به مقصدهای مربوط؛ IP محلی، NextHop واقعی، MAC، SSID و نام رابط‌های نامرتبط صادر نمی‌شوند.
- وضعیت ActiveStore فایروال، شمار قوانین outbound فعال و نوع منبع آن‌ها (Local/GPO/...)؛ نام/مسیر/آدرس قوانین نامرتبط صادر نمی‌شود.
- metadata محدود قوانین فعال گروه `SSTP Kill Switch` برای دیدن اجازهٔ RemoteAccess/DNS و مقصد Any؛ **فایل وضعیت خصوصی Kill Switch خوانده یا منتشر نمی‌شود**، فقط وجودش بررسی می‌شود.
- وضعیت سرویس‌های SSTP/RAS/firewall/task scheduler و IP/port اتصال‌های کاندید سرویس SSTP. مقصدهای VPN و CDN داده شبکه‌اند؛ گزارش را پیش از اشتراک مرور کنید. هیچ چیز خودکار upload نمی‌شود.

## آنچه تغییر نمی‌کند
هیچ firewall/hosts/route/VPN/security setting تغییر نمی‌کند؛ task زمان‌بندی‌شده، بکاپ firewall یا ابزار بازیابی نیز هنوز ساخته نمی‌شود. تنها نوشته ابزار، گزارش JSON محلی است. خواندن سیاست با Administrator برای دسترسی کافی است، نه مجوز تغییر آن.

لانچر `ExecutionPolicy Bypass` را فقط برای همان فرایند PowerShell به‌کار می‌برد تا اسکریپت محلی اجرا شود؛ `Set-ExecutionPolicy` یا تغییر policy پایدار انجام نمی‌دهد. اگر سیاست سازمانی یا Windows Security مانع اجرا شد، آن را غیرفعال نکنید؛ خطا را بفرستید. از PowerShell خود ویندوز استفاده می‌شود، نه exeهای پیوست‌شده.

## حدود و گام بعد
- بررسی قواعد فعال موجود مهم است؛ DefaultOutboundAction=Block به‌تنهایی Allowهای قبلی را خنثی نمی‌کند. Kill Switch فعلی اجازهٔ همه مقصدها روی RemoteAccess و DNS را دارد و معادل فقط‌Level3 نیست.
- محدودیت کل سیستم، مرورگر/چت و ارتباطات دیگر را هم قطع می‌کند؛ پیش از apply باید بازیابی مستقل محلی/زمان‌دار و وضعیت policy/GPO بررسی و آزمایش شوند. این گزارش همیشه `ready_to_apply_isolation=false` دارد.
- SSTP ممکن است برای reconnect یا اعتبارسنجی گواهی به DNS/OCSP/CRL نیاز داشته باشد. نیاز به آن‌ها هنوز معلوم نیست؛ TLS/revocation خاموش نمی‌شود. اگر حفظ «فقط دو دسته مقصد» مانع اتصال امن شود، باید تست متوقف/بازیابی شود، نه امنیت پایین آورده شود.
- IPv6 و interface/route و endpoint متغیر CDN باید صریح در طرح بعد لحاظ شوند. اطلاعات سنجیده‌شده، تضمین enforcement، نبود تله‌متری در مسیر مجاز یا نبود fingerprint فایل نیست.
- آزمون همراه، فقط parser و fixtureهای synthetic روی Windows است؛ از وجود receipt موفق، آزمون واقعی VPN/firewall کاربر یا اجرای isolation نتیجه نگیرید. منبع و hash در مخزن ثبت می‌شود؛ هیچ تغییر خودکار در مخزن SSTP انجام نشده است.
