# Destination Recon R1 — شناسایی مرحله اول بر پایه BAT 3

این بسته چند فایل BAT راه‌انداز دارد؛ خود BATها فهرست hosts را خام و بی‌بکاپ بازنویسی نمی‌کنند، بلکه ابزار همراه را با پروفایل ثابت اجرا می‌کنند. Python، کتابخانه و helper لازم داخل بسته‌اند. نصب Python لازم نیست.

**این مرحله بدون تزریق هوک، بدون رمزگشایی TLS و بدون ثبت payload است.** هدف: غربالگری وابستگی دانلود و شناسایی فرایندهای امضاشده/مقصدهای TCP باقی‌مانده. این گزارش محتوای آپلود یا «فقط آپدیت و هیچ تبادل دیگر» را اثبات نمی‌کند.

## کدام فایل را اول اجرا کنم؟
| BAT | نام‌های مسدود | کاربرد |
| --- | --- | --- |
| `01-Telemetry-Only.bat` | فقط telemetry-in.battle.net | مرجع محدود قبلی، اگر برای مقایسه لازم شد |
| **`02-BAT3-Corrected.bat`** | همان ۲۰ دامنه BAT 3، با حذف :443 نامعتبر از news | **اول این را اجرا کنید**؛ تکرار ادعای قبلی با نسخه اصلاح‌شده، بدون hook |
| `03-BAT3-Plus-OAuth.bat` | ۲۰ دامنه مبنا + oauth.battle.net | یک مقصد اضافه، مستقل از مراحل دیگر |
| `04-BAT3-Plus-Distribution.bat` | مبنا + distribution.version.battle.net | ممکن است شروع/آپدیت متوقف شود |
| `05-BAT3-Plus-US-Version.bat` | مبنا + us.version.battle.net | ممکن است شروع/آپدیت متوقف شود |
| `06-BAT3-Plus-Level3-TLS.bat` | مبنا + level3.ssl.blizzard.com | آزمون یک نام CDN؛ نه همه IPهای CDN |
| `07-BAT3-Plus-Level3.bat` | مبنا + level3.blizzard.com | آزمون یک نام CDN؛ نه همه راه‌های دانلود |

هر بار فقط **یک BAT** اجرا شود. نسخه‌ها انباشته نیستند. پس از گزارش ۰۲، پیش از اجرای همه نسخه‌ها نتیجه را بفرستید؛ اگر مبنای اصلاح‌شده کار نکند، مقایسه نسخه‌های بعدی معنی ندارد.

## مراحل
1. ZIP را در پوشه **جدید** استخراج کنید. WoW بسته، آپدیت خودکار بازی OFF، signed out، بکاپ قدیمی دست‌نخورده و دانلود Paused باشد. Battle.net را از tray کامل Exit کنید.
2. `02-BAT3-Corrected.bat` را با **Run as administrator** اجرا کنید. مسیر همان `G:\World of Warcraft` است. شرایط را واقعاً بررسی و `CONFIRM` سپس پس از دیدن دامنه‌های دقیق `BLOCK` بنویسید.
3. اگر پیام وجود ورودی قبلی/بازیابی دیدید، هیچ اسکریپت قدیمی ۳ یا ۴ را برای پاک‌سازی اجرا نکنید؛ پیام را بفرستید. ابزار ورودی‌های قبلی را خودکار حذف نمی‌کند.
4. فقط وقتی ابزار خواست، Battle.net را دستی باز کنید. تا `READY FOR NETWORK OBSERVATION ONLY` دانلود را Resume نکنید؛ در صورت نرسیدن READY همین نتیجه گزارش شود.
5. پس از READY می‌توانید دستی Resume کنید. پنجره مشاهده **۱۲۰ ثانیه از READY** است، نه لحظه کلیک. Q پایان زودتر مشاهده است. **پایان تایمر/Q آپدیت را Pause نمی‌کند.**
6. در پایان دستی Pause کنید، یا اگر دانلود واقعاً تمام شده Finished را گزارش کنید؛ وضعیت و پیشرفت/توقف را انتخاب کنید. سپس Battle.net را از tray کامل Exit کنید.
7. ابزار hosts را دقیقاً بازیابی و `output\recon-02-….json` می‌سازد. فقط همین JSON را بفرستید؛ `PRIVATE-RECOVERY` را نفرستید. اگر restore موفق نبود journal را پاک نکنید.
8. ادامه با BAT بعدی فقط پس از بسته‌بودن Battle.net/Agent/WoW و با همان پیش‌شرط‌هاست. هیچ پاک‌کردن/Repair/Cancel/rollback/کپی مجدد بازی لازم یا درخواست‌شده نیست. اگر دانلود تمام شد برای آزمون بیشتر آن را از اول شروع نکنید.

## نسبت با BAT 3/4 قبلی
- ۲۰ خط block واقعی BAT 3 مبناست؛ `www.google.com` در آن block نمی‌شد و اینجا هم نمی‌شود.
- `breaking-news.support.blizzard.com:443` در hosts معتبر نیست؛ اینجا نام خالص دامنه آمده، پس نتیجه قبلی لزوماً همین پروفایل جدید را پوشش نمی‌دهد.
- بکاپ قبلی overwrite نمی‌شود؛ فایل hosts بازنویسی انتخابی/پاک‌سازی نمی‌شود. journal خصوصی با original bytes و hashes ایجاد و فقط تغییر خود ابزار بازیابی می‌شود.
- هر ورودی قبلی مربوط به فهرست آزمایش، حتی خط قدیمی :443، باعث توقف بدون تغییر می‌شود. تغییر خارجی hosts را overwrite نمی‌کند.

## محدودیت‌های مهم
- این **denylist** است، نه allowlist. نام‌های ناشناخته، IP مستقیم، DoH، QUIC/UDP و fallback ممکن است خارج از آن باشند. resolve loopback به معنی قطع همه مسیرها نیست.
- hosts برای کل ویندوز است؛ بلوک سایت‌های Google/YouTube/فروشگاه می‌تواند برنامه‌های دیگر را هم موقتاً تحت تأثیر قرار دهد.
- بین مراحل restart دستی لازم است؛ تغییر hosts وسط اتصال باز نتیجه قابل اتکا نمی‌دهد. حتی restart حذف همه cacheهای واسط را تضمین نمی‌کند.
- گزارش شامل نام/هش و وضعیت امضای فرایندهای مشاهده‌شده و مقصدهای عمومی TCP با نمونه‌برداری نیم‌ثانیه‌ای است؛ تعداد نمونه، بایت دانلود/آپلود یا تعداد درخواست نیست. اتصال کوتاه ممکن است دیده نشود.
- هیچ URL/header/body/TLS key یا نام CPU در این مرحله جمع‌آوری نمی‌شود. مقدار حساس حساب لازم نیست. ترافیک رمز‌شده از روی مقصدش قابل تفسیر محتوایی نیست.
- signed Agent مشاهده‌شده اثبات نمی‌کند هر اتصالش برای آپدیت ضروری بوده است. IP به‌تنهایی Host یا نوع داده را ثابت نمی‌کند.
- نشانگر نسخه یا گفته Finished/Play به‌تنهایی صحت کامل نصب را ثابت نمی‌کند. اثر cache/پیشرفت فایل‌ها/اختلاف زمان بین پروفایل‌ها مانع نتیجه‌گیری قطعی است.
- ابزار خودش Battle.net/بازی را launch/kill/suspend/resume نمی‌کند، Update/Pause/Play/Login/Repair ندارد و فایل بازی را تغییر نمی‌دهد. خود updater همچنان می‌تواند فایل بازی را تغییر دهد؛ ابزار rollback آن را تضمین نمی‌کند.
- پس از restore موفق، **دیگر هیچ بلوک این ابزار فعال نیست**؛ اگر تستی ندارید Battle.net را کامل ببندید.
- بررسی امضا ممکن است با سرویس گواهی تماس بگیرد؛ بررسی resolver هم جدا از ترافیک Battle.net است. حفاظت گواهی/TLS/ضدتقلب تغییر نمی‌کند.

## بازیابی و مرحله بعد
پس از crash/power loss، `Restore-Hosts-Only.cmd` را با Administrator اجرا کنید؛ اگر تغییر خارجی وجود داشته باشد ابزار توقف و journal را حفظ می‌کند. دو بسته U1/U2/R1 همزمان اجرا نشوند؛ mutex مشترک دارند.

فایل‌های قدیمی Start-Monitor/Start-Scheduled در این بسته تحویل نمی‌شوند؛ کد مانیتور فقط برای gate ساخت/خودآزمایی همراه است. در آزمایش Recon، Frida استفاده نمی‌شود.

پس از شناسایی پروفایل قابل‌استفاده، مرحله جداگانه پایش محتوای پیش از رمزنگاری روی مقصدهای باقی‌مانده طراحی می‌شود. R1 هیچ ادعایی درباره محتوای آن مقصدها یا fingerprint فایل‌های A→B نمی‌کند.
