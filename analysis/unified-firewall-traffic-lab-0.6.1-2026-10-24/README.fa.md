# Unified Firewall 0.6.1 — آزمون اتصال واقعی دو EXE

این بسته مرحلهٔ بعد از SELFTEST موفق ۰٫۵٫۱ است؛ دوباره‌گرفتن همان گزارش قبلی لازم نیست. **هنوز انتشار نهایی امنیتی نیست، و حفاظت بیرون VPN / Kill-switch ندارد.** این مرحله فقط TCP مستقیم IPv4 را با دو فایل runtime خود بسته می‌سنجد، نه فایل‌های بازی.

## پیش‌نیاز ضروری: مقصد آزمون تحت کنترل

یک سرور آزمایشگاهی با IPv4 عمومی لازم است که مالک آن هستید یا مجوز صریح اجرای سرویس روی آن دارید. دامنهٔ VPN موجود شما به معنی داشتن چنین مجوزی نیست. اگر سرور ندارید، فعلاً آزمون را اجرا نکنید و اطلاع بدهید. هیچ سرویس عمومی ناشناخته‌ای جایگزین نمی‌شود.

Python 3 روی آن سرور و دسترسی ورودی به TCP پورت انتخابی لازم است. ابزار نه نرم‌افزاری نصب می‌کند و نه فایروال سرور را تغییر می‌دهد. اگر پورت بسته است، فقط همان پورت آزمون را مطابق سیاست سرورتان مجاز کنید؛ فایروال را خاموش یا reset نکنید. از سرور/VM آزمایشگاهی و کنسول محلی ویندوز استفاده کنید؛ RDP برای این آزمون پذیرفته نمی‌شود.

### ۱. سمت سرور

فقط فایل `server/echo-server.py` را به سرور آزمایشی خودتان منتقل کنید. سپس:

```bash
python3 echo-server.py --bind 0.0.0.0 --port 39443 --seconds 900 --max-connections 180
```

این سرویس حداکثر ۱۵ دقیقه یا ۱۸۰ اتصال کار می‌کند؛ برای توقف زودتر Ctrl+C. فقط پیام کوتاه دارای nonce تصادفی را برمی‌گرداند، پراکسی/شل/انتقال فایل/HTTP نیست. دامنه، رمز یا اطلاعات ویندوز از کلاینت ارسال نمی‌شود. پیام احراز هویت‌شده یا TLS نیست؛ nonce صرفاً جلوی اشتباه‌گرفتن پاسخ سرویس نامرتبط با پاسخ آزمون را می‌گیرد، نه حملهٔ MITM را. لاگ سرور شامل IP متصل‌شونده و نتیجهٔ پردازش پیام است. روی سرور حساس/تولیدی اجرا نکنید. برنامه هیچ کلید SSH، رمز VPN یا اعتبارنامه‌ای نمی‌خواهد.

### ۲. سمت ویندوز

1. ZIP را در پوشه‌ای **جدید** روی دیسک محلی استخراج کنید. فایل‌های نصب/ژورنال قبلی را پاک یا بازنویسی نکنید. Python x64 همراه بسته است؛ نصب جداگانه لازم نیست.
2. سرور echo را آماده و در حال اجرا نگه دارید.
3. `Traffic-Test.cmd` را با **Run as administrator** اجرا کنید.
4. IPv4 عمومی سرورتان و پورت آن را وارد کنید؛ پورت پیش‌فرض `39443` است. فقط IPv4 عمومی و پورت ۱۰۲۴ تا ۶۵۵۳۵ پذیرفته می‌شود.
5. برای تأیید مجوز سرور، سپس تغییرات موقت قواعد، این دو عبارت را به‌ترتیب وارد کنید:

```text
I CONTROL THIS TEST ENDPOINT
TEST TEMPORARY BLOCKS
```

6. پنجره را نبندید؛ آزمون ممکن است چند دقیقه طول بکشد. در انتها `Export-Lab-Results.cmd` و سپس `EXPORT` را اجرا کنید. ZIP جدید `UnifiedFW-061-LabResults-....zip` را بفرستید. این خروجی شامل گزارش ترافیک است؛ برنامه چیزی خودکار آپلود نمی‌کند.

اگر سرور پاسخ صحیح ندهد، مرحلهٔ پایه متوقف می‌شود و هیچ قاعدهٔ آزمون ساخته نمی‌شود. قطع یا timeout به‌تنهایی موفقیت نیست. برنامه از IP مستقیم و socket استفاده می‌کند؛ DNS/HTTP proxy/TLS در این آزمایش به‌کار نمی‌رود.

## چه ماتریسی بررسی می‌شود؟

A همان `runtime/python.exe` و B همان `runtime/pythonw.exe` است. هر تلاش یک فرایند و اتصال تازه با شناسه و challenge مستقل دارد. کنترل REF از فرایند PowerShell و .NET به همان مقصد متصل می‌شود و برای آن قاعده ساخته نمی‌شود.

| مرحله | A | B | REF |
| --- | --- | --- | --- |
| پایه؛ بدون قاعدهٔ جدید | اتصال و پاسخ صحیح | اتصال و پاسخ صحیح | اتصال و پاسخ صحیح |
| Block فقط A | اتصال برقرار نشود | پاسخ صحیح | پاسخ صحیح |
| Block فقط B | پاسخ صحیح | اتصال برقرار نشود | پاسخ صحیح |
| Block هر دو | اتصال برقرار نشود | اتصال برقرار نشود | پاسخ صحیح |

در هر مرحله سه دور برای هر ستون ثبت می‌شود. پس از هر مرحله قواعد همان نشست Restore، موجودی کامل فایروال با خط مبنا مقایسه و اتصال هر سه دوباره بررسی می‌شود. حداکثر ۷۲ تلاش اتصال در ماتریس کامل وجود دارد؛ بخشی از آن‌ها باید در کلاینت مسدود شود. هیچ سرویس یا فایل بازی فراخوانی نمی‌شود.

**فقط دو فایل runtime همراه بسته، فقط یک IPv4 و پورت مشخص، فقط TCP** تحت Block آزمایشی قرار می‌گیرند. وایت‌لیست سراسری یا قاعدهٔ عمومی شبکه نصب نمی‌شود. پروفایل‌ها، Allowهای خارجی، hosts، DNS، سرویس‌ها و ETW/audit تغییر نمی‌کنند. هش دو فایل قبل از پذیرش نقشه و پیش از probe دوباره بررسی می‌شود؛ این اعتبار ناشر یا تصویر حافظه را تضمین نمی‌کند.

## محافظ‌های اجرا و خطا

- موتور نشست و Package=null اصلاح‌شدهٔ ۰٫۵٫۱ حفظ شده‌اند. ریشهٔ ژورنال عمداً همان `%ProgramData%\UnifiedFirewallLab-050` است. نشست قبلی باید Restored باشد؛ در غیر این صورت آزمون جدید رد می‌شود.
- یک قفل مشترک محافظت‌شده تا پایان آزمون نگه داشته می‌شود. هر مرحله نشست جداگانه با قواعد Block محدود و نام‌های مالک‌شده دارد. اعمال/بازیابی از نام دقیق و تصویر قاعده و هفت فیلتر استفاده می‌کند؛ حذف گروهی/Force restore وجود ندارد.
- قواعد ابتدا Disabled ساخته و تصویرشان پیش از بررسی معنایی ثبت می‌شود؛ سپس فقط پس از تأیید فعال می‌شوند. ActiveStore هم بازخوانی می‌شود.
- Restore در پایان هر مرحله و هنگام خطای عادیِ قابل‌گرفتن تلاش می‌شود، ولی بسته‌شدن اجباری پنجره، crash یا قطع برق تضمین cleanup ندارد. تایم‌اوت/kill فقط برای فرایند probe است، نه کنترلر تغییر فایروال.
- اگر نتیجه `restore_failed`، خطای drift، یا گزارش ناقص داشت، Apply/آزمون را تکرار نکنید؛ ژورنال را نگه دارید و گزارش یا تصویر پنجره را بفرستید. `RESTORE` در کنسول `Open-Lab.cmd` برای نشست ثبت‌شده موجود است، اما روی تغییر خارجی force نمی‌کند.
- میان آخرین بازخوانی و cmdlet ویندوز CAS اتمی وجود ندارد. تغییر هم‌زمان مدیریتی می‌تواند آزمون را نامعتبر کند. تصویر اولیه و فایل‌های جزئی محلی برای بررسی نگه داشته می‌شوند؛ بکاپ کامل فایروال در خروجی ZIP صادر نمی‌شود.

## تفسیر نتیجه

- `passed`: ماتریس مشخص اتصال برای **همین دو image، همین مقصد IPv4/TCP، همین زمان و محیط** با کنترل مرجع و Restore تطبیق داشته است.
- `failed`: دست‌کم یک EXE در مرحله‌ای که باید مسدود می‌بود اتصال TCP برقرار کرده است؛ حتی اگر handshake بعداً خطا دهد.
- `inconclusive`: سرور/کنترل مرجع/فرایند probe/بازیابی یا دادهٔ آزمون قابل تأیید نبوده است؛ هرگز موفقیت محسوب نمی‌شود.

این ابزار packet capture یا رخداد قطعیِ WFP-drop جمع نمی‌کند. نتیجهٔ اتصال با قواعد و کنترل هم‌زمان سنجیده می‌شود، نه اثبات علت همهٔ timeoutها. IP محلی و IP مشاهده‌شده توسط سرور ثبت می‌شود، اما به‌تنهایی عبور از SSTP یا نبود نشت را اثبات نمی‌کند.

هنوز آزمون نشده/پیاده نشده: هم‌زیستی عملی whitelist سراسری با blacklist، مسیر VPN، IPv6، UDP، اتصال‌های قبلاً باز، تعویض/قطع تونل، استثناهای حمل SSTP، Kill-switch، مهاجرت کامل تاریخچه/PTR/DNS/WFP/hosts و انتشار EXE واحدِ امضاشده. `APPLY LAB` تنظیمات اصلی را در این مرحله اجرا نکنید.

## سایر بخش‌ها

`Open-Preview.cmd` ویرایشگر مشترک چند EXE و رصد فقط‌خواندنی TCP است؛ تغییر تنظیمات آن قواعد فعال را به‌روز نمی‌کند. مسیر اصلی Apply همچنان صریحاً آزمایشگاهی است. دامنه در whitelist پشتیبانی نشده؛ IP/CIDR/range مجاز است. اولویت Block بلک‌لیست با Allow دور زده نمی‌شود؛ این مرحلهٔ ترافیک هنوز whitelist را نصب نمی‌کند.

بازیابی اختصاصی orphan قبلی از این بسته حذف شده، چون گزارش شما تکمیل آن را تأیید کرد؛ آن کار نباید دوباره اجرا شود. ژورنال/بکاپ نسخهٔ قبلی را نگه دارید.

## کیفیت و شواهد توسعه

شواهد در `evidence/` و `QA.json` هستند. تست‌های واحد و mock روی Linux، اتصال واقعی به echo روی sandbox localhost و کنترل مرجع PowerShell در Linux اجرا می‌شوند؛ این‌ها اجرای کنترلر ترافیک روی Windows PowerShell 5.1 نیستند. پذیرش قبلی ۰٫۵٫۱ فقط ساخت/بازیابی دو قاعده را اثبات کرده بود، نه آزمون فعلی ترافیک.

manifest صحت فایل‌های توزیع را می‌سنجد؛ امضای ناشر یا ریشهٔ اعتماد نیست. runtime از بستهٔ ارسالی کاربر، بدون تغییر و با تطبیق هش‌ها، همراه شده است. در GitHub فقط سورس و شواهد هستند، نه runtime باینری. اجرای تست‌های توسعه ممکن است evidence را تغییر دهد؛ آن‌ها را روی کپی اجرا کنید.
