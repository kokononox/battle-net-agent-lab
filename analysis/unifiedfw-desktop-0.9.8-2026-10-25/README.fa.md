# Unified Firewall Desktop 0.9.8 RC / LAB

نسخهٔ قابل‌حمل ویندوز x64، رابط PowerShell Windows Forms و runtime داخلی Python. این انتشار آزمایشی است؛ تست شبکه و GUI واقعی ویندوز در محیط ساخت انجام نشده و «بدون نشتی» تأیید نمی‌شود.

## ارتقا از ۰٫۹٫۷٫۱

1. صبر کنید عملیات جاری تمام شود و رابط را ببندید. فایل‌ها را هنگام Apply/Restore جایگزین نکنید.
2. از پوشهٔ فعلی، از جمله private-state، نسخهٔ پشتیبان بگیرید. بستن رابط قواعد و Audit را خاموش نمی‌کند.
3. ZIP کوچک `Unified-Firewall-Desktop-0.9.7.1-to-0.9.8-Hotfix.zip` را در همان پوشهٔ دارای Start.cmd استخراج کنید و فایل‌های ثابت را جایگزین کنید؛ پوشهٔ تو‌در‌تو نسازید. private-state در ZIP نیست و باید حفظ شود. مالک، تنظیمات و پشتیبان‌ها را حذف یا با نصب دیگری ادغام نکنید.
4. Start.cmd را اجرا کنید؛ بالای پنجره 0.9.8 باشد. برای اعمال بومی/بازیابی/پاک‌سازی DNS، آن را صریحاً Run as administrator باز کنید. ارتقای دسترسی خودکار نیست.

بستهٔ کامل برای نصب تازه هم ارائه شده است. اگر نصب دیگری قواعد فعال دارد، ابتدا با همان نصب و ژورنالش وضعیت و بازیابی را بررسی کنید. این Hotfix فقط برای ۰٫۹٫۷٫۱ است، نه نسخهٔ قدیمی‌تر یا تغییریافته. فایل‌های runtime از ۰٫۹٫۷٫۱ عوض نشده‌اند.

## وایت‌لیست، بازه و اولویت

- در صفحهٔ «وایت‌لیست و سیاست»، «افزودن بازهٔ IP / پورت» و «ویرایش / تبدیل خط به بازه» موجودند. برای ویرایش، نشانگر متن را در خط مقصد بگذارید. پیش‌نمایش پذیرفته‌شده همان خط را جایگزین می‌کند؛ لغو، خط قبلی را حفظ می‌کند.
- مقصد: IP، CIDR، از IP تا IP، wildcard انتهایی یا فهرست IP دقیق. پروتکل TCP/UDP و پورت از/تا شامل هر دو انتهاست. بازهٔ پورت وایت‌لیست به‌صورت بومی ذخیره می‌شود، نه هزاران خط جدا.
- قالب دستی هر خط: `8.8.8.8|TCP|443-445` یا `8.8.8.8|UDP|53`. قالب `8.8.8.8|ANY|*` تمام پروتکل‌ها/پورت‌هاست. IP/CIDR قدیمیِ بدون پسوند هم برای سازگاری یعنی تمام پروتکل‌ها و پورت‌ها؛ در بازبینی نهایی دقت کنید.
- نام دامنه، مجوز بومی ثابت نیست و خودکار Resolve نمی‌شود. انتقال چند مورد از رصد، الحاق/حذف تکرار دارد؛ نام خام قبل از اعمال باید به IP معتبر تبدیل شود. IP مشترک CDN معادل دامنهٔ منحصر‌به‌فرد نیست.
- در ویرایش ردیف بلک‌لیست، دکمهٔ «تبدیل به بازهٔ IP / پورت» اضافه شده است. پذیرش پیش‌نمایش ردیف قبلی را جایگزین می‌کند. بازهٔ پورت بلک‌لیست هنوز به تک‌پورت‌ها باز می‌شود: سقف ۲۵۶ ردیف و ۱۰۲۴ قاعدهٔ بالقوه؛ بدون برش مخفی. حدود و EXE دقیق نمایش داده می‌شوند.
- **داخل تونل انتخاب‌شده، وایت‌لیست از بلک‌لیست تنظیمات همین برنامه مقدم است**؛ فقط هم‌پوشانی همان IP/پروتکل/پورت. در full_isolation بقیهٔ مقصدها با خروجی پیش‌فرض Block منع می‌شوند؛ Block متعارض خود برنامه ساخته نمی‌شود.
- **خارج تونل، وایت‌لیست مجوز خروج مستقیم نیست.** قواعد Block متعلق به دیگران و فایل hosts دست‌نخورده می‌مانند؛ Allow آن‌ها را دور نمی‌زند.
- مسیر قدیمی «پیش‌نمایش» برای تحلیل است و قابلیت اعمال وایت‌لیست ندارد. برای حفاظت واقعی، مسیر مستقل زیر را استفاده کنید. `vpn_allowlist` بدون فول ایزولیشن همچنان فقط پیش‌نمایش است.

## اعمال فول ایزولیشن و کیل‌سوییچ SSTP

1. حالت `full_isolation` را انتخاب کنید، وایت‌لیست را تکمیل و «ذخیرهٔ سیاست» را بزنید. ذخیره به معنی اعمال نیست.
2. اگر بلک‌لیست Native قدیمی یا SstpKillSwitch قدیمی فعال است، ابتدا با ابزار خودش Restore کنید؛ برنامه آن‌ها را خودکار حذف/تصاحب نمی‌کند. گذار از ابزار قدیمی با قطع‌و‌وصل کنترل‌شده انجام شود؛ هیچ ادعای گذار بدون وقفه وجود ندارد.
3. یک SSTP تمام‌تونل متصل باشد؛ چند VPN، split tunneling، پرس‌وجوی ناقص پروفایل‌ها یا تشخیص نامطمئن رد می‌شود.
4. «بررسی و اعمال فول ایزولیشن / کیل‌سوییچ» را بزنید؛ تصویر قواعد Allow، سه پروفایل، رابط، سرور، DNS، مقصد/پروتکل/پورت و دامنهٔ اثر را بخوانید. ادامه فقط با تأیید دکمه‌ای است؛ متن تایپی لازم نیست.
5. بعد از پایان، «وضعیت ایزولیشن / محافظ» را بخوانید. `configuration_verified` یعنی بررسی همان لحظهٔ پیکربندی، نه تست بسته/اثبات نبود نشت. heartbeat محافظ و تطبیق تنظیمات ذخیره‌شده با سیاست فعال جدا گزارش می‌شوند.

### موتور چه می‌کند؟

- ژورنال محافظت‌شده در `%ProgramData%\UnifiedFirewallIsolation-098` با دسترسی Administrator/SYSTEM ساخته می‌شود. تصویر کامل قواعد Allow قبل از غیرفعال‌سازی ثبت، checksum و بازخوانی می‌شود؛ نوشتن تنظیمات هم پشتیبان محلی تأییدشده دارد.
- خروجی پیش‌فرض Domain/Private/Public در PersistentStore روی Block قرار می‌گیرد. Allowهای خروجی محلیِ فعال، حتی متعلق به پروفایل فعلاً غیرقابل‌اعمال، پس از ثبت تصویر غیرفعال می‌شوند. Allow غیرمحلی/GPO و bypass احراز هویت، مجوز فعال‌سازی نمی‌گیرند.
- وایت‌لیست روی نام دقیق رابط SSTP و InterfaceType=RemoteAccess محدود است، سراسری برای برنامه‌ها. داخل تونل هم فقط مقصد/پروتکل/پورت اجازه می‌گیرد.
- استثنای اتصال SSTP: فقط svchost معتبر مایکروسافت، سرویس SstpSvc، TCP/443 و IPهایی که به TCP برقرارِ همان سرویس و سرور پروفایل تطبیق دارند. سرور دامنه‌ای فقط از کش خوانده می‌شود؛ DNS بیرون تونل برای کشف سرور باز نمی‌شود. عدم اثبات، عملیات را رد می‌کند؛ fallback گسترده وجود ندارد.
- DNS سیستم فقط برای Dnscache، TCP/UDP 53 و DNSهای همان رابط، داخل همان تونل اجازه دارد. DNS فیزیکی، DHCP عمومی و همهٔ RemoteAccessها آزاد نمی‌شوند. این سخت‌گیری می‌تواند DHCP، تمدید شبکه، بعضی VPNها یا اتصال مجدد وابسته به DNS بیرون تونل را مختل کند؛ خودکار برای رفع مشکل دسترسی گسترده نمی‌شود.
- Task با نام `UnifiedFW-Isolation-<owner>` و SYSTEM از کد کپی‌شده در پوشهٔ محافظت‌شده اجرا می‌شود؛ نه از فایل قابل‌تغییر در پوشهٔ قابل‌حمل. در شروع ویندوز هم اجرا می‌شود. GUI لازم نیست باز بماند.
- محافظ دوره‌ای خروجی پیش‌فرض Block را نگه می‌دارد و Allow محلی تازه را فقط با ثبت تصویر قبل از تغییر غیرفعال می‌کند. خطا باعث Restore/Allow خودکار نمی‌شود. ژورنال بزرگ فقط هنگام تغییر نوشته می‌شود؛ heartbeat کوچک جداست.
- قطع VPN یا بستن رابط، پروفایل‌ها را Allow نمی‌کند. اتصال به همان رابط/سرورِ پین‌شده می‌تواند با قواعد پایدار ادامه یابد؛ تغییر نام/رابط/سرور، اجازهٔ تازهٔ خودکار نمی‌گیرد. دوباره بررسی و اعمال لازم است؛ نام/IP در کد ثابت نشده است.
- به‌روزرسانی سیاست فعال از مسیر Apply درجا انجام می‌شود؛ ابتدا Restore و آزادکردن پروفایل‌ها انجام نمی‌شود. شکست میانی با وضعیت partial/critical و حفظ محدودیت‌های موجود گزارش می‌شود.

### محدودیت امنیتی مهم

این محافظ دوره‌ای، ضمانت اتمی در برابر Administrator، GPO، برنامه‌های امنیتی دیگر یا فیلترهای WFP خارج از مدل نیست. Allow خارجی تازه ممکن است قبل از شناسایی اثر کند؛ Allow غیرمحلی تازه قابل قرنطینه نیست و وضعیت بحرانی می‌شود. رفتار اتصال‌های از قبل برقرار، راه‌اندازی مجدد، IPv6 و قطع ناگهانی باید روی دستگاه واقعی با مشاهدهٔ بسته آزمایش شود. سرویس‌اسکوپ SstpSvc روی هر سیستم قابل اثبات نیست؛ اگر تشخیص رد شد، استثنا را دستی به همهٔ برنامه‌ها گسترش ندهید. **این انتشار تأیید «بدون نشتی» نیست.**

## بازیابی و تنظیمات پیش‌فرض

- هر دو بخش بلک‌لیست و وایت‌لیست دکمهٔ «پیش‌فرض تنظیمات» و «پشتیبان‌ها / بازیابی تنظیمات» دارند. قبل از تغییر، تنظیمات و پیش‌نویس نمایش‌داده‌شده پشتیبان/بازخوانی می‌شوند؛ شکست پشتیبان‌گیری تغییر را متوقف می‌کند. محل: `private-state/policy-backups`؛ سقف ۲۰۰۰، بدون حذف خودکار. فایل‌های قدیمی را پیش از رسیدن به سقف در محل خصوصی بایگانی کنید.
- پیش‌فرض بلک‌لیست فقط همان لیست را خالی می‌کند. پیش‌فرض وایت‌لیست آن را خالی و حالت ذخیره‌شده را blacklist_only می‌کند. EXEها، مالک و بخش دیگر حفظ می‌شوند. بازیابی هم فقط بخش منتخب و با نسل تازه است؛ پیش‌نویس ذخیره‌نشده جدا برمی‌گردد.
- **تنظیمات پیش‌فرض یا ذخیرهٔ لیست خالی، قواعد فعال را Restore نمی‌کند.** وضعیت ذخیره و اعمال متفاوت‌اند. اگر نسل/هش/مالک تنظیمات با سیاست فعال فرق کند در وضعیت اعلام می‌شود.
- «بازیابی ایزولیشن» یا `Isolation-Recovery.cmd` با Administrator: Task متعلق به نشست متوقف می‌شود؛ فقط قواعد دقیق ثبت‌شده حذف، Allowهای بی‌تغییر به تصویر قبلی و فقط فیلد DefaultOutboundAction پروفایل‌ها به مقدار قبلی، از جمله NotConfigured، بازمی‌گردد. تعارض/تغییر خارجی به‌زور بازنویسی نمی‌شود؛ ژورنال نگه داشته می‌شود. این عمل حفاظت را صریحاً برمی‌دارد.
- `Recovery.cmd`: بازیابی موتور بلک‌لیست قدیمی؛ مستقل از ایزولیشن. ژورنال قدیمی در `%ProgramData%\UnifiedFirewallLab-050` است.
- `Audit-Recovery.cmd`: بازیابی سیاست Audit؛ مستقل از قواعد. Audit بعد از بستن GUI می‌ماند تا صریح بازگردانده شود.
- خطا یا بسته‌شدن اجباری هنگام تغییر Native به معنی «هیچ تغییری نکرد» نیست. Apply را کورکورانه تکرار نکنید؛ وضعیت/ژورنال و بازیابی مربوط را بخوانید. اگر Task متوقف شد ولی Restore به‌دلیل drift رد شد، محدودیت‌های باقی‌مانده حفظ می‌شوند؛ حفاظت کامل ادعا نمی‌شود.

## قابلیت‌های حفظ‌شده و اصلاحات قبلی

- بلک‌لیست IP در یک جدول با تفکیک پیش‌نویس، ذخیره و وضعیت زمان‌دار قواعد ویندوز است؛ دکمهٔ ذخیره، Apply نیست. اتصال ردیف رصد به EXE دقیق و انتخاب چند مورد حفظ شده است.
- تیک EXEها با شناسه‌های تخت، انتخاب‌های پنهان و فیلتر مدیریت می‌شود؛ نام یکسان با مسیر متفاوت یکی نمی‌شود.
- DNS برای هر مسیر کامل EXE + دامنه یک ردیف ثابت دارد؛ تکرار آدرس و تکرار اجرا شمارنده/IP/PID/زمان همان ردیف را به‌روز می‌کنند. هویت خام PID/زمان تولد برای انتساب شواهد حفظ می‌شود.
- پالس روی کل زمینهٔ ردیف است؛ قرمز فقط شاهد منع واقعی Security 5157 با هویت و زمان مربوط، آبی مشاهدهٔ فعالیت است، **نه اثبات رسیدن به مقصد**. نبود شاهد منع، «آزاد قطعی» نیست. وضعیت منع مرتبط با IP پاسخ DNS، خطای DNS، hosts و نامعلوم جداست؛ هم‌بستگی IP اثبات مسدودشدن خود نام دامنه نیست.
- تایمر تک‌ورودی و دریافت نتیجه یک‌باره مانع تکرار پنجرهٔ hosts و گیرکردن دکمه‌ها در حالت مشغول می‌شود؛ خطای نمایش یا Dispose هم آزادسازی را در finally دارد.
- «فقط پاک‌سازی کش DNS» مستقل از hosts، سرورهای DNS، Winsock و ETW است. موفقیت/شکست آن جدا گزارش می‌شود. بازنشانی hosts همهٔ نگاشت‌های سفارشی را با پشتیبان/بازبینی حذف می‌کند؛ با پاک‌کردن صرف کش اشتباه نگیرید.
- بازگردانی پشتیبان hosts، پشتیبان از وضع فعلی و کنترل digest دارد؛ شکست flush باعث تکرار نوشتن hosts نمی‌شود. نتیجه در صفحه/گزارش است، نه زنجیرهٔ MessageBox.
- hosts سراسری است؛ وایت‌لیست نمی‌تواند نگاشت hosts را خنثی کند. مسیرهای فایروال، hosts و Audit تأیید و بازیابی مستقل دارند. تایپ متن تأیید از رابط و Recovery حذف شده؛ تأیید/لغو دکمه‌ای باقی است.

## اعتبارسنجی، runtime و حریم خصوصی

نتایج دقیق آزمون‌های Python، PowerShell و parser در `evidence/release-validation.json` و فایل‌های مرتبط هستند. سناریوهای ایزولیشن شامل تقدم دقیق پروتکل/پورت، تشخیص SSTP، رد Allow غیرمحلی، ثبت تصویر، خرابی در checkpointها، drift، بازیابی NotConfigured و به‌روزرسانی بدون آزادکردن پروفایل است؛ آداپتورها ساختگی‌اند. Windows PowerShell 5.1، WinForms واقعی، DPI، Task Scheduler/SYSTEM، ACL و APIهای شبکهٔ ویندوز در این محیط Linux اجرا نشده‌اند.

runtime داخلی رسمی Python 3.13.12 از ۰٫۹٫۷٫۱ بایت‌به‌بایت حفظ شده است. MANIFEST-SHA256 صحت فایل‌های ثابت را بررسی می‌کند، نه امضای ناشر/Authenticode. موتور قدیمی تغییر قواعد، hosts و Audit حفظ شده‌اند؛ موتور ایزولیشن جدید و مستقل است. برنامه production-ready اعلام نمی‌شود.

private-state و گزارش‌ها شامل مسیر EXE، IP، دامنه، زمان و اطلاعات شبکه‌اند؛ خصوصی نگه دارید. بستهٔ تحویلی private-state کاربر ندارد؛ evidence فقط دادهٔ مصنوعی آزمون است. ژورنال محافظت‌شده برای بازیابی ضروری است؛ برای رفع خطا آن را حذف نکنید و از Firewall Reset یا EmergencyReset قدیمی به‌جای بازیابی محدود استفاده نکنید.
