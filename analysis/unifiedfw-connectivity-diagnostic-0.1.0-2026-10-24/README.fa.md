# عیب‌یابی اتصال HTTPS — نسخهٔ ۰.۱.۰

این بسته مستقل برای بررسی timeout متناوب است، نه فعال‌سازی حفاظت. **هیچ قاعدهٔ فایروال، مسیر، تنظیم VPN یا تنظیم امنیتی سیستم را ایجاد، حذف یا تغییر نمی‌دهد.** هیچ سرویس یا وظیفهٔ زمان‌بندی‌شده‌ای ندارد و پس از پایان باز نمی‌ماند. Administrator لازم نیست و ابزار درخواست ارتقای دسترسی نمی‌کند.

## استفادهٔ فعلی

۱. کل ZIP را در پوشه‌ای جدید و محلی استخراج کنید؛ در پوشهٔ نسخهٔ ۰.۸.۰ نریزید و فایل یا ژورنال قبلی را پاک نکنید.
۲. VPN را همان‌طور که برای آزمون قبل متصل بود نگه دارید. ابزار دیگری از آزمایشگاه هم‌زمان اجرا نشود. فعلاً آزمون بدون VPN لازم نیست.
۳. `Start-Connectivity-Diagnostic.cmd` را با دوبار کلیک اجرا کنید؛ Run as administrator لازم نیست.
۴. آدرس کامل HTTPS همان فایل PHP و سپس IP عمومی سایت را وارد کنید. آدرس/IP در کد ثابت نشده‌اند. فایل PHP تازه‌ای برای آپلود در این بسته نیست؛ همان پاسخ‌دهندهٔ قبلی استفاده می‌شود.
۵. برای وضعیت فعلی VPN بنویسید `ON`. این فقط برچسب گفتهٔ کاربر در گزارش است؛ ابزار اتصال VPN را اثبات یا تغییر نمی‌دهد.
۶. در پاسخ به تأیید مالکیت/مجوز مقصد دقیقاً بنویسید `I CONTROL THIS TEST ENDPOINT`.
۷. تا نمایش `18/18` و مسیر `REPORT ZIP` صبر کنید. معمولاً حدود ۱ تا ۳ دقیقه؛ با خطاهای اجرایی ممکن است بیشتر شود. فاصلهٔ چهارثانیه‌ای از پایان یک درخواست تا آغاز بعدی است و زمان DNS اولیه جداست. برای توقف از Ctrl+C استفاده کنید؛ ابزار برای ذخیرهٔ نتیجهٔ ناتمام تلاش می‌کند. بستن اجباری پنجره ممکن است ساخت ZIP را قطع کند ولی این برنامه قواعدی ندارد که نیاز به Restore داشته باشند.
۸. فایل `UnifiedFW-Connectivity-Results-....zip` در کنار فایل CMD به‌صورت خودکار ساخته می‌شود. **نیازی به Export-Lab-Results.cmd قبلی نیست.** ZIP را پیش از ارسال بررسی کنید و همان را بفرستید.

اگر پنجره پیش از شروع خطا داد، تصویر خطا را بفرستید. اعتبارسنجی گواهی، ModSecurity یا تنظیمات امنیتی را خاموش نکنید. اگر Windows اجرای اسکریپت دانلودشده را منع کرد، آن خطا را گزارش کنید؛ ابزار ExecutionPolicy را تغییر نمی‌دهد و از Bypass استفاده نمی‌کند.

## چه آزمایش می‌شود؟

- شش دور شامل A، B و REF؛ مجموعاً **۱۸ تلاش**، کاملاً ترتیبی، بدون موازی‌سازی، تکرار خودکار درخواست ناموفق یا پنهان‌کردن نتیجهٔ قبلی.
- A از `runtime/python.exe`، B از `runtime/pythonw.exe` و REF از فرایند Windows PowerShell/.NET استفاده می‌کند. ترتیب جابه‌جا می‌شود تا هر کلاینت دو بار در هر جایگاه قرار گیرد.
- بین هر دو تلاش چهار ثانیه فاصله است. سقف اتصال TCP همان سه ثانیهٔ نسخهٔ ۰.۸.۰ است؛ برای بهترشدن ظاهری نتیجه افزایش نیافته است. سقف بیرونی اجرای هر فرایند تشخیصی ۲۰ ثانیه است؛ timeout فرایند، خطای اجراست، نه اثبات بلاک.
- هر تلاش اتصال TCP و challenge تازه دارد. فقط یک IPv4 عمومی منتخب و TCP ۴۴۳، یک hostname برای SNI/Host و یک path فایل PHP استفاده می‌شود. DNS اولیه باید شامل همان IPv4 باشد. هیچ fallback IP، پراکسی HTTP، redirect، retry یا HTTP بدون TLS وجود ندارد.
- TLS نام و زنجیرهٔ گواهی را با سازوکار پیش‌فرض Python/.NET بررسی می‌کند؛ callback پذیرش همهٔ گواهی‌ها یا تغییر trust store وجود ندارد. سرویس‌های سیستمی بررسی زنجیره ممکن است خودشان ترافیک جدا داشته باشند؛ ادعای «هیچ ترافیک سیستمی دیگری» نداریم.
- مرحلهٔ فعال در زمان خطا ثبت می‌شود: آماده‌سازی TLS، اتصال TCP، handshake TLS، ارسال HTTP، خواندن پاسخ و بررسی echo، یا اجرای فرایند. مرحله به‌تنهایی علت اصلی مشکل را مشخص نمی‌کند. زمان کل probe و زمان کل فرایند، تاریخ UTC، کد خطا و مسیر/هش دو EXE در گزارش می‌آیند؛ مدت دقیق تک‌تک زیرمرحله‌ها اندازه‌گیری نمی‌شود.

## تفسیر و محدودیت

`all_18_attempts_succeeded` فقط یعنی هر ۱۸ اتصال در همین اجرا صحیح بوده است؛ سلامت همیشگی اینترنت، عبور قطعی از VPN، هم‌زیستی قواعد، kill-switch یا نبود نشت را تأیید نمی‌کند. هر شکست/نتیجهٔ ناقص به `incomplete_or_failures_observed` می‌انجامد؛ خطای 10013 هم در این ابزار موفقیت محسوب نمی‌شود.

runtimeها byte-identical با نسخهٔ ۰.۸.۰ هستند، اما چون بسته در پوشه‌ای جداست **مسیر EXE متفاوت است**. موفقیت این اجرا خطا یا قواعد امنیتی مختص مسیر نسخهٔ قبلی را رد نمی‌کند. گزارش برای کمک به تشخیص است، نه نسبت‌دادن قطعی خطا به هاست/VPN/فایروال.

فایل PHP قبلی انقضای مطلق `2026-10-26T05:47:49Z` دارد؛ زمان از نخستین بازدید حساب نمی‌شود. پاسخ HTTP 410 پس از انقضا اختلال شبکه محسوب نمی‌شود و فایل جدید نیاز دارد. پس از پایان بررسی‌ها همان فایل PHP را از هاست حذف کنید.

ZIP خروجی فقط نتیجه، Build Info و هش‌ها را دارد؛ درخواست‌های خام، stderr کامل محلی و کلیدها داخل آن نیستند. ممکن است URL سایت، IP عمومی و محلی، مسیر برنامه، زمان آزمون و بخش کوتاهی از خطای اجرا در نتیجه باشد. ابتدا بررسی کنید. هیچ گزارشی خودکار آپلود نمی‌شود.

تست‌های توسعه روی Linux انجام شده‌اند: کنترلر با فرایندهای شبیه‌سازی‌شده و TLS واقعی محلی Python/.NET، شامل رد گواهی ناشناس، نام نادرست، redirect و echo غلط. **این نسخهٔ جدید هنوز روی ویندوز کاربر اجرا نشده است.** runtime از بستهٔ قبلی کاربر بدون تغییر منتقل شده؛ امضای ناشر دوباره اعتبارسنجی نشده. manifest هش است، نه امضای ناشر. آزمون‌ها روی کپی بسته اجرا شوند چون فایل evidence/pycache ممکن است تولید شود.
