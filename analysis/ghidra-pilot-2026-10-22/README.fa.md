# آزمون عملی Ghidra روی بستهٔ Retail 70448

## نتیجه

Ghidra برای تحلیل تدریجی DLL کوچک در این بسته کارآمد بود، اما آزمون محدود Wow.exe هنوز خروجی قابل اتکای کافی برای تأیید کارآمدی روی کل بازی نداد. «تولید شبه‌کد» معادل «بازسازی درست منطق» نیست.

## دامنه و ورودی

- تاریخ اجرا: 2026-10-22؛ Ghidra 12.2 PUBLIC؛ Amazon Corretto JDK 25.0.4.10.1؛ Linux headless.
- ورودی از `binaries/retail-70448` در commit `521685db3ff95b45cceda81dea2b17a9792c066c` دریافت شد.
- هش هر پنج پارت، ZIP بازسازی‌شده و سه فایل استخراج‌شده با manifest مخزن تطبیق داشت. این تطبیق، اصالت ناشر یا اعتبار امضای Authenticode را اثبات نمی‌کند.
- هر سه فایل PE AMD64 هستند و دایرکتوری CLR آن‌ها صفر است.
- فقط libxell.dll و Wow.exe با Ghidra آزموده شدند؛ wow_loader.dll صرفاً استخراج و هش/هدر آن بررسی شد.
- هیچ EXE/DLL ورودی اجرا نشد؛ هیچ ورود حساب، اتصال بازی، تغییر TLS/anti-cheat یا تغییر نصب انجام نشد.

## libxell.dll

- زمان کل import/analysis/دیکامپایل نمونه/ذخیره: 31.457 ثانیه؛ سقف تحلیل 120 ثانیه؛ حداکثر 2 CPU.
- Ghidra تعداد 1666 تابع و 33384 دستور شناسایی کرد؛ این‌ها شمارش ابزارند، نه تعداد قطعی توابع واقعی.
- 12 تابع اول با اندازهٔ بدنه حداقل 40 بایت، غیر external و غیر thunk، انتخاب شدند؛ نمونه تصادفی یا نمایندهٔ کل DLL نیست.
- 12/12 نمونه از نظر API دیکامپایل موفق بودند. زمان هر نمونه 3 تا 20 میلی‌ثانیه بود.
- آزمون جداگانه از 10 export نیز شبه‌کد تولید کرد. برخی نمونه‌های نخست عمدتاً کدهای رشته/حافظه یا runtime هستند.
- در exportهای `INTC_D3D11_Xess...`، بررسی یک اشاره‌گر global و انتقال کنترل از جدول function pointer دیده می‌شود؛ رفع ابهام هدف فراخوانی و امضای پارامترها هنوز لازم است.
- خروجی exportها هشدار unresolved jumptable/indirect jump دارد؛ امضای `(void)` را نباید امضای واقعی API تلقی کرد.

## Wow.exe

- زمان کل: 220.883 ثانیه؛ heap تنظیم‌شده 2500M؛ سقف تحلیل 180 ثانیه؛ حداکثر 2 CPU.
- تحلیل خودکار به سقف 180 ثانیه رسید و کامل نشد. پروژه با وضعیت جزئی ذخیره شد و post-script اجرا شد.
- در وضعیت جزئی، 106757 تابع و 828993 دستور گزارش شد. به علت خطاها، تحلیل ناقص و احتمال تشخیص اشتباه کد/داده، این اعداد اندازهٔ معتبر کل برنامه نیستند.
- از 12 نمونهٔ ترتیبی، 8 مورد از نظر API شبه‌کد دادند و 4 مورد با bad instruction/overlap شکست خوردند.
- حتی برخی نمونه‌های «موفق» شامل `halt_baddata`، کنترل‌فلو ناقص، رجیسترهای بدون منشأ روشن و دستورهای غیرمعمول هستند؛ بنابراین 8/12 را نباید نرخ بازیابی صحیح کد دانست.
- یک analysis task خطای `body must contain the entry point` داد؛ PDB پیدا نشد و DLLهای وابسته به پروژه import نشده‌اند.
- علت این مشکلات هنوز مشخص نشده؛ از این آزمون نمی‌توان packed/obfuscated بودن فایل، خرابی فایل یا شکست قطعی Ghidra را نتیجه گرفت.

## تصمیم پیشنهادی

1. برای DLLهای قابل تحلیل، ادامهٔ کار با Ghidra همراه با اصلاح type/signature و ثبت RVA مفید است.
2. برای Wow.exe، قبل از خروجی‌گیری انبوه باید sectionها، entry point، مرز کد/داده، unwind metadata و آدرس‌های هدف معتبر بررسی شوند؛ سپس چند تابع معنایی مشخص با شواهد cross-reference انتخاب شوند.
3. مدت تحلیل بیشتر می‌تواند پوشش را بهتر کند، اما به‌تنهایی رفع خطای دیکد را تضمین نمی‌کند.
4. برای هدف تله‌متری، باید از رشته/پیام/فراخوانی مرتبط در Wow.exe شروع کرد، نه DLL گرافیکی یا توابع ابتدایی مرتب‌شده بر اساس آدرس.
5. این آزمون هیچ رفتار تله‌متری، ارسال داده، الگوریتم update یا رفتار زمان اجرا را اثبات نکرد.

## فایل‌ها و بازتولید

- `output/`: شمارش‌ها و شبه‌کد نمونهٔ خام Ghidra؛ بدون نام‌گذاری یا اصلاح دستی.
- `scripts/Probe.java`: نمونه‌گیری ترتیبی و دیکامپایل حداکثر 12 تابع با timeout بیست‌ثانیه‌ای برای هر تابع.
- `scripts/ExportProbe.java`: دیکامپایل حداکثر 10 export.
- `logs/`: لاگ ابزار با مسیر محیط کاری نرمال‌شده؛ فاقد لینک دانلود خصوصی یا token.
- `run.sh`: فرمان‌های معادل برای اجرای دستی؛ workflow یا اجرای خودکار CI اضافه نشده است.
- پروژه‌های باینری Ghidra و خود باینری‌های بازی دوباره وارد Git نشده‌اند. برای بازسازی پروژه باید ورودی‌های فعلی مخزن و همین اسکریپت‌ها استفاده شوند.
