# لانچر اجرایی ETW Control 0.1.1

درخواست کاربر: اجرای بستهٔ کنترل بدون وارد کردن دستور PowerShell.

## تغییر
یک لانچر Windows x64 با نام WLab-ETW-Control.exe اضافه شد. منطق کنترل ETW 0.1 تغییر نکرده است. فایل‌های Control.wprp و Run-Control.ps1 داخل EXE قرار دارند و برای ممیزی در پوشهٔ تازهٔ WLab-Control-* کنار EXE نیز نوشته می‌شوند. هیچ فایل از بستهٔ قدیمی لازم نیست.

لانچر با UAC عادی درخواست administrator می‌کند؛ تأیید لازم است. سپس پس از تأیید توضیح آزمایش، یک پنجرهٔ واضح PowerShell باز می‌کند و تا بسته‌شدن آن صبر می‌کند. فایل result در زیرپوشهٔ RESULT آن پوشهٔ کار خواهد بود. در صورت شروع دوباره، mutex فقط از تکرار همان لانچر جلوگیری می‌کند؛ پیام به پنجرهٔ PowerShell موجود اشاره می‌کند. بازی باز باشد، اسکریپت قبل از trace متوقف می‌شود.

PowerShell داخلی ویندوز همچنان موتور اجرای کنترل است، اما کاربر دستور وارد نمی‌کند. اسکریپت embedded با -EncodedCommand استاندارد UTF-16LE، بدون ExecutionPolicy Bypass/Unrestricted یا تغییر policy اجرا می‌شود. Base64 فقط فرمت انتقال متن به PowerShell است، نه رمزنگاری یا پنهان‌سازی. در حالت embedded فقط اتصال متغیر base به پوشهٔ کار جایگزین می‌شود. source کامل همراه است. هیچ bypass ضدویروس، حفاظت بازی، تنظیمات ETW یا security policy اضافه نشده است؛ اگر سیاست سازمانی/WDAC/AppLocker/Add-Type را مسدود کند باید خطا بررسی شود، نه اینکه تنظیمات امنیتی غیرفعال شوند.

پروفایل، اندازهٔ بافرها، loopback 448 بایتی، session تصادفی اختصاصی WPR، شرط فضای خالی، gate ورود ETL به ZIP و همهٔ محدودیت‌های نسخهٔ 0.1 برقرارند. کامپایل .NET و merge/stop زمان قطعی تضمین‌شده ندارند و قطع اجباری پنجره ممکن است session را باقی بگذارد؛ recovery فقط نام اختصاصی همان session را هدف می‌گیرد. launcher-info.json در پوشهٔ کار است، نه الزاماً داخل READY-TO-SEND.zip. هیچ مخفی‌سازی پنجره، نصب، دانلود روی دستگاه کاربر یا آپلود خودکار وجود ندارد.

## آزمون
Cross-compile با Go رسمی و SHA-256 تطبیق‌داده‌شده با فهرست رسمی go.dev انجام می‌شود. تمام وابستگی‌های لانچر از کتابخانهٔ استاندارد Go هستند. بررسی PE و دستور build انجام می‌شود؛ این‌ها جایگزین اجرای Windows، آزمون UAC، سیاست‌های محلی، پنجرهٔ کنسول یا capture/stack واقعی نیستند. باینری unsigned است؛ اگر ویندوز یا ابزار امنیتی مانع اجرا شد، خطا ارسال شود، نه اینکه حفاظت غیرفعال شود.

هیچ runtime Windows در این محیط اجرا نشده و ادعای موفقیت ETW/بازی/رمزگشایی/ارسال CPU/BIOS وجود ندارد. مشخصات کنترل در analysis/etw-control-2026-10-24 commit 32e706304cd7e1d4c2e03049f24f127666e2cd34 ثبت است.

## ساخت
داخل source با Go رسمی:
```
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 GOTOOLCHAIN=local go build -trimpath -buildvcs=false -ldflags="-H windowsgui -s -w" -o WLab-ETW-Control.exe .
```
فقط source و گزارش build در شاخهٔ تحلیل ثبت می‌شوند؛ EXE از طریق فایل جلسه تحویل داده می‌شود، نه به صورت متن یا دادهٔ باینری داخل GitHub push_files. main و BIOS Path GUI دست‌نخورده‌اند.
