# رصدگر پیشنهادی اتصال برنامه — نسخهٔ ۰٫۱

این بسته ادامهٔ candidate ثبت‌شده است، نه ثبت دوبارهٔ نصاب. فقط با انتخاب صریح candidate موجود و تأیید محلی، ۱۵ نمونه از جدول TCP می‌گیرد و پیشنهادهای IP/port هر برنامه را در root جداگانهٔ محافظت‌شده ذخیره می‌کند. فاصلهٔ نمونه‌ها دو ثانیه است؛ با هزینهٔ cmdletها، مدت معمول حدود۳۰ثانیه یا بیشتر است. deadline نرم ۳۰۰ثانیه بین فراخوانی‌هاست، نه timeout سخت برای cmdlet ویندوزیِ متوقف‌شده.

## اجرای آزمایشی روی همان ویندوز و همان حساب

1. ZIP را در پوشهٔ محلی تازه و جدا استخراج کنید؛ روی برنامهٔ قبلی کپی نکنید. candidate موفق را دوباره نسازید. شبکه، SSTP و baseline همان وضعیت بمانند. هیچ نصاب یا برنامه‌ای را صرفاً برای این آزمون شروع نکنید.
2. `Run-Observer.cmd` را با **Run as administrator، همان حساب ویندوز** اجرا کنید. Windows PowerShell5.1 x64/STA لازم است؛ ادمین برای خواندن candidate محافظت‌شده و ذخیرهٔ خصوصی است، نه تغییر شبکه. PS7 ابزار qualification ویندوز نیست.
3. پنجره داخل `ProgramData\UnifiedFW-ProgramCandidates-01` باز می‌شود. وارد پوشهٔ candidate قبلی شوید و فقط `candidate.json` همان انتخاب موفق را Open کنید. EXE انتخاب نکنید. انتخاب «آخرین candidate» خودکار نیست؛ اگر چند مورد دارید و نمی‌دانید کدام است، Cancel کنید و فقط همین ابهام را بگویید؛ شناسه و عکس نفرستید. ابزار فقط یک candidate را می‌خواند، actor همان حساب و قالب/receipt/checksum/ACL را کنترل می‌کند؛ ادغام چند پروفایل ندارد.
4. برنامه‌های نمایش‌داده‌شده را **محلی** بازبینی کنید؛ اگر درست‌اند، `Observe and save suggestions` را حداکثر ظرف دو دقیقه بزنید. Cancel هیچ نمونهٔ TCP یا ذخیرهٔ پیشنهاد ایجاد نمی‌کند؛ بررسی فایل برای نمایش review قبلاً انجام شده است. consent ثبت candidate قبلی اجازهٔ مشاهده محسوب نشده؛ این دکمه رضایت تازه برای مشاهده و ذخیرهٔ خصوصی است، نه approval مقصد یا اجرای برنامه.
5. تا پایان صبر کنید و فقط فایل تازهٔ `UFW-PROGRAM-OBSERVER-01-*.json` کنار بسته را ارسال کنید، حتی در لغو/خطا. گزارش شامل شمارنده‌ها و stage/code است؛ نه IP، PID، مسیر، hash، candidate ID یا SID. **candidate.json، suggestions.json، EXE، عکس یا transcript پنجرهٔ خصوصی را نفرستید.** اگر JSON ساخته نشد فقط پیام کوتاه startup/stage/code را بدون مسیر خصوصی بفرستید.

اگر برنامهٔ منتخب همین حالا اجرا نمی‌شود، صفر مشاهده طبیعی است؛ برای پرکردن خروجی فایروال را باز نکنید و برنامه را اجرا نکنید. این اجرای نخست، بازخوانی candidate در process مستقل و مسیر رصد/ذخیره روی Windows را می‌آزماید؛ صفر مشاهده به معنی پوشش شبکهٔ برنامه یا تأیید نبود فینگرپرینت نیست. انتظار نتیجه بر اساس رفتار واقعی همان اجراست؛ چیزی را برای گرفتن pass تغییر ندهید.

## قرارداد و محدودیت‌ها

- فایل EXE با همان reader قبلی در سه نوبت مشاهده می‌شود: پیش از review، پس از رضایت/پیش از نمونه‌برداری، و بعد از نمونه‌برداری. path/hash/fileID/volume/length/architecture باید با candidate برابر باشند. candidate نیز سه بار بازخوانی و head مقایسه می‌شود؛ تغییر یا actor متفاوت متوقف می‌شود. این‌ها pin اتمیک کل نشست نیستند و در برابر administrator مخرب/rollback دفاع عمومی نیستند.
- فقط PIDهایی که image path برابر برنامهٔ منتخب دارند، با PID/زمان شروع/مسیر یکسان قبل و بعد از هر جدول TCP نسبت داده می‌شوند. فرزندان، سرویس‌ها، helper انتخاب‌نشده و PIDصفر خودکار اضافه نمی‌شوند. فرایند غیرقابل‌خواندن/خارج‌شده قابل نسبت‌دادن نیست. این تطبیق اثبات hash کد بارشده در حافظه نیست؛ ممکن است process پیش‌تر از نسخهٔ دیگری در همان مسیر بارشده باشد. هیچ تصمیم اجرایی نباید به این نسبت‌دهی متکی شود.
- جدول TCP جهت آغاز اتصال را ثابت نمی‌کند؛ دادهٔ خصوصی `direction=unknown_tcp_table` دارد. فقط Established/SynSent با IP یک‌پخشی و پورت معتبر، با scope محدود، پیشنهاد می‌شوند؛ loopback، unspecified، multicast، IPv4 reserved>=224، IPv4/IPv6 link-local و scopeدار کنار گذاشته می‌شوند. private LAN addresses ممکن است در پیشنهاد بمانند؛ این‌ها هم تأیید نیستند. listening/TIME_WAIT/UDP رصد قابل‌اتکا نیستند. نمونه‌برداری می‌تواند اتصال کوتاه، مسدودشده، پیش/پس از بازه یا فاقد هویت خواندنی را نبیند. خروجی نه مسیر TLS/HTTP است، نه دامنه، نه کل برنامه. IP ممکن است CDN/shared/dynamic باشد؛ بدون بازبینی نباید grant شود.
- حداکثر۲۵۶ مقصد متمایز و۶۵۵۳۶ ردیف در هر snapshot؛ رسیدن به سقف یا شکست هر مرحله، موفقیت کامل محسوب نمی‌شود و partial endpoints را خودکار ذخیره نمی‌کند. بسته native callها را hard-timeout نمی‌کند؛ در توقف طولانی فقط وضعیت را گزارش کنید، نه اجرای هم‌زمان.
- پیشنهاد خصوصی در `ProgramData\UnifiedFW-ProgramObservations-01\UfwProgramObservation-...\suggestions.json` با ACL فقط Administrators/SYSTEM، CreateNew، Flush و readback ذخیره می‌شود؛ root مستقل از candidate و baseline است. شامل ارجاع خصوصی candidate/head و IP/port/count/program_id است، نه path یا PID. checksum امضای trusted/ضد rollback و ACL رمزگذاری نیست. write_status=attempted_may_exist_inspect_if_failed یعنی فایل ممکن است باقی مانده باشد؛ خودکار حذف/تکرار نکنید.
- هیچ اجرای target، تغییر firewall/VPN/route/DNS/audit/task، packet capture، DNS/PTR lookup، TLS interception، تأیید Authenticode یا خواندن baseline journal ندارد. shell انتخاب فایل/سیستم عامل/.NET compiler ممکن است metadata/cache/Temp/recents یا ترافیک مستقل داشته باشند؛ نبود ترافیک کل سیستم اثبات نشده است. از Network/preview دوری کنید.
- phase اجرایی candidate تغییر نمی‌کند؛ destination approval/ready_for_apply/execution_authority/no_leak/fingerprint_certified همواره false هستند. این بسته native Apply/recovery/SSTP bootstrap/reconnect یا تغییر مود را پیاده نمی‌کند. مرحلهٔ بعد از مشاهدهٔ واقعی، بازبینی صریح مقصدهای هر برنامه است، نه افزودن خودکار آنها.

## آزمون

وابستگی‌های reader و candidate و سه module storage بایت‌به‌بایت از نسخهٔ ثبت‌شده‌اند. آزمون‌های این نسخه reducer، callbacks، actual Linux file I/O و مسیرهای خطا/لغو/حریم خصوصی را می‌سنجند؛ Windows native TCP/process enumeration/file picker/ACL و PS5.1 زنده در محیط ساخت اجرا نشده‌اند. receipt قدیمی candidate جای qualification این flow جدید نیست. شواهد دقیق شمارنده‌ها در evidence/ ذخیره می‌شوند. این نسخه تا دریافت نتیجهٔ واقعی ویندوز، آزمایشی است.
