# Unified Firewall Desktop 0.9.10 RC / LAB

نسخهٔ قابل‌حمل ویندوز x64، رابط PowerShell Windows Forms و runtime داخلی Python. این انتشار آزمایشی است؛ تست شبکه و GUI واقعی ویندوز در محیط ساخت انجام نشده و «بدون نشتی» تأیید نمی‌شود.

## ارتقا از ۰٫۹٫۹

1. اگر ایزولاسیون نسخهٔ قبلی فعال است، قبل از ارتقا با همان نسخه وضعیت و «بازیابی ایزولاسیون» را انجام دهید. بازیابی حفاظت ایزولاسیون را برمی‌دارد؛ تا اعمال موفق دوباره، آن را فعال فرض نکنید. صبر کنید عملیات جاری تمام شود و رابط را ببندید. فایل‌ها را هنگام Apply/Restore جایگزین نکنید.
2. از پوشهٔ فعلی، از جمله private-state، نسخهٔ پشتیبان بگیرید. بستن رابط قواعد و Audit را خاموش نمی‌کند.
3. ZIP کوچک `Unified-Firewall-Desktop-0.9.9-to-0.9.10-Hotfix.zip` را در همان پوشهٔ دارای Start.cmd استخراج کنید و فایل‌های ثابت را جایگزین کنید؛ پوشهٔ تو‌در‌تو نسازید. private-state در ZIP نیست و باید حفظ شود. مالک، تنظیمات و پشتیبان‌ها را حذف یا با نصب دیگری ادغام نکنید.
4. Start.cmd را اجرا کنید؛ بالای پنجره 0.9.10 باشد. برای اعمال بومی/بازیابی/پاک‌سازی DNS، آن را صریحاً Run as administrator باز کنید. ارتقای دسترسی خودکار نیست.

بستهٔ کامل برای نصب تازه هم ارائه شده است. اگر نصب دیگری قواعد فعال دارد، ابتدا با همان نصب و ژورنالش وضعیت و بازیابی را بررسی کنید. این Hotfix فقط برای ۰٫۹٫۹ است، نه نسخهٔ قدیمی‌تر یا تغییریافته. فایل‌های runtime نسبت به ۰٫۹٫۹ عوض نشده‌اند.

## دو سیاست روشن؛ ایزولاسیون برای کل ویندوز

در رابط فقط دو سیاست اصلی وجود دارد:

1. **فقط بلک‌لیست:** انسدادهای ثبت‌شده برای EXEهای دقیق؛ این حالت به‌تنهایی بقیهٔ اینترنت را محدود نمی‌کند. وایت‌لیست ذخیره‌شده در این حالت مجوزی اعمال نمی‌کند.
2. **وایت‌لیست / ایزولاسیون کل سیستم:** محدودسازی خروجی همهٔ برنامه‌های ویندوز، مستقل از تیک EXEها. دو روش اتصال دارد:
   - **اتصال معمولی — بدون الزام VPN:** فقط IP/پروتکل/پورت وایت‌لیست از رابط‌های موجود مجاز می‌شود. VPN لازم نیست؛ اگر رابط VPN از قبل وجود داشته باشد، انتخاب مسیر با ویندوز است و این روش مسیر فیزیکی را اجبار نمی‌کند. خروجی سایر مقصدها پیش‌فرض Block است. هیچ استثنای خودکار DNS، DHCP، LAN یا انتقال VPN ساخته نمی‌شود؛ نام‌گشایی، تمدید IP و اتصال VPN ممکن است قطع شوند. فقط مقصدهای لازم را آگاهانه در وایت‌لیست وارد کنید. محدودیت فعلی آدرسهای ویژه/خصوصی حفظ شده است.
   - **فقط از VPN — SSTP / کیل‌سوییچ:** فقط وایت‌لیست داخل رابط دقیق SSTP منتخب، همراه با استثناهای محدود کنترل تونل و DNS داخل آن. خروج مستقیم مجاز نمی‌شود؛ با قطع VPN، خروج پیش‌فرض Block باقی می‌ماند. فعلاً روش VPN فقط SSTP تمام‌تونل را پشتیبانی می‌کند، نه هر نوع VPN.

این دو روش، ایزولاسیون خروجی کل سیستم هستند، نه سیاست صرفاً یک برنامه و نه ادعای کنترل تمام بسته‌ها/ورودی ویندوز. در هر دو روش، وایت‌لیست از بلک‌لیست تنظیمات همین ابزار در محدودهٔ روش منتخب مقدم است؛ hosts و Block ابزارهای دیگر دور زده نمی‌شوند.

کدهای داخلی برای سازگاری: `blacklist_only`، `direct_isolation` (معمولی)، `full_isolation` (VPN). گزینهٔ مبهم `vpn_allowlist` دیگر انتخاب رابط نیست؛ تنظیمات قدیمی آن فقط خوانده می‌شود. باید روش جدید را بررسی و صریحاً ذخیره کنید؛ هیچ تبدیل ذخیره‌شده یا فعال‌سازی خودکاری انجام نمی‌شود.

### گردش کار

۱. سیاست و روش اتصال را انتخاب کنید. ۲. وایت‌لیست را تکمیل و سیاست را ذخیره کنید. ۳. «بررسی سادهٔ تنظیمات و مشکل‌ها» را بزنید. ۴. در صورت نبود مانع، «بررسی و اعمال ایزولاسیون کل سیستم» را اجرا و خلاصهٔ فارسیِ تغییر سراسری را آگاهانه تأیید کنید. بررسی، ذخیره یا تیک‌زدن، Apply نیست.

تغییر بین روش معمولی و VPN روی نشست فعال بدون Restore مجاز نیست. ابتدا روش قبلی را بازیابی، سپس روش جدید را بررسی و اعمال کنید. در فاصلهٔ بازیابی تا اعمال موفق، ایزولاسیون این ابزار فعال نیست. شکست عملیات هیچ Allow یا آزادسازی گستردهٔ خودکاری انجام نمی‌دهد.

## پیش‌نمایش ساده، بدون صفحهٔ کد

- دکمهٔ بررسی به صفحهٔ «بررسی سیاست / مشکل‌ها» می‌رود، نه JSON. ستون‌ها: نوع، مشکل/نکته، مورد و اثر، راه رفع/ادامه.
- هم‌پوشانی مجاز خطا نیست: IP/پورت، EXE و مجوز هم‌پوشان مشخص می‌شوند و توضیح می‌دهد وایت‌لیست مقدم است. برای بسته‌ماندن مقصد، مجوز هم‌پوشان را حذف/محدود کنید.
- برای ایزولاسیون روی ویندوز، بررسی فقط `Prepare` خواندنی را اجرا می‌کند: دسترسی مدیر، تشخیص SSTP در روش VPN، منبع قواعد، نشست قبلی و پروفایل‌ها. این دکمه Apply/Restore، تغییر فایروال، hosts یا Audit ندارد. خطاهای رایج با راه‌حل فارسی نمایش داده می‌شوند؛ خطای ناشناخته موفقیت اعلام نمی‌شود.
- بررسی بلک‌لیست، تنظیمات ذخیره‌شده را توضیح می‌دهد؛ وضعیت قواعد واقعی ویندوز از آن معلوم نیست و باید جدا خوانده شود. بررسی غیر ویندوزی، آمادگی واقعی را نامعلوم نشان می‌دهد.
- JSON فقط از «جزئیات فنی — اختیاری» قابل مشاهده است. ویرایش سیاست/وایت‌لیست، نتیجهٔ قبلی را برای ویرایش جدید نامعتبر می‌کند. نتیجه، مربوط به زمان بررسی است و اتصال یا نبود نشتی را تضمین نمی‌کند.

## بسته‌های فعالیت: یک ردیف اصلی، مسیرهای قابل انتخاب

- زبانهٔ پیش‌فرض رصد «بسته‌های فعالیت» است. هر نام دقیق DNS، مانند `telemetry-in.battle.net`، یک ردیف اصلی دارد؛ حتی اگر Agent.exe و Setup.exe هر دو آن را پرسیده باشند. نام‌های متفاوت صرفاً به خاطر شباهت متن «telemetry» ادغام نمی‌شوند.
- بسته را انتخاب و «تیک مسیرها / انتقال یکجا» را بزنید. مسیرها با EXE کامل، IP، پروتکل/پورت معلوم، PID/زمان تولد و منبع شاهد نمایش داده می‌شوند. «تیک همهٔ مسیرها» و «برداشتن همهٔ تیک‌ها» موجود است. انتقال به پیش‌نویس بلک‌لیست/وایت‌لیست گروهی است؛ یا خود نام دقیق دامنه را یک بار به hosts بفرستید.
- پاسخ DNS به تنهایی پورت ندارد؛ TCP/443 حدس زده نمی‌شود. برای آن مسیر صریحاً TCP/UDP و بازه، یا Any را انتخاب کنید. Any در بلک‌لیست یعنی دو بازهٔ TCP و UDP از 1 تا 65535؛ در وایت‌لیست یعنی همهٔ پروتکل‌ها. EXE بلک‌لیست باید از قبل در برنامه‌ها ثبت شده باشد؛ اگر یک EXE ثبت نشده باشد هیچ بخش از انتقال انجام نمی‌شود.
- مسیر تکراری همان EXE/IP/پروتکل/پورت تجمیع می‌شود. نام دامنه «فرایند مستقل» فرض نمی‌شود و هویت شواهد خام پاک نمی‌شود. انتساب DNS به مسیر فقط با هویت دقیق فرایند، IP یکسان و ترتیب زمانی است؛ IP مشترک چند نام، اثبات نام همین سوکت نیست.
- انتخاب همه فقط مسیرهای ثبت‌شده در این رصد را پوشش می‌دهد، نه فعالیت‌های ناشناخته/آینده. پوشش تمام فعالیت شبکه، DoH داخلی، کش‌ها، درایورها یا همهٔ پروتکل‌ها تضمین نشده است. IP مشترک ممکن است خدمات دیگر را هم شامل شود. نام‌های بدون DNS در بستهٔ EXE دقیق نمایش داده می‌شوند.
- انتقال ≠ ذخیره ≠ اعمال روی ویندوز. بلک‌لیست IP مخصوص EXE است؛ وایت‌لیست فعلی و hosts سراسری‌اند، نه مخصوص یک EXE. بررسی و تأیید دکمه‌ای باقی است؛ تایپ متن تأیید لازم نیست.

## اصلاح تشخیص DNS و خطاهای تصاویر ۰٫۹٫۸

- خط مبنا اکنون همانند رصد زنده، snapshot فایل واقعی hosts را می‌خواند؛ دیگر ثابت «در دسترس نیست» گزارش نمی‌کند. خطا/عدم دسترسی همچنان نامعلوم است، نه آزاد. این snapshot زمان شروع رصد است؛ پس از تغییر hosts رصد تازه بگیرید.
- ستون آخرین پاسخ، پاسخ همان رویداد اخیر است، نه مخلوط تمام پاسخ‌های تاریخی. `0.0.0.0`، `::`، صفر IPv4-mapped و loopback با برچسب پاسخ تهی/محلی نمایش داده می‌شوند؛ مقصد اینترنتی برای بلک‌لیست IP نیستند. دامنه را به hosts بفرستید. نگاشت عمومی مثل `::ffff:8.232.70.12` به IPv4 واقعی تبدیل می‌شود.
- DNS موفق صرفاً یعنی پاسخ DNS؛ نه اتصال موفق. پاسخ مخلوط، خطای DNS، درخواست هنوز پایان‌نیافته، تعارض hosts با پاسخ عمومی و منع WFP هرکدام مبنای مستقل دارند. از رنگ آبی نسخهٔ قدیم نمی‌توان نتیجه گرفت دامنه از راه دیگری وصل شده است.
- ذخیرهٔ hosts محلی با فایل واقعی فرق دارد. «بررسی فایل واقعی hosts» فقط می‌خواند. برای تغییر ویندوز، پیش‌نویس را ذخیره و «پیش‌نمایش / اعمال hosts» را با Administrator انجام دهید. ذخیرهٔ محلی موفق به معنی Apply موفق نیست.
- خطای بازهٔ پورت با نمایش بومی بازه برطرف شد. پاسخ تهی از گزینهٔ مقصد IP حذف می‌شود؛ آدرسهای خصوصی/ویژه همچنان با قاعدهٔ ایمنی رد می‌شوند و پیام شمارهٔ ردیف و مقصد را مشخص می‌کند. هیچ ذخیرهٔ ناقص یا آزادسازی مخفی انجام نمی‌شود.
- دکمهٔ «ایزولاسیون / کیل‌سوییچ» در بالای نوار کناری موجود است. وضعیت اولیه نامعلوم است؛ آخرین بررسی زمان دارد و رنگ سبز فقط پس از بررسی پیکربندی، اجرای محافظ و heartbeat تازه نمایش داده می‌شود. این رنگ تأیید نبود نشتی نیست. نصب یا ذخیره، محافظ را خودکار فعال نمی‌کند.

## وایت‌لیست، بازه و اولویت

- در صفحهٔ «وایت‌لیست و سیاست»، «افزودن بازهٔ IP / پورت» و «ویرایش / تبدیل خط به بازه» موجودند. برای ویرایش، نشانگر متن را در خط مقصد بگذارید. پیش‌نمایش پذیرفته‌شده همان خط را جایگزین می‌کند؛ لغو، خط قبلی را حفظ می‌کند.
- مقصد: IP، CIDR، از IP تا IP، wildcard انتهایی یا فهرست IP دقیق. پروتکل TCP/UDP و پورت از/تا شامل هر دو انتهاست. بازهٔ پورت وایت‌لیست به‌صورت بومی ذخیره می‌شود، نه هزاران خط جدا.
- قالب دستی هر خط: `8.8.8.8|TCP|443-445` یا `8.8.8.8|UDP|53`. قالب `8.8.8.8|ANY|*` تمام پروتکل‌ها/پورت‌هاست. IP/CIDR قدیمیِ بدون پسوند هم برای سازگاری یعنی تمام پروتکل‌ها و پورت‌ها؛ در بازبینی نهایی دقت کنید.
- نام دامنه، مجوز بومی ثابت نیست و خودکار Resolve نمی‌شود. انتقال چند مورد از رصد، الحاق/حذف تکرار دارد؛ نام خام قبل از اعمال باید به IP معتبر تبدیل شود. IP مشترک CDN معادل دامنهٔ منحصر‌به‌فرد نیست.
- در ویرایش ردیف بلک‌لیست، دکمهٔ «تبدیل به بازهٔ IP / پورت» اضافه شده است. پذیرش پیش‌نمایش ردیف قبلی را جایگزین می‌کند. بازهٔ پورت بلک‌لیست اکنون فشرده و بومی است: برای 10000-65535 یک ردیف با همین بازه، نه ۵۵۵۳۶ ردیف؛ حتی 1-65535 پشتیبانی می‌شود. سقف ۲۵۶ مقصد و ۱۰۲۴ قاعدهٔ بالقوه حفظ شده؛ بدون برش مخفی. حدود و EXE دقیق نمایش داده می‌شوند.
- **در روش اتصال منتخب، وایت‌لیست از بلک‌لیست تنظیمات همین برنامه مقدم است**؛ فقط هم‌پوشانی همان IP/پروتکل/پورت. در هر دو روش ایزولاسیون بقیهٔ مقصدها با خروجی پیش‌فرض Block منع می‌شوند؛ Block متعارض خود برنامه ساخته نمی‌شود.
- **در روش فقط VPN، وایت‌لیست مجوز خروج مستقیم نیست.** قواعد Block متعلق به دیگران و فایل hosts دست‌نخورده می‌مانند؛ Allow آن‌ها را دور نمی‌زند.
- مسیر قدیمی تحلیل برای سازگاری API باقی است ولی دکمهٔ رابط به آن نمی‌رود؛ بررسی ساده به‌جای گزارش بلاکرهای قدیمی نمایش داده می‌شود. فعال‌سازی فقط از موتور ایزولاسیون مستقل است.

## جزئیات روش فقط VPN / کیل‌سوییچ SSTP

1. سیاست «وایت‌لیست / ایزولاسیون کل سیستم» و روش «فقط از VPN — SSTP / کیل‌سوییچ» را انتخاب کنید، وایت‌لیست را تکمیل و «ذخیرهٔ سیاست» را بزنید. ذخیره به معنی اعمال نیست.
2. اگر بلک‌لیست Native قدیمی یا SstpKillSwitch قدیمی فعال است، ابتدا با ابزار خودش Restore کنید؛ برنامه آن‌ها را خودکار حذف/تصاحب نمی‌کند. گذار از ابزار قدیمی با قطع‌و‌وصل کنترل‌شده انجام شود؛ هیچ ادعای گذار بدون وقفه وجود ندارد.
3. یک SSTP تمام‌تونل متصل باشد؛ چند VPN، split tunneling، پرس‌وجوی ناقص پروفایل‌ها یا تشخیص نامطمئن رد می‌شود.
4. «بررسی و اعمال ایزولاسیون کل سیستم» را بزنید؛ تصویر قواعد Allow، سه پروفایل، رابط، سرور، DNS، مقصد/پروتکل/پورت و دامنهٔ اثر را بخوانید. ادامه فقط با تأیید دکمه‌ای است؛ متن تایپی لازم نیست.
5. بعد از پایان، «وضعیت ایزولیشن / محافظ» را بخوانید. `configuration_verified` یعنی بررسی همان لحظهٔ پیکربندی، نه تست بسته/اثبات نبود نشت. heartbeat محافظ و تطبیق تنظیمات ذخیره‌شده با سیاست فعال جدا گزارش می‌شوند.

### موتور چه می‌کند؟

- ژورنال محافظت‌شده در `%ProgramData%\UnifiedFirewallIsolation-098` با دسترسی Administrator/SYSTEM ساخته می‌شود. تصویر کامل قواعد Allow قبل از غیرفعال‌سازی ثبت، checksum و بازخوانی می‌شود؛ نوشتن تنظیمات هم پشتیبان محلی تأییدشده دارد.
- خروجی پیش‌فرض Domain/Private/Public در PersistentStore روی Block قرار می‌گیرد. Allowهای خروجی محلیِ فعال، حتی متعلق به پروفایل فعلاً غیرقابل‌اعمال، پس از ثبت تصویر غیرفعال می‌شوند. Allow غیرمحلی/GPO و bypass احراز هویت، مجوز فعال‌سازی نمی‌گیرند.
- وایت‌لیست روی نام دقیق رابط SSTP و InterfaceType=RemoteAccess محدود است، سراسری برای برنامه‌ها. داخل تونل هم فقط مقصد/پروتکل/پورت اجازه می‌گیرد.
- استثنای اتصال SSTP: فقط svchost معتبر مایکروسافت، سرویس SstpSvc، TCP/443 و IPهایی که به TCP برقرارِ همان سرویس و سرور پروفایل تطبیق دارند. سرور دامنه‌ای فقط از کش خوانده می‌شود؛ DNS بیرون تونل برای کشف سرور باز نمی‌شود. عدم اثبات، عملیات را رد می‌کند؛ fallback گسترده وجود ندارد.
- DNS سیستم فقط برای Dnscache، TCP/UDP 53 و DNSهای همان رابط، داخل همان تونل اجازه دارد. DNS فیزیکی، DHCP عمومی و همهٔ RemoteAccessها آزاد نمی‌شوند. این سخت‌گیری می‌تواند DHCP، تمدید شبکه، بعضی VPNها یا اتصال مجدد وابسته به DNS بیرون تونل را مختل کند؛ خودکار برای رفع مشکل دسترسی گسترده نمی‌شود.
- Task با نام `UnifiedFW-Isolation-<owner>` و SYSTEM از کد کپی‌شده در پوشهٔ محافظت‌شده اجرا می‌شود؛ نه از فایل قابل‌تغییر در پوشهٔ قابل‌حمل. در شروع ویندوز هم اجرا می‌شود. GUI لازم نیست باز بماند.
- محافظ دوره‌ای خروجی پیش‌فرض Block را نگه می‌دارد و Allow محلی تازه را فقط با ثبت تصویر قبل از تغییر غیرفعال می‌کند. خطا باعث Restore/Allow خودکار نمی‌شود. ژورنال بزرگ فقط هنگام تغییر نوشته می‌شود؛ heartbeat کوچک جداست.
- قطع VPN یا بستن رابط، پروفایل‌ها را Allow نمی‌کند. اتصال به همان رابط/سرورِ پین‌شده می‌تواند با قواعد پایدار ادامه یابد؛ تغییر نام/رابط/سرور، اجازهٔ تازهٔ خودکار نمی‌گیرد. دوباره بررسی و اعمال لازم است؛ نام/IP در کد ثابت نشده است.
- به‌روزرسانی سیاست فعال از مسیر Apply درجا انجام می‌شود؛ ابتدا Restore و آزادکردن پروفایل‌ها انجام نمی‌شود. شکست میانی با وضعیت partial/critical و حفظ محدودیت‌های موجود گزارش می‌شود.

### محدودیت امنیتی مهم

این محافظ دوره‌ای، ضمانت اتمی در برابر Administrator، GPO، برنامه‌های امنیتی دیگر یا فیلترهای WFP خارج از مدل نیست. Allow خارجی تازه ممکن است قبل از شناسایی اثر کند؛ Allow غیرمحلی تازه قابل قرنطینه نیست و وضعیت بحرانی می‌شود. رفتار اتصال‌های از قبل برقرار، راه‌اندازی مجدد، IPv6 و قطع ناگهانی باید روی دستگاه واقعی با مشاهدهٔ بسته آزمایش شود. سرویس‌اسکوپ SstpSvc روی هر سیستم قابل اثبات نیست؛ اگر تشخیص رد شد، استثنا را دستی به همهٔ برنامه‌ها گسترش ندهید. **این انتشار تأیید «بدون نشتی» نیست.**

## بازیابی و تنظیمات پیش‌فرض

- هر دو بخش بلک‌لیست و وایت‌لیست دکمهٔ «پیش‌فرض تنظیمات» و «پشتیبان‌ها / بازیابی تنظیمات» دارند. قبل از تغییر، تنظیمات و پیش‌نویس نمایش‌داده‌شده پشتیبان/بازخوانی می‌شوند؛ شکست پشتیبان‌گیری تغییر را متوقف می‌کند. محل: `private-state/policy-backups`؛ سقف ۲۰۰۰، بدون حذف خودکار. فایل‌های قدیمی را پیش از رسیدن به سقف در محل خصوصی بایگانی کنید.
- پیش‌فرض بلک‌لیست فقط همان لیست را خالی می‌کند. پیش‌فرض وایت‌لیست آن را خالی و حالت ذخیره‌شده را blacklist_only می‌کند. EXEها، مالک و بخش دیگر حفظ می‌شوند. بازیابی هم فقط بخش منتخب و با نسل تازه است؛ پیش‌نویس ذخیره‌نشده جدا برمی‌گردد.
- **تنظیمات پیش‌فرض یا ذخیرهٔ لیست خالی، قواعد فعال را Restore نمی‌کند.** وضعیت ذخیره و اعمال متفاوت‌اند. اگر نسل/هش/مالک تنظیمات با سیاست فعال فرق کند در وضعیت اعلام می‌شود.
- «بازیابی ایزولیشن» یا `Isolation-Recovery.cmd` با Administrator: Task متعلق به نشست متوقف می‌شود؛ فقط قواعد دقیق ثبت‌شده حذف، Allowهای بی‌تغییر به تصویر قبلی و فقط فیلد DefaultOutboundAction پروفایل‌ها به مقدار قبلی، از جمله NotConfigured، بازمی‌گردد. تعارض/تغییر خارجی به‌زور بازنویسی نمی‌شود؛ ژورنال نگه داشته می‌شود. این عمل حفاظت را صریحاً برمی‌دارد.
- `Recovery.cmd`: بازیابی موتور بلک‌لیست قدیمی؛ مستقل از ایزولیشن. ژورنال قدیمی در `%ProgramData%\UnifiedFirewallLab-050` است.
- `Audit-Recovery.cmd`: بازیابی سیاست Audit؛ مستقل از قواعد. Audit بعد از بستن GUI می‌ماند تا صریح بازگردانده شود.
- خطا یا بسته‌شدن اجباری هنگام تغییر Native به معنی «هیچ تغییری نکرد» نیست. Apply را کورکورانه تکرار نکنید؛ وضعیت/ژورنال و بازیابی مربوط را بخوانید. اگر Task متوقف شد ولی Restore به‌دلیل drift رد شد، محدودیت‌های باقی‌مانده حفظ می‌شوند؛ حفاظت کامل ادعا نمی‌شود.

## قابلیت‌های حفظ‌شده و اصلاحات قبلی

- بلک‌لیست IP در یک جدول با تفکیک پیش‌نویس، ذخیره و وضعیت زمان‌دار قواعد ویندوز است؛ دکمهٔ ذخیره، Apply نیست. اتصال ردیف رصد به EXE دقیق و انتخاب چند مورد حفظ شده است.
- تیک EXEها با شناسه‌های تخت، انتخاب‌های پنهان و فیلتر مدیریت می‌شود؛ نام یکسان با مسیر متفاوت یکی نمی‌شود.
- DNS برای هر مسیر کامل EXE + دامنه یک ردیف ثابت دارد؛ تکرار آدرس و تکرار اجرا شمارنده/IP/PID/زمان همان ردیف را به‌روز می‌کنند. هویت خام PID/زمان تولد برای انتساب شواهد حفظ می‌شود.
- پالس روی کل زمینهٔ ردیف است؛ زرد یعنی رویداد DNS و آبی فقط نمونهٔ TCP، **نه اثبات رسیدن درخواست به مقصد**. قرمز با مبنای جدا: شاهد منع Security 5157، یا پاسخ DNS تهی/محلی. پاسخ تهی، شاهد منع WFP نیست و شمارندهٔ منع را افزایش نمی‌دهد. نبود شاهد منع، «آزاد قطعی» نیست. وضعیت منع مرتبط با IP پاسخ DNS، خطای DNS، hosts و نامعلوم جداست؛ هم‌بستگی IP اثبات مسدودشدن خود نام دامنه نیست.
- تایمر تک‌ورودی و دریافت نتیجه یک‌باره مانع تکرار پنجرهٔ hosts و گیرکردن دکمه‌ها در حالت مشغول می‌شود؛ خطای نمایش یا Dispose هم آزادسازی را در finally دارد.
- «فقط پاک‌سازی کش DNS» مستقل از hosts، سرورهای DNS، Winsock و ETW است. موفقیت/شکست آن جدا گزارش می‌شود. بازنشانی hosts همهٔ نگاشت‌های سفارشی را با پشتیبان/بازبینی حذف می‌کند؛ با پاک‌کردن صرف کش اشتباه نگیرید.
- بازگردانی پشتیبان hosts، پشتیبان از وضع فعلی و کنترل digest دارد؛ شکست flush باعث تکرار نوشتن hosts نمی‌شود. نتیجه در صفحه/گزارش است، نه زنجیرهٔ MessageBox.
- hosts سراسری است؛ وایت‌لیست نمی‌تواند نگاشت hosts را خنثی کند. مسیرهای فایروال، hosts و Audit تأیید و بازیابی مستقل دارند. تایپ متن تأیید از رابط و Recovery حذف شده؛ تأیید/لغو دکمه‌ای باقی است.

## اعتبارسنجی، runtime و حریم خصوصی

نتایج دقیق آزمون‌های Python، PowerShell و parser در `evidence/release-validation.json` و فایل‌های مرتبط هستند. سناریوهای ایزولیشن شامل تقدم دقیق پروتکل/پورت، تشخیص SSTP، رد Allow غیرمحلی، ثبت تصویر، خرابی در checkpointها، drift، بازیابی NotConfigured و به‌روزرسانی بدون آزادکردن پروفایل است؛ آداپتورها ساختگی‌اند. Windows PowerShell 5.1، WinForms واقعی، DPI، Task Scheduler/SYSTEM، ACL و APIهای شبکهٔ ویندوز در این محیط Linux اجرا نشده‌اند.

runtime داخلی رسمی Python 3.13.12 از ۰٫۹٫۷٫۱ بایت‌به‌بایت حفظ شده است. MANIFEST-SHA256 صحت فایل‌های ثابت را بررسی می‌کند، نه امضای ناشر/Authenticode. موتور قدیمی نوشتن قواعد، hosts و Audit حفظ شده‌اند؛ اعتبارسنجی درخواست بومی برای پذیرش بازهٔ پورت معتبر به‌روز شده است؛ موتور ایزولیشن جدید و مستقل است. برنامه production-ready اعلام نمی‌شود.

private-state و گزارش‌ها شامل مسیر EXE، IP، دامنه، زمان و اطلاعات شبکه‌اند؛ خصوصی نگه دارید. بستهٔ تحویلی private-state کاربر ندارد؛ evidence فقط دادهٔ مصنوعی آزمون است. ژورنال محافظت‌شده برای بازیابی ضروری است؛ برای رفع خطا آن را حذف نکنید و از Firewall Reset یا EmergencyReset قدیمی به‌جای بازیابی محدود استفاده نکنید.

گزارش بخش‌به‌بخش بازبینی، محدودیت‌ها و چک‌لیست ویندوز در `ALL-TABS-REVIEW.fa.md` است.

## ارتقای محافظ پس از بازیابی

نام protected journal و marker داخلی 098 حفظ شده تا بازیابی قطع نشود؛ عنوان رابط 0.9.10 است. محافظ فعال نسخهٔ قدیم بی‌اجازه جایگزین نمی‌شود: بررسی/Apply روی آن پیام «ابتدا بازیابی نسخهٔ قبلی» می‌دهد. فقط پس از رسیدن نشست قبلی به restored و هنگام اعمال جدید، نسخهٔ محافظ در پوشهٔ امن با فایل موقت خصوصی/جایگزینی و readback ارتقا می‌یابد. حذف protected journal، reset گسترده یا پاک‌کردن private-state راه ارتقا نیست.
