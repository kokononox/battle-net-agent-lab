# HF1.2 — کاندید آفلاین، فقط برای بازبینی سورس

این بسته نسخهٔ اجرایی یا تأییدیهٔ ایزولاسیون نیست. روی سیستم آزمایش جایگزین HF1.1 نشود و با آن Apply انجام نشود. هیچ تغییر مخزن یا تغییری در سیستم ویندوز کاربر انجام نشده است.

## هدف ثابت
پایهٔ کوچک و قابل بررسی برای نصب/دانلود Battle.net روی مسیر مجاز SSTP؛ نه افزودن امکانات عمومی بیشتر. وایت‌لیست IP/پورت نمی‌تواند عدم ارسال فینگرپرینت در اتصال مجاز را ثابت کند.

## تغییرات
- کامپایلر، نام دقیق قانونِ کنترل اتصال SstpSvc به سرور مشاهده‌شده روی TCP/443 را جدا می‌کند.
- Arm پس از ساخت و مهرکردن قوانین غیرفعال، فقط همین قانون را با همان بررسی سخت‌گیرانه فعال می‌کند؛ سپس پروفایل‌ها Block و Allowهای قبلی قرنطینه می‌شوند. وایت‌لیست برنامه و DNS داخل تونل در مرحلهٔ بعد فعال می‌شوند.
- اگر فعال‌سازی یا بررسی قانون حمل SSTP شکست بخورد، هنوز تغییری در حالت پیش‌فرض پروفایل‌ها یا Allowهای قبلی شروع نشده است. این یک اصلاح ترتیب است، نه تراکنش اتمیک و نه اثبات علت قطعی حادثهٔ قبلی.
- Restore دارای استثنای صرفاً حذف است: قانون غیرفعال Allow متعلق به همان session/owner با تصویر مهرشده، فقط در صورت تفاوت InterfaceAlias، قابل حذف است. نام، گروه، توضیح، Local بودن، جهت، وضعیت و همهٔ سایر فیلدها بررسی می‌شوند؛ یک خواندن تازه پیش از حذف نیز لازم است. تصویر ژورنال بازنویسی نمی‌شود. این استثنا برای فعال‌سازی، Verify یا قوانین دیگر استفاده نمی‌شود و قوانین فعالِ دچار تغییر Alias همچنان نیازمند بررسی هستند.
- خواندن گروهی فقط یک نمونهٔ آزمایشی مستقل است و وارد کنترلر نشده: یک بار قوانین و هفت مجموعه فیلتر از یک Store خوانده و با کلید دقیق نمایه می‌شوند. تطابق نام حساس به حروف است و نام‌های دارای wildcard به‌عنوان داده پردازش می‌شوند. Snapshot اتمیک نیست و برای تصمیم تغییر/تأیید امنیتی قابل استفاده نیست.
- ژورنال بادوام، ترتیب Restore، و توقف guardian پس از Restore موفق حفظ شده‌اند. تغییرات فایروال موازی نشده‌اند.

## محدودیت‌های باز
- شروع VPN از حالت خاموش، DNS بدون cache، اعتبارسنجی TLS/گواهی، تغییر IP سرور، DHCP و سناریوهای reboot هنوز راهکار کامل و آزمون ویندوز ندارند. هیچ مجوز عمومی DNS یا TCP/443 برای دورزدن این مشکل اضافه نشده است.
- علت دقیق تغییر Alias در حادثهٔ قبل هنوز قطعی نشده؛ ترتیب قبلی یک خطر واقعی وابستگی داشت، اما مدل جای شاهد ویندوز را نمی‌گیرد.
- سرعت واقعی روی Windows اندازه‌گیری نشده. «هشت خواندن مجموعه» فقط شمار فراخوانی در آزمون بدل است؛ نه تعداد فراخوانی کل برنامه، نه ادعای چندبرابر سریع‌تر شدن.
- آزمون‌های این مرحله روی Linux/PowerShell 7 و بدل NetSecurity اجرا شده‌اند؛ سازگاری PowerShell 5.1 و رفتار واقعی Windows هنوز تأیید نشده‌اند.

## محتوای بسته
دو فایل تغییرکرده، نمونهٔ مستقل خواندن گروهی، دو آزمون جدید، diff، گزارش‌ها و SHA256. runtime، launcher، نصاب و فایل اجرای Apply وجود ندارد. اجرای آزمون‌ها به درخت سورس HF1.1 و وابستگی‌های آزمون اصلی نیاز دارد؛ این بسته ابزار آمادهٔ اجرا نیست.

## قدم بعدی
آزمون فقط‌خواندنیِ برابری تصویرهای گروهی و قدیمی در ویندوز، پیش از اتصال این بهینه‌سازی به Prepare. سپس طراحی و آزمون جداگانهٔ bootstrap اتصال SSTP در حالت خاموش؛ بدون بازکردن دسترسی عمومی و بدون آزمون Apply جدید تا تکمیل پیش‌نیازها.
