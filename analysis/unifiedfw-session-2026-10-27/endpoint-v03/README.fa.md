# گام فعلی: مشاهدهٔ مقصد SSTP v0.3

مشاهده‌گر واقعی فقط‌خواندنی آماده شده؛ هنوز روی Windows اجرا نشده است. ۵۸ assertion مدل/adapter جدید و ۸۴ assertion lifecycle قبلی در Linux گذشتند. چهار ماژول v0.2 بدون تغییر بایت‌اند. helper واقعی C# کامپایل و ABI x64 بررسی شد؛ این تست معادل فراخوانی APIهای Windows نیست.

تطبیق نام سرور/IP با cache محلی و TCP/443 مربوط به PID میزبان SstpSvc انجام می‌شود؛ دو مشاهدهٔ هویت زنده و دو snapshot پردازش/flow مقایسه می‌شوند. PID، زمان ایجاد پردازش، مسیر سیستم/hash فایل، اعضای سرویس و tuple/CreationTime اتصال بررسی می‌شوند. snapshotها اتمیک نیستند. PID مشترک فقط همبستگی پردازش است، نه مالکیت سرویس. حتی میزبان تک‌سرویس هم service-tag یا TLS را ثابت نمی‌کند.

**Authenticode عمداً فراخوانی نمی‌شود:** اعتبارسنجی زنجیره/ابطال ممکن است retrieval شبکه‌ای ضمنی داشته باشد. نتیجهٔ امضا همیشه false است؛ مسیر/hash اثبات اعتماد یا سلامت حافظهٔ پردازش نیست. هیچ lookup/probe/dial/hangup یا تغییر شبکه/فایروال درخواست نمی‌شود. JSON و احتمالاً فایل موقت Add-Type نوشته می‌شوند.

اقدام بعدی کاربر: فقط اجرای بستهٔ جداگانهٔ v0.3 با همان کاربر Windows و Administrator، در وضعیت فعلی VPN؛ بازگرداندن JSON پالایش‌شده حتی در شکست. Apply/Restore و تغییر VPN ممنوع نیستند به عنوان تصمیم مالک سیستم، ولی در این گام درخواست یا لازم نیستند. برای این آزمون انجامشان ندهید. اگر cache خالی بود ابزار آن را نامشخص گزارش می‌کند؛ خودکار DNS lookup یا استثنا نمی‌سازد.

هیچ binding روی کارت فیزیکی ندارد؛ Wi-Fi/Ethernet عملی هنوز آزموده نشده‌اند. ready_for_apply، no-leak، pin approved، اعتماد امضا، service tag، DNS/TLS bootstrap همگی تأیید نشده‌اند. هدف نهایی همچنان نصاب اختصاصی Battle.net است، نه گسترش داشبورد.

فایل‌ها و راهنمای اجرای فارسی در package؛ ZIP باینری در مخزن ذخیره نمی‌شود. PACKAGE-SUMMARY.json هش ZIP تحویلی را ثبت می‌کند. build.py و QA مسیرهای sandbox آزمایش را دارند و مستقیماً روی Windows کاربر اجرا نشوند؛ فقط محتویات package مخصوص اجرای Windows است.
