# Unified Firewall 0.8.0 — آزمون HTTPS/PHP روی هاست سی‌پنل

**نسخهٔ آزمایشی، نه انتشار نهایی امنیتی.** این نسخه پاسخ‌دهندهٔ PHP کوچک روی سایت مجاز شما را جایگزین نیاز به سرویس TCP اختصاصی می‌کند. نیازی به SSH، root، پورت جدید، Composer، تغییر وردپرس یا دادن رمز به ابزار نیست. هنوز سایت کاربر، PHP روی هاست و کنترلر جدید روی ویندوز آزمایش نشده‌اند.

## الان فقط این مرحله را انجام دهید

۱. بستهٔ ویندوز را در **پوشه‌ای جدید و محلی** استخراج کنید؛ روی نسخهٔ قبلی ننویسید و ژورنال قبلی را پاک نکنید.
۲. بستهٔ کوچک `UnifiedFW-PHP-Responder-0.8.0.zip` را روی رایانه استخراج کنید. در cPanel → File Manager به document root همان سایت بروید (اغلب `public_html`، ولی برای دامنهٔ افزوده ممکن است پوشهٔ دیگری باشد).
۳. **فقط فایل `.php` با نام `ufw-probe-...php`** را آپلود کنید؛ نام آن را تغییر ندهید. هیچ فایل موجود، `index.php`، `.htaccess` یا تنظیم سایت/SSL را بازنویسی نکنید. فایل دقیق و زمان انقضا در `DEPLOYMENT.json` بستهٔ کوچک آمده است.
۴. آدرس کامل فایل را با HTTPS در مرورگر باز کنید؛ نمونهٔ قالب: `https://YOUR-DOMAIN/ufw-probe-....php`. پاسخ JSON با `ready: true` فقط نشان می‌دهد همان پاسخ‌دهنده اجرا می‌شود؛ این نتیجهٔ آزمون فایروال نیست.
۵. اگر کد PHP به‌صورت متن/دانلود دیده شد، همان فایل را حذف کنید و ادامه ندهید؛ PHP اجرا نشده است. اگر ۴۰۴/۴۰۳/خطای SSL/۴۱۰ دیدید، متن یا عکس خطا را بفرستید. تنظیمات امنیتی هاست یا ModSecurity را خاموش نکنید. ۴۱۰ با پیام `temporary_probe_expired` یعنی زمان فایل تمام شده و باید فایل تازه بگیرید.
۶. در بستهٔ ویندوز، **`HTTPS-Endpoint-Check.cmd` را معمولی اجرا کنید؛ Run as administrator لازم نیست.** این ابزار یک درخواست آزمایشی HTTPS می‌فرستد و هیچ تغییری در فایروال، VPN یا route نمی‌دهد.
۷. آدرس کامل HTTPS فایل و IP عمومی منتخبِ سایت را وارد کنید. IP باید یکی از پاسخ‌های IPv4 DNS همان hostname باشد. IP اشتراکی می‌تواند مناسب باشد؛ SNI و Host برای همان دامنه و گواهی آن استفاده می‌شوند. در صورت CDN، IP نمایش‌داده‌شده در cPanel لزوماً IP فعلی DNS دامنه نیست؛ ابزار از IP دیگر به‌صورت خودکار استفاده نمی‌کند.
۸. برای تأیید مالکیت/مجوز مقصد، بنویسید `I CONTROL THIS TEST ENDPOINT`.
۹. تا پایان صبر کنید؛ سپس `Export-Lab-Results.cmd` را اجرا کنید و `EXPORT` بنویسید. فایل `UnifiedFW-080-LabResults-....zip` را قبل از ارسال بررسی کنید. نتیجهٔ `endpoint_ready` فقط پاسخ درست سایت از همین یک کلاینت است، نه تأیید مسیر VPN یا هم‌زیستی فایروال.

**فعلاً `HTTPS-Coexistence-Test.cmd` را اجرا نکنید.** ابتدا گزارش بررسی سایت و سپس گزارش پیش‌بررسی مسیر باید بررسی شوند. سرویس TCP و کلید SSH مرحلهٔ قبلی پاک شده‌اند؛ این روش به آن‌ها وابسته نیست.

## جزئیات پاسخ‌دهندهٔ PHP

- PHP نسخهٔ ۷٫۴ یا جدیدتر با JSON و قابلیت‌های استاندارد لازم است؛ هیچ بسته یا کتابخانه‌ای نصب نمی‌شود.
- فایل زمان انقضای مطلق UTC، حدود ۴۸ ساعت پس از ساخت، دارد. انقضا از نخستین بازدید محاسبه نمی‌شود و به ساعت درست هاست وابسته است. پس از انقضا، پاسخ ۴۱۰ می‌دهد؛ فایل خودکار حذف نمی‌شود. پس از اتمام آزمون خودتان آن را حذف کنید.
- GET فقط وضعیت کوتاه و زمان انقضا را می‌دهد. POST فقط JSON مشخصِ چهار فیلد `kind/nonce/request_id/role` با اندازهٔ حداکثر ۱۰۲۴ بایت و عمق محدود را می‌پذیرد و همان challenge را همراه `REMOTE_ADDR` برمی‌گرداند.
- نه فایل می‌نویسد، نه فرمان/شل اجرا می‌کند، نه فایل دیگری include می‌کند، نه سرویس راه می‌اندازد و نه درخواست خروجی شبکه می‌زند. احراز هویت/رمز ندارد؛ نام تصادفی فایل **جای احراز هویت نیست**. دادهٔ حساس به آن نفرستید.
- پاسخ no-store است؛ هیچ نشست/کوکی در کد ساخته نمی‌شود. وب‌سرور/هاست ممکن است طبق تنظیمات خودش مسیر و IP را لاگ کند. ابزار تنظیم لاگ میزبان را تغییر نمی‌دهد.
- `REMOTE_ADDR` ممکن است متعلق به پراکسی/CDN هاست باشد. `X-Forwarded-For` قابل اعتماد فرض نمی‌شود و IP برگشتی، اثبات مبدأ واقعی یا عبور از VPN نیست.
- اجرای پاسخ‌دهنده روی هاست و مجازبودن این درخواست‌های محدود تابع سیاست ارائه‌دهندهٔ شماست. در صورت منع، متوقف شوید؛ محدودیت هاست دور زده نمی‌شود.

## اتصال HTTPS چگونه محدود می‌شود؟

- فقط URL استاندارد `https://hostname/path.php` با hostname لاتین، بدون user/password، query، fragment یا پورت سفارشی پذیرفته می‌شود. URLهای HTTP، IP به‌جای hostname، path مبهم، `%` و `..` رد می‌شوند.
- پورت فقط TCP ۴۴۳ و آدرس اتصال فقط یک IPv4 عمومی انتخاب‌شده است. دامنه فقط برای DNS اولیه، SNI، Host و بررسی گواهی استفاده می‌شود؛ این قابلیت، وایت‌لیست دامنه‌ای سراسری نیست.
- DNS IPv4 یک‌بار پیش از شروع کنترلر بررسی می‌شود. هیچ DNS، پراکسی HTTP سیستم/محیط، تلاش روی IP دیگر، fallback به HTTP یا دنبال‌کردن redirect در خود probe انجام نمی‌شود. اگر سایت به www/دامنهٔ دیگری redirect می‌کند، URL نهایی درست را به ابزار بدهید؛ اعتبارسنجی گواهی را خاموش نکنید.
- Python با زنجیرهٔ اعتماد پیش‌فرض، hostname verification و حداقل TLS 1.2 اجرا می‌شود. کنترل مستقل PowerShell از SslStream و بررسی پیش‌فرض نام/زنجیرهٔ گواهی دات‌نت استفاده می‌کند، callback پذیرش همگانی ندارد و پیش از ارسال challenge نسخهٔ TLS 1.2 یا جدیدتر را لازم می‌داند. رفتار بررسی گواهی سیستم/دات‌نت، از جمله دسترسی‌های احتمالی سرویس‌های سیستم برای ساخت زنجیره، با ادعای «هیچ ترافیک سیستمی دیگری وجود ندارد» یکی نیست؛ این ابزار چنین ادعایی ندارد.
- پاسخ باید HTTP 200، JSON محدود، challenge همان درخواست و IP معتبر برگشتی داشته باشد. پاسخ HTML، گواهی نامعتبر، redirect، دادهٔ بزرگ، encoding فشرده یا framing مبهم موفقیت محسوب نمی‌شود. پاسخ Content-Length و chunked محدود پشتیبانی می‌شود.
- حداکثر دادهٔ پاسخ ۲۰۴۸ بایت و بودجهٔ wire پاسخ ۳۲۷۶۸ بایت است. probeهای Python و مرجع دات‌نت مهلت حدود ۸ ثانیه دارند؛ timeout/kill فرایند child تنها نشانهٔ خطای اجرا است، نه اثبات بلاک. کنترلر تغییر فایروال هرگز timeout/kill خودکار ندارد.

## مرحلهٔ بعد: پیش‌بررسی مسیر بدون تغییر فایروال

بعد از تأیید گزارش بررسی سایت، VPN را روشن نگه دارید و `HTTPS-Coexistence-Preflight.cmd` را با Run as administrator اجرا کنید. همان URL و IP را وارد کنید. این ابزار، به‌جز DNS اولیه و فایل گزارش محلی، فقط وضعیت فایروال، فایل‌ها، VPN و route انتخابی را می‌خواند؛ **هیچ درخواست HTTPS به مقصد و هیچ قاعدهٔ فایروال نمی‌سازد.** نتیجهٔ `ready_for_scoped_test` فقط آمادگی خوانده‌شده در همان لحظه است.

IP مقصد باید با IP اتصال VPN فرق داشته باشد و route انتخاب‌شدهٔ ویندوز باید با یک پروفایل SSTP متصل منطبق باشد. هیچ نام پروفایل مشخصی در کد ثابت نشده و route/VPN تغییر نمی‌کند. اگر split tunneling باعث انتخاب مسیر مستقیم شود، آزمون متوقف می‌شود؛ ابزار خودکار route نمی‌افزاید و VPN را قطع/وصل نمی‌کند.

## آزمون زندهٔ محدود، فقط پس از بررسی دو گزارش

`HTTPS-Coexistence-Test.cmd` را در کنسول محلی ویندوز، نه RDP، با Run as administrator اجرا کنید. عبارت اول `I CONTROL THIS TEST ENDPOINT` و عبارت دوم `TEST SCOPED COEXISTENCE` است. پنجره و VPN باز بمانند و آزمون دیگری هم‌زمان اجرا نشود.

فقط `runtime/python.exe` و `runtime/pythonw.exe` بسته، یک IPv4 و TCP ۴۴۳ تحت قواعد آزمایشی قرار می‌گیرند. برنامهٔ دیگری را هم‌زمان با همین runtimeها اجرا نکنید. کنترل REF از فرایند PowerShell و .NET به همان IP، hostname و path متصل می‌شود. هر probe یک اتصال و challenge تازه دارد.

ماتریس: پایه، وایت‌لیست شامل مقصد، وایت‌لیست خارج از مقصد، وایت‌لیست شامل مقصد با BL فقط A، فقط B، هر دو، و وایت‌لیست خارج از مقصد همراه BLِ A. در هر مرحله سه دور A/B/REF و سپس سه دور پس از Restore وجود دارد؛ حداکثر ۱۲۶ تلاش. مراحل ماتریس و دامنهٔ projection در `README-TCP-0.7.fa.md` نیز توضیح داده شده‌اند، ولی برای هاست سی‌پنل از launcherهای HTTPS این راهنما استفاده کنید، نه ابزار TCP قبلی.

کامپایلر اصلی مکمل وایت‌لیست را می‌سازد؛ این آزمون فقط تصویر آن را روی همین دو EXE/یک IP/یک پورت نصب می‌کند. قواعد بخش وایت‌لیست `RemoteAccess` و بخش بلک‌لیست `Any` interface هستند. هیچ Allow جبرانی، `Program=Any`، rule سراسری یا kill-switch نصب نمی‌شود. Block صریح بلک‌لیست با مجازبودن مقصد در وایت‌لیست خنثی نمی‌شود. فعال‌سازی وایت‌لیست سراسری در `APPLY LAB` همچنان مسدود است.

یک TCP connect موفق در مرحلهٔ بلاک، حتی اگر TLS/HTTP بعداً خطا دهد، شکست آزمون بلاک است. خطای منابع/آماده‌سازی/اجرای فرایند هم بلاک موفق حساب نمی‌شود. کنترل مرجع و اتصال‌های مجاز و بازیابی باید معتبر باشند؛ قطع اتصال به‌تنهایی موفقیت نیست.

## بازیابی و مرز تضمین

- نام‌های مالک‌شده، snapshot کامل قاعده و هفت فیلتر، ایجاد Disabled، capture پیش از بررسی معنایی، بازخوانی ActiveStore، قفل مشترک و ژورنال قبلی حفظ شده‌اند. مسیر ژورنال `%ProgramData%\UnifiedFirewallLab-050` و marker داخلی `0.6.0` عمداً سازگار مانده است. نشست Restoredنشده مانع اجرای جدید است.
- قبل و بعد از هر دور، مسیر/مبدأ/metric/پروفایل دوباره خوانده می‌شود. تغییر مشاهده‌شده باعث توقف و تلاش برای Restore می‌شود؛ این مشاهدهٔ دوره‌ای packet capture یا مراقبت پیوسته نیست و قطع گذرا/نشت بین بررسی‌ها را تضمین نمی‌کند.
- هر مرحله کل قواعد همان نشست مشترک را عمداً Restore و موجودی کامل فایروال را با خط مبنا مقایسه می‌کند. قواعد خارجی، profile، hosts، DNS، VPN، route یا سرویس سیستم تغییر داده نمی‌شوند. حذف گروهی یا Force Restore وجود ندارد.
- Restore در خطای معمول تلاش می‌شود؛ بستن اجباری پنجره، crash یا قطع برق تضمین cleanup ندارد. در drift یا `restore_failed` آزمون را تکرار نکنید؛ ژورنال را نگه دارید و گزارش/عکس بفرستید. `Open-Lab.cmd` → `RESTORE` فقط نشست ثبت‌شده و بدون force را بازیابی می‌کند.
- ویندوز CAS اتمی بین خواندن و cmdlet ندارد. این نسخه هنوز وایت‌لیست سراسری، IPv6/UDP واقعی، اتصال‌های باز قبلی، قطع VPN، kill-switch و نبود نشت را تأیید نمی‌کند. EXE واحد امضاشده و مهاجرت کامل ویژگی‌های قدیمی هم تکمیل نشده‌اند.

## شواهد، اصلاح قبلی و حریم خصوصی

آزمون واقعی بلک‌لیست ۰٫۶٫۱ روی ویندوز کاربر موفق بوده است؛ نتیجهٔ آن به معنی تأیید این کنترلر جدید نیست. ایراد ۰٫۷ در محدودکردن childِ TCP به پوشهٔ traffic-jobs، در حالی‌که نشست جدید در coexistence-jobs بود، اصلاح شده و تست پذیرش/رد مسیرهای واقعی child افزوده شده است. خطا می‌توانست probe را متوقف کند؛ چنین خطایی نباید بلاک موفق محسوب شود.

تست‌های این نسخه روی Linux شامل TLS واقعی محلی با CA خصوصیِ فقط آزمایشی، رد گواهی ناشناس و نام نادرست، header/JSON محدود و کنترلر با native/network/route doubles هستند. trust store سیستم در تست‌ها تغییر نمی‌کند. **PHP در محیط توسعه در دسترس نبوده و خود فایل PHP روی مفسر/هاست واقعی اجرا نشده؛ بررسی کد PHP استاتیک است. اجرای Windows PowerShell 5.1، GUI/DPI، سایت و PHP کاربر هنوز نیاز به تأیید دارند.** جزئیات دقیق در QA.json و evidence است، نه ادعای حفاظت.

خروجی ZIP فقط resultها و مشخصات QA/Build و هش‌ها را جمع می‌کند، نه requestها، بکاپ کامل فایروال، ژورنال محافظت‌شده، رمز یا کلید. ممکن است URL فایل، hostname، IPهای سایت/مبدأ و نام پروفایل/سرور VPN و مسیر EXE داخل گزارش باشد؛ قبل از اشتراک بررسی کنید. هیچ چیز خودکار آپلود نمی‌شود. گزارش ناتمام فقط snapshot است، نه نتیجهٔ نهایی.

manifest کنترل تغییر فایل است، نه امضای ناشر/ریشهٔ اعتماد. runtime همان نسخهٔ بستهٔ کاربر با تطبیق byte/hash است؛ ناشر دوباره اعتبارسنجی نشده. در GitHub فقط سورس/شواهد روی شاخهٔ analysis ذخیره می‌شوند، نه runtime و نه گزارش خصوصی ویندوز کاربر. تست‌های توسعه evidence را تغییر می‌دهند؛ فقط روی کپی اجرا شوند.
