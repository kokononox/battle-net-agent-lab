# بازسازی نخستین dispatcher از export شمارهٔ ۱ لودر

## نتیجهٔ تازه

مسیر import فایل اصلی به export شمارهٔ ۱ لودر از بررسی قبلی شناخته شده بود. در این گام، برای اولین بار نخستین dispatcher بدنهٔ این export در RVA 0x22EFF0 تحلیل نمادین شد؛ بازخوانی import/TLS کشف تازه محسوب نمی‌شود.

ترجمهٔ دستورهای حسابیِ آغازین از روی بایت‌های فایل و حساب ۳۲ بیتی انجام شد. مقدار DWORD سراسری به‌صورت متغیر آزاد باقی ماند، نه ثابت برابر مقدار دیسک. ۲۶ پرسش شاخه‌ای بررسی شد. هفت مرز خروج از نخستین dispatcher قابل‌رسیدن‌اند:

- 0x22F119
- 0x22F47B
- 0x22F4E2
- 0x22F3FF
- 0x22F5A2
- 0x22F607
- 0x22F54F

پرسش وجود ورودی پوشش‌داده‌نشده برای این dispatcher در Z3 برابر unsat شد. این فقط پوشش نخستین تصمیم‌گیری است، نه پوشش کل تابع، رسیدن به تمام این مسیرها در اجرای بازی یا نبود رفتار استثنایی.

بررسی مستقل با کتابخانهٔ استاندارد و decoder محدود MOV/CMP/پرش نسبی، بدون Capstone و Z3، ۱۰٬۰۰۴ ورودی را پیمود؛ هر هفت مرز در نمونه‌ها دیده شد. هفت شاهد حل‌کننده با محاسبهٔ مستقل تأیید شدند و بایت‌های ۴۹ دستور گزارش با فایل تطبیق یافت. نمونه‌گیری جایگزین اثبات همگانی نیست. دو خراب‌سازی شاهد/آدرس رد شد. یک خطای مقایسهٔ طول opcode در نخستین اجرای بررسی‌کننده اصلاح شد؛ فقط اجرای موفق نهایی مبنای verification.json است.

اگر مقدار global برابر بایت فعلی دیسک باشد، مرز نخست 0x22F119 است. **ثابت‌بودن مقدار دیسک در runtime فرض نشده است.** این مرز، هدف پیگیری مشروط است نه مسیر واقعی مشاهده‌شده.

## چرا اسکن مستقیم API کافی نبود

نام APIهای منتخبِ حفاظت/handler در واردات مستقیم دو فایل وجود نداشت. فهرست مستقل importها نشان می‌دهد لودر ۳۶ descriptor با FirstThunk مشترک دارد؛ پس نگاشت سادهٔ یک اسلات به یک API مشخص معتبر نیست. این ساختار قبلاً ثبت شده بود و کشف جدید نیست. نبود نام API به معنی استفاده‌نشدن از آن نیست. inventory.json فقط ثبت محدود بررسی قبلی است و producer کامل آن در این بسته نیست؛ نتیجهٔ تازه متکی به export-dispatch.json و source/export_dispatch.py است.

## حدود و قدم بعد

هنوز هیچ تابعی به‌عنوان رمزگشا، کلید، نویسندهٔ صفحات هدف یا handler استثنا شناسایی نشده است. هیچ بایت آماده‌شدهٔ جدیدی از صفحات بازی بازیابی نشده؛ دریافت/serialization/ارسال CPU یا BIOS نیز اثبات نشده است.

قدم بعد، تحلیل اثرهای هفت مرز بر حافظه و فراخوانی‌هاست؛ مرز مشروطِ 0x22F119 نقطهٔ شروع قابل‌بررسی است. تا یافتن رابطه‌ای مشخص، آن را مسیر آماده‌سازی صفحات یا رمزگشا نمی‌نامیم. اتصال خودکار import به اجرای export هم فرض نشده است.

هیچ ورودی PE اجرا/patch نشد، بازی attach نشد، protection تغییر نکرد و ابزار Windows جدیدی ساخته نشد. main و GUI 0.2 تغییری نکردند.

## بازتولید

ورودی: wow_loader.dll با SHA256 برابر c0a3c393db5cee834387e4f151fb97b109370330a0ed02310f597cad999b6b0c در /data/wlab-inputs. مسیرهای ثابت اسکریپت‌ها باید در محیط دیگر تنظیم شوند. وابستگی تولید: capstone 5.0.9 و z3-solver 4.16.0؛ بررسی مستقل فقط Python 3 می‌خواهد.

```bash
PYTHONPATH=/data/wlab-deps:source python source/export_dispatch.py
python source/verify_export.py
```

source/anchors.py و source/entry_paths.py فقط inventory و زمینهٔ ورودی را تولید می‌کنند. تمام یافته‌های نقش حفاظتی همچنان فرضیه‌اند، نه خروجی این inventory.
