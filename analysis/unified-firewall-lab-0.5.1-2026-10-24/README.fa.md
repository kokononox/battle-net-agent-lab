# Unified Firewall 0.5.1 — بستهٔ پذیرش آزمایشگاهی ویندوز

## اصلاح خطای ویندوز و بازیابی آزمون قبلی — ابتدا این بخش

دو گزارش واقعی ویندوز نشان دادند Package در فیلتر برنامهٔ desktop مقدار null دارد، نه Any. نسخهٔ ۰٫۵٫۱ فقط برای همین فیلتر، property موجود با مقدار null یا رشتهٔ Any را بدون محدودیت Package می‌پذیرد. property مفقود، رشتهٔ خالی، SID، آرایه و مقادیر عددی پذیرفته نمی‌شوند. استثنای عددی پروتکل نیز فقط به فیلد Protocol محدود شده است. خطاهای بعدی نام فیلد ناسازگار را گزارش می‌کنند.

**این ساخت هنوز آزمایشگاهی است و حفاظت بیرون VPN ندارد.** Package=null در گزارش واقعی مشاهده شده، ولی اجرای SELFTEST اصلاح‌شده در ویندوز هنوز در محیط توسعه انجام نشده است.

### ترتیب اجرای این بسته برای نشست ناموفق گزارش‌شده

1. در پوشه‌ای جدید استخراج کنید؛ نصب قبلی و ProgramData را دست نزنید. این بسته runtime را همراه دارد؛ Python جداگانه لازم نیست.
2. `Recover-Known-Test.cmd` را با Run as administrator اجرا کنید. این فرمان فقط قاعدهٔ Disabledِ مشخص‌شده در گزارش شما را بررسی می‌کند. برای اجازهٔ حذف همان قاعده عبارت زیر را دقیق وارد کنید:

```text
REMOVE KNOWN DISABLED TEST RULE
```

3. فقط اگر `Recovery completed` نمایش داده شد، در **همین نسخهٔ ۰٫۵٫۱**، `Open-Lab.cmd` را با Administrator اجرا کنید، `SELFTEST LAB` و سپس `TEST RULES` را وارد کنید. نسخهٔ ۰٫۵٫۰ را دوباره تست نکنید.
4. `Export-Lab-Results.cmd` و `EXPORT`، سپس فایل `UnifiedFW-051-LabResults-....zip` را ارسال کنید. هم نتیجهٔ repair و هم SELFTEST در گزارش قرار می‌گیرند؛ بکاپ و ژورنال کامل صادر نمی‌شوند. اگر repair خطا داد، ادامه ندهید؛ همین خروجی گزارش یا `private-state/recovery-jobs/.../result.json` را بفرستید.

### حدود بازیابی اختصاصی

- برای owner و session مشخص همان دو گزارش است؛ ابزار عمومی Force Restore نیست. پروفایل فایروال، قاعده‌های دیگر، سرویس‌ها، hosts و اتصالات را تغییر نمی‌دهد؛ هیچ قاعده‌ای فعال نمی‌شود.
- قاعدهٔ اول در هر دو گزارش Disabled و ثابت بوده؛ قاعدهٔ دوم موجود نبوده است. قبل از حذف، تصویر کامل قاعده و هفت فیلتر، هر دو store، نام دومِ ناموجود و ژورنالِ همان نشست دوباره بررسی می‌شوند. اگر قاعده فعال، تغییرکرده یا قواعد/نشست دیگری مشاهده شود، عملیات متوقف می‌شود. چک کامل بلافاصله پیش از حذف تکرار می‌شود؛ محدودیت نبود CAS اتمی ویندوز همچنان برقرار است.
- قبل از حذف، بکاپ همان ژورنال و رکورد intent در پوشهٔ محافظت‌شده ثبت می‌شوند. اگر پس از حذف قطع شود، اجرای دوبارهٔ همان repair می‌تواند با intent ثبت‌شده تکمیل شود. بدون چنین intent، ناپدیدبودن قاعده پذیرفته نمی‌شود. پس از تکمیل، قاعده‌ای که دوباره ظاهر شود خودکار حذف نخواهد شد.
- تصویر unsealed به‌عنوان قاعدهٔ معمول برنامه تصاحب یا فعال نمی‌شود. بعد از حذف تأییدشده و مشاهدهٔ نبود هر دو نام، نشست قبلی Restored علامت می‌خورد. ریشهٔ ژورنال عمداً همان UnifiedFirewallLab-050 باقی مانده تا نشست قبلی قابل بازیابی باشد.
- فایل recovery-expected.json حاوی اثرانگشت فنی همان قاعده و مسیر runtime گزارش شماست؛ داخل بستهٔ تحویلی شخصی قرار دارد و نباید عمومی منتشر شود. داده‌های تستِ گزارش ویندوز برای سورس عمومی ناشناس‌سازی شده‌اند.

### جلوگیری از تکرار orphan در خطاهای اعتبارسنجی

در مسیر جدید، بعد از ساخت Disabled و تأیید نام/گروه/نشانگر نشست/مالکیت، تصویر کامل ابتدا در ژورنال ثبت می‌شود. اعتبارسنجی معنایی بعد از ثبت و پیش از Enable است. بنابراین خطای معنایی بعدی می‌تواند بدون فعال‌شدن قاعده Restore شود. پنجرهٔ توقف بین ساخت و ثبت هنوز وجود دارد و هیچ ادعای حذف کامل آن یا تحمل خاموشی واقعی نمی‌شود.

---

**این فایل بستهٔ نهاییِ امنیتی نیست.** ویرایشگر مشترک و رصد چند EXE همراه با آداپتور واقعی فایروال و آزمون پذیرش ارائه می‌شود. رابط گرافیکی، PowerShell 5.1، NetSecurity و دستورات ACL هنوز روی ویندوز اجرا و تأیید نشده‌اند. موفقیت آزمون‌های لینوکسی جای آن‌ها را نمی‌گیرد.

## چه چیزی آماده شده؟

- انتخاب هم‌زمان حداکثر ۳۲ فایل EXE با مسیر کامل و SHA-256 مستقل؛ وابسته به نام Wow.exe نیست.
- بلک‌لیست هر برنامه یا مجموعه‌ای از برنامه‌ها: IP، CIDR یا بازه، TCP/UDP و پورت مقصد.
- موتور مشترک whitelist/blacklist با محاسبهٔ دقیق بازه‌های IPv4/IPv6 و گزارش هم‌پوشانی.
- اولویت Block بلک‌لیست برای همان EXE/پورت/پروتکل؛ افزودن Allow برای دورزدن Block انجام نمی‌شود.
- رصد TCP چند برنامه با جداسازی مسیر، PID، زمان شروع و دو سر اتصال؛ بدون تغییر سرویس، ETW یا audit. این رصد، گواه بسته‌های عبوری/مسدودشده نیست؛ UDP مقصد نیز رصد نمی‌شود.
- ورود مرحله‌ای تنظیمات نسخه‌های قبلی، بدون اجرای کد قدیمی و بدون حذف/تصاحب قواعد آن‌ها. تنظیمات وایت‌لیست دارای دامنه فعلاً یک‌جا رد می‌شوند؛ IP/CIDR/range پشتیبانی می‌شود.
- **مسیر واقعی و جداگانهٔ LAB** برای ساخت Blockها، بازخوانی هفت فیلتر، بررسی ActiveStore و Restore قواعد ثبت‌شدهٔ همان نشست.
- تست ویندوز `SELFTEST LAB`: ساخت دو Block محدود برای runtime خود بسته، خواندن قواعد، Restore، مقایسهٔ کامل موجودی فایروال قبل/بعد.

## مرز مهم حفاظت

| حالت | ویرایش / پیش‌نمایش | مسیر واقعی LAB |
| --- | --- | --- |
| blacklist_only | بله | Block مخصوص EXE روی همهٔ اینترفیس‌ها |
| vpn_allowlist | بله | Block مکمل whitelist روی **تمام RemoteAccess**؛ نه فقط یک پروفایل SSTP |
| full_isolation | فقط مدل تصمیم | **مسدود؛ Kill-switch پیاده نشده است** |

وایت‌لیست VPN محافظ بیرون تونل نیست. با قطع VPN مسیر عادی می‌تواند ترافیک را عبور دهد. انتخاب یک EXE نیز وایت‌لیست سراسری را به همان EXE محدود نمی‌کند. فقط مقصدهای واجد شرایط بدون Block جدید می‌مانند؛ اگر سیاست موجود DefaultOutbound=Block یا Block دیگری داشته باشد، ایجاد Allow صورت نمی‌گیرد و اتصال الزاماً برقرار نمی‌شود.

مانیتور قطع‌و‌وصل/تغییر مسیر، استثناهای امن حمل SSTP، مدیریت Allowهای خارجی برای ایزوله‌سازی کامل، بررسی بسته‌های IPv4/IPv6 و تست نبود نشت هنوز انجام نشده‌اند. **برای بازی/سامانهٔ حساس به حفاظت این نسخه اتکا نکنید.** ابزارهای ETW قبلی برای این مرحله لازم نیستند.

## محتویات و روش اجرا

در پوشه‌ای جدید روی دیسک محلی استخراج کنید، نه داخل نصب قبلی. برنامهٔ قبلی و بکاپ‌هایش را حذف/بازنویسی نکنید. Windows x64، Windows PowerShell 5.1، WinForms، NetSecurity و VpnClient لازم‌اند. Python همراه بسته است؛ نصب یا دانلود لازم نیست. این یک پوشهٔ portable است، نه EXE واحدِ تازه کامپایل‌شده و نه نصب‌کنندهٔ امضاشده.

### ۱. ویرایشگر و رصد — بدون اعمال قواعد

`Open-Preview.cmd` را اجرا کنید. انتخاب EXE، افزودن بلک‌لیست، ذخیرهٔ whitelist و پیش‌نمایش در همین پنجره است. تیک‌ها انتخاب هدف رصد/افزودن/حذف هستند، نه کلید روشن‌وخاموش سیاست. برخی خواندن‌های رصد ممکن است به دسترسی بیشتر نیاز داشته باشند و خطا/نقص نمونه‌برداری صریحاً گزارش می‌شود.

**تغییر تنظیمات، حذف EXE و بستن پنجره، قواعد LAB قبلاً اعمال‌شده را تغییر نمی‌دهد یا Restore نمی‌کند.** برای هر تغییر سیاست ابتدا Restore و سپس Apply تازه لازم است. به‌روزرسانی اتمیِ زنده پشتیبانی نشده است.

### ۲. ابتدا آزمون پذیرش روی ویندوز آزمایشگاهی / VM

این مرحله پیشنهاد اجرای فوری روی رایانهٔ بازی نیست. از کنسول محلی استفاده کنید، نه RDP یا سیستمی که قطع ارتباطش زیان دارد.

1. ابزارهای قدیمی را از مسیر خودشان **Restore** کنید و اجرا/زمان‌بند آن‌ها را متوقف کنید. ابزار جدید حق حذف قواعد قدیمی را ندارد.
2. `Open-Lab.cmd` را با **Run as administrator** باز کنید. هیچ UAC خودکار، تغییر دائمی ExecutionPolicy یا Bypass وجود ندارد. اگر سیاست سازمانی جلوی اجرا را گرفت، امنیت ویندوز را پایین نیاورید.
3. `STATUS` را وارد کنید. فقط وضعیت پروفایل‌های فایروال، VPNهای current-user/all-users، قواعد قدیمی شناخته‌شده، bypassهای احراز هویت‌شده و ژورنال خوانده می‌شود. قاعده یا پروفایل عوض نمی‌شود؛ فایل گزارش/قفل محلی ممکن است ایجاد شود.
4. دوباره باز کنید، `SELFTEST LAB` و سپس `TEST RULES` را وارد کنید. این دستور **دو قاعدهٔ واقعی موقت** برای `runtime/python.exe` و `pythonw.exe`، مقصد `1.1.1.1/32`، فقط TCP پورت 9 می‌سازد. هیچ اتصال/بسته‌ای برای آزمون ارسال نمی‌کند و وایت‌لیست سراسری نصب نمی‌کند.
5. نتیجه باید `ok=true`، `restored=true` و `baseline_strict_equal=true` داشته باشد. تغییر هم‌زمان توسط ویندوز/برنامه‌ای دیگر باعث رد آزمون می‌شود؛ این را موفقیت تفسیر نکنید.
6. `Export-Lab-Results.cmd` با تأیید `EXPORT` گزارش‌های همین آزمون را در ZIP محلی قرار می‌دهد. آپلود خودکار ندارد. قبل از اشتراک‌گذاری بازبینی کنید؛ مسیرها، نام VPN/سرور و IPها ممکن است در گزارش باشند. رمز، اعتبارنامه، بکاپ کامل فایروال و ژورنال محافظت‌شده جمع‌آوری نمی‌شوند.

**موفقیت SELFTEST فقط پذیرش ساخت/بازیابی دو Block است؛ نه تست GUI، وایت‌لیست VPN، UDP، تداخل واقعی دو ماژول، قطع تونل، نشت یا عبور بسته.**

### ۳. Apply واقعی تنظیمات — فقط برای آزمون آگاهانه

فقط پس از بررسی نتیجهٔ آزمون روی همان ویندوز و در محیط آزمایشگاهی:

- تنظیمات ذخیره‌شدهٔ ویرایشگر را بررسی کنید؛ برای ایزوله‌سازی کامل این نسخه مناسب نیست.
- کنسول LAB: `APPLY LAB` و سپس تأیید دقیق `I ACCEPT LAB NETWORK CHANGES`.
- برای تنظیمات واردشده، تأیید جداگانهٔ `OLD TOOLS RESTORED` لازم است. سوابق ورود پاک نمی‌شوند و قواعد قدیمی تصاحب نمی‌شوند؛ گارد ویندوز همچنان قواعد شناخته‌شدهٔ فعال قدیمی را رد می‌کند.
- قبل از Apply، هش EXEها دوباره در Python و PowerShell خوانده می‌شود. این هش، هویت فایل روی دیسک است، نه اعتبار ناشر یا تصویر بارشده در حافظه. تعویض فایل بعد از خواندن در این نسخه مهار نشده است.
- قفل تنظیمات تا پایان Apply نگه داشته می‌شود. برای هر نشست یک ژورنال مشترک شامل هر دو ماژول وجود دارد؛ تا Restore نشست قبلی Apply تازه رد می‌شود.
- گارد: سه پروفایل روشن، عدم منع قواعد محلی، نبود فیلتر bypass احراز هویت‌شده و نبود قواعد فعال قدیمی شناخته‌شده. در حالت وایت‌لیست، خواندن کامل VPN و حداقل SSTP متصل، بدون VPN متصلِ نوع دیگر، لازم است. نام پروفایل/سرور ثابت نیست. این بررسی، اثبات بایندینگ RAS/مسیر بسته نیست و پس از شروع پایش دائم نمی‌شود.
- ساخت فقط در PersistentStore، ابتدا **Disabled**، سپس تأیید معنا و هفت فیلتر و ثبت تصویر، سپس Enabled و بازخوانی. پس از پایان، معنا و هفت فیلتر ActiveStore هم بررسی می‌شوند. Apply چندقاعده‌ای اتمی نیست؛ هنگام ساخت، شکست یا تغییر خارجی ممکن است سیاست ناقص باشد. نتیجهٔ خطا هرگز به‌دروغ «هیچ تغییری نشده» اعلام نمی‌شود.
- هیچ تغییر در پروفایل‌ها، DefaultOutbound، قواعد خارجی، hosts، DNS، سرویس‌ها، audit یا ETW انجام نمی‌شود. مقدار پیشین `NotConfigured` با `Allow` جایگزین نمی‌شود، چون اصلاً پروفایل نوشته نمی‌شود.

### ۴. Restore و رفتار خطا

کنسول LAB را دوباره با Administrator باز کنید و `RESTORE` بنویسید. نیازی به فایل تنظیمات قبلی یا همان owner محلی نیست؛ ژورنال مشترک محافظت‌شده مبناست. نسخهٔ سالم و بدون تغییر همین بسته را نگه دارید.

- ژورنال ثابت: `%ProgramData%\UnifiedFirewallLab-050`، فقط SYSTEM و Administrators؛ مالک و DACL بررسی می‌شوند و برای فایل‌های جدید هنگام ساخت تعیین می‌شوند. مسیر reparse/UNC و مجوز نامطمئن پذیرفته نمی‌شود. این مسیر را پاک یا ویرایش نکنید.
- قفل فایل، اجراهای هم‌زمان این موتور را رد می‌کند؛ برنامه‌های مدیریتی دیگر ویندوز را قفل نمی‌کند.
- حذف فقط با نام دقیق و **برابری تصویر کامل ثبت‌شدهٔ قاعده و هفت فیلتر** صورت می‌گیرد؛ حذف wildcard/group وجود ندارد.
- اگر قاعدهٔ مالک‌شده بیرون از برنامه تغییر کرده باشد، Restore متوقف می‌شود؛ «Force restore»، بازنویسی قاعدهٔ خارجی یا ادعای موفقیت ندارد. قواعدی که تا آن لحظه بررسی/حذف شده‌اند ممکن است قبلاً بازیابی شده باشند.
- اگر فرایند بین ساخت Disabled و ثبت تصویر آن متوقف شود، قاعدهٔ Disabledِ بدون تصویر خودکار حذف/تصاحب نمی‌شود و `unsealed_rule_requires_inspection` گزارش می‌شود. بررسی دستی متخصص لازم است. برای سایر نقاط آزمایش‌شدهٔ میانی، ژورنال امکان Restore مجدد می‌دهد؛ تست خاموشی واقعی/خرابی دیسک انجام نشده است.
- پس از Apply ناموفق، `RESTORE` را اجرا و نتیجه را بررسی کنید. بستن پنجره یا reboot به معنی Restore نیست. فایروال را خاموش نکنید و سیاست کلی آن را reset نکنید.
- بین بازخوانی و cmdlet مخرب، ویندوز CAS اتمی ارائه نمی‌کند؛ تغییر هم‌زمان خارجی هنوز یک محدودیت است. SHA-256 ژورنال برای تشخیص خرابی است، نه امضای رمزنگاری؛ مدیر دیگر می‌تواند آن را تغییر دهد. قاعدهٔ خارجی با تصویر کاملاً یکسان از قاعدهٔ خود برنامه قابل تمایز نیست.

## آزمون‌های اجراشده در محیط توسعه

شواهد ماشینی در `evidence/` و `QA.json` هستند. آزمون‌های Python و PowerShell با mock/fixture روی Linux اجرا شده‌اند، نه ویندوز. شمارش assertion با شمارش test method یکسان نیست. جزئیات نقاط شکست و orphanهای عمدی صریح‌اند.

اجرا برای توسعه‌دهنده:

```text
python -m unittest discover -s tests -p "test_*.py"
pwsh -NoProfile -File tests/Test-Observer.ps1
pwsh -NoProfile -File tests/Test-PolicyTransaction.ps1
pwsh -NoProfile -File tests/Test-LiveSession.ps1
pwsh -NoProfile -File tests/Test-NativeAdapter.ps1
pwsh -NoProfile -File tests/Test-KnownRecovery.ps1
pwsh -NoProfile -File tests/Test-WindowsFixture.ps1
pwsh -NoProfile -File tests/Check-Parse.ps1
```

موتور mock قدیمی در experimental برای آزمون سیاست باقی مانده؛ آداپتور واقعی از موتور نشست جدید lab استفاده می‌کند. `MANIFEST-SHA256.json` صحت فایل‌های توزیع را می‌سنجد؛ ریشهٔ اعتماد یا امضای ناشر نیست. اجراهای تست ممکن است فایل‌های evidence را بازنویسی کنند و در نتیجه manifest بسته تغییر کند؛ تست‌های توسعه را روی یک کپی جداگانه اجرا کنید.

## موارد باز برای نسخهٔ نهایی

- اجرای GUI، PowerShell 5.1، سازنده‌های ACL، NetSecurity و SELFTEST روی Windows واقعی.
- آزمون واقعی چند EXE و whitelist/blacklist هم‌زمان با endpointهای کنترل‌شده، بررسی بسته و بازیابی قبل/بعد.
- Kill-switch ایمن خارج VPN، استثناهای حمل SSTP و DNS/IPv6، سرویس/مانیتور دائم و قطع‌و‌وصل/تعویض پروفایل؛ بدون این موارد ادعای نبود نشت مجاز نیست.
- مهاجرت کامل تاریخچه، PTR، DNS/WFP و hosts و قابلیت‌های قدیمی؛ فعلاً همهٔ آن‌ها به برنامهٔ جدید منتقل نشده‌اند.
- نصب/به‌روزرسانی/امضا و بسته‌بندی EXE واحد در صورت نیاز، تست خرابی فرایند واقعی و برق.
