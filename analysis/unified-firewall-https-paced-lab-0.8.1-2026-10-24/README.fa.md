# Unified Firewall 0.8.1 — آزمون هم‌زیستی HTTPS با فاصلهٔ چهار ثانیه

**بستهٔ آزمایشگاهی، نه انتشار نهایی امنیتی.** تغییر اصلی نسبت به ۰.۸.۰ زمان‌بندی درخواست‌های HTTPS است، نه قواعد یا دامنهٔ حفاظت. نسخهٔ جدید هنوز روی ویندوز کاربر آزمایش نشده است.

## برای ادامهٔ همین آزمایش

بررسی قبلی سایت و مسیر SSTP موفق بوده است. دو اجرای هم‌زیستی ۰.۸.۰ به‌علت timeout، قبولی کامل نداشته‌اند و بازیابی/برابری فایروال در گزارش‌ها تأیید شده است. سپس ابزار تشخیصی مستقل، با چهار ثانیه فاصله، هر ۱۸ اتصال A/B/REF را روی ویندوز موفق ثبت کرده است. این فقط دلیل انجام آزمون جدید است؛ علت timeoutها را ثابت نمی‌کند. بستهٔ تشخیصی در مسیر EXE دیگری اجرا شده است.

۱. ZIP جدید را در **پوشه‌ای جدید و محلی** استخراج کنید. روی ۰.۸.۰ ننویسید. پوشهٔ قبلی و ژورنال محافظت‌شده را پاک نکنید.
۲. فعلاً فایل تازه‌ای برای سایت لازم نیست؛ از همان PHP و URL قبلی استفاده کنید. انقضای مطلق آن `2026-10-26T05:47:49Z` است. ساعت انقضا از دانلود/بازدید جدید شروع نمی‌شود. پس از پایان آزمایش فایل PHP را از هاست حذف کنید.
۳. VPN با همان پروفایل SSTP متصل بماند. آزمون را در کنسول محلی، نه Remote Desktop، اجرا کنید. ابزار آزمایشی قبلی یا برنامه‌ای با runtimeهای همین بسته هم‌زمان اجرا نشود.
۴. روی `HTTPS-Coexistence-Test.cmd` راست‌کلیک و Run as administrator بزنید. آدرس کامل HTTPS فایل PHP و IPv4 عمومی منتخب سایت را وارد کنید.
۵. تأیید اول `I CONTROL THIS TEST ENDPOINT` و تأیید دوم `TEST SCOPED COEXISTENCE` است.
۶. **حدود ۱۰ تا ۱۵ دقیقه فرصت بدهید؛ در خطا/کندی ممکن است بیشتر شود.** مکث‌های چهارثانیه‌ای عمدی هستند. پنجره را اجباری نبندید و VPN را قطع نکنید. کنترلر فایروال timeout/kill خودکار ندارد.
۷. پس از پایان، `Export-Lab-Results.cmd` را اجرا و `EXPORT` وارد کنید. خروجی جدید `UnifiedFW-081-LabResults-....zip` است؛ قبل از ارسال بررسی شود. هیچ گزارشی خودکار آپلود نمی‌شود.
۸. اگر `drift` یا `restore_failed` دیدید، آزمون را تکرار و ژورنال را پاک نکنید؛ گزارش و عکس را بفرستید. بازیابی عادی فقط با `Open-Lab.cmd` → `RESTORE` و تطبیق دقیق قواعد ثبت‌شده انجام می‌شود؛ Force/group delete نداریم.

برای استفاده روی سیستم/مقصد جدید، ابتدا `HTTPS-Endpoint-Check.cmd` بدون Administrator (یک درخواست بدون قواعد) و سپس `HTTPS-Coexistence-Preflight.cmd` با Administrator (فقط خواندن مسیر/تنظیمات و DNS اولیه، بدون درخواست HTTPS یا قواعد) را اجرا و نتایج را بررسی کنید. خود آزمون زنده نیز پیش از اتصال/اعمال قواعد، admission، محیط، مسیر و نشست قبلی را دوباره بررسی می‌کند. آزمون با مسیر مستقیم/نامعلوم یا نشست Restoreنشده متوقف می‌شود.

## تغییر دقیق زمان‌بندی

- حداکثر ۱۲۶ تلاش تازه و ترتیبی؛ همان ماتریس پایه و شش حالت WL/BL. اتصال موفق یا ناموفق قبلی دوباره استفاده نمی‌شود.
- **حداقل چهار ثانیه از پایان یک probe تا probe بعدی** با ساعت monotonic؛ درون دورها، بین ماتریس‌ها و در مرز Restore/apply حفظ می‌شود. اگر کار بازیابی بیش از چهار ثانیه طول کشیده باشد، انتظار اضافی لازم نیست.
- بعد از هر مکث و بلافاصله پیش از هر درخواست HTTPS مسیر دوباره بررسی می‌شود؛ بررسی‌های قبل و بعد هر دور هم حفظ شده‌اند. این بررسی دوره‌ای packet capture یا محافظت پیوسته در برابر قطع VPN نیست.
- مهلت اتصال TCP همان سه ثانیهٔ قبلی است؛ TLS/HTTP و اجرای child نیز همان بودجهٔ قبلی را دارند. هیچ retry یا نادیده‌گرفتن خطای مرجع اضافه نشده است.
- گزارش جدید اعلان `https_pacing`، شمارهٔ سراسری probe، فاصلهٔ مشاهده‌شده، شروع/پایان UTC و مرحلهٔ فعال TCP/TLS/HTTP در خطاهای شبکه را ثبت می‌کند. timeout فرایند، خطای اجراست و بلاک موفق محسوب نمی‌شود.
- classifier برای گزارش‌هایی که اعلان pacing دارند، ترتیب و حداقل فاصله‌ها را نیز بررسی می‌کند؛ گزارش قدیمی هنوز برای سازگاری قابل خواندن است، ولی pacing جدید به آن نسبت داده نمی‌شود.
- متن خطای «بررسی اتصال پس از Restore» روشن‌تر شده است: شکست اتصال و شکست بازیابی سیاست دو نتیجهٔ جدا هستند؛ فیلد restore و مقایسهٔ خط مبنا باید جداگانه خوانده شوند.

## مرز قواعد و قبولی، بدون تغییر

فقط دو فایل `runtime/python.exe` و `runtime/pythonw.exe` داخل همین بسته، یک IPv4 و TCP ۴۴۳ درگیرند. بخش وایت‌لیست تصویر محدود قواعد Block مکمل روی RemoteAccess است؛ بخش بلک‌لیست Block با Any interface است. هیچ Allow جبرانی، Program Any، قاعدهٔ سراسری، تغییر profile/default policy، تغییر VPN/DNS/route یا kill-switch نصب نمی‌شود. بلک‌لیست صریح با مجازبودن IP در وایت‌لیست خنثی نمی‌شود.

مراحل: پایه؛ WL شامل مقصد؛ WL خارج از مقصد؛ WL شامل مقصد و BL فقط A؛ فقط B؛ هر دو؛ و WL خارج از مقصد همراه BLِ A. مرجع PowerShell مستقل است و نباید قطع شود. هر مرحله سه دور هنگام آزمون و سه دور پس از بازیابی دارد. هر خطای مرجع/اتصال مجاز، بازیابی ناموفق، تغییر مسیر یا اجرای نامعتبر، مانع قبولی است. TCP موفق در مرحلهٔ بلاک، حتی با شکست TLS بعدی، موفقیت بلاک نیست.

معماری ژورنال/نام مالک و snapshot دقیق قواعد و هفت فیلتر تغییری نکرده است. ایجاد Disabled، capture و تأیید قبل از Enable، بازخوانی ActiveStore، قفل مشترک و Restore فقط قواعد دقیقاً بدون تغییر حفظ شده‌اند. مسیر ژورنال `%ProgramData%\UnifiedFirewallLab-050` و marker داخلی ۰.۶.۰ عمداً سازگار مانده‌اند. crash/قطع برق/بستن اجباری پنجره cleanup را تضمین نمی‌کند و ویندوز CAS اتمیک میان read/cmdlet ندارد.

## HTTPS، هاست و حریم خصوصی

یک IPv4 عمومی که در DNS همان hostname باشد و TCP ۴۴۳ استفاده می‌شود. hostname برای SNI/Host و اعتبارسنجی گواهی است؛ وایت‌لیست دامنه‌ای سراسری نیست. HTTP بدون TLS، پراکسی HTTP، fallback IP و redirect دنبال نمی‌شود. Python/.NET نام و زنجیرهٔ گواهی را با روش پیش‌فرض و TLS 1.2 یا بالاتر بررسی می‌کنند؛ callback پذیرش همه یا تغییر trust store وجود ندارد. سرویس‌های سیستم برای زنجیرهٔ گواهی ممکن است ترافیک مستقل داشته باشند.

PHP همان فایل محدود قبلی است: JSON challenge، بدون نوشتن فایل، اجرای فرمان، include وردپرس یا درخواست خروجی. نام تصادفی احراز هویت نیست؛ اطلاعات حساس به آن نفرستید. REMOTE_ADDR ممکن است IP پراکسی هاست باشد و اثبات مسیر VPN نیست. تنظیمات SSL/ModSecurity/امنیتی هاست را خاموش نکنید. بعد از انقضای مطلق، پاسخ 410 اختلال فایروال یا شبکه محسوب نمی‌شود؛ فایل جدید لازم است.

ZIP خروجی نتیجه‌ها، Build/QA و هش‌ها را می‌گیرد، نه درخواست خام، کلید/رمز، بکاپ کامل سیاست یا ژورنال محافظت‌شده. مسیر EXE، URL سایت، IP مبدأ/مقصد و نام پروفایل/سرور VPN ممکن است داخل آن باشد؛ پیش از ارسال بررسی کنید. report ناتمام snapshot است، نه نتیجهٔ نهایی.

قبولی احتمالی این آزمون فقط همین تصویر محدود WL/BL را تأیید می‌کند؛ نه وایت‌لیست سراسری، اتصال‌های قدیمی، UDP/IPv6، kill-switch، قطع VPN یا نبود نشت. مهاجرت همهٔ قابلیت‌های قدیمی و EXE واحد امضاشده هنوز تمام نشده‌اند. UI فقط برچسب نسخه گرفته و بازطراحی/تأیید GUI روی ویندوز انجام نشده است. runtime از بستهٔ کاربر byte-identical منتقل شده؛ امضای ناشر دوباره بررسی نشده و manifest صرفاً هش است، نه امضا.

تست‌های محلی شامل کنترلر با doubles شبکه/Windows provider، ساعت monotonic شبیه‌سازی‌شده، early-wake، حفظ فاصله در مرز Restore، توقف تغییر مسیر بعد از مکث، عدم retry، حفظ ناموفق‌بودن مرجع و TLS واقعی محلی مثبت/منفی است. این‌ها جای آزمون واقعی نسخهٔ ۰.۸.۱ روی ویندوز را نمی‌گیرند. تست‌های توسعه فقط روی کپی اجرا شوند.
