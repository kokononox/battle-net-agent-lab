# Unified Firewall 0.7.0 — آزمون محدود هم‌زیستی بلک‌لیست و وایت‌لیست

**این بسته انتشار نهایی امنیتی نیست.** هدف این مرحله سنجش قواعد مشترک با دو فایل آزمایشی است، نه فعال‌کردن وایت‌لیست سراسری، قطع‌کن اضطراری VPN یا اثبات نبود نشت. نسخهٔ ۰٫۶٫۱ روی ویندوز کاربر ماتریس بلک‌لیست دو فایل و Restore برابر خط مبنا را گذرانده است؛ آزمون جدید ۰٫۷٫۰ هنوز روی ویندوز اجرا نشده است.

## الان از کجا شروع کنیم؟

۱. ZIP را در **پوشه‌ای جدید و محلی** استخراج کنید؛ روی نسخهٔ قبلی کپی نکنید و ژورنال قبلی را پاک نکنید.
۲. VPN را روشن نگه دارید. مقصد آزمون باید IPv4 عمومی متعلق به سروری باشد که مالک یا مجاز به استفاده از آن هستید. **IP مقصد باید با IP اتصال سرور VPN متفاوت باشد و مسیر ویندوز به آن از SSTP بگذرد.** ممکن است دو IP روی یک سرور باشند؛ دو دستگاه مجزا الزام نیست. ابزار هیچ route یا تنظیم VPN را برای فراهم‌کردن این شرط تغییر نمی‌دهد.
۳. ابتدا فقط `Coexistence-Preflight.cmd` را با **Run as administrator** اجرا کنید و IP و پورت آزمون را وارد کنید. پیش‌فرض پورت `39443` است.
۴. این پیش‌بررسی فایل‌ها، فایروال، VPN و مسیر انتخابی را می‌خواند؛ **نه اتصال آزمایشی به مقصد می‌زند، نه قاعده می‌سازد، نه فایروال/VPN/route را تغییر می‌دهد.** فایل گزارش محلی ساخته می‌شود. نتیجهٔ `ready_for_scoped_test` فقط آمادگی اولیه است، نه پاسخ‌گویی سرور یا تأیید امنیت.
۵. `Export-Lab-Results.cmd` را اجرا کنید و `EXPORT` بنویسید؛ فایل `UnifiedFW-070-LabResults-....zip` را بررسی و ارسال کنید. هیچ آپلود خودکاری وجود ندارد.

اگر فقط همان IP اتصال VPN را دارید، یا پیش‌بررسی خطای مسیر دارد، **آزمون زنده را اجرا نکنید**. افزودن route دستی، دست‌کاری VPN، غیرفعال‌کردن فایروال یا استفاده از سرویس ناشناس راه‌حل این مرحله نیست.

## پس از تأیید پیش‌بررسی: آماده‌کردن مقصد

در این بسته هیچ کلید SSH، اعتبارنامه، نصب خودکار یا اتصال خودکار به سرور وجود ندارد. سرویس موقت و کلید مرحلهٔ قبلی پاک شده‌اند؛ نباید فعال فرض شوند.

فایل `server/echo-server.py` باید روی سرور مجازِ مقصد با Python 3 استاندارد اجرا شود. نمونهٔ زمان‌دار:

```bash
python3 echo-server.py --bind 0.0.0.0 --port 39443 --seconds 1800 --max-connections 180
```

سرویس حداکثر ۳۰ دقیقه یا ۱۸۰ اتصال عمر می‌کند؛ با Ctrl+C زودتر متوقف می‌شود. این فرمان به‌خودی‌خود فایروال سرور را تغییر نمی‌دهد و کاربر غیرریشه/محدود برای اجرا مناسب‌تر است. تنها دسترسی مجاز به پورت آزمون را طبق سیاست سرور فراهم کنید؛ فایروال را خاموش یا reset نکنید. سرویس echo کوتاه، بدون shell/proxy/انتقال فایل و بدون TLS یا احراز هویت است. nonce جلوی اشتباه‌گرفتن پاسخ سرویس نامرتبط را می‌گیرد، نه حملهٔ MITM. لاگ شامل IP مبدأ است. روی محیط حساس تولیدی اجرا نکنید.

## اجرای آزمون زندهٔ محدود

فقط بعد از تأیید پیش‌بررسی و فعال‌بودن responder روی مقصد مجاز:

- `Coexistence-Test.cmd` را با Run as administrator، در کنسول محلی و نه RDP اجرا کنید.
- همان IP و پورت را وارد کنید.
- عبارت اول: `I CONTROL THIS TEST ENDPOINT`
- عبارت دوم: `TEST SCOPED COEXISTENCE`
- VPN روشن و پنجره باز بماند. پیشرفت مرحله‌ها چاپ می‌شود؛ فرایند کنترلر تغییر فایروال timeout یا kill خودکار ندارد.
- پس از نتیجهٔ نهایی/`Press Enter to close`، از `Export-Lab-Results.cmd` خروجی بگیرید؛ هم‌زمان آزمون دیگری اجرا نکنید.

A برابر `runtime/python.exe`، B برابر `runtime/pythonw.exe` و REF کنترل مستقل PowerShell/.NET است. هیچ EXE بازی یا برنامهٔ دیگر انتخاب/اجرا نمی‌شود. هر تلاش فرایند/سوکت و شناسهٔ تازه دارد.

## چرا این آزمون سراسری نیست؟

کامپایلر اصلی وایت‌لیست، مکمل مجموعهٔ مجاز IPv4/IPv6 را به Block روی `RemoteAccess` تبدیل می‌کند و هیچ Allow جبرانی نمی‌سازد؛ بلک‌لیست مستقل برای هر EXE/پروتکل/پورت است. Block صریح بلک‌لیست با قرارگرفتن مقصد داخل وایت‌لیست حذف یا دور زده نمی‌شود.

در این آزمایش ابتدا همان نقشهٔ کامل کامپایل می‌شود، ولی **فقط تصویر محدودشدهٔ آن روی دو EXE بسته، یک IPv4 و یک پورت TCP** نصب می‌شود. قواعد بخش وایت‌لیست همچنان `RemoteAccess` و قواعد بلک‌لیست `Any` interface هستند. قاعدهٔ عمومی `Program=Any`، مکمل سراسری شبکه یا Allow ساخته نمی‌شود. آدرس جایگزین داخل دادهٔ سیاست صرفاً برای ساخت حالت «خارج از وایت‌لیست» است و هیچ اتصالی به آن زده نمی‌شود.

بنابراین حتی `passed` فقط هم‌زیستی همین تصویر محدودشده را نشان می‌دهد؛ **عملکرد وایت‌لیست سراسری، نبود نشت یا عبور قطعی هر بسته از تونل را اثبات نمی‌کند.** فعال‌سازی وایت‌لیست سراسری در مسیر `APPLY LAB` این نسخه هم بسته شده است. Apply از رابط اصلی همچنان غیرفعال است؛ هیچ فعال‌سازی تولیدی خودکار نداریم.

## محافظ‌های مسیر و بازیابی

- پیش‌بررسی از `Find-NetRoute`، آدرس مبدأ، `Get-NetIPInterface` و VPNهای current-user/all-users استفاده می‌کند. مسیر باید با نام یک SSTP متصل منطبق باشد؛ نام خاصی مثل پروفایل فعلی کاربر در کد ثابت نیست و DNS resolve انجام نمی‌شود.
- قبل و بعد از هر دور سه‌تایی، انتخاب مسیر/مبدأ/metric/نام پروفایل دوباره خوانده می‌شود. تغییر مشاهده‌شده باعث توقف و تلاش برای Restore می‌شود. این snapshotها packet capture، احراز رمزنگاری‌شدهٔ نوع آداپتر یا مراقبت پیوسته نیستند؛ تغییر گذرا بین خواندن‌ها یا قطع تونل، تضمین عدم نشت ندارد.
- قواعد ابتدا Disabled ساخته می‌شوند؛ تصویر کامل قاعده و هفت فیلتر پیش از بررسی معنایی ثبت، سپس پس از تأیید فعال و در ActiveStore بازخوانی می‌شود. فایل‌های اجرایی هنگام پذیرش نقشه و پیش از probe هش می‌شوند؛ این امضای ناشر/اعتبار تصویر حافظه نیست.
- یک هماهنگ‌کننده و قفل مشترک در `%ProgramData%\UnifiedFirewallLab-050` نگه داشته می‌شود. این مسیر و نشانگر داخلی `0.6.0` عمداً با بازیابی قبلی سازگار مانده‌اند. نشست قبلیِ Restoredنشده مانع آزمون جدید است.
- هر مرحله از نام دقیق مالک‌شده و تصویر کامل برای بازیابی استفاده می‌کند؛ حذف گروهی، دست‌زدن به قواعد خارجی، profile/hosts/DNS/VPN/service/route یا Force Restore وجود ندارد.
- آزمون هر مرحله را به خط مبنا برمی‌گرداند؛ ویرایش/جابه‌جایی مرحله، به‌روزرسانی داغ قواعد فعال نیست. کل نقشهٔ همان نشست عمداً توسط هماهنگ‌کننده Restore می‌شود؛ دو موتور مستقل به جان قواعد یکدیگر نمی‌افتند. استقلال diff فقط در تست‌های محلیِ برنامه‌ریزی بررسی شده است، نه ویرایش زندهٔ مستقل هر بخش.
- در خطای معمول قابل‌گرفتن Restore تلاش می‌شود؛ crash، قطع برق یا بستن اجباری پنجره تضمین بازیابی ندارد. در خطای drift یا `restore_failed` آزمون را تکرار نکنید. ژورنال را نگه دارید و گزارش/عکس پنجره بفرستید؛ `Open-Lab.cmd` و `RESTORE` برای نشست ثبت‌شده موجود است، اما تغییر خارجی را force نمی‌کند.
- ویندوز بین خواندن و cmdlet CAS اتمی ندارد. تغییر مدیریتی هم‌زمان می‌تواند نتیجه را نامعتبر کند. اجرای دو آزمون هم‌زمان ممنوع است.

## سایر ابزارها و گزارش

`Open-Preview.cmd` همان ویرایشگر مشترک حداکثر ۳۲ EXE، چندانتخابی و رصد فقط‌خواندنی TCP است؛ ویرایش فایل تنظیمات قواعد فعال را به‌روز نمی‌کند. حذف/افزودن بلک‌لیست در نقشه، وایت‌لیست را بازنویسی نمی‌کند؛ تغییر وایت‌لیست هم مشخصات قواعد بلک‌لیست را عوض نمی‌کند. دامنه در whitelist پشتیبانی نشده؛ فقط IP/CIDR/range.

`Traffic-Test.cmd` برای آزمون قدیمی بلک‌لیست مستقل باقی مانده است؛ گزارش موفق ۰٫۶٫۱ موجود است و فعلاً لازم نیست تکرار شود. `SELFTEST LAB` قدیمی هم برای این مرحله لازم نیست. بازیابی اختصاصی orphan قدیمی عمداً در بسته نیست.

خروجی ZIP شامل resultهای lab/traffic/coexistence و مشخصات QA/Build و هش‌هاست، نه requestها، بکاپ کامل فایروال، ژورنال محافظت‌شده، رمز یا کلید. ممکن است نام پروفایل/سرور VPN، مسیر EXE، نام قاعده و IPهای مبدأ/مقصد داخل گزارش باشد؛ قبل از اشتراک بررسی کنید. گزارش ناتمام با هشدار به‌عنوان snapshot صادر می‌شود و نتیجهٔ نهایی محسوب نمی‌شود.

## دامنهٔ تأییدنشده

وایت‌لیست سراسری، IPv6/UDP در ترافیک واقعی، اتصال‌های قبلاً باز، قطع و تعویض VPN، استثناهای حمل SSTP، kill-switch و حذف نشت، مهاجرت کامل PTR/DNS/WFP/hosts/history و EXE واحد امضاشده هنوز تأیید یا تکمیل نشده‌اند. مشاهدهٔ route با شواهد قطعی مسیر بسته برابر نیست.

تست‌های Python/PowerShell و آداپترهای ساختگی این نسخه روی Linux اجرا شده‌اند. این تست‌ها اجرای زندهٔ کنترلر جدید روی Windows PowerShell 5.1 یا تأیید GUI نیستند. شواهد دقیق در `evidence/` و `QA.json` است. manifest کنترل تغییر فایل است، نه امضای ناشر یا ریشهٔ اعتماد؛ runtime از بستهٔ ارسالی کاربر با تطبیق byte/hash بدون تغییر کپی شده است. فقط سورس/شواهد وارد شاخهٔ analysis در GitHub می‌شود، نه باینری و نه اطلاعات خصوصی ویندوز کاربر. تست‌های توسعه evidence را تغییر می‌دهند؛ روی کپی اجرا شوند.
