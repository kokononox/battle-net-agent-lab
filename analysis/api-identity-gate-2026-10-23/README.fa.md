# گیت شناسایی API، پیش از ادامهٔ شاخهٔ handler

## نتیجهٔ بررسی تازه

wrapper کامل در بازهٔ pdata [0x20062EC, 0x2006320) از همان اسلات حل‌نشدهٔ 0x20A0750 استفاده می‌کند. بدنهٔ کوتاه ۱۳ دستور دارد: آرگومان ورودی را نگه می‌دارد، RCX را صفر می‌کند، اسلات موردنظر را call می‌کند، آرگومان اولیه را به اسلات دوم می‌دهد، خروجی اسلات سوم را با مقدار EDX=0xC0000409 به اسلات چهارم tail-call می‌کند. مقصدهای RIP-relative هر چهار انتقال از بایت‌ها محاسبه شدند. GNU objdump تمام مرزهای دستور را مستقل تأیید کرد.

این شکل با مسیر مدیریت خطا/خاتمه سازگار است؛ وجود این الگو هنوز هویت APIها را ثابت نمی‌کند. نام احتمالی برای اسلات نخست SetUnhandledExceptionFilter است. مستند Microsoft برای آن، ورودی NULL و بازگرداندن آدرس filter قبلی را توضیح می‌دهد، که با چند call site و ذخیرهٔ خروجی قبلی سازگار است. این تطبیق معنایی فقط فرضیه است، نه symbol بازیابی‌شده یا export match.

منابع قرارداد عمومی:

- https://learn.microsoft.com/en-us/windows/win32/api/errhandlingapi/nf-errhandlingapi-setunhandledexceptionfilter
- https://learn.microsoft.com/en-us/windows/win32/api/errhandlingapi/nf-errhandlingapi-unhandledexceptionfilter

## چرا توقف حدس‌زدن مهم است

نام import در دادهٔ در دسترس احراز نشده، مقدار دیسک runtime function pointer نیست و آدرس زنده هم نداریم. در این وضعیت، دنبال‌کردن بی‌پایان زیرتابع‌های دیگر را «رمزگشایی» نمی‌نامیم. برای این شاخه، ابتدا باید نام مقصد به‌طور معتبر تعیین شود. اگر واقعاً API معمول مدیریت استثنا باشد، این شاخه دیگر نامزد مستقیمِ اولویت‌دار برای بازکردن صفحات بازی نیست؛ این نتیجه تمام رفتار callbackها یا دیگر شاخه‌های لودر را رد نمی‌کند.

## آزمون تعیین‌کنندهٔ بعدی — هنوز ساخته یا اجرا نشده

آزمون پیشنهادی فقط یک خواندن ۸ بایتی از loaded wow_loader.dll + RVA 0x20A0750 است؛ همراه با هویت فرایند، base/path/size ماژول و تطبیق SHA فایل لودر. سپس pointer باید با آدرس دقیق exportهای ماژول‌های Windows متناظر در همان فرایند تطبیق یابد.

شرط‌ها:

- فقط اگر mapping، commit و readability تأیید شوند؛ توقف در PAGE_NOACCESS، guard، تغییر هویت یا خواندن ناقص.
- بدون dump کامل، خواندن صفحات کد هدف، debugger، تغییر protection یا نوشتن در فرایند.
- نام DLL مالک pointer به‌تنهایی نام تابع را ثابت نمی‌کند. تطبیق دقیق export با ماژول/فایل متناظر لازم است؛ aliasها باید حفظ شوند.
- اگر pointer به trampoline، کد hook، offset غیرexport یا ناحیهٔ ناشناخته برسد، نتیجه unresolved است؛ زنجیرهٔ دلخواه دنبال نمی‌شود.
- حتی تطبیق موفق API فقط binding نمونه‌برداری‌شده را روشن می‌کند، نه اجرای آن، صحت فرضیهٔ رمزگشایی یا ارسال اطلاعات.

این آزمون به اجرای محدود روی Windows کاربر نیاز دارد. محیط فعلی Linux است؛ چنین آزمایشی اینجا اجرا نشده و EXE جدیدی در این گام ساخته نشده است. خواندن موفق یا بی‌اثر بودن آن بر بازی تضمین نمی‌شود. هیچ نتیجهٔ Windows یا دسترسی زنده جعل نشده است.

## وضعیت

هیچ رمزگشا، کلید، کد آماده‌شده یا ارسال CPU/BIOS اثبات نشده است. ورودی PE اجرا/patch نشد. main و GUI 0.2 تغییری نکردند. پاسخ شخص ثالث هم پیش‌نیاز این گیت نیست.
