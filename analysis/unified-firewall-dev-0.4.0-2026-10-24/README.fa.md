# Unified Firewall 0.4.0 DEV — ادغام مرحله‌ای بلک‌لیست و وایت‌لیست

**این بسته نسخهٔ عملیاتی نهایی نیست. Apply و Restore فایروال در آن عمداً غیرفعال‌اند.**

این مرحله، دو سورس همین گفتگو را مبنا می‌گیرد: SSTP Whitelist 0.1.2 و WoW Blacklist با نسخهٔ داخلی 0.1.8 (هرچند نام ZIP دریافتی 0.1.0 بود). برنامهٔ دیگری روی میزکار کاربر دیده یا تغییر داده نشده است.

## قابلیت‌های پیاده‌شده

- یک پنجرهٔ مشترک برای ثبت چند EXE، وایت‌لیست، بلک‌لیست، پیش‌نمایش قواعد و رصد TCP.
- انتخاب تا ۳۲ EXE با هر نام، مسیر کامل و SHA256 مستقل؛ محدودیت نام Wow.exe برداشته شده است.
- تشخیص مسیر تکراری بدون حساسیت به بزرگی حروف. مسیر نسبی، UNC، ADS، مسیر مبهم و reparse point پذیرفته نمی‌شوند. هدر PE و پایداری فایل هنگام هش‌گیری بررسی می‌شود؛ امضای ناشر، بی‌خطر بودن فایل یا هویت تصویر داخل حافظه تأیید نمی‌شود.
- انتخاب هدف یک ردیف بلک‌لیست برای یک یا چند برنامه. تغییر یکی، فهرست سایر EXEها را جایگزین نمی‌کند.
- IP، CIDR و بازهٔ شروع–پایان برای IPv4 و IPv6، با محاسبهٔ بازه‌ای و بدون شمردن IPها.
- قواعد کاندید با شناسهٔ مستقل مالک/بخش/مسیر برنامه و مشخصات صریح دامنهٔ اثر تولید می‌شوند.
- ذخیرهٔ یکپارچهٔ تنظیمات با قفل و شمارهٔ نسل؛ یک درخواست قدیمی نمی‌تواند ویرایش جدید را بازنویسی کند.
- رصد چندبرنامه‌ای به‌صورت فقط‌خواندنی: تطبیق مسیر کامل، PID، زمان شروع فرایند، نشانی و پورت محلی و مقصد. استفادهٔ مجدد از PID بین دو snapshot همان نمونه رد می‌شود. دو EXE یا دو نمونهٔ یک EXE که مقصد مشترک دارند، یکی نمی‌شوند.
- ورود **تنظیمات** قدیمی به‌صورت مرحله‌ای؛ هیچ قانون قدیمی adopt یا حذف نمی‌شود و فایل اصلی تغییر نمی‌کند.
- موتور تراکنش مرحلهٔ قبلی در `experimental` حفظ شده و طرح مشترک به backend شبیه‌سازی‌شدهٔ فایل‌محور متصل و تست شده است؛ نه به NetSecurity واقعی.

## سیاست رفع تداخل

سیاست مشترک با سه mode تعریف شده است:

- `blacklist_only`: فقط محدودیت‌های هر برنامه در طرح لحاظ می‌شوند؛ ادعای Kill Switch ندارد.
- `vpn_allowlist`: وایت‌لیست سراسری روی **همهٔ رابط‌های RemoteAccess و همهٔ برنامه‌ها** است؛ بلک‌لیست برای برنامه‌ها و پورت/پروتکل منتخب، محدودیت تکمیلی می‌سازد. این mode حفاظت بیرون VPN نیست.
- `full_isolation`: قصد حفاظت بیرون تونل را هم ثبت می‌کند؛ ولی تا حل استثناهای SSTP، Allowهای موجود و ناظر اتصال، همیشه مسدود از فعال‌سازی است.

در قصد سیاست، مقصد داخل وایت‌لیست اگر برای همان EXE/پورت/پروتکل بلک شده باشد، همچنان مسدود است. این هم‌پوشانی به‌عنوان `blacklist_overrides_whitelist` همراه علت گزارش می‌شود؛ هیچ Allow بی‌خبر برای خنثی‌کردن آن ساخته نمی‌شود. تفاوت پورت یا TCP/UDP یا EXE حفظ می‌شود.

پیش‌نمایش تصمیم، فقط قصد همین تنظیمات را توضیح می‌دهد. `eligible_not_effectively_verified` به معنی «این سیاست مانع آن نیست» است، نه اثبات دسترسی؛ قوانین خارجی فایروال و مسیر واقعی در این نسخه بررسی/تغییر نمی‌شوند. `block` هم نتیجهٔ سیاست است، نه شاهد packet drop.

تفاوت مهم: «Undo تراکنش قبلی» با «برداشتن محدودیت یک بخش در تنظیمات جدید» یکی نیست. کد dry-diff و تست تراکنش نشان می‌دهند حذف جزء بلک‌لیست می‌تواند وایت‌لیست را نگه دارد؛ این رفتار هنوز روی فایروال واقعی تأیید نشده است. هیچ Reset سراسری یا Restore به Allow وجود ندارد.

## وضعیت اجرا و بسته

فایل `Open-Preview.cmd` رابط توسعه‌ای Windows x64 را باز می‌کند. runtime Python همراه بسته از فایل ارسالی قبلی **بدون تغییر** آمده؛ هر ۳۴ فایل با manifest همان بسته تطبیق داده شدند. runtime روی این محیط اجرا نشده و امضای ناشر آن دوباره بررسی نشده است. مجوز Python در `runtime/LICENSE.txt` حفظ شده است.

راه‌انداز از RemoteSigned فقط برای فرایند فرزند PowerShell استفاده می‌کند؛ سیاست دائمی کاربر/سیستم تغییر نمی‌کند و Bypass ندارد. اگر سیاست سازمانی یا امضا جلوی اجرا را گرفت، همان خطا را گزارش کنید و امنیت ویندوز را پایین نیاورید. ارتقای دسترسی خودکار انجام نمی‌شود.

**این بسته را در پوشه‌ای تازه و جدا نگه دارید. روی نصب قبلی کپی نکنید، private-state قبلی را جابه‌جا نکنید و Restore قدیمی را از این پوشه اجرا نکنید.** لازم نیست فعلاً آن را روی سیستم بازی اجرا کنید. این نسخه حفاظت نصب نمی‌کند و نباید به آن برای جلوگیری از خروج ترافیک تکیه کرد.

در رابط:

۱. چند فایل را انتخاب کنید؛ سپس برنامه‌های هدف را تیک بزنید. تیک‌ها فقط هدف عملیات فعلی‌اند و کلید فعال/غیرفعال کردن قواعد نیستند.
۲. در سیاست مشترک، mode و هر خط یک مقصد وایت‌لیست را ذخیره کنید. دامنه فعلاً در این رابط پذیرفته نمی‌شود؛ ورود config قدیمی دارای domain به‌صورت کامل رد می‌شود، نه اینکه دامنه‌ها بی‌خبر حذف شوند.
۳. در تب بلک‌لیست، مقصد و پورت و TCP/UDP را برای برنامه‌های تیک‌خورده اضافه کنید.
۴. پیش‌نمایش همهٔ قواعد، هم‌پوشانی‌ها و موانع فعال‌سازی را نشان می‌دهد. توضیح یک جریان، دقیقاً به یک برنامهٔ تیک‌خورده و یک IP تکی نیاز دارد.
۵. رصد انتخابی بین ۱ تا ۱۲۰ ثانیه است و توقف نرم دارد. گزارش در `private-state/jobs/<id>` می‌ماند. خطای خواندن یا تعداد نمونهٔ موفق صفر را «نبود ترافیک» تعبیر نکنید.

گزارش‌ها مسیر برنامه‌ها، SHA256، PID و مقصدهای شبکه را دارند؛ آپلود خودکار، DNS query یا جمع‌آوری رمز وجود ندارد. ثبت ردیف TCP، نمونه‌برداری از وضعیت socket است؛ نه تعداد درخواست، شمار دقیق اتصال‌های عمرکامل، محتوای بسته یا اثبات مسدودسازی. UDP/DNS/WFP این نسخهٔ قدیمی هنوز به ناظر جدید منتقل نشده‌اند؛ فرایند فرزند هم بدون انتخاب صریح فایلش وارد رصد نمی‌شود.

## ورود تنظیمات قدیمی

- بلک‌لیست: فایل `private-state/settings.json` نصب قبلی را انتخاب می‌کند؛ مسیر برنامه، هش قبلی و متن فهرست بررسی می‌شود. داده‌ها در نصب جدید ذخیره می‌شوند؛ فایل و مالکیت قبلی دست‌نخورده‌اند.
- وایت‌لیست: config JSON با schema نسخهٔ ۱ یا ۲ را برای IP/CIDR/بازه می‌پذیرد. دامنه‌ها تا تکمیل DNS snapshot و رضایت صریح، قابل ورود نیستند.
- بعد از import، طرح هشدار می‌دهد قوانین قبلی ممکن است همچنان فعال باشند. پاک‌کردن خودکار قواعد قدیمی یا فرض غیرفعال‌بودنشان مجاز نیست.
- تاریخچه، برچسب‌ها، مقایسهٔ ضبط‌ها، ویرایش hosts، PTR و DNS/WFP ابزار قبلی **هنوز مهاجرت داده نشده‌اند**. این بسته جایگزین کامل قابلیت‌های قبلی نیست و چیزی از آن‌ها را پاک نمی‌کند.

## تست‌های انجام‌شده

- ۴۸ روش تست Python روی لینوکس: ثبت چند برنامه، دامنهٔ EXE/پورت/پروتکل، هم‌پوشانی، تغییر هش، ورودی نامعتبر، قفل/نسل تنظیمات، import اتمیک، مالکیت و dry-diff، و درخواست/پاسخ واقعی در subprocess.
- تست‌ها شامل ۵۱۲ مقایسهٔ تصمیم در یک فضای کوچک آدرس برای دو برنامه‌اند.
- ۱۲ assertion تطبیق frame رصد در PowerShell 7.4.6 روی fixtureها؛ شامل PID reuse، مسیر متفاوت با نام یکسان، دو نمونهٔ یک EXE و ردیف تکراری.
- ۱۲ assertion اتصال طرح مشترک به تراکنش mock: حذف یک برنامه بدون حذف قواعد دیگری، برداشتن بلک‌لیست بدون پاک‌شدن وایت‌لیست و حفظ قانون Block خارجیِ مصنوعی.
- parse اسکریپت‌های PowerShell بررسی شده است. **هیچ تست رابط WinForms، runtime ویندوز، PowerShell 5.1 واقعی، رصد زندهٔ ویندوز، Apply، Restore یا نبود نشت انجام نشده است.**

کدها و خروجی‌های قابل‌بازبینی زیر `tests` و `evidence` هستند. runtime 3.13.12 بسته با Python 3.13.15 محیط تست یکسان نیست؛ تفاوت اجرا باید در تست ویندوز بررسی شود.

## قبل از نسخهٔ عملیاتی نهایی

اتصال واقعیِ محدود NetSecurity، قفل/ژورنال و Restore مشترک روی ویندوز، مهاجرت مالکیت قواعد موجود، تشخیص endpoint و سرویس SSTP، مدیریت Allowهای خارجی، DNS/IPv6، ناظر قطع‌و‌وصل، مهاجرت قابلیت‌های باقی‌ماندهٔ بلک‌لیست، تست رابط و سپس آزمایش کنترل‌شدهٔ نشت باید تکمیل شوند. تا آن زمان `activation_allowed=false` است و API درخواست‌های apply/restore/hosts_apply را رد می‌کند.

## توسعه و تکرار تست

```text
python tests/run_tests.py
pwsh -NoProfile -File tests/Test-Observer.ps1
pwsh -NoProfile -File tests/Test-PolicyTransaction.ps1
pwsh -NoProfile -File tests/Check-Parse.ps1
```

تست‌ها فقط fixtureها و فایل‌های موقت خود را تغییر می‌دهند. نسخهٔ گیت‌هاب source/evidence است؛ برای بازکردن رابط به runtime هم نیاز دارد که در ZIP کامل، همراه مجوز و هش‌ها آمده است.
