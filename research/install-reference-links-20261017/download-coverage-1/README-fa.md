# تطبیق ارجاع‌های Install/Encoding با Download ذخیره‌شده

این ابزار فقط یک سؤال را پاسخ می‌دهد: ارجاع‌های ثابت به‌دست‌آمده از گزارش قبلی، در متادیتای Download همین بیلد چه رکوردها، تگ‌ها و اندازه‌های encoded دارند؟ هیچ فایل بازی نصب، دانلود، تعمیر یا خراب اعلام نمی‌شود.

## اقدام روی ویندوز
۱. کل ZIP را در پوشه‌ای تازه، بیرون از بازی و Lab، استخراج کنید. با نسخه‌های قبلی مخلوط نکنید. Python 3.10+ کافی است و pip لازم نیست.
۲. CHECK-INSTALL-DOWNLOAD.cmd را اجرا کنید. پس از خواندن و تأیید محدوده، همان Lab موجود را انتخاب کنید؛ نه پوشهٔ بازی. Diagnostic build باید install-download-coverage-1 باشد.
۳. فقط INSTALL-DOWNLOAD-COVERAGE-to-share.json را از زیرپوشهٔ تازهٔ Results همین بسته بفرستید. اگر توقف کرد، متن تشخیص کنسول را بفرستید؛ دسترسی‌ها را تغییر ندهید و Administrator لازم نیست.

## محدودهٔ دقیق
- فقط فایل دقیق objects/5beff4cf8122da27a6788d9062c8d3c2-74562151.decoded در Lab انتخابی: یک گذر ترتیبی، حداکثر 74,562,151 بایت. تمام داده‌های خوانده‌شده برای MD5/CKey و SHA256 ثابت محاسبه می‌شوند؛ هیچ تگ/رکوردی پیش از موفقیت هویت نهایی منتشر نمی‌شود.
- جست‌وجوی نام فایل‌ها، پیمایش پوشهٔ کش، استخراج payload، اسکن آرشیو یا ساخت inventory انجام نمی‌شود. این یک گذر متادیتا است، نه تکرار مرور سنگین محلی.
- فایل Encoding و inventory و هیچ فایل بازی خوانده نمی‌شوند. شبکه، دریافت جدید، تغییر بازی یا Lab صفر است. فقط گزارش جدید در Results خود بسته نوشته می‌شود.
- دو ورودی کوچک داخل بسته هم بررسی می‌شوند: Install برابر 24,078 بایت و مراجع مشتق‌شده از گزارش قبلی برابر 20,275 بایت. هویت هر دو pin شده است.
- اگر Download دقیق موجود نباشد، گزارش نامعلوم تولید می‌شود: دانلود/تغییرنام/جابجایی کش یا تکرار اسکن نکنید.
- توقف زمانی پنج دقیقه است؛ توقف یا نبود ارجاع مجوز ادامهٔ خودکار نیست. نامعلوم مساوی مفقود/خراب بودن فایل بازی نیست.

## نتیجه چه چیزی را ثابت نمی‌کند؟
همهٔ گونه‌های Install در مراجع حفظ شده‌اند؛ هیچ سیاست انتخاب نصب از حدس تگ‌ها نتیجه‌گیری نمی‌شود. matching-or-unclassified صرفاً تشخیص تاریخی برای Windows/x86_64/EU/enUS است و پروفایل فعلی را دوباره اعتبارسنجی نمی‌کند.
اندازهٔ encoded در Download با اندازهٔ decoded در Install متفاوت است و این دو برابر فرض نمی‌شوند. وجود EKey در Download اثبات وجود/صحت payload محلی یا نیاز به دانلود نیست. هیچ جایگزین EKey انتخاب نمی‌شود.
گزارش قبلی Encoding منبع مراجع ثابت است، نه اثبات تازهٔ Encoding یا snapshot بازی. installation_ready و apply_authorized همچنان false و required_network_download_bytes نامعلوم می‌مانند.

## آزمون
۴۰ آزمون جدید Linux و ۶۹ آزمون رگرسیون هویت موفق‌اند. مسیر مثبت از Download مصنوعی و جایگزینی صریح pin فقط در تست استفاده می‌کند. اجرای بومی Windows و اجرای واقعی Download با این ابزار هنوز تأیید نشده‌اند. خواندن بدنهٔ Download/Encoding واقعی در محیط دستیار در این مرحله انجام نشده است.

روش اختیاری CLI: python -B install_download_coverage.py --help و سپس --lab با مسیر Lab. استفاده از --lab همان محدودهٔ دسترسی را بدون پنجرهٔ تأیید اجرا می‌کند.
