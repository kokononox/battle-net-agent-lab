# مانیتور محلی حریم خصوصی Retail — U1

این ابزار برای **مشاهدهٔ آپدیت واقعی روی سیستم خودتان** است؛ خودش بازی را آپدیت، Pause، Cancel، Repair، حذف یا اجرا نمی‌کند. فایل بازی را تغییر نمی‌دهد، لاگ خام/کلید TLS/محتوای درخواست را ذخیره یا آپلود نمی‌کند و وارد حساب نمی‌شود. فقط `.build.info` را برای شمارهٔ نسخه می‌خواند؛ اسکن ۱۳۰ گیگابایتی وجود ندارد.

**این ابزار دیوار تضمینی «فقط دانلود» نیست.** Frida برای مشاهدهٔ API داخل فرایندِ معتبر Blizzard بارگذاری می‌شود؛ این ابزارگذاری می‌تواند زمان‌بندی یا پایداری را تغییر دهد. ناشناس‌بودن، نبود همهٔ تله‌متری، دریافت‌نشدن اطلاعات توسط سرور، و مجاز/پشتیبانی‌شده‌بودن ابزار توسط Blizzard تضمین نمی‌شود. با بازی بسته آزمایش کنید؛ ابزار به Wow.exe یا ضدتقلب متصل نمی‌شود. اگر ابزار امنیتی ویندوز آن را مسدود کرد، توقف کنید؛ آنتی‌ویروس، Secure Boot یا بررسی گواهی را خاموش نکنید.

## وضعیت فعلی پروژه
آزمون H1 در دو VM نشان داد نام CPU داخل ورودی پیش از TLS به telemetry-in.battle.net در حالت عادی دیده شد و با مسدودسازی همان دامنه در نمونه دیده نشد؛ Agent و سرویس نسخه/CDN همچنان فعالیت داشتند. این نتیجه برای راه‌اندازی بود، نه آپدیت کامل Retail. U1 هنوز خودِ آپدیت شما را آزمایش نکرده است؛ نتیجه فقط بعد از اجرای شما معلوم می‌شود. فایل‌های بازی دارای اثر انگشت اختصاصی هستند یا نه همچنان سؤال باز است.

## دریافت و اجرا
1. بستهٔ ساخته‌شدهٔ `Local-Retail-Privacy-Monitor-U1` را از artifact اجرای مرتبط GitHub بگیرید و **کل ZIP را Extract کنید**؛ از داخل ZIP اجرا نکنید. Python یا نصب pip لازم نیست؛ runtime و وابستگی‌های هش‌پین‌شده همراه بسته‌اند. بسته بزرگ‌تر از اسکریپت ساده است چون Frida/Python دارد، اما بازی یا فایل آپدیت همراهش نیست.
2. نسخهٔ پشتیبان قدیمی روی اکسترنال را حفظ کنید. مسیر آزمایش فقط `G:\World of Warcraft` است؛ بکاپ را انتخاب نکنید. بازی بسته، آپدیت خودکار بازی خاموش و دانلود دستی فعلاً Pause باشد. پیش از اجرای اصلی، Battle.net را از tray هم ببندید. اگر Agent همچنان فعال باشد ابزار بدون بستن آن توقف می‌کند؛ ابزار هیچ PID متعلق به شما را نمی‌کشد.
3. روی `SelfTest-Only.cmd` راست‌کلیک → **Run as administrator**. خروجی باید `SELFTEST PASS` باشد. فقط خودآزمایی loopback و ورودی منفی EncryptMessage اجرا می‌شود؛ این آزمون جلسهٔ TLS واقعی یا آپدیت را اثبات نمی‌کند. اگر شکست خورد، آپدیت را برای این آزمایش ادامه ندهید؛ فایل `selftest-to-share.json` را بفرستید.
4. برای اجرای اصلی، `Start-Monitor.cmd` را با **Run as administrator** باز کنید. خودآزمایی دوباره داخل همان سیستم انجام می‌شود. مسیر نصب را وارد کنید؛ پیش‌شرط‌ها را فقط اگر واقعاً برقرارند با `CONFIRM` تأیید کنید.
5. منوی ۱ صرفاً مشاهده است. برای آزمون H1، **گزینهٔ ۲** و سپس `BLOCK` را انتخاب کنید. فقط `telemetry-in.battle.net` در hosts به 127.0.0.1 و ::1 نگاشت می‌شود و کش DNS ویندوز پاک می‌شود. هیچ hosts/blocklist قبلی شما حذف یا جایگزین نمی‌شود؛ اگر برای این دامنه ورودی قبلی باشد، ابزار از تغییرش خودداری و توقف می‌کند.
6. وقتی ابزار گفت، Battle.net را **خودتان باز کنید**، signed out بمانید و آپدیت را همچنان Pause نگه دارید. تا پیام **READY FOR OBSERVATION ONLY** نیامده ادامه ندهید. این پیام یعنی یک Agent با امضای معتبر Blizzard و قلاب‌های send/WSASend/EncryptMessage دیده شده، **نه تأیید نبود آپلود**. اگر READY نیامد، Update نزنید.
7. بعد از READY می‌توانید **خودتان** آپدیت را ادامه دهید. Initializing و Download هر دو در همان مشاهده‌اند؛ هیچ توقف خودکار یا دستور Update در ابزار وجود ندارد. بازی را هنگام اتصال مانیتور اجرا نکنید. شکست احتمالی آپدیت را با Cancel/Repair یا حذف فایل‌ها جبران نکنید؛ وضعیت و گزارش را بفرستید.
8. بعد از پایان آپدیت یا Pause دستی، در پنجرهٔ مانیتور Q بزنید و وضعیت واقعی را انتخاب کنید. پاسخ شما «گزارش کاربر» است، نه اثبات مستقل تکمیل. سقف پنجرهٔ مشاهده ۴ ساعت است. پایان ثبت، خود آپدیت را متوقف نمی‌کند.
9. فقط `output\report-....json` را بفرستید. **پوشهٔ PRIVATE-RECOVERY را نفرستید**؛ حاوی بکاپ خصوصی hosts شما برای بازیابی است. گزارش قابل اشتراک حاوی شمارهٔ نسخه، هش فایل اجرایی Blizzard، مقصدهای TCP عمومی، Host احتمالی، شمار ورودی API و نشانهٔ تطبیق نام CPU است؛ خود نام CPU، مسیر نصب، query/header/body یا اطلاعات ورود در گزارش صادر نمی‌شود. گزارش شامل IP سرور مقصد است، نه IP داخلی سیستم شما. خود ابزار گزارش را جایی ارسال نمی‌کند. تأیید امضای Windows ممکن است به سرویس گواهی ارتباط بگیرد.

## بازگردانی و توقف
- hosts در پایان به **بایت‌های اصلی** برگردانده می‌شود؛ اگر ابزار دیگری هم‌زمان آن را ویرایش کرده باشد، برای حفظ تغییرات آن ابزار از بازنویسی خودداری و `needs_manual_attention_journal_kept` اعلام می‌شود. این وضعیت را گزارش کنید؛ بکاپ را حذف نکنید.
- اگر برق قطع شد یا پنجره بسته شد، پوشهٔ ابزار را نگه دارید؛ `Restore-Hosts-Only.cmd` را با Administrator اجرا کنید. این کار فقط تغییر همان اجرای خود ابزار را برمی‌گرداند. شروع بعدی نیز بازیابی معلق را تشخیص می‌دهد و وارد تست تازه نمی‌شود. قفل تک‌نمونه اجازه نمی‌دهد اجرای دوم hosts مربوط به مشاهدهٔ فعال را بازگرداند.
- پس از بازگردانی hosts، **محدودسازی این دامنه دیگر برقرار نیست**؛ اگر Battle.net باز باشد فعالیت عادی آن می‌تواند ادامه یابد. در پایان/خطا قبل از خروج، آپدیت را تمام‌شده یا دستی Pause کرده باشید. Ctrl+C هم بازی را Pause نمی‌کند.
- نسخهٔ U1 برای نصب پوشه‌ای با اتصال NTFS junction/reparse آزمایش نشده و چنین مسیرهایی را رد می‌کند؛ symlink را برای دورزدن این محافظ عوض نکنید.

## مرز شواهد
این نسخه برای حفاظت از پایداری سیستم واقعی فقط attach می‌کند: فرایند Battle.net را launch، suspend، resume، gate یا terminate نمی‌کند؛ در نتیجه **اولین درخواست‌ها ممکن است پیش از اتصال از دست بروند**. قلاب‌ها آرگومان/بافر/نتیجهٔ API یا TLS verification را تغییر نمی‌دهند. نمونهٔ ورودی ۱۶KiB است و برای هر فرایند سقف دارد؛ اشباع در گزارش علامت می‌خورد. جزئیات تا ۲۰۴۸ ورودی ذخیره و شمارهای تجمیعی بعد از آن ادامه می‌یابند، با سقف جداگانهٔ تعداد گروه‌ها. تعداد ورودی API مساوی تعداد درخواست شبکه یا حجم بایت روی سیم نیست.

Host از همان بافر یا تاریخچهٔ کانال استخراج می‌شود و درجهٔ شاهد مشخص است؛ این اتصال رمزنگارانه به IP مقصد یا اثبات کامل درخواست نیست. TLS context reuse، ترتیب هم‌زمان، HTTP/2، OpenSSL، QUIC، رمزگذاری/فشرده‌سازی برنامه‌ای و فرایندهای خارج از فهرست نقاط کورند. نام CPU فقط در حافظه با مقدار مرجع سیستم تطبیق می‌یابد؛ نبود این رشته، نبود همهٔ داده‌های سخت‌افزاری را ثابت نمی‌کند. موفقیت EncryptMessage صرفاً موفقیت محلی رمزنگاری است، نه ارسال یا دریافت سرور. تغییر شمارهٔ نسخه و پاسخ Finished نیز صحت همهٔ فایل‌ها یا completion واقعی را اثبات نمی‌کند.

## وضعیت انتشار
فقط بسته‌ای قابل استفادهٔ آزمایشی است که workflow اختصاصی ساخت آن **خودآزمایی native ویندوز و آزمون‌های ایمنی را پاس کرده** و artifact مربوط به همان run منتشر شده باشد. پاس بودن CI فقط خود ابزار را می‌آزماید؛ پایداری روی HP/Windows 11 شما یا موفقیت آپدیت واقعی را تضمین نمی‌کند. رانر بزرگ/پولی فعال نمی‌شود؛ سهمیهٔ استاندارد GitHub Actions تابع حساب است.
