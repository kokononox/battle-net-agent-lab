# S2 — تمرین مسیر بازیابی، بدون تغییر شبکه

این بسته **ایزولاسیون یا کیل‌سوییچ را فعال نمی‌کند**. پیش از محدودکردن اینترنت کل Windows باید بدانیم Task Scheduler می‌تواند یک کار محلی SYSTEM را در زمان تعیین‌شده اجرا کند. این گام دو بخش مقدماتی را می‌سنجد: خروجی گرفتن از سیاست فایروال و اجرای زمان‌دار یک worker بسیار محدود که فقط رسید می‌نویسد.

## چه کاری می‌کند؟
- در ProgramData یک پوشه یکتا و خصوصی می‌سازد؛ دسترسی Allow فقط برای Administrators و SYSTEM، بدون inheritance از پوشه بالاتر. فایل‌ها را خودکار حذف نمی‌کند.
- با netsh **export** یک فایل firewall-before.wfw می‌سازد. این فایل ممکن است نام برنامه‌ها/مسیرها/آدرس‌های خصوصی داشته باشد؛ **آپلودش نکنید**. ابزار محتویاتش را در گزارش عمومی نمی‌ریزد.
- یک Scheduled Task یکتا با نام RetailIsolation-S2-Probe-… برای SYSTEM و ۴۵ ثانیه بعد ثبت می‌کند. worker کپی‌شده در همان پوشه خصوصی فقط یک JSON رسید می‌نویسد؛ import فایروال یا فرمان شبکه ندارد.
- حداکثر۱۲۰ثانیه برای رسید منتظر می‌ماند؛ هویت نشست، SYSTEM، scope و نتیجه Task را کنترل می‌کند؛ سپس فقط task خودش را، با کنترل هویت، حذف می‌کند. taskهای دیگر دست‌نخورده‌اند.
- خلاصه تنظیمات profile فایروال قبل/بعد را مقایسه می‌کند. این مقایسه همه rule/filterهای شبکه را نمی‌سنجد و تضمین عدم تغییر خارجی سیاست نیست.
- یک JSON کوچک قابل‌اشتراک در output می‌نویسد. آپلود خودکار ندارد.

## چه کاری نمی‌کند؟
هیچ firewall import، New/Set/Disable firewall rule، تغییر hosts/route/VPN، قطع/وصل اینترنت، کنترل فرایند Blizzard، Update/Pause، تغییر فایل بازی یا کاهش اعتبارسنجی TLS وجود ندارد. این بار برخلاف S1، **فایل backup و task موقت ساخته می‌شود**؛ فقط‌خواندن مطلق نیست، اما شبکه را تغییر نمی‌دهد. ExecutionPolicy Bypass فقط فرایند همین PowerShell است، نه policy پایدار.

موفقیت S2 **فقط آماده‌بودن این اجزای اولیه** را نشان می‌دهد؛ بازیابی واقعی firewall import، رفتار در قطع VPN/ری‌استارت/خرابی برق، مداخله GPO و enforcement تست نشده‌اند. independent_network_rollback_proven و ready_to_apply_isolation همچنان false می‌مانند. از backup این تمرین برای overwrite کورکورانه سیاست آینده استفاده نکنید؛ Apply آینده snapshot تازه و روش بازیابی دقیق و تست‌شده لازم دارد.

## اجرا
1. در پوشه تازه Extract کنید. نه S1 و نه runtime/Python لازم نیست.
2. WoW بسته و Update روی Pause؛ VPN و کیل‌سوییچ فعلی را تغییر ندهید. BAT99 یا Enable/Disable/EmergencyReset اجرا نکنید.
3. Start-Recovery-Rehearsal.cmd را با Run as administrator اجرا کنید. در مدت انتظار پنجره را نبندید؛ اینترنت/چت نباید به‌وسیله این ابزار قطع شود.
4. فقط فایل output/s2-rehearsal-to-share-….json را بفرستید. پوشه خصوصی ProgramData، فایل .wfw، worker/receipt خصوصی یا exportهای دیگر را نفرستید. اگر STOP دیدید همان متن را بفرستید؛ با خاموش‌کردن Windows Security یا سیاست سازمانی دورش نزنید.

اگر پنجره زود بسته شد، task باقی‌مانده فقط رسید می‌نویسد و هیچ rule را تغییر نمی‌دهد؛ مجدداً ابزار را برای پاک‌کردن همه taskها اجرا نکنید. نام task یکتا و پوشه خصوصی را نگه دارید تا همان مورد بررسی شود. backup خصوصی را تا پایان بررسی نگه دارید؛ پاک‌سازی بعداً دستی و فقط با مسیر دقیق خواهد بود.

## کنترل منبع
SHA256SUMS.txt و رسید ساخت همراه‌اند. آزمون Windows شامل parser/AST،۱۷ fixture مصنوعی و اجرای واقعی همین rehearsal (export و task SYSTEM) روی runner موقت استاندارد است؛ نه آزمون سیستم شما، نه تست firewall import و نه دانلود بازی. فایل‌های واقعی policy از runner هم آپلود نمی‌شوند. هیچ داده‌ای به مخزن SSTP شما فرستاده نمی‌شود.
