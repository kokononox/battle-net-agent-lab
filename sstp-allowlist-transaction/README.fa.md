# P4 — موتور مرجع تراکنش با مدل فایلی؛ نه فایروال واقعی

این ماژول مدل «guard / پروفایل‌ها / Allowهای قدیمی / قواعد خود ابزار» را به journal واقعی P2 وصل می‌کند. **تنها adapter آن model.json است. هیچ cmdlet فایروال/VPN/DNS یا guard واقعی ندارد.** P3 هنوز برای اعمال شبکه به این موتور متصل نیست. دستور Enable/Disable این فایل صرفاً عملیات روی مدل تست است، نه فرمان قابل استفادهٔ کاربر.

## ترتیب
Enable: ثبت snapshot اولیه؛ ثبت intent پیش از هر عملیات؛ guard مدل؛ غیرفعال‌کردن Allowهای مدل؛ Block کردن default مدل؛ ساخت قواعد خود مدل؛ بررسی کامل وضعیت مدل؛ حذف guard مدل. Disable: تطبیق وضعیت فعلی با journal؛ حفظ snapshot اولیه؛ ثبت وضعیت واقعی پیشرفت جزئی؛ گرفتن guard مدل؛ بازگردانی مقادیر اولیهٔ دقیق، از جمله NotConfigured؛ حذف قواعد خود مدل؛ بررسی همهٔ مقادیر؛ حذف guard مدل.

برای pending، خواندن تازه از adapter تعیین می‌کند عملیات هنوز اجرا نشده یا اجرا شده ولی ack ثبت نشده است. هیچ قدمی صرفاً بر اساس cursor قدیمی تکرار نمی‌شود. تمام منابعِ قبلاً تأییدشده و هنوز اجرا‌نشده نیز با frontier مورد انتظار مقایسه می‌شوند؛ هر اختلاف خارجی توقف می‌دهد. عملیات بدون intent پیشین که اتفاقاً به مقدار desired رسیده باشد، خودکار به ابزار نسبت داده نمی‌شود.

قفل جداگانهٔ transaction.lock کل یک فراخوانی را می‌پوشاند؛ قفل داخلی journal نیز برای نوشتن‌ها برقرار است. پس از خروج هیچ فرایند یا handle اختصاصی باقی نمی‌ماند. نبود یا خرابی journal اجازهٔ reset یا بازکردن شبکه نمی‌دهد. تغییر جهت Enable وسط Disable ناتمام رد می‌شود. Disable از Enable نیمه‌تمام در مدل قابل تعریف است، ولی این به معنی آزمون restore واقعی Windows نیست.

## آزمون
۳۸ حالت termination فرایند: ۳۶ حالت قبل/بعد هر کدام از۹عملیات در هر دو جهت Enable/Disable. intent پیش از termination به فایل نوشته شده، worker با Environment.Exit(73) واقعاً خاتمه می‌یابد و recovery در powershell.exe جدید اجرا می‌شود. دو حالت اضافه، Disable از Enable نیمه‌تمام را پیش/پس از یک تغییر پروفایل مدل بررسی می‌کنند. termination داخل syscall فایل، قطع برق و reboot واقعی در این آزمون نیست. مدل adapter فایل را عادی می‌نویسد؛ مدل خرابی دیسک/WFP نیست.

برای هر حالت، journal، نتیجهٔ بازیابی، تکرار بی‌اثر و این invariant مدل بررسی می‌شوند: یا guard مدل blocked است یا کل مدل دقیقاً baseline یا policy نهایی است. **این invariant هیچ ادعایی دربارهٔ بسته‌های شبکه ندارد.** تست اضافه: journal مفقود/primary خراب/ساختار semantically نامعتبر، تغییر خارجی، قفل همزمان و منع برگشت از Disable نیمه‌تمام.

## کار باقی
guard و readback واقعی WFP/NetSecurity، قرارداد snapshot تمام شروط، adapter تغییر Allowهای قبلی/default/قواعد خود، unmanaged/GPO، مدیریت inbound/LAN، binding دقیق SSTP، قطع‌وصل/DNS/IPv6/boot و آزمون packet مستقل. هیچ فایل اجرایی محصول یا تضمین no-leak از P4 نتیجه نمی‌شود.
