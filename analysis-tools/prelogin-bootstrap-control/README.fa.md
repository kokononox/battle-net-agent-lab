# کنترل مستقل بوت‌استرپ b2، بدون Frida

این کنترل برای بررسی مانع a12c/a12d است، نه بازآزمایی رمزگشایی شبکه و نه اثبات عدم ارسال اطلاعات. فقط روی Windows 2025 تازهٔ GitHub، شاخهٔ تحقیق، push مجاز و attempt اول اجرا می‌شود. هیچ Frida package نصب یا import نمی‌شود و هیچ کد، DLL، hook یا certificate به هدف تزریق نمی‌شود.

همان observer موجود با Popen عادی، همان bootstrap SHA و بررسی Authenticode، همان محیط پاک فرزند و سقف ۱۵۰ ثانیه اجرا می‌شود. انتخاب زبان فقط در چارچوب guard قبلی مجاز است؛ polling فقط قبل از شروع helper و در حالت no_targets است. Install، ورود به حساب، دانلود بازی و دسترسی از راه دور درخواست نمی‌شوند. شواهد a11 و مسیر paused مهمان دست‌نخورده می‌مانند.

## خروجی

فقط گزارش allowlist منتشر می‌شود: وضعیت و نام مجاز فرایندها، پرچم‌های helper، قابل‌مشاهده‌بودن window station، دسترسی input desktop، تعداد فرایندهای هم‌session/متفاوت/نامشخص و پنجره‌های متعلق به فرایندهای محدود، همراه با تعداد نمونه‌های root در حال اجرا یا خارج‌شده. هیچ PID/session ID، مسیر، متن UI، شناسهٔ سیستم، UUID یا هش UUID صادر نمی‌شود. root_state_before_cleanup از poll در آخرین snapshot پیش از cleanup است، نه exit ناشی از taskkill.

گزارش بر پایهٔ سه snapshot نگه‌داشته‌شده است و همهٔ پنجره‌ها/desktopها یا تاریخچهٔ کامل GUI را پوشش نمی‌دهد. عدم مشاهدهٔ پنجره، نبود آن روی تمام دسکتاپ‌ها را ثابت نمی‌کند. گزارش شبکهٔ plaintext یا packet capture ندارد و network_payload_observed=false است.

## تفسیر از پیش تعیین‌شده

- اگر Agent اینجا دیده شود ولی در a12d دیده نشده باشد، اختلاف قابل پیگیری در روش اجرا/ابزار به‌دست می‌آید؛ هنوز علت قطعی Frida نیست.
- اگر همین مانع بدون Frida تکرار شود، Frida شرط لازمِ ایجاد مانع نیست؛ محیط، پنجره/session و خود bootstrap بررسی می‌شوند. علت دقیق از این کنترل به‌تنهایی معلوم نیست.
- اگر station/desktop در دسترس نباشد، فقط محدودیت دسترسی observer ثابت می‌شود؛ خودکار به این معنا نیست که bootstrap قطعاً به همین علت متوقف شده است.

مقایسه با a12d روی همان ماشین نیست. Popen عادی و روش stdio با Frida spawn متفاوت‌اند؛ پس این آزمایش A/B تک‌متغیره و اثبات causality نیست. هیچ نتیجهٔ سراسری دربارهٔ تمام کاربران، نسخه‌ها یا تلمتری از این کنترل به‌تنهایی استخراج نمی‌شود.

۲۵ آزمون محلی شامل scope، pin پیش از launch، پالایش GUI/session، ممنوعیت ادعای causality/injection، حدود شمارنده و duplicate JSON پاس شده‌اند؛ نتیجهٔ کنترل ویندوز جداگانه منتشر خواهد شد. فقط reports/prelogin-bootstrap-control-runtime.json و CI receipt عمومی‌اند؛ فایل مشاهدهٔ کاملِ موقت upload نمی‌شود.
