# G65 — بررسی مقدارهای خروجی و مالک اتصال، بدون صدور دادهٔ خام

همان Windows موقت، کنترل‌های بومی، کش گواهی معتبر، hosts موقت و سیاست دو مقصد G63 حفظ می‌شوند. هیچ فایل یا تنظیم RC کاربر تغییر نمی‌کند. Install، ورود یا پذیرش حقوقی کلیک نمی‌شود.

## دادهٔ خروجی
ناظر، HTTP1 را در حافظه از ورودی پذیرفته‌شدهٔ Winsock و plaintext پیش از EncryptMessage بازسازی می‌کند و فقط دسته‌ها را صادر می‌کند: route عمومی ثابت، تعداد و نوع segmentهای مسیر، دستهٔ کلید و مقدار query، فرم Range/Accept و واژه‌های ثابت محصول/پلتفرم در User-Agent. خروجی مقدار خام query، مسیر یا User-Agent ندارد. مقادیر opaque/UUID/hex تا داشتن شواهد دیگر نامعلوم‌اند؛ شکل hash به معنی hash دانلود نیست.

پیش از isolation، helper شش GET ثابت به versions/cdns عمومی agent/bna/bnt روی همان us.version.battle.net انجام می‌دهد. بدون cookies/proxy/redirect و با بررسی ابطال فعال است. متن جدول خصوصی و محدود باقی می‌ماند؛ فقط tokenهای نسخه و hex در حافظه برای مقایسه استفاده می‌شوند. تطابق دقیق با token مرجع عمومی یک شاهد برای انتخاب دانلود است، نه مجوز کلی حریم خصوصی. خود helper داده‌ای از درخواست‌های installer بازتاب نمی‌دهد.

نام ماشین، نام کاربر و MachineGuid همین runner فقط در حافظه برای مقایسهٔ literal و md5/sha1/sha256/base64 بدون salt استفاده می‌شوند. مقدارها، hash آن‌ها یا خود MachineGuid صادر/فایل نمی‌شوند. این مقایسه فقط همین شناسه‌ها و تبدیل‌های محدود را پوشش می‌دهد؛ عدم تطابق به معنای نبود fingerprint، شناسهٔ salted، ترکیبی یا مشتق‌شده از سخت‌افزار نیست. اشارهٔ عمومی به platform/architecture نیز به‌تنهایی اثبات بی‌ضرربودن نیست. مقدارهای خالی/عمومی/نامعلوم جدا می‌مانند.

## TCP
snapshot، State را صریحاً به نام ثابت تبدیل می‌کند. PID صفر، TIME_WAIT، PID تحت مشاهده، مالک زندهٔ خارج از مشاهده و مالک نامعلوم/خارج از snapshot جدا هستند. فقط نام‌های ثابت سیستم و ردهٔ ناشر امضای معتبر (Blizzard/Microsoft/other) صادر می‌شوند؛ PID/path/subject خام صادر نمی‌شود. snapshot پیوسته نیست و race/truncation ممکن است؛ امضای معتبر هم دلیل بی‌ضرربودن ترافیک نیست. فقط Blizzard verified به‌طور خودکار late-attach می‌شود؛ process دیگر صرف داشتن اتصال مجوز attach نمی‌گیرد.

هیچ مورد از GET بودن، بدنهٔ خالی، واژهٔ دانلود، تطابق یک token یا کنترل CI موفق حکم نبود فینگرپرینت نمی‌دهد. رخدادهای API هم لزوماً شمار یکتای درخواست رسیده به سرور نیستند. نتیجهٔ نهایی هر الگو باید با این محدودیت‌ها بیان شود.

## افزودهٔ G65 بر G64
فرضیهٔ پارامتر توالی فقط با مشاهدهٔ واقعی و تطابق بررسی می‌شود: routeهای ثابت /v1/summary و /v2/summary و کلیدهای ثابت seqn/since/sequence شناخته می‌شوند. یک GET عمومی مستقل /v2/summary به مرجع آماده‌سازی اضافه شده است. عدد فقط اگر با seqn header جدول عمومی یا ستون Seqn جدول Product/Seqn/Flags دقیقاً یکسان باشد، fixed_public_sequence_exact می‌گیرد؛ صرف عددی‌بودن کافی نیست. عدد خام صادر نمی‌شود. callback، مقصد یا مجوز شبکهٔ برنامه تغییر نمی‌کند.

User-Agent علاوه بر واژه‌ها با fullmatch قالب محدود Agent/version بررسی می‌شود. هر متن اضافه این fullmatch را باطل می‌کند. یکسانی نسخه با tokenهای مرجع عمومی جدا گزارش می‌شود. تطابق قالب به‌تنهایی اثبات منبع یا نبود همهٔ fingerprintها نیست. این آزمایش نه User-Agent را بازنویسی می‌کند و نه query را حذف می‌کند.
