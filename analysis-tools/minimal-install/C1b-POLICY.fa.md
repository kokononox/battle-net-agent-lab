# C1b — شش آزمایش نصب تازه با محافظ DNS کالیبره‌شده

این سیاست پیش از اجرای batch ثبت می‌شود. نسخه منجمد Unified Firewall 0.9.10 تغییر نمی‌کند. گزارش C1 قدیمی و نتیجه‌های توقف پیش از اجرا دست‌نخورده باقی می‌مانند؛ C1b هویت، schema، approval و پوشه گزارش جدا دارد.

## پیش‌نیاز انجام‌شده
ماژول calibrated_os_resolver_v2 در D2، run 40159217028 با منبع abdebd333340c7015258d97a9cd5ab4c51a17dc2، روی سه VM مستقل برای telemetry-in.battle.net، level3.blizzard.com و us.version.battle.net qualified شد. هر مورد سه بررسی پذیرفته‌شده accepted_no_data، کنترل مستقل سالم، صفر شکست بررسی و بازیابی فایل و پاسخ DNS دارد. هیچ نصب‌کننده‌ای در D2 اجرا نشد. گزارش‌ها و SHA256 artifactها در reports/minimal-install-dns-d2 نگه داشته می‌شوند.

## طراحی C1b
- r1 و r2: کنترل بدون تغییر hosts؛ هیچ خواندن/نوشتن/flush توسط ماژول مداخله انجام نمی‌شود.
- r3 و r4: نگاشت دقیق telemetry-in.battle.net، دو تکرار مستقل.
- r5: نگاشت دقیق level3.blizzard.com.
- r6: نگاشت دقیق us.version.battle.net.

همه VMها تازه و GitHub-hosted Windows-2025 هستند؛ max-parallel=6 و fail-fast=false. هم‌زمانی واقعی فقط از زمان شروع/پایان هدف سنجیده می‌شود، نه تنظیم matrix. setup همان SHA256 و اندازه قبلی را باید داشته باشد و امضای Blizzard و native UI guards تغییر نکرده‌اند. setup قبل از مداخله دریافت و تأیید می‌شود. ورود حساب، دانلود بازی، TLS bypass یا تغییر فایروال مجاز نیست.

## دروازه مداخله
از همان ماژول آزموده‌شده D2 استفاده می‌شود، نه صرف پذیرش کد خطا. قبل از هر نوشتن، هدف و کنترل مستقل downloader.battle.net باید پاسخ عمومی در resolver معمول و IPv4 داشته باشند. سپس backup، نگاشت دقیق 0.0.0.0/::، readback و flush موفق لازم است. در هر سه خانواده معمول/IPv4/IPv6، فقط پاسخ تماما unspecified یا خطای دقیق DNS 11004 پذیرفته می‌شود؛ کنترل باید همچنان سالم باشد و readback قبل/بعد probe برقرار بماند. خطاهای دیگر، پاسخ عمومی هدف، loopback، timeout، خرابی helper و خطای کنترل باعث توقف می‌شوند.

پیش از اجرا، دوره‌ای حدود هر ۱۵ ثانیه و پیش از اعلام نصب موفق دوباره بررسی می‌شود؛ این نمونه‌برداری است، نه نظارت پیوسته. شواهد baseline، تک‌تک بررسی‌ها، نتیجه کنترل و بازیابی در calibration گزارش ثبت می‌شوند. حین بررسی، وقفه resolver ممکن است باعث توقف محافظه‌کارانه شود؛ نتیجه ناموفق به تنهایی اثبات ضروری بودن دامنه نیست.

پس از پایان رصد، bytes اصلی و flush باید بازیابی شوند و هدف و کنترل دوباره پاسخ عمومی بدهند. برگشت فایل بدون بازگشت DNS، restored محسوب نمی‌شود. تعارض فایل دیگران بازنویسی نمی‌شود. خطای بازیابی نتیجه نهایی را stopped می‌کند.

## معیار نتیجه و محدودیت
معیار نصب همان signed_binary_version_v1 باقی می‌ماند؛ همه شرط‌های امضا، نسخه PE، مسیر رجیستری، ثبات فایل، پایان Setup و اجرای client لازم‌اند. گزارش‌های کنترل و مداخله همگی منتشر می‌شوند؛ مورد متوقف‌شده حذف نمی‌شود. خطای ابزار، ناپایداری فایل و خطای UI با شکست ناشی از دامنه اشتباه گرفته نمی‌شود.

این روش فقط مسیر resolver ویندوز را هدف می‌گیرد. نصب موفق با این مداخله، نبود تلمتری یا مسدودبودن DoH/IP مستقیم را ثابت نمی‌کند؛ به تنهایی اثبات غیرضروری بودن قطعی دامنه هم نیست. لازم است نسخه/هش خروجی‌های موفق هم‌گروه باشد و بعدا آزمون تکرارپذیر block/unblock با انتساب ترافیک انجام شود. flags اثبات انسداد کامل تلمتری و ضرورت مقصد همچنان false هستند. EXE نهایی هنوز منتشر نمی‌شود.
