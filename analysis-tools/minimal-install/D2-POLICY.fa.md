# D2 — اعتبارسنجی محافظ کالیبره‌شده پیش از هر نصب تازه

این مرحله سه VM تازه Windows-2025 دارد، یک دامنه در هر VM: telemetry-in.battle.net، level3.blizzard.com، us.version.battle.net. نصب‌کننده دانلود یا اجرا نمی‌شود و سیاست فایروال/TLS/نسخه 0.9.10 تغییر نمی‌کند. دروازه قدیمی C1 و گزارش‌های تاریخی همچنان دست‌نخورده‌اند؛ ماژول جدید فقط پس از این اعتبارسنجی قابل اتصال به آزمایش نصب بعدی است.

پیش از نوشتن hosts، resolver معمول و IPv4 باید برای خود دامنه هدف و کنترل مستقل downloader.battle.net پاسخ فقط-عمومی بدهند. نبود IPv6 در baseline به عنوان انسداد تفسیر نمی‌شود. فایل اصلی باید معمولی/بدون reparse، با قالب محدود و پس از probe همچنان بدون تغییر باشد؛ backup پیش از نوشتن انجام می‌شود.

پس از نگاشت فقط دامنه هدف به 0.0.0.0 و ::، readback و flush موفق الزامی است. در هر بررسی، برای هر سه حالت معمول/IPv4/IPv6 هدف، فقط پاسخ غیرخالی تماما unspecified یا خطای دقیق DNS 11004 مجاز است. هم‌زمان کنترل مستقل باید در حالت معمول و IPv4 همچنان فقط پاسخ عمومی بدهد؛ فایل نیز قبل و بعد از probe عین نگاشت مورد انتظار باشد. پاسخ عمومی هدف، loopback، مخلوط صفر/عمومی، خطاهای دیگر، timeout و خرابی helper همگی رد می‌شوند.

سه بررسی پیاپی باید برقرار بماند. هیچ شکست بررسی از تاریخچه پاک نمی‌شود. پس از بازیابی دقیق bytes اصلی و flush موفق، پاسخ معمول و IPv4 هدف و کنترل باید دوباره عمومی باشند؛ برگشت فایل به تنهایی معادل restored نیست. تعارض فایل شخص ثالث بازنویسی نمی‌شود. خطای بازیابی یا خطای DNS هنگام بازیابی مانع qualified شدن است.

این معیار فقط اثر مداخله در مسیر resolver سیستم‌عامل را می‌سنجد. سه بررسی متوالی پوشش پیوسته زمان یا اثبات عدم دورزدن بین نمونه‌ها نیست؛ هیچ ادعای قطع DoH، اتصال مستقیم IP، همه تلمتری یا دریافت سمت سرور وجود ندارد. نتیجه qualified به معنی آماده بودن محافظ برای مرحله ادغام است، نه نصب موفق یا اثبات ضرورت مقصد.
