# G37 — کارگزار آفلاین با جلسهٔ محدود

نمونهٔ آفلاینِ توسعه‌یافته از G36 است. نه EXE، نه proxy نصاب و نه اتصال شبکهٔ واقعی. مسیر G36 دست‌نخورده باقی مانده است؛ نمونهٔ حاضر schema جدید `offline_download_catalog_v2` دارد و policy قدیمی را خودکار قبول نمی‌کند.

## قرارداد
کاتالوگ مورد اعتماد علاوه بر resourceهای ثابت، session شامل `resource_ids` به ترتیب، `max_requests` و `max_total_bytes` دارد. هر resource فقط یک بار در فهرست است؛ هیچ resource خارج از فهرست یا موجودی استفاده‌نشده قبول نمی‌شود. بودجهٔ درخواست دقیقاً برابر تعداد resourceها و بودجهٔ payload برابر مجموع اندازهٔ آن‌هاست. کل payload برنامه‌ریزی‌شده حداکثر512MiB است. بودجهٔ بایت HTTP درخواست‌ها از planهای ثابت مشتق می‌شود.

کلاینت هنوز فقط `resource_id` می‌دهد. درخواست باید دقیقاً گام بعدی باشد؛ انتخاب دلخواه، تکرار یا عقب‌گرد، جلسه را قبل از fetch به حالت failed می‌برد. ورودی نامعتبر هم terminal است. یک اشتباه کاربر می‌تواند جلسه را متوقف کند؛ این رفتار fail-closed عمدی است، نه رابط کاربری نهایی.

سهم درخواست و بایت مورد انتظار پیش از fetch رزرو می‌شود. پاسخ ردشده یا خطای transport سهم را برنمی‌گرداند. هیچ retry، reset یا resume در API وجود ندارد. خطا و interruption جلسه را terminal می‌کند. جلسهٔ کامل مجدداً باز نمی‌شود. cancel قبل از گام بعدی ادامه را متوقف می‌کند. قفل، گام‌ها را سری می‌کند و duplicate هم‌زمان سهم اضافه ایجاد نمی‌کند.

اندازه‌ها سقف payload مورد انتظار و بایت‌های برنامه‌ریزی‌شدهٔ HTTP هستند، نه اندازهٔ واقعی سیم شبکه، TLS، ACK یا حافظهٔ streaming. در این نمونه transport فقط fixture در حافظه برمی‌گرداند و پیش از بررسی اندازه، bytes پاسخ را در اختیار دارد؛ این روش برای دریافت آنلاین فایل بزرگ کافی نیست.

## بازتولید

```bash
python -I analysis-tools/download-broker-g37/run_tests.py --report evidence-local.json
```

50آزمون (27قرارداد درخواست و23جلسه)، شامل1000ورودی تزریقی،156توالی مهاجمانه و32درخواست هم‌زمان. در مدت هر test ساخت socket ممنوع شده است. کاتالوگ همراه خالی/deny-all است؛ مسیرهای audit-fixture و reviewها فقط دادهٔ ساختگی آزمون‌اند. هیچ مجوزی برای endpoint واقعی Battle.net ایجاد نشده است.

## مرز امنیت و محدودیت
کد، کاتالوگ، hash اعتماد و ایجاد session در اختیار کنترلر مورد اعتماد فرض شده‌اند. این کتابخانه sandbox درون‌پردازشی نیست. کد مهاجم داخل همان پردازش می‌تواند API را دور بزند؛ ادعای دفاع علیه آن نداریم. کلاینت نباید بتواند session تازه، Catalog یا transport بسازد.

محدودیت فقط در طول عمر یک نمونهٔ session است. جلوگیری از session تازه یا replay پس از restart/crash، journal امن، اعتبار مستقل کاربر، زمان انقضا و راه‌اندازی کنترلر هنوز پیاده نشده‌اند. برای همین نمونهٔ جدید نباید به‌عنوان endpoint کلاینتِ بدون احراز هویت عرضه شود.

ترتیب انتخاب resource و تعداد fetch در جلسه محدود شده‌اند، ولی کلاینت هنوز می‌تواند درخواست را دیر بدهد یا کل جلسه را رها کند. زمان‌بندی/قطع زودهنگام، IP عمومی و fingerprint TLS آینده حذف نمی‌شوند. منابع کاتالوگ هم باید با منشأ و محتوای قابل بررسی تأیید شوند؛ SHA-256 و status=approved به‌خودی‌خود اثبات حریم خصوصی نیستند.

cancel فعلی با lock سری می‌شود و توقف network I/O درحال‌اجرا را اثبات نمی‌کند؛ در transport آنلاین باید timeout، توقف اتصال، محدودیت streaming و بازیابی crash مستقل اضافه شود. کنترل مستقیم خروجی برنامه، Job، فایروال، DNS/IP pin، TLS معتبر، اصالت فایل و سازگاری نصب دستی Battle.net هنوز در این نمونه ادغام نشده‌اند. هیچ CA، bypass TLS، استثنای task یا تغییر سیاست ویندوز اضافه نشده است.
