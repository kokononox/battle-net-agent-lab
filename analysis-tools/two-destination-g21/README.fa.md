# G21 — تشخیص هدفمند نصب دو مقصد

ادامهٔ G20 فقط روی Windows GitHub-hosted تازه؛ Desktop 0.9.10 تغییر نمی‌کند.
دو مقصد دقیق level3.blizzard.com و us.version.battle.net؛ پروکسی فقط IPهای public ثابت، HTTP 80/443 و us.version:1119 را دارد. نام/SNI و مالک native TCP و هویت/Job در هر ارسال بررسی می‌شوند. DNS، مقصد سوم، CA یا TLS interception اضافه نشده‌اند. فرض مرز همان G20 است: دفاع در برابر Administrator مخرب یا تزریق در فرایند Runner اثبات نشده است.

## تغییرات محدود
- دو خطای مالک صفر/چندگانه جدا می‌شوند؛ هر دو بسته می‌مانند، retry یا fail-open اضافه نشده.
- شمارنده‌های ClientHello و relay با read/attempted/confirmed socket.send bytes جدا هستند. confirmed به معنی پذیرش محلی send است، نه دریافت یا پردازش برنامهٔ مقابل. attempted با send ناقص ممکن است همان بایت را دوباره بشمارد؛ حجم یکتای داده نیست. خطا/EOF هر دو در finally ثبت می‌شوند.
- هنگام بسته‌شدن lease، پروکسی پذیرش را متوقف و اتصال‌ها را drain می‌کند. پس از فرصت محدود، بازیاب می‌تواند آن را اجباری ببندد؛ proxy_drain_complete=false یا نبود receipt یعنی لاگ نهایی همهٔ اتصال‌ها تضمین نشده. هیچ شرط پذیرش تسک/BITS برای Restore سست نشده است.
- تشخیص صفحهٔ نصب همان validator سخت‌گیرانهٔ قبلی است. فقط زمان‌بندی حداکثر ۱۲ بررسی در طول مشاهده پخش شده و snapshotهای enum مجاز UI افزوده شده‌اند. متن خام، path یا screenshot منتشر نمی‌شوند. صفحه ناشناخته کلیک نمی‌شود؛ اصلاح واقعی ممکن است به نشانگرهای این اجرا نیاز داشته باشد.
- گزارش پیش از cleanup و پس از نتیجه در stdout با manifest/hash ثبت می‌شود. یک Linux job جدا با actions:read خروجی همان job را می‌خواند و فقط JSON دارای هویت صحیح/هش معتبر را artifact می‌کند؛ raw logs، token و signed URL منتشر نمی‌شوند. در صورت قطع کامل Runner پیش از چاپ checkpoint، بازیابی گزارش تضمین نیست.

## دامنهٔ اجرا و مرز نتیجه
یک اجرای real_setup، مشاهدهٔ ۱۸۰ ثانیه، فقط زبان و صفحهٔ شناخته‌شدهٔ setup-options؛ بدون حساب، بازی یا کلیک ناشناخته. مشاهدهٔ فایل/Continue اثبات نصب کامل نیست. TLS رمزگشایی نشده؛ معنی داده‌های رمز‌شده نامشخص می‌ماند. انتقال‌های BITS نمونه‌برداری‌اند. ثبت تغییر PrintJobCleanupTask به معنی انتساب آن به نصاب نیست و هیچ استثنایی برای آن ایجاد نشده است.

Windows job فقط روی پیام commit دقیق `lab: approved two destination real Setup G21 20261025` و اولین attempt اجرا می‌شود. تست‌های محلی fake جای آزمون native Windows نیستند. publisher روی VM پاک جداست؛ token آن وارد محیط نصاب نمی‌شود. این بسته ابزار نهایی کاربر نیست.
