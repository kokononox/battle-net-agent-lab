# آزمون G13: شکست حین راه‌اندازی و امتناع از بازیابی ناامن

فقط برای ماشین موقت GitHub-hosted Windows-2025، با تأیید دقیق workflow و مؤلفه‌های ساختگی. هیچ Setup واقعی اجرا نمی‌شود و پروژه ۰.۹.۱۰ تغییر نمی‌کند.

سه سناریو: قطع ناظر پیش از ثبت owner.json، قطع پس از شروع سرویس و پیش از ساخت task، و تزریق task خارج از دفتر مؤلفه‌های مجاز. دو سناریوی اول باید mutex رهاشده را توسط SYSTEM بازیابی کنند، اعضای Job زنده را احراز و متوقف کنند، سپس hosts/فایروال/IIS را بازگردانند. یک handle بدون مالکیت، عمر شیء mutex را تا بازیابی حفظ می‌کند؛ Driver بعد از crash آن را acquire نمی‌کند.

در سناریوی ناشناخته، inventory واقعی در محدوده پوشه محافظت‌شده fixture باید task و PID خارج از دفتر را تشخیص دهد و از Restore خودداری کند. Driver فقط پس از ثبت و تأیید این امتناع، همان task ساختگی را با احراز دقیق اقدام و هویت PID/زمان ایجاد حذف می‌کند؛ بازیابی دوم با هویت SYSTEM انجام می‌شود. این حذف، رفع کنترل‌شده آزمایش است؛ رفتار خودکار برای مؤلفه ناشناخته نیست.

محدودیت: فقط دو checkpoint مشخص startup و یک نوع task ناشناخته آزموده می‌شوند؛ تشخیص عمومی سرویس‌های بتل‌نت، همه شکست‌های ممکن و جداسازی محتوای HTTPS اثبات نمی‌شود. در شکست احراز، import بی‌قیدوشرط ممنوع می‌ماند. نتیجه باید از JSON واقعی تأیید شود، نه صرفاً وضعیت CI. ضرورت تلمتری موضوع این آزمون نیست.

نتیجه تأییدشده: `reports/startup-install-g13/RESULT.fa.md`؛ هر سه سناریو به نتیجه مورد انتظار رسیدند، با محدودیت‌های صریح در گزارش.
