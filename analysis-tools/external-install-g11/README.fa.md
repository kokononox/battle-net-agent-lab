# G11: آزمون واقعی ترتیب برداشتن یک قانون محدود، نه مرز کامل نصب

مؤلفه‌ها ساختگی و متعلق به آزمایش‌اند. یک سرویس SCM و یک Scheduled Task بیرون از Job مالک اجرا می‌شوند. قانون Block فقط به مسیر دقیق EXE آزمایش تعلق دارد؛ هیچ Allow موجود، profile، policy پیش‌فرض، hosts یا تنظیم TLS تغییر نمی‌کند. هیچ نصاب/حساب Battle.net اجرا نمی‌شود.

canary همین EXE فقط GET ثابت `/agent/versions` به IP عمومی پین‌شده `us.version.battle.net:1119` می‌فرستد؛ body، کوکی یا شناسه ندارد و پاسخ خام صادر نمی‌شود. baseline پیش از قانون باید HTTP 200 باشد. زیر قانون، اتصال باید پیش از شروع مالک، پس از crash مالک با زنده‌بودن سرویس/وظیفه و پس از پایان سرویس با زنده‌بودن وظیفه رد شود. سپس مؤلفه‌های دقیق شناخته‌شده متوقف، ثبت سرویس/وظیفه حذف، هویت فرایندها و پایانشان بررسی می‌شوند؛ تنها بعد از آن همان قانون اختصاصی حذف و canary تازه باید دوباره پاسخ 200 بگیرد.

watchdog SYSTEM پیش از fixtureها ثبت می‌شود. مسیر پاکسازی در حالت عادی، always-step و watchdog یکسان است: اگر حذف مؤلفه‌ها و پایان فرایندهای شناخته‌شده تأیید نشود، حذف قانون Block مجاز نیست؛ ماشین موقت با محدودیت باقی‌مانده کنار گذاشته می‌شود. اجراهای مصنوعی خودشان نیز زمان‌دارند. فایل‌ها و پیکربندی موقت فقط SYSTEM/Administrators دسترسی دارند و به artifact صادر نمی‌شوند.

این آزمون از نوع known-fixture است: پوشش کشف خودکار سرویس/وظیفه ناشناخته، ضدیت با Administrator مهاجم، رقابت ایجاد مؤلفه جدید همزمان با release، watchdog ناگهانی واقعی و اعمال همزمان دروازه کامل G8 هنوز اثبات نشده‌اند. guard موارد ناشناخته/پوشش خراب در این مرحله فقط منطق تصمیم‌گیری است. `full_install_boundary_proven=false` باقی می‌ماند. موفقیت G11 اجازه اجرای خودکار Setup نیست.
