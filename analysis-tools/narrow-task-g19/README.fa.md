# G19 — فقط تغییر زمان شروع CalendarTrigger تسک دقیق SvcRestartTask

این طبقه‌بندی فقط هویت کامل `\Microsoft\Windows\SoftwareProtectionPlatform\SvcRestartTask` با SHA256 نام کامل `4023f1322db1c44e9afe47a715033f592132e209dd8511b71be83c290ae8c7a2` را پوشش می‌دهد؛ نه تسک هم‌نام در مسیر دیگر و نه سایر تغییرهای ویندوز.

شرط‌های لازم:
- خط مبنا با SYSTEM پیش از اجرای هدف و از ماشین تازه ثبت شود.
- COM handler به DLL زیر System32 اشاره کند؛ تغییرمسیر TreatAs/LocalServer32 و overlayهای بررسی‌شده پذیرفته نشوند.
- امضای DLL در خط مبنا Valid و ناشر Microsoft باشد؛ رجیستری binding، شناسه کلاس، مسیر و SHA256 فایل در بررسی بعدی تغییر نکنند. COM handler برای آزمون فعال نمی‌شود.
- در XML فقط متن یک CalendarTrigger/StartBoundary معتبر عوض شود. namespace، ساختار، ترتیب، اکشن، آرگومان، COM data، principal، فعال‌سازی و تمام سایر مقادیر حفظ شوند. DTD/entity رد می‌شوند.
- تغییر DLL/binding حتی بدون تغییر XML یک مانع مستقل است.

آزمون‌های منفی ساختاری و تصمیم بازیابی در حافظه انجام می‌شوند؛ هیچ تسک حساس ویندوز به اکشن مخرب تغییر داده نمی‌شود. آزمون‌ها یک‌بار روی fixture ساختگی و دوباره روی کپی خط مبنای واقعی اجرا می‌شوند. این سطح آزمون با آزمایش تغییر زندهٔ تسک/انتقال BITS واقعی یکی نیست.

دو بازو، بدون Setup و با Setup pinned، هنوز فقط ۹۰ثانیه آفلاین و حداکثر ادامهٔ صفحهٔ زبان را پوشش می‌دهند. تغییرهای ناشناختهٔ دیگر، سرویس، هدف بیرون Job، تعریف انتقال تازه/تغییریافته یا پایش ناقص BITS همچنان مانع بازیابی‌اند. قرنطینه latch می‌شود.

این بررسی‌ها snapshot و نمونه‌برداری‌اند؛ حفاظت اتمیک در برابر تمام raceها، مقابله با مهاجم دارای دسترسی Administrator، رهگیری جامع شبکه یا نصب موفق را اثبات نمی‌کنند. صف BITS دوثانیه‌ای ممکن است job گذرا را نبیند. هیچ مجوز خروج شبکه برای هدف صادر نمی‌شود. نسخهٔ Unified Firewall Desktop 0.9.10 تغییر نمی‌کند.

گزارش به‌وضوح اختلاف خام، تغییر زمان‌بندی طبقه‌بندی‌شده و مانع باقی‌مانده را جدا می‌کند. موفقیت فقط وقتی اعلام می‌شود که آزمون‌های منفی، خط مبنای واقعی، پایان هدف، بازیابی SYSTEM و canary پس از بازیابی همگی تأیید شوند؛ نه صرفاً سبزشدن workflow.
