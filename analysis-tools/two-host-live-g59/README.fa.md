# G59 — مشاهدهٔ WinHTTP و یونیکد

این آزمایش جدا از محصول RC کاربر است. دو مقصد مجاز و محدودیت فایروال تغییر نکرده‌اند. فقط اجرا روی Windows موقت GitHub مجاز است.

افزوده‌ها: WinINet A/W، WinHttpOpen/Connect/OpenRequest/SendRequest/WriteData/ReceiveResponse/ReadData، ثبت ورودی پیش از فراخوانی و نتیجهٔ بعد از بازگشت، ثبت خروجی خواندن همگام. حالت async یا ناشناختهٔ WinHTTP خروجی کامل تلقی نمی‌شود. درخواست‌های افزوده‌شده با AddRequestHeaders، رفتار redirect، کوکی‌های خودکار، دیگر APIها و TLS مستقل هنوز پوشش کامل ندارند.

هشت کنترل بومی باید پیش از اجرای نصب‌کننده بگذرند: Winsock دو معماری، WinINet A/W دو معماری، WinHTTP دو معماری. کنترل‌ها HTTP loopback هستند، نه اثبات رمزگشایی TLS. هیچ تضعیف اعتبارسنجی گواهی یا نصب CA انجام نمی‌شود.

نام متغیرهای قدیمی wininet_inputs و wininet_response_chunks برای سازگاری مانده است؛ layer هر رکورد، خانوادهٔ API را مشخص می‌کند. before/after همان فراخوانی دوبار به عنوان دو درخواست شمرده نمی‌شود. WinHttpWriteData قطعهٔ بدنه است نه یک درخواست مستقل. مقادیر URL، هدر و بدنه خصوصی می‌مانند؛ فقط خلاصهٔ پالایش‌شده منتشر می‌شود.

خواندن UI تنها برای دسته‌بندی ثابت و کد BLZ است؛ لینک باز نمی‌شود و متن کامل یا URL منتشر نمی‌شود. یک Continue مرحلهٔ زبان مجاز است؛ Install، ورود، اجرای بازی یا پذیرش حقوقی انجام نمی‌شود.

صفر رکورد یا موفقیت CI به معنای نبود فینگرپرینت نیست.
