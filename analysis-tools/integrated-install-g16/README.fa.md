# G16 — پذیرش peer همراه فایروال و بازیابی SYSTEM

فقط fixture ساختگی در GitHub-hosted Windows-2025 تازه، با approval دقیق و push نخست. هیچ نصاب واقعی اجرا نمی‌شود؛ نسخه ۰.۹.۱۰ دست‌نخورده است.

درگاه G15 به سیاست واقعی فایروال/hosts و بازیابی component-first متصل است. چهار هویت ثابت root، leaf، سرویس و task پس از احراز PID/زمان ایجاد/مسیر، SHA-256 فایل fixture، عضویت زنده Job و تعریف ثبت‌شده سرویس/task توسط کنترل‌کننده ثبت می‌شوند. ثبت خودکار مؤلفه واقعی یا اعتماد صرف به نام EXE وجود ندارد. سرویس و task تحت SYSTEM کار می‌کنند.

در هر دو سناریو، هر چهار مؤلفه باید مستقیم به IP ثابت us.version روی 1119 مسدود و از پروکسی ثبت‌شده HTTP 200 بگیرند. کلاینت جدید با همان EXE ولی PID ثبت‌نشده، سرویس لغومجوزشده، زمان ایجاد جعلی و هویت جعلی ناظر باید بدون تلاش dial به upstream رد شوند. بازثبت پس از احراز باید مجدداً موفق شود.

دفتر peer اکنون به هویت زنده Supervisor و phase=active در lease نیز وابسته است. در سناریوی crash، ناظر واقعاً کشته می‌شود و سرویس زنده باید قبل از deadline مستقل، در احراز اتصال رد شود؛ کنترل بعدی در هر admission/ارسال است، نه انتظار برای polling. در سناریوی عادی بازیابی SYSTEM صریحاً فراخوانی می‌شود؛ در crash، deadline طبیعی ثبت‌شده باید اجرا شود.

بازیابی ابتدا lease را می‌بندد، دفتر peer را خالی و پروکسی را متوقف می‌کند؛ سپس ناظر، Job و مؤلفه‌ها پایان می‌یابند و تنها پس از احراز خروجشان hosts/فایروال/IIS بازگردانده می‌شوند. خطای پوشش مجوز import بی‌قیدوشرط نیست.

محدودیت‌ها: probe واقعی فقط IPv4/TCP/1119 و GET ثابت /agent/versions است، نه نصب یا TLS یا دانلود کامل. تنها همین چهار fixture ثابت ثبت شده‌اند. inventory در مسیر Recover بررسی می‌شود؛ Monitor زنده G14 در این اجرای خاص راه‌اندازی نمی‌شود. WFP، socket duplication، تزریق در فرایند مجاز، اتمی بودن check/dial، همه انواع سرویس و نبود نشتی در همه پروتکل‌ها اثبات نشده‌اند. استثناهای مدیریت GitHub Runner جدا از مجوز هدف می‌مانند. تلمتری موضوع آزمون نیست.

گزارش شواهد تفکیک‌شده G16/G16a: `reports/peer-firewall-g16a/RESULT.fa.md`. normal_release روی سورس اولیه تأیید شد؛ supervisor_crash روی نسخه تشخیصی با deadline طبیعی ۱۲۰ ثانیه و task محدود تأیید شد. معطلی و لغو نخستین سناریوی crash با علت نامعلوم در گزارش حفظ شده است.
