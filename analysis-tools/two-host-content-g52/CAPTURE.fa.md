# ثبت محلی محتوای ارتباط دو مقصد — نمونهٔ تشخیصی

هدف: مشاهدهٔ درخواست‌های واقعی مربوط به level3.blizzard.com و us.version.battle.net، نه آزمایش مجددِ امکان دانلود و نه اعلام نبود فینگرپرینت.

## وضعیت و پیش‌نیاز

این اسکریپت تازه آماده شده و در ویندوز آزمایش اجرایی نشده است. نسخهٔ فایروال شما تغییر نکرده است. این بسته برنامهٔ نصب‌شونده نیست و Wireshark یا درایور ندارد.

به Wireshark به‌همراه قابلیت ضبط Npcap نیاز دارد. اگر قبلاً نصب نیست، فعلاً اسکریپت را اجرا نکنید؛ نصب Npcap یک تغییر جداگانهٔ سیستمی است. فقط از منبع رسمی https://www.wireshark.org/download.html استفاده کنید. نصب یا ارتقا را این بسته خودکار انجام نمی‌دهد. محدودیت Execution Policy را دور نزنید؛ اگر اجرای فایل طبق سیاست ویندوز ممنوع است، توقف کنید.

## کارهایی که انجام نمی‌دهد

- هیچ تغییری در فایروال، hosts، پراکسی، گواهی‌ها یا تنظیمات DNS نمی‌دهد.
- برنامهٔ بتل‌نت یا نصب‌کننده را اجرا نمی‌کند؛ دانلود مصنوعی و درخواست HTTP تولید نمی‌کند.
- برای حل نام، درخواست شبکه‌ای جدید نمی‌فرستد؛ فقط کش موجود DNS را می‌خواند، یا IPهایی را می‌گیرد که خودتان از اتصال موفق مشاهده کرده‌اید.
- TLS را رمزگشایی نمی‌کند و هیچ داده‌ای را به سرور یا این گفتگو ارسال نمی‌کند.

## اجرای محدود

۱. ZIP را در پوشه‌ای محلی و غیر اشتراکی باز کنید. PowerShell را همان‌جا باز کنید. ابتدا فقط رابط‌های قابل ضبط را فهرست کنید:

```powershell
powershell.exe -NoProfile -File .\Capture-TwoDestinations.ps1
```

۲. شماره یا نام رابطی را انتخاب کنید که ارتباط دانلود واقعاً از آن دیده می‌شود. شمارهٔ ۱ در مثال زیر فقط مثال است؛ انتخاب خودکار نداریم. در VPN ممکن است رابط فیزیکی فقط تونل رمز‌شده را نشان دهد یا رابط داخلی قابل ضبط نباشد. تنظیم محافظ را عوض نکنید.

```powershell
powershell.exe -NoProfile -File .\Capture-TwoDestinations.ps1 -CaptureInterface "1" -Seconds 90 -Consent
```

اسکریپت فقط رکوردهای مستقیم A/AAAA موجود در کش برای دو نام را استفاده می‌کند. اگر کش خالی باشد یا تنها CNAME وجود داشته باشد، توقف می‌کند؛ به دامنهٔ دیگری یا ضبط کل شبکه گسترش نمی‌یابد. در صورت نیاز، IP مشاهده‌شده در رصد اتصال موفق را صریح بدهید:

```powershell
# DOCUMENTATION ONLY: replace placeholders with actual observed IP addresses.
# .\Capture-TwoDestinations.ps1 -CaptureInterface "<interface>" -RemoteIP "<observed-IP-1>","<observed-IP-2>" -Seconds 90 -Consent
```

این ارتباطِ IP با نام دامنه، اثبات‌شده فرض نمی‌شود. IP را از حدس یا مثال اینترنتی نگیرید.

۳. ضبط را پیش از درخواست مورد بررسی آغاز کنید و فعالیت عادی دانلود را انجام دهید. نیازی به پایان یک دانلود کامل نیست. توقف خودکار با رسیدن به ۹۰ ثانیه یا حدود ۶۴ مگابایت انجام می‌شود؛ در دانلود سریع ممکن است سقف حجم بسیار زود برسد. اجرای فرمان ضبط نیازمند دسترسی مجاز Npcap است؛ خطای دسترسی را با خاموش‌کردن فایروال حل نکنید.

## خروجی خصوصی و مشاهده

خروجی زیر LocalAppData کاربر، در پوشهٔ TwoDestinationEvidence و زیرپوشه‌ای تصادفی قرار می‌گیرد:

- traffic.PRIVATE.pcapng: بسته‌های کامل دوطرفه برای مجموعهٔ IP انتخاب‌شده.
- metadata.PRIVATE.json: IPها، رابط، فیلتر، زمان و وضعیت پایان فرمان؛ تأیید کامل‌بودن پوشش نیست.

فایل pcapng را محلی در Wireshark باز کنید. فیلتر نمایشی اولیه:

```text
http.request
```

سپس درخواست‌های دیده‌شده به همین دو نام:

```text
http.request && (http.host == "level3.blizzard.com" || http.host == "us.version.battle.net")
```

فیلتر دوم درخواست با Host دارای پورت یا قالب متفاوت را ممکن است حذف کند؛ ابتدا همهٔ http.request را ببینید. برای هر درخواست، Host، روش، مسیر کامل، query، هدرها، Cookie، Authorization و بدنه را بررسی کنید. Follow TCP Stream می‌تواند متن بیشتری نشان دهد اما شامل پاسخ و دادهٔ خصوصی نیز هست. صرف GET بودن، نبود بدنه، اندازهٔ کوچک، یا اسم «دانلود» تأیید بی‌خطر بودن نیست. HTTP ساده هم می‌تواند محتوای برنامه‌ای فشرده/رمز‌شده یا شناسهٔ hash‌شده داشته باشد.

برای یافتن ارتباط‌های رمز‌شده/احتمالاً رمز‌شده در نمونه:

```text
tls || quic
```

خروجی خالی این فیلتر اثبات نبود رمزگذاری نیست؛ ممکن است ضبط از وسط اتصال شروع شده، تشخیص پروتکل انجام نشده یا رابط اشتباه باشد. ترافیک ناشناخته را با «بی‌خطر» جایگزین نکنید.

## معیار نتیجه‌گیری

برای هر درخواست، اطلاعات دیده‌شده و دلیل طبقه‌بندی را ثبت کنید:

- مرتبط با دریافت فایل/نسخه: تنها تا حدی که متن درخواست و قالب داده پشتیبانی می‌کند؛ شناسهٔ محصول یا پلتفرم را نیز صریح ثبت کنید.
- شناسه یا مشخصات دستگاه: مانند شناسهٔ پایدار، مشخصات سخت‌افزار یا نام کاربری دستگاه؛ وجود یک فیلد لزوماً هدف استفادهٔ سرور را ثابت نمی‌کند.
- نامشخص: مقدار opaque، hash، دادهٔ رمز‌شده، معنای اثبات‌نشده یا پوشش ناقص.

ارسال IP مبدأ، مشخصات اتصال و برخی ویژگی‌های پروتکل به سرور بخشی از ارتباط است؛ این با ارسال مستقیم فهرست سخت‌افزار یکی نیست و باید جدا گزارش شود. حتی نمونهٔ بدون مشخصات صریح، نبود تمام روش‌های فینگرپرینت یا رفتار در زمان دیگر را ثابت نمی‌کند.

## محدودیت‌های مهم

- فیلتر بر IP است نه فرایند و نه اثبات نام میزبان؛ IP مشترک ممکن است ترافیک برنامه‌ها/نام‌های دیگری را وارد کند.
- فقط یک رابط و مجموعهٔ IP ثابت ابتدای ضبط پوشش داده می‌شود؛ تغییر IP، رابط‌های دیگر، اتصال قبلی یا رسیدن به سقف حجم می‌تواند پوشش را ناقص کند.
- این ضبط PID/مسیر برنامه را معتبر نسبت نمی‌دهد؛ انتساب فرایند باید با شواهد مستقل همان زمان انجام شود.
- فایل خام ممکن است حاوی کوکی، توکن، شناسه و محتوای سایر ارتباط‌های روی IP مشترک باشد. آن را عمومی یا خودکار در چت بارگذاری نکنید. بسته خروجی را بی‌نام‌سازی نمی‌کند.
- خروجی خالی، موفقیت dumpcap و حتی وجود چند GET معمولی، حکم «فقط دانلود» نیست.
