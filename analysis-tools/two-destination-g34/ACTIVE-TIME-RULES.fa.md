# G34 — فعال‌سازی پژوهشی فقط دو قاعدهٔ دقیق

در این مرحله Classify.py علاوه بر قاعدهٔ قدیمی SvcRestartTask، فقط RefreshCache و Registration را برای تغییر صرفاً TimeTrigger/StartBoundary طبقه‌بندی می‌کند. PrintJobCleanupTask در مجموعهٔ مجاز نیست.

NarrowTimeRules.py، روی baseline تحت SYSTEM و ثبت‌شده پیش از target/gate و current تحت SYSTEM تکیه می‌کند. snapshotهای focus باید با XML موجود در inventory همان سمت سازگار باشند. pin دقیق Actions، Principals، ACL، فایل و binding، و بررسی تازهٔ امضای Microsoft پیش از گیت الزامی‌اند. تغییری غیر از یک StartBoundary معتبر پذیرفته نمی‌شود. نبود/خرابی/ناسازگاری شواهد باعث پذیرش نمی‌شود.

تغییر binding، فایل یا مجوز در دو هویت مورد اعتماد حتی بدون تغییر XML نیز مانع ایجاد می‌کند. وجود rule به معنی اعتماد کلی به یک نام Task یا ناشر نیست. شمار مجازها و هویت تک‌تک آن‌ها در PowerShell جداگانه کنترل می‌شود؛ حداکثر دو قاعدهٔ جدید و یک قاعدهٔ قدیمی ممکن است پذیرفته شوند.

ShadowSchedule.review همچنان فقط دید تحلیلی می‌دهد. منبع تصمیم واقعی classification.json است؛ projection مجوز در focus summary از همان نتیجه خوانده می‌شود. آزمایش‌های live پیش از گیت، از تعریف و اندازه‌گیری واقعی همان VM استفاده می‌کنند ولی فقط نسخه‌های حافظه‌ای را تغییر می‌دهند؛ هیچ Task هدف برای آزمون دستکاری نمی‌شود.

پروتکل هدف، فایل نصاب، Job/owner guard و قواعد خروجی شبکه تغییر نکرده‌اند. کنترل همچنان بدون اجرای Setup است. اگر چهار تغییر قبلی رخ دهند، انتظار ۴ تغییر خام، ۳ reschedule طبقه‌بندی‌شده (۲ جدید + ۱ قدیمی) و یک مانع PrintJobCleanupTask است. بازیابی با باقی‌ماندن این مانع باید رد شود، نه اینکه موفق جلوه داده شود.
