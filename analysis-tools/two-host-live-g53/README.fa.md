# G53 — مشاهده زنده محدود راه‌اندازی نصب‌کننده روی ماشین موقت گیت‌هاب

هدف: ثبت محتوای درخواست‌های واقعی دو مقصد، نه تکرار بحث امکان دانلود. این مرحله فقط startup حداکثر۹۰ثانیه را مشاهده می‌کند؛ دکمه نصب/ورود/نصب بازی کلیک نمی‌شود و تکمیل دانلود ادعا نمی‌شود.

نصب‌کننده رسمی۱.۰.۶۸ با اندازه۴۷۰۰۸۸۰ و SHA256 ثابت و امضای معتبر بلیزارد پیش از اجرا بررسی می‌شود. دریافت و نصب وابستگی ناظر و DNS پیش از ایزولاسیون انجام می‌شود.

فقط روی RUNNER_ENVIRONMENT=github-hosted با رضایت marker ثابت اجرا می‌شود. قواعد آزمایشی، outbound و inbound پیش‌فرض را Block و اجازه‌های قبلی را موقتاً غیرفعال می‌کنند. IPهای حل‌شدهٔ همین دو دامنه مجازند. دو تصویر واقعی Runner.Listener/Runner.Worker برای مدیریت CI استثنای جدا دارند؛ این استثنا بخشی از محصول یا اثبات شبکهٔ بدون استثنا نیست. IP مشترک، تطابق پورت/نام میزبان و تغییر DNS محدودیت باقی می‌مانند. عدم وجود allow اضافی و سیاست فعال قبل از launch بررسی می‌شود. فایل خام export فایروال منتشر نمی‌شود. این روش، همان RC یا تنظیم واقعی کاربر نیست.

ناظر Frida پیش از resume روی root وصل می‌شود، child gating دارد، root در Job با kill-on-close قرار می‌گیرد. send همگام و WSASend با completion همگام جمع می‌شود؛ عملیات asynchronous با completion نامشخص، TLS و APIهای دیگر شفاف فرض نمی‌شوند. ترافیک بر مبنای peer socket و IP و سپس Host درخواست محدود می‌شود. محتوای HTTP1 در حافظه بازسازی می‌شود؛ URL کامل، مقادیر هدر، بدنه و مشخصات سخت‌افزار صادر نمی‌شوند. نام هدرهای غیرشناخته هم به برچسب other تبدیل می‌شود.

پس از توقف Job، پردازش‌ها/سرویس‌های شناخته‌شده هدف متوقف و نبودشان بررسی می‌شود؛ سپس snapshot فایروال فقط در این VM مصرفی بازگردانده می‌شود. خطای پاکسازی مانع اعلام موفقیت است. این wrapper تضمین شناسایی هر helper/service با نام ناشناخته نیست و نباید روی سیستم کاربر استفاده شود.

گزارش API input است نه packet capture مستقل و نه تحویل به سرور. فرایندهای خارج از child gating، shared-IP، split/reused socket، همپوشانی send و WSASend، روش‌های async/HTTP2/QUIC، دادهٔ opaque، شناسهٔ کدگذاری‌شده و تغییر زمان‌بندی بر اثر hook شکاف پوشش‌اند. سطر صفر برای مقصد، verdict نامشخص است. hardware_field_name_hint فقط سرنخ لغوی است؛ نه اثبات قصد جمع‌آوری، نه رد فینگرپرینت. هیچ گزارش نبود اطلاعات شخصی صادر نمی‌شود.

ناظر پیش از resume آمادهٔ مشاهدهٔ بارگذاری ماژول است؛ نصب واقعی hookها با hooks_installed جدا شمارش می‌شود. آماده بودن module observer را با وجود hook فعال یا پوشش کامل یکی نگیرید.
