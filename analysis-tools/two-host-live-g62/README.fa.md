# G62 — مشاهدهٔ محدود Schannel با کنترل TLS واقعی

همان دو نام مجاز و اصلاح محلی hosts از G61 حفظ شده است. فقط Windows موقت GitHub؛ هیچ تغییری روی RC کاربر نیست.

## SSPI
AcquireCredentialsHandleA/W فقط برای بستهٔ Schannel/UNISP دنبال می‌شود. InitializeSecurityContextA/W فقط context مربوط به دو نام مجاز را مرتبط می‌کند. کدهای handshake ثبت می‌شوند. SECBUFFER_DATA قبل از EncryptMessage کپی و پس از بازگشت، همراه نتیجهٔ API گزارش می‌شود؛ دادهٔ خروجی DecryptMessage فقط با SEC_E_OK خوانده می‌شود. return value و بافر برنامه تغییر نمی‌کند. handleها/کلیدها صادر نمی‌شوند؛ فقط index محلی و نام مجاز صادر می‌شود. خواندن حداکثر 32 بافر، 1MiB هر فراخوانی و 16MiB مجموع با سقف 1000 رویداد است. آدرس‌های export تکراری یک بار hook می‌شوند؛ لایه‌های wrapper متفاوت ممکن است رخداد تکراری دهند، پس API observation تعداد یکتای درخواست شبکه نیست.

رمزگشایی فقط در همین context ثبت‌شده پوشش دارد، نه همهٔ TLSها، نه OpenSSL، نه TLS داخلی دیگر. نبود داده یا شکست handshake نشانهٔ نبود فینگرپرینت نیست. دادهٔ قبل از EncryptMessage به معنای رسیدن به سرور نیست.

## کنترل مثبت TLS1.2
علاوه بر هشت کنترل قبلی، دو fixture بومی x86/x64 با SslStream روی loopback اجرا می‌شوند. گواهی self-signed فقط برای localhost در My همان runner ساخته می‌شود؛ هیچ گواهی Root یا اعتماد سراسری نصب نمی‌شود. client فقط fingerprint گواهی دقیق ساخته‌شده را می‌پذیرد و با TcpClient فقط به loopback وصل می‌شود. اعتماد زنجیرهٔ عمومیِ گواهی مصنوعی آزموده نمی‌شود؛ این کنترلِ پین‌شده برای سنجش مشاهدهٔ متن در TLS واقعی است، نه آزمون اعتبارسنجی PKI بتل‌نت. callback مخصوص fixture است و هیچ تغییری در اعتبارسنجی TLS برنامهٔ اصلی نمی‌دهد. کلاینت و سرور باید دادهٔ مشخص را دقیق دریافت کنند و ناظر هم همان متن را قبل از EncryptMessage و بعد از DecryptMessage ببیند. حالت localhost در هوک فقط با پرچم مخصوص fixture فعال است؛ اجرای واقعی این پرچم را ندارد.

گواهی My پس از کنترل حذف و حذفش بررسی می‌شود؛ اصلاً Root trust ساخته نمی‌شود. گذشتن این cleanup شرط لازم اجرای installer است؛ fallback workflow نیز state باقی‌مانده را پاک می‌کند. کنترل اعتماد localhost در زمان اجرای installer وجود ندارد. فقط متادیتای پالایش‌شده منتشر می‌شود، نه متن درخواست/پاسخ واقعی، لاگ خام یا دادهٔ سیستم. TLS کنترل موفق با TLS بتل‌نت یکی فرض نمی‌شود.
