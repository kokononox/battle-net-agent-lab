# مسیر جدید: فقط دو مقصد، نه آزمایش ضرورت تلمتری

دو نام تأییدشده کاربر فقط us.version.battle.net و level3.blizzard.com هستند؛ level3.ssl.blizzard.com جزو مجازها نیست. بررسی تأثیر تلمتری بر نصب از این طرح حذف شده است. هدف نهایی، نصب با فقط همین دو مقصد و سپس استخراج/تفکیک محتوای درخواست‌های همین دو است؛ مجاز بودن مقصد به معنی مجاز بودن همه داده‌های ارسالی نیست.

G1 فقط دروازه شبکه را روی Windows-2025 موقت و بدون دانلود/اجرای نصب‌کننده اعتبارسنجی می‌کند. نسخه منجمد Unified Firewall 0.9.10 و داده‌های کاربر دست‌نخورده‌اند. این مرحله نتیجه نصب یا طبقه‌بندی محتوای Battle.net نیست.

## محدودیت خروجی
درگاه واسط EXE اختصاصی فقط HTTP با Host دقیق روی ۸۰ یا CONNECT روی ۴۴۳ می‌پذیرد. CONNECT به تنهایی کافی نیست: قبل از بازکردن اتصال بیرونی، ClientHello باید SNI دقیق و یکسان با مقصد مجاز داشته باشد. ECH، نبود SNI، نام دیگر، IP خام، زیر‌دامنه دیگر و ناسازگاری Host/authority رد می‌شوند. فقط IPهای عمومی از پیش حل‌شده همین دو نام قابل استفاده‌اند؛ در طول محدودیت، خود واسط DNS خارجی نمی‌فرستد.

فایروال ویندوز روی هر سه profile فعال و default outbound Block می‌شود؛ Allowهای محلی موجود غیرفعال می‌شوند. فقط EXE واسط می‌تواند به IPهای پین‌شده دو نام، TCP 80/443 وصل شود. فرایندهای نصب و فرزندانشان استثنای خروج مستقیم ندارند؛ UDP، QUIC و DNS خارجی هم Allow ندارند. دسترسی loopback برای ارتباط با واسط/IPC محلی است، نه مقصد خارجی. نگاشت IP مشترک به تنهایی معیار تشخیص دامنه نیست؛ کنترل Host و SNI هم اعمال می‌شود.

تنها استثنای مدیریت مربوط به EXEهای واقعی Runner.Listener و Runner.Worker گیت‌هاب است تا خود محیط آزمایش قابل کنترل بماند؛ این استثنا به Setup، Agent یا فرزندان عادی آن‌ها اعطا نمی‌شود. پس ادعای «تمام شبکه VM فقط دو مقصد دارد» نمی‌کنیم؛ محدودیت مربوط به ترافیک نرم‌افزار نصب است. وجود Allow مؤثر دیگری در ActiveStore باعث رد دروازه می‌شود.

G1 مسیر مستقیم IPv4 از harness به دو مقصد مجاز و یک مقصد منفی با baseline سالم را آزمایش می‌کند: همه باید مستقیم رد شوند و HTTP از واسط به دو مقصد پاسخ بگیرد. نام ثالث و CONNECT با SNI ثالث باید توسط واسط رد شوند. IPv6/UDP در این مرحله فقط از پیکربندی فایروال پوشش سیاستی دارند؛ نبود مسیر قابل‌آزمایش یا نبود packet capture با اثبات عملی همه مسیرها اشتباه نمی‌شود. وضعیت qualified_proxy_and_ipv4_gate، تأیید همه مسیرهای شبکه یا همه پروتکل‌ها نیست.

## بازیابی و مرز شواهد
پیش از محدودیت، export بومی سیاست فایروال و اثرانگشت فیلدهای تغییرپذیر گرفته می‌شود. task مستقل SYSTEM برای import خودکار backup بعد از ۱۸۰ ثانیه باید ثبت شود، سپس محدودیت اجازه اجرا دارد. در finally سیاست import و فیلدهای تغییرکرده بررسی می‌شوند؛ تنها پس از تأیید، task حذف می‌شود. خطای بازیابی نتیجه را stopped می‌کند.

TLS شکسته یا رمزگشایی واسط نمی‌شود؛ CA جدید یا غیرفعال‌کردن اعتبارسنجی گواهی نداریم. کنترل SNI، Host و مقصد هنوز محتوای درون HTTPS یا HTTP Host رمز‌شده را نشان نمی‌دهد. آن بخش باید بعداً در مرز API برنامه و پیش از رمزگذاری بررسی شود. raw trace، backup فایروال، مسیرهای خصوصی، شناسه‌ها، header/body یا فایل اجرایی به artifact عمومی راه ندارد. محدودیت‌های پروکسی یا برنامه‌ای که از پروکسی استفاده نمی‌کند، نباید به اشتباه «دو دامنه برای نصب کافی نیستند» تفسیر شوند.


## G2 — هدایت شفاف، نه اتکا به تنظیم پروکسی برنامه
G1 در run 40161062734، اعمال/تأیید/بازیابی فایروال و رد مسیر مستقیم هر سه fixture را ثبت کرد. پاسخ HTTP آزمون HEAD ریشه برای us.version تأیید نشد؛ نتیجه G1 عمداً stopped باقی می‌ماند و به عنوان دروازه تأییدشده یا نتیجه نصب گزارش نمی‌شود. از آن داده علت دقیق این پاسخ‌ندادن مشخص نیست.

G2 پیش از هر محدودیت، GET واقعی /agent/versions را برای us.version و GET / را برای level3 از همان واسط آزمایش می‌کند. تنها با baseline HTTP سالم، ادامه ممکن است. برای حذف وابستگی به اینکه نصاب تنظیمات پروکسی را رعایت می‌کند یا نه، چهار listener محلی HTTP/TLS روی IPv4 و IPv6 برقرار می‌شود. فقط دو نام دقیق، پس از backup فایل hosts و ثبت watchdog، به 127.0.0.1 و ::1 هدایت می‌شوند؛ IPهای بیرونی اصلی از قبل و مستقل پین شده‌اند تا recursion پیش نیاید. یک فرایند تازه باید فقط پاسخ loopback برای هر دو نام ببیند.

HTTP مستقیم برنامه با Host اصلی و TLS خام با SNI اصلی در listener محلی دریافت می‌شوند و فقط پس از تطبیق نام به IP پین‌شده همان نام می‌روند. TLS تا سرور اصلی ادامه دارد، نه TLS با گواهی واسط. درخواست HTTP درون HTTPS هنوز رمز‌شده است و درباره محتوای آن ادعا نمی‌شود. IPv4/IPv6 loopback، رد نام ثالث و SNI ثالث، پاسخ سالم دو مقصد و بسته‌بودن TCP مستقیم از harness زیر فایروال آزمایش می‌شوند. این مرحله همچنان packet capture یا اثبات جامع UDP/IPv6 خارجی نیست.

بازیابی فایل hosts نیز به finally و watchdog اضافه شده و در تعارض با تغییر دیگران، بازنویسی نمی‌شود. G2 همچنان **بدون نصب‌کننده** است. قبل از استفاده برای نصب واقعی، rollback باید ابتدا job-object متعلق به نصب‌کننده و همه فرزندانش را terminate و خالی‌شدنش را تأیید کند، سپس محدودیت شبکه را بردارد؛ بازگردانی خودکار صرف فایروال در حالی که Setup هنوز زنده است برای نسخه نصب مجاز نیست.
