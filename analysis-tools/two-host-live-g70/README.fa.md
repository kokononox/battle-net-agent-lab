# G70 — ردیابی محدود منشأ کلید نامنطبق
فقط برای پرسشِ باز G69: leaf مسیر نامنطبق پیش از ارسال، در کدام خواندن فایل یا پاسخ ورودی دیده می‌شود و پشتهٔ ارسال از کدام offset نسبی Agent می‌گذرد؟ مرجع عمومی G69 بدون lookup یا دانلود تازه بازاستفاده می‌شود. بایت خام فایل/شبکه، نام فایل، مسیر، کلید، query و Range در artifact یا log نوشته نمی‌شوند. دادهٔ خام فقط در RAM runner برای equality می‌ماند؛ retention برابر 32MiB FIFO و سقف capture هر process برابر 128MiB است.

دریافت موفق recv، WSARecv با completion فوری، ReadFile همگامِ فایل از نوع disk، پاسخ WinINet/WinHTTP و plaintext نسخهٔ SSPI در دامنهٔ قبلی بررسی می‌شود. کلید فقط در RAM به نمایش ASCII lower/upper، UTF16LE lower و binary16 تبدیل و جست‌وجو می‌شود. 63 بایت overlap فقط برای stream شبکه/SSPI نگه داشته می‌شود، نه ReadFile که ممکن است seek داشته باشد. close باعث قطع tail می‌شود. بایت‌ها ممکن است payload رمز‌شده یا فشرده باشند؛ منفی شدن جست‌وجو علت را رد نمی‌کند. mmap، I/O pending و خروجی decompression پوشش کامل ندارند. شمار gaps/eviction گزارش می‌شود.

پشته‌ها فقط نام دستهٔ ماژول و offset نسبی دارند؛ مطلق ASLR، symbol، نام آزاد و مسیر صادر نمی‌شوند. برابر بودن کلید با بایت قبلی فقط evidence وقوع قبلی است: نه اثبات وابستگی علّی، نه عمومی بودن دادهٔ دریافت‌شده، نه نبود fingerprint. تقدم در گزارش یعنی ترتیب دریافت observationها، نه ساعت دقیق اجرای threadها. کلید خارج از مرجع همچنان unknown می‌ماند.

90 تست کشف شد؛ Linux یک تست Windows را skip کرد. کنترل‌های بومی جدید x86/x64 سه کلید synthetic را به ReadFile، recv و WSARecv وصل می‌کنند؛ 10 کنترل قبلی هم لازم‌اند. شکست هر کنترل پیش از installer مانع اجرای target می‌شود. تست‌ها و fixtureها در loopback اجرا می‌شوند و از آمار واقعی جدا هستند.

سیاست شبکه، revocation/TLS، تشخیص process و محدودیت UI عوض نشده‌اند. فقط دو مقصد قبلی و استثنای قبلی مدیریت CI؛ نه login، نه Install click و نه دانلود کامل. 0.9.10 و main دست‌نخورده‌اند. فقط یک اجرای 120ثانیه‌ای؛ تکرار خودکار پس از شکست وجود ندارد. گزارش هیچ unknown را مجاز اعلام نمی‌کند.

برای جلوگیری از تکرار catalogهای بزرگ، compose.py تمام فایل‌های پایهٔ G69 را با SHA256های ثابت base-manifest.json کنترل می‌کند، نسخهٔ محلیِ مرحله را در analysis-tools/two-host-live-g70-runtime می‌سازد و فقط overlayهای همین پوشه را اعمال می‌کند. JSONهای پین‌شده byte-for-byte حفظ می‌شوند. این کار تغییری در فایل‌های G69 ایجاد نمی‌کند.

اولین آماده‌سازی 40292278079 قبل از هر اجرای target متوقف شد: hashes محلی تمام فایل‌های پایه با blob SHAهای commit یکسان بودند؛ checkout ویندوز برای byte pin مناسب نبود. compose اکنون bytes را از git show HEAD:path می‌خواند و سپس همان SHA256 ثابت را کنترل می‌کند؛ به‌جای پذیرش پایان‌خط متفاوت یا حذف pin. این یک اصلاح پیش‌اجراست؛ target قبلی برای تکرار وجود نداشت.
