# G63 — کش گواهی با اعتبارسنجی سخت‌گیرانه

مبنای G62: کنترل TLS واقعی x86/x64 موفق؛ در مسیر واقعی us.version.battle.net کد CRYPT_E_REVOCATION_OFFLINE ثبت شد. این آزمایش صرفاً کفایت آماده‌سازی کش را می‌سنجد و موفقیت دانلود را از پیش فرض نمی‌کند.

## ترتیب
1. ده کنترل قبلی باید بگذرند و گواهی fixture حذف شده باشد. نصب‌کننده هنوز اجرا نشده است.
2. Prepare همان دو نام، IP snapshot و دانلود/امضای bootstrap را آماده می‌کند.
3. helper مستقل پیش از blocking، فقط به یکی از IPv4های snapshot مربوط به us.version.battle.net روی 443 وصل می‌شود و SslStream معمول با SNI همان نام، TLS1.2 و checkCertificateRevocation=true اجرا می‌کند. callback پذیرش گواهی ندارد، هیچ دادهٔ کاربردی HTTP ارسال نمی‌کند. Windows ممکن است طبق اعتبارسنجی عادی اطلاعات CA/ابطال را در این مرحلهٔ آماده‌سازی دریافت و cache کند؛ مرحلهٔ آماده‌سازی هنوز ایزوله نیست، مانند دانلود bootstrap و dependencyهای قبلی.
4. X509Chain با RevocationMode.Online، RevocationFlag.ExcludeRoot و VerificationFlags.NoFlag باید معتبر باشد. گواهی‌های عمومی زنجیره فقط خصوصی و موقت در runner ذخیره می‌شوند؛ هیچ Root یا CA دست‌ساز نصب نمی‌شود.
5. همان فایروال دو مقصد و استثنای مدیریت CI اعمال و hosts محلی تأیید می‌شود.
6. process مستقل زنجیرهٔ ذخیره‌شده را با RevocationMode.Offline و همان NoFlag بررسی می‌کند. این mode فقط سیاست نام‌دار offline بررسی ابطال است، نه پذیرش خطا؛ Chain.Build باید true باشد. اعتبارسنجی نام در TLS آنلاین اولیه انجام می‌شود؛ X509Chain آفلاین خودش آزمون hostname نیست. ExtraStore شامل همان گواهی‌های زنجیرهٔ معتبر اولیه است، نه trust anchor جدید.
7. فقط اگر هر دو مرحله موفق باشند، installer تحت محدودیت اجرا و SSPI/محتوا مانند G62 مشاهده می‌شود. اگر کافی نباشد، اجرا متوقف و نتیجهٔ شکست گزارش می‌شود.

هیچ registry flag، trust callback، جایگزینی return value، خاموش‌کردن revocation یا استثنای جدید شبکه برای برنامه اضافه نمی‌شود. API برنامهٔ اصلی عوض نمی‌شود. موفقیت helper تضمین استفادهٔ installer از همان cache/زنجیره/سیاست یا بازتولید تمام محیط کاربر نیست؛ باید از SSPI واقعی نتیجه را دید. اعتبار پاسخ‌های cache را Windows در زمان Chain.Build ارزیابی می‌کند؛ این آزمایش عمر مستقل OCSP/CRL را صادر یا ادعای ماندگاری نامحدود نمی‌کند.

همه چیز روی Windows موقت GitHub و شاخهٔ پژوهشی است. فایل/تنظیم RC کاربر تغییر نمی‌کند. گزارش تنها boolها، نوع ثابت خطا و status flags است؛ certificate DER، IPها، pathها، URLهای CA، header/body و متن خام منتشر نمی‌شود. ترافیک زمان آماده‌سازی با ترافیک installer قاطی نمی‌شود.
