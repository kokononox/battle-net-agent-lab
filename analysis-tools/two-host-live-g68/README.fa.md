# G68 — مسیر کاملِ مستقل و حسابداری ارسال مشاهده‌شده

هدف: تفکیک انتخاب اشیای عمومی دانلود از مسیر/مقدار ناشناخته، و مشخص‌کردن منشأ بایت‌هایی که parser HTTP نمی‌شناخت. مشاهده‌گر هنوز مجوز معنایی صادر یا محتوا را فیلتر نمی‌کند.

## مرجع پیش از مشاهده
12 GET ثابت مستقل برای metadata عمومی agent و bna انجام شد؛ 80275 بایت بدنه دریافت شد. از versions/cdns رسمی و configها با MD5 محتوایی منطبق با کلید، و DL با کنترل EKey/BLTE/chunk/CKey/اندازه، 1241 مسیر کامل مرجع استخراج شد. مسیرهای اضافهٔ size/patch-index نیز فقط از همان BuildConfig معتبر گرفته شدند. manifest و config عمومی دریافت شدند، نه فایل اجرایی یا بدنهٔ آرشیو.

دریافت پژوهشی از us.cdn.blizzard.com، همان HTTPS اعلام‌شده در cdns و استفاده‌شده در G43، بود. این مقصد صرفاً برای ساخت مرجع مستقل است و به allowlist runtime برنامه اضافه نشده است. اطلاعات PKI/مرجع از ترافیک installer جداست. هیچ ورودی installer به fetcher داده نشد. proxy/cookie/auth/redirect/query و بدنهٔ درخواست در fetcher وجود ندارند؛ TLS عادی سیستم و hostname verification فعال‌اند. هیچ policy یا CA تغییر نکرده است. یک بار خطای عدد مورد انتظار تست مصنوعی HTTP (23 به‌جای طول واقعی 24) اصلاح شد؛ قبل از هر push، تمام 70 تست گذشتند.

public-reference-fixtures.json، بایت‌های عمومی 12 دریافت را حفظ می‌کند. SHA256 هر receipt، MD5 configها، EKey/CKey و تمام مسیرهای DL در تست‌های آفلاین بازاعتبارسنجی می‌شوند. catalog با SHA256 ثابت پین شده است؛ پین محلی جای امضای ناشر را نمی‌گیرد. codecهای خالص BLTE/DL از public-manifest-g43/manifests.py در commit f1aa3a0344ff5e3329ec31853c560cbaec4f9dbf استخراج شدند. build_public_reference.py فقط روش پژوهشی بازتولید است و workflow آن را اجرا نمی‌کند.

## مقایسه
فقط equality کل path بدون query پذیرفته می‌شود. hash شبیه، prefix، query اضافه، مسیر درصدکدگذاری‌شده، fanout غلط، suffix و slash اضافه به تطابق تبدیل نمی‌شوند. path و Range خام صادر نمی‌شوند. Range اگر اندازهٔ شیء معلوم باشد فقط از نظر حدود سنجیده می‌شود؛ تطابق با رکورد archive و نبود کانال شناسه در Range اثبات نمی‌شود. هیچ مسیر ناشناخته یا hostname metadata به مجوز تبدیل نمی‌شود.

## پوشش مشاهده
TransportAudit ورودی پذیرفته‌شدهٔ send/WSASend زیر پوشش فعلی را به HTTP candidate، رکوردهای کامل TLS، opaque و ناقص تفکیک می‌کند. تمام بایت‌ها باید حسابداری شوند. نوع رکورد TLS رمزگشایی نیست؛ ciphertext به plaintext SSPI یک‌به‌یک منتسب نمی‌شود. hook خواندنی closesocket، مرز reuse سوکت را برای parserها جدا می‌کند؛ return value یا buffer برنامه تغییر نمی‌کند.

همهٔ شواهد همچنان محدود به فرایندها، APIها و زمان مشاهده‌اند. TIME_WAIT/PID صفر با مالک زنده اشتباه نمی‌شود، اما snapshotها پیوسته نیستند. coverage_complete=false باقی است؛ این مرحله دانلود کامل را اجرا نمی‌کند. همان ویندوز موقت، بررسی کامل گواهی/ابطال، دو مقصد قبلی و استثنای قبلی مدیریت CI، کنترل بومی پیش از نصاب، یک Continue شناخته‌شده و cleanup باقی‌اند. 0.9.10 و main تغییر نمی‌کنند.
