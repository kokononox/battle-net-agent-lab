# چرخهٔ عمر host_id — مرحلهٔ اول، فقط توقف و اجرای مجدد فرایند

دو startup محدود پیش از حساب روی **همان runner موقت GitHub**، با همان bootstrapper دارای pin و امضای معتبر. مرحلهٔ اول از driver بدون تغییر H3/e7 استفاده می‌کند: تنظیم LSO، آزمون بومی x86/x64 و observer محافظت‌شدهٔ ماشین تمیز. مرحلهٔ دوم فقط پس از خروج تمام فرایندهای مرتبط، همان فایل Setup را در همان مسیر اجرا می‌کند. فایل‌ها، registry و پیکربندی بین دو مرحله پاک یا ویرایش نمی‌شوند.

- اقدام رابط کاربری فقط helper موجودِ صفحهٔ دقیق زبان، یک بار در هر startup است. هیچ Install، پذیرش توافق، ورود یا دانلود بازی درخواست نمی‌شود.
- در مرحلهٔ دوم فرایند ریشه و فرزندان پیش از resume ابزارگذاری و تصویرشان با Authenticode و هویت PID بررسی می‌شود؛ child environment فاقد توکن GitHub است.
- نام‌گذاری host_id فقط برای Agent با SHA-256 نگاشت ایستای تأییدشده انجام می‌شود. فقط context `/1/4/1` رویداد StartAgent دارای hardware معتبر، UUIDv4 استاندارد و مقصد POST تله‌متری پذیرفته می‌شود.
- مقادیر فقط در حافظه برای مقایسهٔ equality می‌مانند. شناسه، hash شناسه، نام ماشین، بدنه، کلید TLS، capture و باینری artifact یا commit نمی‌شوند. UUID موجود در unit test کاملاً مصنوعی است.
- تنها یک شناسهٔ یکتا در هر مرحله و صفر خطا/افت collector، ابزارگذاری تمام فرایندها، pin معتبر و گذر gate اجازهٔ نتیجهٔ برابر/متفاوت می‌دهد. نبود داده یا چند شناسه، نتیجهٔ نامشخص است.
- ارسال ciphertext تا شبکه توسط همان correlator سخت‌گیر H3 بررسی می‌شود؛ این شرط را با پذیرش/ذخیرهٔ سرور اشتباه نمی‌گیریم. مقایسهٔ شناسه به معنی اثبات اتصال به حساب نیست.

## مرز نتیجه

حتی اگر شناسه برابر باشد، فقط ماندگاری در **توقف و اجرای مجدد فرایند روی همان ماشین و پیکربندی** ثابت می‌شود؛ نه ری‌استارت ویندوز، حذف/نصب مجدد، یکتایی جهانی، HWID دائمی یا علامت‌گذاری فایل WoW. این آزمایش شامل نصب کامل Desktop App نیست. مرحلهٔ اول و دوم warm/cold متفاوت‌اند و تغییر مجموعهٔ فرایندها/رویدادها باید در نتیجه دیده شود. در صورت تفاوت شناسه هم نمی‌گوییم «غیرقابل ردیابی».

آزمون‌ها: `python -m unittest discover -s analysis-tools/prelogin-host-lifecycle -p 'test_*.py' -v`.

Workflow به branch تحقیق، commit message یکتا و run_attempt=1 محدود است؛ فقط JSON پس از اعتبارسنجی allowlist منتشر می‌شود. اجراهای گزارش یا تغییر docs هدف را دوباره راه نمی‌اندازند.

## a5: شناسایی فقط‌خواندنی فرزند ردشده

پیش از رد و بدون resume، فایل PE حداکثر ۱۲۸ MiB خوانده و هش می‌شود؛ WinVerifyTrust با همان سیاست trust/revocation اصلی و نام ناشر از signer تأییدشده اجرا می‌شود. خروجی ناشر فقط یکی از blizzard/microsoft/other_verified/unverified است. نام فایل تنها از فهرست ثابت عمومی و مسیر فقط به صورت طبقهٔ محل گزارش می‌شود؛ subject، مسیر، command line و شناسهٔ ماشین صادر نمی‌شوند. تغییر فایل حین بررسی موجب حذف ادعای metadata معتبر می‌شود. هش این قسمت، هش فایل اجرایی است نه هش host_id. حتی امضای معتبر هم خودکار اجازهٔ اجرا نمی‌دهد: `execution_authorized=false` و فهرست مجاز فرایندها بدون تغییر مانده است.

## a6: مجوز محتوایی محدود AgentHelper.exe

فرزند a5 به‌صورت معلق بررسی شد: WinVerifyTrust=0، ناشر Blizzard، فایل 3,642,064 بایتی با SHA-256 `a3a444e6bd163732a648967c01a5fd509f7f33d6963b381c19bdffb604138651`. مقایسهٔ فقط‌خواندنی ZIP خصوصی کاربر دو فایل هم‌هش با basename برابر AgentHelper.exe یافت. مجوز جدید فقط همین basename+hash، امضای معتبر Blizzard، فرزند مستقیم Agent تأییدشده با یکی از دو hash از قبل دیده‌شده، هویت زندهٔ والد ثابت، پوشهٔ مشترک نسخه زیر ProgramData/Battle.net/Agent و مسیر فاقد reparse را می‌پذیرد. helper نیز قبل از resume ابزارگذاری می‌شود. این مجوز شامل cmd، سایر ناشران یا سایر نسخه‌های helper نیست.
