# G39 — قرنطینهٔ خصوصیِ HTTP پیش از ارسال

نمونهٔ آفلاین برای اصلاح شکاف hash-only در شواهد قبلی است. proxy یا سرور شبکه ندارد، به G34/G37 متصل نشده و هیچ درخواست ناشناخته‌ای را مجاز نمی‌کند. مسیرهای قبلی و main تغییر نکرده‌اند.

## جریان داده
`QuarantineGate.inspect_http(raw)` درخواست کاملِ ازقبل‌بافرشده را دریافت می‌کند. فقط HTTP قابل‌مشاهده با GET/HEAD/POST و Host دقیق همان دو میزبان را می‌پذیرد. پارسر قبل از ذخیره‌سازی، حد اندازه، CRLF، Host یکتا، Content-Length دقیق، نبود Transfer-Encoding و نبود درخواست اضافه/پایپ‌لاین را کنترل می‌کند. TLS/CONNECT وارد این مسیر نمی‌شوند. این پارسر فایروال یا مرز HTTP production نیست.

تمام ورودی‌ها blocked باقی می‌مانند؛ هیچ تابع upstream یا callback عبور در API وجود ندارد. در حالت قابل ثبت، یک رکورد خصوصی با path، query و headerها ساخته می‌شود و وضعیت آن pending/approval_granted=false است. Body خام و کل raw request روی دیسک ذخیره نمی‌شوند؛ فقط طول و SHA-256 بدنه در همان رکورد خصوصی قرار می‌گیرند. بنابراین بررسی معناییِ body هنوز ممکن نیست و body ناشناخته مجاز نمی‌شود.

مقادیر Authorization، Proxy-Authorization، Cookie، Set-Cookie، X-Api-Key و X-Auth-Token حتی در رکورد خصوصی حذف می‌شوند؛ فقط وجود و طول آن‌ها می‌ماند. این فهرست شناسایی جامع اسرار نیست: query/path یا header ناشناخته می‌تواند شناسه یا secret داشته باشد. همهٔ رکوردهای خصوصی بالقوه حساس‌اند.

رسید قابل انتشار فقط decision ثابت blocked، reason محدود به enum، capture_id تصادفی، private_stored و upstream_attempts=0 دارد. نام میزبان، path، hash مسیر، header، digest بدنه و شناسهٔ دستگاه در رسید عمومی وجود ندارد. خطای سیستم یا پیام ناشناخته به متن ثابت تبدیل می‌شود. تصمیم privacy-safe از این رسید قابل استنتاج نیست.

## ذخیرهٔ خصوصیِ آزموده‌شده
این backend فقط POSIX است. پوشهٔ ازقبل‌ساخته‌شده باید owner جاری و mode0700 داشته باشد؛ فایل‌ها با0600 و نام تصادفی ساخته می‌شوند. symlink نهایی پوشه، symlink/hardlink فایل، permission drift، overwrite و capture_id شامل traversal رد می‌شوند. عملیات فایل با dir_fd به پوشهٔ بازشده متصل است. سقف16رکورد/1MiB کل،262144بایت هررکورد و قفل تک‌پردازشی اعمال می‌شود؛ موجودی هنگام بازکردن دوباره محاسبه می‌شود. سقف کل درخواست32768بایت و body4096بایت است. quota یا خطای ذخیره‌سازی، هیچ مجوز عبوری ایجاد نمی‌کند.

پوشهٔ والد و کنترلر مورد اعتماد فرض شده‌اند. دفاع علیه همان کاربر محلی، root/admin، تزریق در پردازش، چند کنترلر هم‌زمان یا crash/power-loss کامل ثابت نشده است. مجوز فایل معادل رمزگذاری در حالت ذخیره نیست. هیچ TTL یا حذف امن تضمین‌شده‌ای وجود ندارد؛ سیاست نگه‌داری کوتاه و حذف توسط کنترلر آینده لازم است. فایل خصوصی را در Git/CI/artifact یا چت منتشر نکنید.

## ویندوز
هیچ ادعایی دربارهٔ ACL ویندوز نداریم. `PrivateStore` روی Windows عمداً با `windows_storage_not_validated` متوقف می‌شود. backend ویندوز باید جداگانه با ACL محدود SYSTEM/Administrators، کنترل reparse/hardlink، quota و آزمون VM معتبر پیاده و تأیید شود. این fallback نباید به ذخیره در پوشهٔ موقت یا فایل عمومی تبدیل شود.

## آزمون

```bash
python -I analysis-tools/request-quarantine-g39/run_tests.py --report evidence-local.json
```

30آزمون روی Linux/POSIX با دادهٔ ساختگی اجرا می‌شوند و ایجاد socket در مدت هر آزمون ممنوع است. فایل‌های خصوصی آزمون در TemporaryDirectory ساخته و پس از آزمون حذف می‌شوند؛ هیچ رکورد خصوصی به گزارش یا payload انتشار کپی نمی‌شود. فقط کد، تست و نتیجهٔ پالایش‌شده منتشر می‌شوند.

## ادغام آینده
این نمونه تضمین نمی‌کند پراکسی فعلی قبل از فراخوانی آن چیزی نفرستاده باشد؛ اصلاً به آن پراکسی متصل نشده است. برای ادغام واقعی، admission مالک/Job و lease باید حفظ شوند و hook قبل از هر dial/send برای درخواست ناشناخته قرار گیرد. timeout خواندن، backpressure، پاسخ محلی blocked، کنترل منابع و تست قطع/بازیابی هم لازم‌اند. ثبت اطلاعات بعد از ارسال در شبکه جایگزین پیشگیری نیست.

رکورد خصوصی تنها worksheet بررسی است: تعیین ضرورت، احتمال شناسه‌بودن فیلدها، اندازهٔ خالص و اصالت فایل و سیاست resource همچنان کار جداگانه است. پاسخ/فایل واقعی در این نمونه وجود ندارد و expected_bytes یا hash فایل از روی request ساخته نمی‌شود. HTTPS ناشناخته صرفاً با SNI یا دامنه تأیید نمی‌شود و هیچ CA، interception یا bypass TLS اضافه نشده است.
