# G14 — پایش ثبت مؤلفه تازه و بستن درگاه هنگام ناشناخته

این پوشه فقط آزمایش با مؤلفه‌های ساختگی در Windows-2025 موقت GitHub است؛ نصاب واقعی اجرا نمی‌شود. پروژه ۰.۹.۱۰ تغییری ندارد. workflow فقط با approval دقیق، شاخه پژوهش و نخستین تلاش push اجرا می‌شود.

سه ماشین مستقل: یک سرویس جدید در پوشه‌ای خارج از root شناخته‌شده، یک scheduled task جدید خارج از آن root، و یک فرزند با EXE متفاوت در Job مالک. OutsideProbe بی‌اثر و مدت‌دار است و هیچ کد شبکه‌ای ندارد.

Inventory پیش از تزریق، تعریف سرویس‌ها و XML وظایف کل ماشین را snapshot می‌کند؛ Monitor با هویت SYSTEM تغییرهای جدید و اعضای Job را بررسی می‌کند. مؤلفه تازه خودکار مجاز نمی‌شود. تصاویر کشف‌شده در دفتر خصوصی باقی می‌مانند تا صرف حذف ثبت سرویس/task، فرایند زنده را پنهان نکند. Recover با مشاهده تغییر ناشناخته یا خطای پوشش، سیاست پیش‌فرض Block را آزاد نمی‌کند؛ پروکسی دو مقصد نیز متوقف می‌شود. Driver باید هم شکست اتصال مستقیم و هم شکست اتصال loopback به پروکسی را پس از قرنطینه احراز کند.

رفع ناشناخته فقط توسط Driver آزمایش و با احراز نام، تعریف اقدام، PID/زمان ایجاد/مسیر و SHA-256 fixture انجام می‌شود. سپس اجرای جداگانه SYSTEM پایان مؤلفه‌های شناخته‌شده و بازیابی تنظیمات را بررسی می‌کند. این حذف خودکار مؤلفه‌های واقعی نیست.

محدودیت حیاتی: پایش polling است، نه سد کرنلی پیش از اولین دستور یا اولین بسته. ممکن است مؤلفه کوتاه‌عمر بین snapshotها دیده نشود؛ تا زمان تشخیص، پروکسی محلی می‌تواند قابل دسترس باشد. این مرحله نبود نشتی قبل از تشخیص، همه مسیرهای اجرای خارج از Job، یا محتوای HTTPS را اثبات نمی‌کند. تغییر نامرتبط در ثبت‌های کل ماشین نیز عمداً می‌تواند آزمون را متوقف کند؛ به‌طور خام برای نصب واقعی آماده نیست. در شکست، import بی‌قیدوشرط ممنوع و کنارگذاشتن VM موقت مجاز است. ضرورت تلمتری موضوع این مرحله نیست.
