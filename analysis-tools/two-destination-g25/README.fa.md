# G25 — پایان نصب و نقش فرایندهای کلاینت
آماده‌سازی گواهی دقیقاً همان G24 و قبل از gate است. Setup فقط پس از همان گیت دو مقصد اجرا می‌شود. هیچ ورودی حساب، کلیک جدید، مقصد یا مجوز اضافی اضافه نشده است. Desktop 0.9.10 ثابت است.

هدف تشخیص این است که نمونه‌های متعدد Battle.net.exe فرایندهای عادی چندبخشی هستند یا exit/اجرای مجدد واقعی. در لحظهٔ ایجاد، handle با زمان ایجاد و عضویت زندهٔ همان Job تطبیق می‌یابد؛ نقش فقط از switch شناخته‌شدهٔ --type و query محدود WMI خوانده و به enum تبدیل می‌شود. command line/PID/path خام صادر نمی‌شود و این داده هرگز مجوز شبکه نمی‌دهد. قبل از پایان اجباری Job، وضعیت زنده/خروج واقعی و code ثبت می‌شود. بازماندگان به‌عنوان بسته‌شونده توسط controller مشخص‌اند، نه crash.

علاوه بر UI نصب قبلی، watcher فقط‌خواندنی پنجره‌های اعضای زندهٔ Job را با مسیرهای شناخته‌شدهٔ نصب می‌بیند. هیچ عمل روی client/login انجام نمی‌شود. نام/مقدار کنترل‌های حساس طبق helper قبلی خوانده/منتشر نمی‌شود. فقط enum و وجود کنترل رمز به‌صورت bool ذخیره می‌شود. UI و processها به‌تنهایی اثبات نصب کامل نیستند.

پس از پایان Job و هنوز زیر gate، فایل‌های مشخص launcher و client مشاهده‌شده، hash/PE و Authenticode کامل با همان helper بررسی می‌شوند؛ هیچ فایل تازه اجرا نمی‌شود و failure/timeout بررسی امضا موفق تلقی نمی‌شود. رجیستری uninstall در مسیرهای ثابت فقط خوانده می‌شود. تأیید سخت‌گیرانه به کلیک معتبر نصب، خروج طبیعی صفر Setup، امضای معتبر launcher/client، ثبت صحیح نصب، بقای یک فرایند اصلی حداقل۶۰ثانیه و مشاهدهٔ کنترل‌های login در دو نمونه با فاصلهٔ۳۰ثانیه نیاز دارد. نبود شاهد به معنی شکست قطعی نصب نیست؛ completion_not_verified است. پرچم legacy installation_verified تا بازبینی شاهدها false می‌ماند.

Application error/WER1000/1001 فقط با نام‌های شناخته‌شده و codeهای محدود ثبت می‌شود؛ scope کل VM است و attribution قطعی به PID ادعا نمی‌شود. فایل‌های عمومی به۲۵۶ رکورد کاهش یافته‌اند چون artifactهای نصب به‌طور هدفمند بررسی می‌شوند. collector تعمیرشدهٔ G24 با سقف محدود حفظ شده است.
