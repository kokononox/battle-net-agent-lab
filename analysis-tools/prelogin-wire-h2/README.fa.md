# H2: پیوند پیام پیش از TLS به ارسال سوکت و بستهٔ شبکه

این آزمایش ادامهٔ سؤال اول است؛ سؤال دوم و بررسی فایل‌های WoW اجرا نمی‌شود.

## هدف و سطح اثبات

ابزار H1 ورودی EncryptMessage را می‌دید اما ciphertext سوکت را کنار می‌گذاشت. H2:

1. فقط مشاهده می‌کند: متن ورودی EncryptMessage و خروجی رمز‌شدهٔ همان فراخوانی موفق را خصوصی نگه می‌دارد.
2. خروجی رمز‌شده را با bytes پذیرفته‌شدهٔ ارسال هم‌زمان همان فرایند تطبیق می‌دهد. ارسال ناقص فقط به اندازهٔ پذیرفته‌شده حساب می‌شود.
3. همان bytes را با جریان TCP بازسازی‌شده از capture کارت شبکه تطبیق می‌دهد. این مرحله جدا از موفقیت API است.
4. برای یک درخواست HTTP/1 یگانه و کامل در context، اگر پاسخ رمزگشایی‌شده و ciphertext ورودی آن به سوکت همان اتصال و جهت معکوس capture پیوند بخورد، فقط کد HTTP را صادر می‌کند. contextهای چنددرخواستی، pipelining و HTTP/2 از این ادعای پاسخ کنار گذاشته می‌شوند.

هیچ ACK، موفقیت API یا کد HTTP به معنی اثبات ذخیرهٔ سرور نیست. کد HTTP نیز مطابق معنای خودش تفسیر می‌شود؛ مثلاً 4xx پذیرش موفق payload نیست.

## کنترل اجباری پیش از نصاب

گردش‌کار یک برنامهٔ C# متعلق به آزمایش را با compiler موجود ویندوز می‌سازد. برنامه و یک child از همان تصویر، یک HEAD ثابت به `https://example.com/` می‌فرستند. این fixture اتصال HTTPS واقعی با اعتبارسنجی پیش‌فرض گواهی دارد؛ loopback یا فراخوانی ساختگی موفق EncryptMessage نیست. نام کاربر، CPU، فایل، حساب یا اطلاعات سخت‌افزار در درخواست fixture گذاشته نمی‌شود. fixture کلید خصوصی/CA نصب نمی‌کند و callback پذیرش همهٔ گواهی‌ها ندارد.

کنترل باید هر دو فرایند را پیش از resume ثبت کند، دو درخواست را تا capture شبکه و دو پاسخ را تا جهت معکوس همان اتصال پیوند دهد و فراخوانی عمداً نامعتبر EncryptMessage را ناموفق تشخیص دهد. خطای hook، افت رویداد یا شکست هر معیار ⇒ **عدم اجرای Battle.net**. جزئیات شکست به‌صورت وضعیت/شمارش allowlist ثبت می‌شود؛ خروجی خام fixture هم عمومی نیست.

## اجرای هدف و قیود

- فقط GitHub-hosted Windows تازه، attempt اول، شاخهٔ تحقیق و commit message مشخص در workflow.
- فقط منبع رسمی موجود در `scripts/observe_agent.py`؛ SHA-256 bootstrapper در اجرای b3 باید `f4643a2086c0cecb1ab68cc601bf38c1a0a6f7ef5914ad03375cc9449385bec6` باشد (هویت نسخهٔ فعلی در بررسی مستقل c1؛ این تصویر با H1 یکسان نیست). تغییر نسخه ⇒ توقف، نه حذف pin یا جایگزینی بی‌اعلام.
- امضای Authenticode و ناشر Blizzard برای root/child، نام تصویر مجاز و هویت PID پیش از resume کنترل می‌شوند. child نامعتبر متوقف می‌شود.
- فقط یک بار انتخاب/Continue صفحهٔ زبان با guardهای فعلی مخزن؛ **بدون Install، حساب، پذیرش شروط حقوقی یا دانلود بازی**. اجرای هدف 90 ثانیه مشاهده می‌شود؛ مرحلهٔ bootstrapper از قبل از اجرا ثبت می‌شود.
- هیچ argument، return value، بافر هدف، hosts، CA، TLS verification یا keylog تغییر نمی‌کند.
- دادهٔ CPU مرجع فقط در RAM و فقط برای مقایسهٔ boolean روی VM آزمایش استفاده می‌شود. schema پیام StartAgent از تصویر دقیق صاحب پیام خوانده و hash تصویر دوباره کنترل می‌شود؛ فیلد ناشناخته ⇒ عدم تأیید سخت‌افزار.
- خام ETL/PCAP، متن درخواست/پاسخ، مسیرها، شناسه‌ها، hash شناسه و باینری upload یا commit نمی‌شوند.

## محدودیت‌ها و جلوگیری از قطعیت کاذب

- SSPI و HTTP/1 با Content-Length پوشش داده می‌شوند؛ OpenSSL/BoringSSL، QUIC، HTTP/2، framingهای دیگر و تمام فرایندهای ممکن پوشش کامل ندارند.
- تکمیل I/O غیرهم‌زمان پیاده‌سازی نشده است؛ WSASend/WSARecv هم‌پوشان یا pending «ارسال موفق» تلقی نمی‌شوند.
- نوشتن/خواندن هم‌زمان روی یک سوکت، هم‌زمانی رمزنگاری در context، شکاف capture و تطبیق غیرمنحصربه‌فرد مانع ادعای پیوند می‌شوند.
- retransmission یکسان TCP حذف می‌شود؛ overlap متناقض باعث رد آن جریان است. شکاف با حدس پر نمی‌شود. IPv4 fragment و IPv6 extension پشتیبانی‌نشده صریح شمرده می‌شوند.
- capture حلقوی 64MB ممکن است ابتدا را از دست بدهد؛ parser حداکثر فایل 128MB، 500هزار بسته و 96MB payload می‌پذیرد. نبود تطبیق ⇒ نبود ارسال نیست.
- سقف hook: هر فراخوانی تا 128KiB؛ هر فرایند تا 1024 رویداد؛ Manager تا 4096 رویداد/16MiB. رسیدن به سقف یا خطای ثبت، نتیجهٔ سخت‌افزار روی شبکه را ارتقا نمی‌دهد.
- مقایسهٔ بایت‌ها در این ابزار شاهد مستقیم محتواست ولی اثبات ریاضی تمام provenance شبکه یا دریافت پایگاه‌دادهٔ سرور نیست. checksumهای packet اعتبارسنجی نمی‌شوند؛ offload و retransmission می‌توانند ظاهر capture را تغییر دهند.
- fixture تماس خارجی و instrumentation زمان‌بندی را تغییر می‌دهند؛ runner کاملاً دست‌نخورده فرض نمی‌شود. وضعیت Battle.net پیش از اجرا باید پاک باشد.

## کنترل محلی انجام‌شده در 2026-10-24

- 32 آزمون مصنوعی parser/correlation/sanitizer پاس شدند: ارسال ناقص/شکسته، failed/async، هم‌زمانی، چند تطبیق، فرایند نامرتبط، جهت پاسخ، ترتیب و retransmission، wrap شمارهٔ TCP، overlap متناقض، fragmentation، JSON با کلید تکراری، نشت دادهٔ خام و ادعای بدون gate.
- `node --check` برای hook و `py_compile` برای ماژول‌ها پاس شدند؛ این‌ها اثبات اجرای Frida/ویندوز نیستند.
- classifier جدید با پیام واقعی baseline تاریخی H1 و تصویر هم‌هش آزمایش شد؛ سخت‌افزار و تطبیق CPU را شناخت و تصویر نادرست را رد کرد. این کنترل استفادهٔ دوباره از شاهد قبلی است، نه runtime تازه.
- اعتبارسنجی بومی و نتیجهٔ هدف باید جداگانه از JSON runtime خوانده شوند؛ این سند پیشاپیش موفقیت آن‌ها را اعلام نمی‌کند.
