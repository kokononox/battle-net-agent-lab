# G9: مهار فرزندان با داده ساختگی، نه اجرای نصب

این مرحله بدون دانلود یا اجرای Battle.net، بدون تغییر شبکه و بدون ایجاد سرویس/وظیفه اجرا می‌شود. harness اختصاصی از همین سورس روی ماشین موقت Windows-2025 برای x86 و x64 ساخته می‌شود؛ فایل اجرایی به artifact راه ندارد.

هر معماری دو حالت را بررسی می‌کند: پایان صریح Job Object و کشته‌شدن ناگهانی مالک. فرایند ریشه suspended ساخته، پیش از resume عضو job و عضویت آن بررسی می‌شود؛ فرزند عادی باید job را به ارث ببرد. درخواست breakaway باید با خطای دسترسی رد شود. هویت فرایند پیش از مشاهده خروج با handle، زمان ایجاد و مسیر EXE تطبیق داده می‌شود تا PID بازیافت‌شده شاهد قرار نگیرد. در حالت پایان صریح، تعداد فعال job باید پیش از رهاکردن handle صفر شود؛ در حالت crash، خروج ریشه و فرزند با handleهای بازشده پیش از crash بررسی می‌شود.

آزمون محدود به فرایندهای ساختگی شناخته‌شده است. سرویس‌های SCM و Scheduled Task می‌توانند خارج از این درخت اجرا شوند؛ موفقیت G9 پوشش آن‌ها، ترتیب آزادسازی شبکه، حل race با watchdog، مقاومت در برابر برنامه مهاجم Administrator یا آماده‌بودن نصب واقعی را اثبات نمی‌کند. هیچ policy فایروال در این مرحله برداشته یا اعمال نمی‌شود. فرایندها خواب کوتاه محدود دارند و Job Object دارای KILL_ON_JOB_CLOSE است.

گیت‌های باقی‌مانده: احراز/مهار سرویس و وظایف بیرون از job، آزمون fail-closed هنگام timeout/crash با درگاه شبکه و سپس ثبت درخواست‌های دو مقصد در نصب واقعی. پروژه Unified Firewall Desktop 0.9.10 تغییر نمی‌کند؛ بررسی ضرورت تلمتری از سر گرفته نمی‌شود.
