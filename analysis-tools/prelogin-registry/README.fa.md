# ردیابی محدود UserUUID پیش از حساب

آزمایش a11 فقط روی runner ویندوز موقت، همین شاخه، نخستین attempt و پیام commit دقیق مجاز اجرا می‌شود. ورود، Install، دانلود بازی، حذف/تغییر شناسه، تغییر TLS و reboot/reinstall انجام نمی‌شود.

پیش از هدف، کنترل بومی x64/x86 از کد خود پروژه اجرا می‌شود: فقط کلید مصنوعی `HKCU\Software\BattleNetAgentLab\RegistryProbe` را می‌سازد/می‌خواند/پاک می‌کند؛ با کلید Blizzard کاری ندارد. شکست کنترل مانع راه‌اندازی هدف است. کنترل واقعی JS با mock حافظهٔ دو معماری نیز پیش از اجرا پاس می‌شود.

سپس snapshot فقط‌خواندنی از حضور/نبود UserUUID گرفته می‌شود و درایور قبلاً اعتبارسنجی‌شدهٔ lifecycle با Manager دارای کانال مستقل رجیستری دو startup پیش از حساب را مشاهده می‌کند. native gate شبکهٔ پیشین نیز همچنان لازم است. Manager کپی نسخهٔ H3 با دو تغییر صریح است: ترکیب hook رجیستری با hook شبکه و کانال مستقل پیام‌های reg_. هر فرایند باید پیش از resume هر دو hook را آماده کرده باشد. محدودیت‌های امضا، pin، فرایندهای تحت مالکیت و Helper همان درایور قبلی‌اند.

## مشاهده‌گر

`RegOpenKeyExA/W`، `RegCreateKeyExA/W` و `RegCloseKey` فقط نگاشت handle را نگه می‌دارند. `RegQueryValueExA/W`، `RegGetValueA/W` و `RegSetValueExA/W` فقط برای UserUUID زیر کلید دقیق Blizzard Error مشاهده می‌شوند. پارامتر، خروجی یا دادهٔ برنامه عوض نمی‌شود. سایر مسیرها/نام‌ها منتشر نمی‌شوند. APIهای دیگری مانند فراخوانی مستقیم NtQueryValueKey پوشش داده نشده‌اند؛ نبود event دلیل نبود رفتار نیست.

مقادیر حداکثر 256 بایت، فقط در حافظهٔ ماشین، با UUID پیام سخت‌افزار مقایسه می‌شوند. فقط REG_SZ موفق و UUIDv4 دقیق معتبر است؛ موفقیت size-only شاهد مقدار نیست. تطبیق حساس به حروف است. شناسه یا hash آن، SID، آدرس حافظه و مقدارهای رجیستری در خروجی نیستند. caller_rva فاصلهٔ برگشت از ابتدای تصویر اجرایی است، نه آدرس حافظهٔ خام؛ اگر در ماژول اصلی نباشد null است.

## حدود تفسیر

- خواندن موفق مقدار برابر، شاهد مستقیم API-read است؛ بدون trace تخصیص provider، وابستگی علّی تمام مسیر host_id ثابت نمی‌شود.
- baseline غایب + write موفق برابر، ایجاد مقدار در فاصلهٔ آزمایش را پشتیبانی می‌کند؛ نه نخستین ایجاد جهانی یا یکتایی هر نصب.
- دو startup، آزمایش reboot/reinstall یا فایل WoW نیستند.
- گزارش‌های مثبت تنها پس از کنترل بومی، مشاهدهٔ پاک هر دو مرحله و پیوند پیام‌های سخت‌افزار تا شبکه مجازند؛ وضعیت ناقص ادعای مثبت نمی‌دهد.

خروجی عمومی تنها `reports/prelogin-registry-runtime.json` و خلاصه‌های whitelist شدهٔ lifecycle/شبکه است. دادهٔ خام، باینری، ETL/PCAP و کلید TLS artifact نمی‌شوند. شکست native gate هم با گزارش عمومی ثابت منتشر می‌شود، بدون اجرای هدف.
